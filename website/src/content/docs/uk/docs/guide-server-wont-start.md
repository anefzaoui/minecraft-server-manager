Працюйте за цим списком. Він упорядкований за частотою, з якою кожен пункт є відповіддю, і перші чотири охоплюють більшість випадків.

## 1. Читайте останні двадцять рядків, а не перші

Прокрутіть до **кінця** журналу. Трасування стека Java виводиться зсередини назовні, тому верхня частина стіни тексту є найменш цікавою частиною. Вам потрібен останній рядок `Caused by:` і все, що йде за ним. Цей окремий рядок зазвичай називає проблему.

Дві ознаки вказують, де ви знаходитесь:

- `Exception in thread "main"` або шлях до звіту про збій біля кінця означає, що гра сама зазнала збою.
- Журнал просто зупиняється посередині рядка, без жодного винятку, що означає, що процес було припинено ззовні. Перейдіть до пункту 3.

## 2. UnsupportedClassVersionError означає неправильну версію Java

```
java.lang.UnsupportedClassVersionError: net/minecraft/server/Main has been compiled
by a more recent version of the Java Runtime (class file version 65.0)
```

Файл класу 52 — це Java 8, 60 — 16, 61 — 17, 65 — 21, 69 — 25. Повідомлення означає, що серверу потрібна новіша Java, ніж та, на якій він працює; зворотне, старий пакет на новій Java, зазвичай призводить до помилки міксину або рефлексії.

| Версія Minecraft | Java |
| ---------------- | ---- |
| 1.16.5 і раніше  | 8    |
| 1.17             | 16   |
| 1.18 і 1.19      | 17   |
| 1.20 до 1.20.4   | 17   |
| 1.20.5 до 1.21.x | 21   |
| 26.1 і пізніше   | 25   |

Старі пакети справді потребують Java 8. Новіша версія тут не краща.

## 3. Код виходу 137 — це ядро, а не мод

Журнал зупиняється на півслові, немає звіту про збій, а контейнер повідомляє про 137. Це завершення роботи через брак пам'яті: процес запитав пам'ять, якої машина не мала, тому він був припинений.

Майже завжди розмір купи Java був встановлений на таке ж число, як і пам'ять машини. Купі потрібна пам'ять машини **мінус** власні накладні витрати JVM, які становлять 0,5–1,5 ГБ на сервері з модами. Зменште розмір купи або збільште пам'ять машини. [Скільки ОЗП потрібно серверу](/docs/guide-server-memory/) містить цифри.

## 4. EULA та порт

Дві класичні проблеми з однорядковими виправленнями:

- `You need to agree to the EULA in order to run the server.` Встановіть `eula=true` у `eula.txt` або за допомогою змінної середовища, яку використовує ваша конфігурація.
- `Address already in use` або `FAILED TO BIND TO PORT`. Щось інше займає порт 25565, часто попередня копія того ж сервера, яка ніколи повністю не зупинилася. Знайдіть її та зупиніть, а не змінюйте порт, інакше у вас буде два.

## 5. Моду не вистачає залежності

```
Mod X requires mod Y, which is missing
Fabric API is not installed
```

Моди Fabric переважно потребують Fabric API як окремий файл. Моди Forge та NeoForge перелічують свої залежності в самій помилці. Встановіть зазначену версію, а не найновішу: "requires 0.91.x" означає цей рядок, а 0.92 призведе до такої ж перевірки.

Іноді відсутньою залежністю є сам завантажувач:

```
Mod X requires forge 47.4.14 or above
Mod ID: 'forge', Requested by: 'x', Expected range: '[47.4.14,)', Actual version: '47.4.10'
```

Виправленням є новіша збірка завантажувача, а не інший мод. "47.4.14 або вище" означає будь-яку збірку від цього номера і далі, а Forge не публікує кожен номер, тому версією для встановлення може бути наступна. У модовому пакеті спочатку оновіть пакет: пакет, версія завантажувача якого занадто стара для його модів, є помилкою для його автора.

## 6. Мод призначений для неправильного завантажувача або версії

JAR-файл для іншого завантажувача не повідомляє про помилку ввічливо. Очікуйте помилку міксину, `NoClassDefFoundError` або збій у класі, про який ви ніколи не чули. Перевірте сторінку JAR-файлу: завантажувач і версія Minecraft повинні точно збігатися. 1.20.1 і 1.20.4 — це різні ігри, наскільки це стосується модів.

## 7. Світ створено новішою версією

```
This world was created by a newer version of Minecraft
```

Світи оновлюються вперед і ніколи назад. Відновіть резервну копію зроблену до оновлення або запустіть версію, яку очікує світ. Не існує шляху відкату, який би зберіг чанки неушкодженими.

## Коли збій стався після тижнів нормальної роботи

Інше питання, зазвичай інша відповідь:

- **Збій стався під навантаженням**, з показниками, що показують довгі паузи: збирач сміття, тому подивіться на розмір купи перед модами.
- **Збій стався в одній і тій же точці світу**: пошкоджений чанк або зламана сутність. Звіт про збій зазвичай містить координати.
- **Збій стався одразу після оновлення**: підозрюваним є мод, який оновився, навіть якщо трасування вказує в іншому напрямку. Відкотіть його та подивіться.
- **Збій стався під час перезапуску, хоча раніше все працювало**: перевірте диск. Повний диск призводить до вражаючих і оманливих помилок.

## Отримання допомоги, яка дійсно допомагає

Опублікуйте **весь журнал**, а не останній рядок, і скажіть, що ви змінили перед тим, як він зламався. Вставте його кудись, призначеного для цього, наприклад, [mclo.gs](https://mclo.gs), а не в чат. Включіть версію Minecraft, завантажувач, пакет і його версію, а також скільки купи має сервер. Звіт з цими чотирма фактами отримує відповідь за один раз; без них знадобиться п'ять.

## У Minecraft Server Manager

Збої виявляються за виходом самого контейнера, тому сервер, який вимикається о третій ночі, записується з уривком журналу, а не виявляється наступного дня. Звичайні підозрювані на цій сторінці (EULA, неправильна версія Java, світ з новішої версії, порт, який вже використовується, брак пам'яті Java) розпізнаються в цьому журналі та називаються в записі історії з інструкціями щодо їх усунення, а автоматичний перезапуск залишає їх у спокої, оскільки перезапуск їх не виправить. Звіти про збої аналізуються під час надходження: виняток виділяється, стек можна згортати, а моди, які з'являються в трасуванні, перелічуються як підозрювані.

Будь-який звіт можна надіслати на mclo.gs з його картки, коли вам потрібна допомога (після підтвердження, оскільки публікація є публічною), а меню **Завантажити** консолі містить усі файли журналу в одному zip-архіві, тому "опублікувати весь журнал" — це завантаження, а не археологічний проект. Збій через брак пам'яті записується як збій через брак пам'яті, що заощаджує звичайну годину на звинуваченні мода. Якщо щось інше справді потребує порту, картка **Ігровий порт** на **Налаштування → Конфігурація** переміщує сервер на вільний.

Занадто старий завантажувач змінюється на вкладці **Версії** сервера, яка перевіряє наявність збірки та робить резервну копію перед перебудовою сервера ([зміна версії завантажувача модів](/docs/updates/#changing-the-mod-loader-version)).
