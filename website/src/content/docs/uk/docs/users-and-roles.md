Панель є багатокористувацькою. Керуйте обліковими записами в розділі **Налаштування → Користувачі**.

![Користувачі](/docs/images/settings-users.png)

## Три ролі

| Роль         | Можливості                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **admin**    | Все: керування користувачами, ключами API, глобальними файлами, розширеними налаштуваннями Docker та всіма діями сервера.                   |
| **operator** | Запуск та налаштування серверів (запуск/зупинка, консоль, резервні копії, світи, моди, більшість налаштувань), але не адміністративні зони. |
| **viewer**   | Лише для читання. Перегляд серверів та їхнього статусу, без можливості внесення змін.                                                       |

Кожен користувач, включно з переглядачем, може керувати власною [двофакторною автентифікацією](/docs/two-factor-authentication/), оскільки захист власного входу не є дією з керування сервером.

## Лише для адміністраторів, і чому

Деякі речі навмисно обмежені для адміністраторів:

- **Керування користувачами, ключі API та глобальні файли.**
- **[Публічний API](/docs/public-api/)** — увімкнення `/api/v1` та створення, визначення області дії або відкликання його токенів Bearer лише для читання.
- **Розширені налаштування Docker** — власна назва контейнера, додаткові публікації портів та прив'язка томів. Прив'язка тому може відображати будь-який шлях хоста в контейнер, а в поєднанні з доступом панелі до Docker це фактично root на хості. Ці поля з'являються лише для адміністраторів.

Власні назви контейнерів також не можуть знаходитися у власному просторі імен панелі `msm-`, тому контейнер, названий вручну, ніколи не зможе затінити інший сервер і перенаправити зупинку або команду на неправильний екземпляр.

## Керування обліковими записами

![Зображення профілю](/docs/images/profile-picture.png)

Адміністратори можуть створювати користувачів, змінювати ролі, скидати паролі та видаляти облікові записи з таблиці користувачів. Колонка **2FA** показує, чи ввімкнено двофакторну автентифікацію для кожного користувача; адміністратор може **скинути** 2FA іншого користувача (у випадку втрати телефону та резервних кодів), але ніколи не може вимкнути свою власну без свого пароля, що обробляється самостійним потоком.

Невдалі спроби входу обмежені за кількістю для кожного облікового запису (як за IP-адресою, так і глобальним лічильником для облікового запису), щоб уповільнити спроби підбору пароля, і те саме обмеження поширюється на крок коду 2FA, тому правильний пароль не може скинути лічильник до вгадування коду. Перед цим знаходиться більш грубий обмежувач запитів за IP-адресою клієнта для кінцевих точок входу / 2FA / налаштування, який можна налаштувати за допомогою `RATE_LIMIT_AUTH_PER_15MIN` (за замовчуванням 100; за зворотним проксі-сервером встановіть `TRUST_PROXY`, щоб він використовував реальну IP-адресу клієнта).
