Панель підтримує кількох користувачів. Керуйте обліковими записами в розділі **Налаштування → Користувачі**.

![Користувачі](/docs/images/settings-users.png)

## Три ролі

| Роль              | За замовчуванням для кожного сервера                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **адміністратор** | Усе: керування користувачами, ключами API, глобальними файлами, розширеними переозначеннями Docker та всіма діями сервера.                             |
| **оператор**      | Запуск та налаштування серверів (старт/стоп, консоль, резервне копіювання, світи, модифікації, більшість налаштувань), але не адміністративні області. |
| **переглядач**    | Тільки для читання. Перегляд серверів та їхнього стану, але без внесення змін.                                                                         |

Кожен користувач, включно з переглядачем, може керувати власною [двофакторною автентифікацією](/docs/two-factor-authentication/), оскільки захист власного входу не є дією з керування сервером.

Роль є **типовою** для кожного сервера. Щоб надати комусь інші права на одному сервері, використовуйте дозволи для окремих серверів нижче.

## Дозволи для окремих серверів

Сторінка **Дозволи** (у бічній панелі або **Дозволи сервера** в розділі **Налаштування → Користувачі**) показує таблицю: оператори та переглядачі збоку, сервери — зверху. Клацніть комірку, щоб визначити, що цей користувач може робити на цьому конкретному сервері. Адміністратори не перелічені, оскільки вони завжди мають доступ до всього.

![Дозволи](/docs/images/settings-permissions.png)

Кожна комірка — це набір дозволів:

| Дозвіл                  | Що дозволяє на цьому сервері                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Перегляд**            | Перегляд сервера, його стану, виведення консолі, гравців, історії та статистики.                                                |
| **Керування**           | Запуск, зупинка, перезапуск, завершення та перезбирання сервера.                                                                |
| **Консоль**             | Виконання команд консолі та швидких дій зі світом, надсилання чату та керування командами чату.                                 |
| **Гравці**              | Вигнання, блокування, додавання до білого списку, надання прав оператора та редагування приміток гравців.                       |
| **Контент**             | Встановлення та видалення модів, плагінів, пакетів, світів, датапаків та редагування інвентарю.                                 |
| **Резервне копіювання** | Створення, відновлення, завантаження та видалення резервних копій.                                                              |
| **Файли**               | Перегляд, редагування, завантаження та вивантаження файлів сервера, архівування журналів та пакетів журналів; експорт шаблонів. |
| **Налаштування**        | Зміна налаштувань сервера, властивостей, інтеграцій, значка та версій оновлення.                                                |
| **Видалення**           | Видалення сервера.                                                                                                              |

![Редактор дозволів](/docs/images/permissions-editor.png)

Під таблицею **Що охоплює кожен дозвіл** розкриває кожен дозвіл, показуючи, що може робити людина, що не включено, та точні шляхи в панелі, які він відкриває. Останній список перевіряється тестовим набором на відповідність коду, що виконується.

![Довідник дозволів](/docs/images/permissions-reference.png)

На телефоні таблиця складається в одну картку для кожного користувача з рядком для кожного сервера.

Як частини взаємодіють:

- **Роль — це типове значення.** Оператор отримує всі дозволи на всіх серверах; переглядач — лише "Перегляд". Комірка блідим текстом (у підказці написано "Типове значення ролі") ніколи не змінювалася.
- **Комірка перевизначає роль лише для цього сервера.** Надайте переглядачу "Керування" та "Консоль" на одному сервері, і він зможе його запускати, тоді як усі інші сервери залишаться для нього доступними лише для читання. Заберіть "Видалення" в оператора на вашому основному сервері, і він збереже все інше там.
- **Кожен дозвіл включає "Перегляд".** Ви не можете діяти на сервер, який не можете бачити.
- **Вимкніть усе, щоб приховати сервер.** Він зникає з бічної панелі користувача, інформаційної панелі, резервних копій, розкладів, активності, оновлень, пакетів модів, поточного стану, запущених завдань та шаблонів, а бібліотека світів припиняє його згадувати. Пряме посилання, виклик API або сокет консолі відповідає "не знайдено", так само як і сервер, що не існує.
- **Дії, що охоплюють усю панель, все ще відповідають ролі.** Створення серверів (включно з клонуванням), сховище, користувачі, ключі API, глобальні налаштування та глобальні розклади не є специфічними для сервера, тому переглядач із дозволами на деяких серверах все одно не зможе виконати жодну з цих дій. Оператори зберігають можливість створювати сервери та використовувати глобальні розклади; сховище, користувачі, ключі API та глобальні налаштування доступні лише адміністраторам.
- **Розклади прив'язані до сервера.** Запланований перезапуск, резервне копіювання або команда на сервері вимагає відповідного дозволу там (Керування, Резервне копіювання або Консоль), незалежно від ролі.
- **Шаблони також прив'язані до сервера.** Експорт сервера як шаблону вимагає дозволу "Файли", оскільки архів містить його файли. Шаблон, експортований із сервера, який хтось не може бачити, також прихований від нього.
- **Області, доступні лише адміністраторам, залишаються такими** на кожному сервері: чат-бот, збереження резервних копій та розширені переозначення Docker.

Кожна зміна записується до журналу активності із зазначенням того, хто що змінив; ці записи показуються лише адміністраторам. Видалення користувача видаляє його рядки. Видалення сервера зберігає їх, тому сервер, прихований від когось, залишається прихованим у своїй історії та збережених резервних копіях.

Існуючі інсталяції продовжують працювати без змін: доки адміністратор не змінить комірку, кожен користувач матиме саме те, що йому надала його роль раніше.

## Тільки для адміністраторів, і чому

Кілька речей навмисно обмежені для адміністраторів:

- **Керування користувачами, сховище, глобальні налаштування, ключі API та глобальні файли.**
- **[Публічний API](/docs/public-api/)**: увімкнення `/api/v1` та створення, обмеження або відкликання його токенів доступу (Bearer tokens) лише для читання.
- **Розширені переозначення Docker**: власна назва контейнера, додаткові порти та прив'язані монтування. Прив'язане монтування може відображати будь-який шлях хоста в контейнер і в поєднанні з доступом панелі до Docker фактично надає права root на хості. Ці поля з'являються лише для адміністраторів.

Власні назви контейнерів також не можуть перебувати в просторі імен `msm-` панелі, тому контейнер з ручною назвою ніколи не зможе затінити інший екземпляр і направити команду зупинки або команду на неправильний екземпляр.

## Керування обліковими записами

![Зображення профілю](/docs/images/profile-picture.png)

Адміністратори можуть створювати користувачів, змінювати ролі, скидати паролі та видаляти облікові записи з таблиці "Користувачі". Стовпець **2FA** показує, чи ввімкнено двофакторну автентифікацію для кожного користувача; адміністратор може скинути 2FA іншого користувача за допомогою **Скинути 2FA** в меню дій цього користувача (у випадку втрати телефону та резервних кодів), але ніколи не може вимкнути власну 2FA без свого пароля, що обробляється потоком самообслуговування.

Невдалі спроби входу обмежуються за кількістю для кожного облікового запису (як за IP-адресою, так і загальний лічильник для облікового запису), щоб уповільнити спроби перебору паролів, і той самий ліміт охоплює етап введення коду 2FA, тому правильний пароль не може скинути лічильник перед вгадуванням коду. Перед цим стоїть грубіший обмежувач запитів для кожного IP-клієнта на кінцевих точках входу / 2FA / налаштування, який можна налаштувати за допомогою `RATE_LIMIT_AUTH_PER_15MIN` (за замовчуванням 100; за зворотним проксі встановіть `TRUST_PROXY`, щоб він використовував реальну IP-адресу клієнта).
