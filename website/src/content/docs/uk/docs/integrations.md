Кожен сервер має свої інтеграції в групі **Налаштування**: **Discord**, загальнодоступна **Сторінка статусу**, **Запрошення** в один клік та необов'язкова вкладка **Чат-бот** (тільки для адміністраторів). Ця сторінка охоплює Discord; [запрошення та сторінка статусу](/docs/invites-and-status-page/) охоплюють ці два, а [чат-бот](/docs/chatbot/) має власну сторінку.

## Сповіщення Discord

Панель пересилає події сервера до каналу Discord через вебхук. Без бота, без OAuth.

### Налаштування

1. У Discord: **Налаштування сервера → Інтеграції → Вебхуки → Новий вебхук**. Виберіть канал і скопіюйте URL вебхука.
2. У панелі відкрийте вкладку сервера **Налаштування → Discord**, вставте URL у поле **Webhook URL**, увімкніть картку **on** та натисніть **Зберегти**. URL зберігається у зашифрованому вигляді (у тому ж сховищі, що й ваші ключі API).
3. Використовуйте **Send Test**, щоб підтвердити роботу.

![Інтеграція Discord](/docs/images/integrations-discord.png)

Щоб замінити збережений URL, вставте новий і збережіть; залиште поле порожнім, щоб зберегти поточний. Збережений URL відображається масковано (токен приховано).

### Що надсилається

Сповіщення згруповані за категоріями, які можна вмикати/вимикати. Усі увімкнені за замовчуванням.

| Категорія             | Події                                                         |
| --------------------- | ------------------------------------------------------------- |
| **Старт / стоп**      | Сервер запущено, сервер зупинено                              |
| **Збої**              | Збій, виявлено цикл збоїв, новий звіт про збій                |
| **Резервні копії**    | Створено резервну копію, відновлено резервну копію            |
| **Оновлення**         | Застосовано оновлення, скасовано оновлення, невдале оновлення |
| **Виключення / бани** | Гравця виключено, гравця забанено                             |
| **Сповіщення**        | Речі, які тихо залишають сервер зламаним (див. нижче)         |

### Категорія Сповіщення

`Alerts` — це канал "щось потребує уваги людини" для умов, які раніше були видимі лише в панелі:

| Подія                   | Значення                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `oom`                   | Контейнер було зупинено через брак пам'яті.                                                                                       |
| `unhealthy`             | Процес запущено, але перевірка `mc-health` не проходить: сервер працює, але не функціонує.                                        |
| `startup-stalled`       | Сервер все ще запускається приблизно через 10 хвилин без повідомлення "Done" у логах (з діагностикою проблеми, якщо вона відома). |
| `stop-failed`           | Коректна зупинка не відбулася, і контейнер все ще працює.                                                                         |
| `schedule-failed`       | Невдала запланована перезавантаження / резервне копіювання / команда.                                                             |
| `quota-exceeded`        | Досягнуто ліміту дискового простору в режимі "strict-mode", і сервер було зупинено.                                               |
| `offline-after-restart` | Сервер працював до перезапуску панелі, зараз не працює і не буде автоматично запущений.                                           |
| `port-change-failed`    | Зміна порту не вдалася, і сервер не вдалося повернути на старий порт, тому він не працює.                                         |
| `auto-restart-gave-up`  | Зламаний сервер не було перезапущено, тому що інша дія займала його занадто довго.                                                |

### Як відбувається доставка

Фоновий міст опитує [журнал подій](/docs/activity/) кожні 15 секунд і пересилає відповідні записи. Якщо POST-запит до вебхука тимчасово не вдається, цей запис повторюється під час наступних опитувань, а не втрачається; після кількох невдалих спроб запис пропускається, і збої доставки реєструються не частіше одного разу на годину для кожного сервера. Після перезапуску панелі міст надсилає події, які ще не були доставлені, але не більше ніж за дві години назад; під час свого першого запуску він починає з найновішої події.
