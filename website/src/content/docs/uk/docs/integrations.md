Кожен сервер має свої інтеграції в групі **Налаштування**: **Discord**, загальнодоступна **Сторінка статусу**, **Запрошення** в один клік та необов'язкова вкладка **Чат-бот**. Ця сторінка охоплює Discord (інші мають власну документацію та помічників з налаштування в панелі).

## Сповіщення Discord

Панель пересилає події сервера до каналу Discord через вебхук. Без бота, без OAuth.

### Налаштування

1. У Discord: **Налаштування сервера → Інтеграції → Вебхуки → Новий вебхук**. Виберіть канал і скопіюйте URL вебхука.
2. У панелі відкрийте вкладку сервера **Налаштування → Discord**, вставте URL у поле **Webhook URL**, увімкніть картку **on** і натисніть **Зберегти**. URL зберігається зашифрованим (у тому ж сховищі в стані спокою, що й ваші ключі API).
3. Використовуйте **Send test**, щоб підтвердити роботу.

![Інтеграція Discord](/docs/images/integrations-discord.png)

Щоб замінити збережений URL, вставте новий і збережіть; залиште поле порожнім, щоб зберегти поточний. Збережений URL відображається маскованим (токен приховано).

### Що надсилається

Сповіщення згруповані за категоріями, які можна вмикати/вимикати. Усі увімкнені за замовчуванням.

| Категорія             | Події                                                            |
| --------------------- | ---------------------------------------------------------------- |
| **Старт / стоп**      | Сервер запущено, сервер зупинено                                 |
| **Збої**              | Збій, виявлено цикл збоїв, новий звіт про збій                   |
| **Резервні копії**    | Створено резервну копію, відновлено резервну копію               |
| **Оновлення**         | Оновлення застосовано, оновлення відкочено, оновлення не вдалося |
| **Виключення / бани** | Гравця виключено, гравця забанено                                |
| **Сповіщення**        | Те, що тихо залишає сервер зламаним (див. нижче)                 |

### Категорія Сповіщення

`Alerts` — це канал "щось потребує уваги людини" для умов, які раніше були видимі лише в панелі:

| Подія                   | Значення                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| `oom`                   | Контейнер було зупинено через брак пам'яті.                                                                  |
| `unhealthy`             | Процес запущено, але перевірка `mc-health` не проходить: сервер живий, але не працює.                        |
| `startup-stalled`       | Запуск триває близько 10 хвилин без повідомлення "Done" у логах (з діагностикою проблеми, якщо вона відома). |
| `stop-failed`           | Коректна зупинка не спрацювала, і контейнер все ще працює.                                                   |
| `schedule-failed`       | Плановий перезапуск / резервне копіювання / команда не вдалися.                                              |
| `quota-exceeded`        | Було перевищено квоту диска в суворому режимі, і сервер було зупинено.                                       |
| `offline-after-restart` | Сервер був увімкнений до перезапуску панелі, зараз вимкнений і не буде автоматично запущений.                |
| `crash-report`          | Новий звіт про збій було захоплено та розібрано.                                                             |
| `update-failed`         | Захищене оновлення не призвело до справного стану.                                                           |

### Як відбувається доставка

Фоновий міст опитує [журнал подій](/docs/activity/) кожні 15 секунд і пересилає відповідні рядки. Якщо POST-запит до вебхука тимчасово не вдається, цей рядок повторно надсилається під час наступних опитувань, а не втрачається; назавжди недоступний вебхук вимикається (один рядок журналу на годину) після кількох спроб. Міст ніколи не відтворює події, що сталися до запуску панелі.
