Сторінка **Modpacks** (і вкладка **З модпаку** у [майстрі створення](/docs/servers/)) встановлює модпак як сервер, завжди **прив'язаний до точної версії паку**, тому перезапуск ніколи не зможе непомітно оновити пак без вашого відома.

![Modpacks](/docs/images/modpacks.png)

## Підтримувані платформи

- **CurseForge** - пошук або вставка URL паку. Потребує API-ключа CurseForge для пошуку та приватних паків (додайте його в **Налаштування → API ключі**).
- **Modrinth** - пошук за назвою.
- **FTB** - Feed The Beast паки.
- **GT New Horizons** - експертний пак 1.7.10, встановлюється з власного індексу випусків GTNH. GTNH обирає середовище виконання Java для кожного паку (2.8.0+ працює на **Java 25** через вбудовані патчі lwjgl3ify, старіші випуски на Java 21 або 17), а майстер підвищує ОЗП та диск сервера до розумних мінімумів для нього.
- **Custom zip** - зовсім не опублікований пак: завантажте **експорт модпаку CurseForge** (zip з `manifest.json`, який створює додаток CurseForge для вибраного набору модів) або **будь-який zip з jar-файлами модів**. Панель масово розпізнає маніфест через API CurseForge (або ідентифікує кожен jar за хешем/відбитком/метаданими), попередньо переглядає, що підходить, і встановлює все за один крок - включаючи конфігурації `overrides/` паку, якщо ви погодитесь. Моди, авторам яких заборонено автоматичне завантаження, перелічені з посиланням на браузер та слотом для ручного завантаження замість помилки встановлення.

## Як працює прив'язка

Коли ви обираєте пак, панель визначає точну версію, записує її та встановлює. На сторінці **Оновлення** вам буде повідомлено, коли доступна новіша версія; оновлення є навмисною, захищеною дією з резервним копіюванням перед оновленням та відкатом. Серверам зі стабільною відстежуваною версією ніколи не пропонується бета-версія.

Сервери, створені на дуже старих версіях панелі (до 0.9.7), могли залишитися _неприв'язаними_, що означало, що образ контейнера тихо встановлював найновішу версію паку при кожному запуску. Панель тепер виправляє їх під час завантаження: вона прив'язує кожен до версії, яка фактично встановлена (читається з власних записів панелі або з маніфесту встановлення образу, ніколи не з нововизначеного "найновішого") і реєструє подію. Якщо вона не може визначити, що встановлено, сторінка Налаштування сервера показує попередження з проханням вибрати версію вручну, і будь-яка спроба зберегти неприв'язану конфігурацію модпаку відхиляється.

## Політика оновлення

Кожен сервер має політику оновлення в **Налаштування**, і всі три опції означають те, що вони говорять:

- **Тільки вручну** - нічого ніколи не змінюється самостійно, і сервер повністю виключається з значка оновлення та сторінки Оновлення. Режим "залиште мене в спокої": ідеально підходить для вручну налаштованого або імпортованого паку, який ви ніколи не хочете чіпати.
- **Повідомляти мене** (за замовчуванням) - щоденна перевірка показує доступні оновлення як значок та на сторінці Оновлення; застосування їх завжди залежить від вашого кліку.
- **Автоматичне оновлення** - після запланованої щоденної перевірки очікуючі **оновлення паку** застосовуються тим самим захищеним шляхом, що й ручне оновлення: резервне копіювання перед оновленням, моніторинг стану та автоматичний відкат, якщо нова версія не запускається. Оновлення, які переведуть сервер на іншу версію Minecraft, завжди пропускаються з реєстрацією події - перетворення світу назавжди є рішенням, яке панель відмовляється приймати за вас. Ручні кнопки "перевірити зараз" лише перевіряють; вони ніколи не запускають автоматичні оновлення.

## Оновлення паку

З прив'язаного сервера ви можете оновитися до новішої версії за одну дію. Панель спочатку створює резервну копію, змінює прив'язану версію, перестворює контейнер (перевизначаючи Java, якщо нова версія потребує іншого середовища виконання) та відстежує перший запуск, з достатнім вікном для великих паків, таких як GTNH, які завантажують кілька гігабайтів і створюють світ з кількома сотнями модів при першому запуску.
