Το πάνελ είναι πολυ-χρηστικό. Διαχειριστείτε λογαριασμούς στην ενότητα **Ρυθμίσεις → Χρήστες**.

![Χρήστες](/docs/images/settings-users.png)

## Οι τρεις ρόλοι

| Ρόλος        | Μπορεί να κάνει                                                                                                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **admin**    | Τα πάντα: διαχείριση χρηστών, κλειδιών API, καθολικών αρχείων, προηγμένων παρακάμψεων Docker και κάθε ενέργεια διακομιστή.                                                          |
| **operator** | Εκτέλεση και διαμόρφωση διακομιστών (εκκίνηση/τερματισμός, κονσόλα, αντίγραφα ασφαλείας, κόσμοι, mods, οι περισσότερες ρυθμίσεις), αλλά όχι περιοχές αποκλειστικά για διαχειριστές. |
| **viewer**   | Μόνο για ανάγνωση. Προβολή διακομιστών και της κατάστασής τους, χωρίς καμία αλλαγή.                                                                                                 |

Κάθε χρήστης, συμπεριλαμβανομένου ενός viewer, μπορεί να διαχειριστεί τον δικό του [έλεγχο ταυτότητας δύο παραγόντων](/docs/two-factor-authentication/), επειδή η προστασία του δικού σας λογαριασμού δεν αποτελεί ενέργεια διαχείρισης διακομιστή.

## Αποκλειστικά για διαχειριστές, και γιατί

Λίγα πράγματα είναι σκόπιμα περιορισμένα στους διαχειριστές:

- **Διαχείριση χρηστών, κλειδιά API και καθολικά αρχεία.**
- **Το [δημόσιο API](/docs/public-api/)** - ενεργοποίηση του `/api/v1` και δημιουργία, οριοθέτηση ή ανάκληση των token Bearer μόνο για ανάγνωση.
- **Προηγμένες παρακάμψεις Docker** - προσαρμοσμένο όνομα κοντέινερ, επιπλέον δημοσιεύσεις θυρών και bind mounts. Ένα bind mount μπορεί να αντιστοιχίσει οποιαδήποτε διαδρομή του host σε ένα κοντέινερ, και σε συνδυασμό με την πρόσβαση του πάνελ στο Docker, αυτό είναι ουσιαστικά root στο host. Αυτά τα πεδία εμφανίζονται μόνο για διαχειριστές.

Τα προσαρμοσμένα ονόματα κοντέινερ επίσης δεν μπορούν να ζουν στον δικό τους χώρο ονομάτων `msm-` του πάνελ, οπότε ένα χειροκίνητα ονομασμένο κοντέινερ δεν μπορεί ποτέ να επισκιάσει έναν άλλο διακομιστή και να κατευθύνει λανθασμένα μια εντολή τερματισμού ή εντολής σε λάθος παρουσία.

## Διαχείριση λογαριασμών

![Εικόνα προφίλ](/docs/images/profile-picture.png)

Οι διαχειριστές μπορούν να δημιουργήσουν χρήστες, να αλλάξουν ρόλους, να επαναφέρουν κωδικούς πρόσβασης και να διαγράψουν λογαριασμούς από τον πίνακα Χρηστών. Η στήλη **2FA** δείχνει αν ο κάθε χρήστης έχει ενεργοποιήσει τον έλεγχο ταυτότητας δύο παραγόντων. ένας διαχειριστής μπορεί να **επαναφέρει** τον έλεγχο ταυτότητας δύο παραγόντων ενός άλλου χρήστη (για την περίπτωση απώλειας τηλεφώνου και κωδικών εφεδρείας), αλλά ποτέ να απενεργοποιήσει τον δικό του χωρίς τον κωδικό πρόσβασής του, κάτι που η ροή αυτοεξυπηρέτησης χειρίζεται αντ' αυτού.

Οι αποτυχημένες συνδέσεις έχουν όριο ρυθμού ανά λογαριασμό (τόσο ένας μετρητής ανά IP όσο και ένας καθολικός μετρητής λογαριασμού) για να επιβραδύνουν τις προσπάθειες brute-force, και το ίδιο όριο καλύπτει και το βήμα του κωδικού 2FA, ώστε ένας σωστός κωδικός πρόσβασης να μην μπορεί να επαναφέρει τον μετρητή πριν από την εικασία του κωδικού. Μπροστά από αυτό βρίσκεται ένας πιο χονδροειδής περιοριστής αιτήσεων ανά IP-πελάτη στα τελικά σημεία σύνδεσης / 2FA / ρύθμισης, ρυθμιζόμενος μέσω του `RATE_LIMIT_AUTH_PER_15MIN` (προεπιλογή 100· πίσω από έναν reverse proxy, ορίστε το `TRUST_PROXY` ώστε να βασίζεται στην πραγματική IP του πελάτη).
