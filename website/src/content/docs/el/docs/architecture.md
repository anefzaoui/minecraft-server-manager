Το Minecraft Server Manager είναι μια εφαρμογή Node.js που αποδίδεται στον διακομιστή, με μία μόνο διεργασία. Διαχειρίζεται
διακομιστές Minecraft που εκτελούνται ως κοντέινερ Docker χρησιμοποιώντας την
εικόνα [itzg/docker-minecraft-server](https://github.com/itzg/docker-minecraft-server), επικοινωνώντας με τον
διακομιστή Docker μέσω του API του (ποτέ με κλήση του `docker` CLI).

## Μορφή εκτέλεσης

- **Express + Handlebars** αποδίδουν σελίδες στον διακομιστή. Δεν υπάρχει SPA. Το JavaScript του προγράμματος περιήγησης στο `public/js/`
  είναι χειροποίητη προοδευτική ενίσχυση. Ένα βήμα esbuild (`pnpm run build:js`) το συσκευάζει και το συμπιέζει σε `public/dist/js/`. Η εφαρμογή εξυπηρετεί αυτό το πακέτο όταν είναι παρόν και την ακατέργαστη
  πηγή διαφορετικά, οπότε μια εκτέλεση ανάπτυξης χωρίς build εξακολουθεί να λειτουργεί.
- **`node:sqlite`** (ενσωματωμένο στο Node· το πάνελ απαιτεί Node ≥ 24) είναι η βάση δεδομένων - σύγχρονη,
  μηδενικά εγγενή στοιχεία, λειτουργία WAL. Ένας μικρός δρομέας μετεγκατάστασης εκδόσεων εφαρμόζει τα `src/db/migrations/*` κατά την
  εκκίνηση. Οι προετοιμασμένες δηλώσεις αποθηκεύονται στην κρυφή μνήμη στο `src/db/index.js` με κλειδί το κείμενο SQL.
- **`ws`** μεταφέρει τις ροές ζωντανής κονσόλας και στατιστικών. Και οι δύο είναι **μεταβιβασμένες**: μία ανάντη
  `docker logs --follow` (ή `docker stats`) ανά διακομιστή, αποδιαμεσολαβημένη μία φορά και διανεμημένη σε κάθε
  συνδεδεμένη καρτέλα, αντί για μία ανάντη ανά θεατή. Ο μεταβιβαστής κονσόλας διατηρεί ένα μικρό buffer επανάληψης
  για καρτέλες που συνδέονται αργά και απορρίπτει έναν συνδρομητή του οποίου η υποδοχή πέφτει πολύ πίσω αντί να
  επιβραδύνει την κοινή ροή.
- **`dockerode`** είναι ο μόνος τρόπος με τον οποίο η εφαρμογή επικοινωνεί με το Docker. Το τελικό σημείο ανιχνεύεται αυτόματα ανά πλατφόρμα
  (ονομαστική σωλήνωση Windows έναντι υποδοχής Unix).
- **Όλη η μόνιμη κατάσταση βρίσκεται σε έναν κατάλογο** (`$DATA_DIR`, προεπιλογή `./data`). Η αντιγραφή αυτού του
  καταλόγου μεταφέρει ολόκληρο το πάνελ.

## Στρώματα

Οι εξαρτήσεις ρέουν προς μία κατεύθυνση:

```
                 ┌─────────────────────────────┐
   HTTP  ───────▶│  web/routes/*  (+ middleware)│   ανάλυση & επικύρωση εισόδου, διαμόρφωση απαντήσεων
                 └──────────────┬──────────────┘
                                │
                 ┌──────────────▼──────────────┐
                 │         services/*          │   λογική τομέα (οι πραγματικές λειτουργίες)
                 └───┬─────────┬─────────┬─────┘
                     │         │         │
        ┌────────────▼──┐ ┌────▼────┐ ┌──▼──────────┐
        │   docker/*    │ │  db/*   │ │  storage/*  │   υποδομή
        └───────────────┘ └─────────┘ └─────────────┘
```

- **`web/routes/`** - ένας δρομολογητής ανά τομέα (`servers`, `players`, `worlds`, `crashes`, `blueprints`,
  `files`, …), προσαρτημένος στο `web/app.js`. Οι δρομολογητές επικυρώνουν με zod, καλούν μια υπηρεσία και επιστρέφουν JSON
  ή αποδίδουν μια προβολή. Η επιχειρησιακή λογική δεν ανήκει εδώ. Δύο δρομολογητές είναι προσαρτημένοι στη **δημόσια
  ζώνη**, πριν από το `requireAuth`: `routes/status.js` (προαιρετικές σελίδες κατάστασης HTML ανά διακομιστή) και
  `routes/apiV1.js` (`/api/v1`, ένα API JSON μόνο για ανάγνωση πιστοποιημένο από ένα διακριτικό Bearer που έχει εκδοθεί από διαχειριστή
  από το `services/apiTokens.js`, απενεργοποιημένο εκτός αν ενεργοποιηθεί στις Ρυθμίσεις· δείτε το `docs/public-api.md`).
- **`services/`** - η καρδιά της εφαρμογής. Κάθε υπηρεσία κατέχει έναν τομέα και μπορεί να εξαρτάται από
  την υποδομή και από άλλες υπηρεσίες.
- **`docker/`** - περιτυλίγματα dockerode: `connect` (ανίχνευση τελικού σημείου + υγεία διακομιστή), `containers`
  (δημιουργία/εκκίνηση/διακοπή/επανδημιουργία με bind mounts, όρια μνήμης/CPU και ετικέτες), `logs`, `stats`,
  `images`, και ένας `watcher` που μετατρέπει τα συμβάντα Docker σε ιστορικό + ανίχνευση σφαλμάτων.
- **`db/`** - το περιτύλιγμα SQLite και ο δρομέας μετεγκατάστασης.
- **`storage/`** - η αρχικοποίηση του `./data`, ο **φύλακας διαδρομών** (`safeJoin`, η ραχοκοκαλιά ασφάλειας αρχείων)
  και ο δείκτης μεγέθους στο παρασκήνιο + επιβολή ορίων.

Διατομεακά:

- **`config/`** - διαμόρφωση περιβάλλοντος συν το **κατάλογος πεδίων**: η μοναδική πηγή αλήθειας για τις
  ρυθμίσεις του διακομιστή. Κάθε μεταβλητή περιβάλλοντος itzg καταγράφεται (ετικέτα, βοήθεια, τύπος, μονάδα, προεπιλογή,
  επικύρωση, ενότητα, σημαίες κινδύνου). Ο οδηγός, οι φόρμες ρυθμίσεων και η επικύρωση zod προέρχονται όλες από αυτό, οπότε η έκθεση μιας νέας ρύθμισης είναι μια αλλαγή δεδομένων, όχι νέα υδραυλική διεπαφή χρήστη.
- **`events/`** - το `recordEvent()` είναι το μοναδικό σημείο εισόδου για το αρχείο καταγραφής ιστορικού· τα συμβάντα κύκλου ζωής καταγράφουν επίσης αποσπάσματα αρχείων καταγραφής κοντέινερ στο `data/logs/<id>/events/`.
- **`ws/`** - πιστοποιημένα WebSockets κονσόλας + στατιστικών (cookie συνεδρίας επαληθευμένο κατά την αναβάθμιση, `Origin` ελέγχθηκε για αποκλεισμό κλοπής μεταξύ ιστοτόπων), μεταβιβασμένα ανά διακομιστή (δείτε "Μορφή εκτέλεσης").
- **`logger.js` + `instrument.js`** - το `require('./logger')(label)` επιστρέφει έναν καταγραφέα [Pino](https://getpino.io) ανά ενότητα· επίπεδο από το `LOG_LEVEL`, το `makeFailureThrottle()` διατηρεί έναν βρόχο παρασκηνίου που αποτυγχάνει επίμονα σε μία γραμμή καταγραφής συν μια γραμμή "ανακτήθηκε".
  Το `src/utils/logSanitize.js` αφαιρεί κλειδιά που μοιάζουν με διαπιστευτήρια και διακριτικά webhook από τα δομημένα μεταδεδομένα· το `src/config/logLevel.js` είναι η κοινή λίστα επιτρεπόμενων επιπέδων (διατηρείται ξεχωριστά για να αποφευχθεί ένας κύκλος απαιτήσεων με το `config`). Το `src/instrument.js` είναι μια αδρανής ραφή Sentry, φορτωμένη πρώτα στο `src/server.js`. Το `src/web/middleware/requestLog.js` γράφει μία γραμμή αρχείου καταγραφής πρόσβασης ανά αίτημα (παραλείποντας το `/healthz` και τα στατικά στοιχεία). Το ESLint επιβάλλει `no-console` κάτω από το `src/**`, με τα `preflight.js`, `instrument.js`, και `config/index.js` να εξαιρούνται (εκτελούνται πριν υπάρξει ο καταγραφέας).
- **Περιορισμός ρυθμού** - το `src/web/middleware/rateLimit.js` τοποθετεί το `express-rate-limit` μπροστά από το `/api`
  (`RATE_LIMIT_API_PER_MIN`, προεπιλογή 1200) και τις POST συνδέσεων / 2FA / ρύθμισης
  (`RATE_LIMIT_AUTH_PER_15MIN`, προεπιλογή 100)· το `0` απενεργοποιεί έναν περιοριστή. Χρησιμοποιεί ως κλειδί το `req.ip`, οπότε
  το `TRUST_PROXY` έχει σημασία πίσω από έναν διακομιστή μεσολάβησης. Το `/api/v1` έχει τον δικό του περιοριστή ανά διακριτικό
  (`RATE_LIMIT_PUBLIC_API_PER_MIN`, προεπιλογή 120), με κλειδί ένα hash του διακριτικού Bearer με εφεδρεία IP. Ένας ξεχωριστός μετρητής μαλακής επαναφοράς ανά λογαριασμό στο
  `src/web/middleware/auth.js` χειρίζεται τον αποκλεισμό σύνδεσης (ανά IP και καθολικά ανά λογαριασμό, με φθορά).

## Βασικές συμπεριφορές τομέα

- **Τα Modpacks καρφώνονται πάντα.** Η εικόνα αναβαθμίζει αυτόματα τα μη καρφωμένα πακέτα σε κάθε επανεκκίνηση, οπότε το
  πάνελ επιλύει το "latest" σε ένα συγκεκριμένο αναγνωριστικό έκδοσης κατά τον χρόνο εγκατάστασης και το καρφώνει. Οι αναβαθμίσεις είναι μια
  ρητή ενορχηστρωμένη ροή (`updates/`): προεπισκόπηση → αντίγραφο ασφαλείας πριν την αναβάθμιση → ομαλή διακοπή → επανακαρφίτωση →
  επανδημιουργία → παρακολούθηση υγείας → επαναφορά με ένα κλικ.
- **Η επικάλυψη προσαρμοσμένων τροποποιήσεων** διαχειρίζεται από το πάνελ: οι τροποποιήσεις που προστέθηκαν από τον χρήστη προσγειώνονται στη βιβλιοθήκη που έχει αφαιρεθεί η διπλοεγγραφή και συνδέονται σκληρά στον διακομιστή, ώστε να επιβιώνουν από τις ενημερώσεις πακέτων. Η απενεργοποίηση είναι ευαίσθητη στην κλάση.
- **Οι θύρες** εκχωρούνται από ένα βασικό σχήμα (παιχνίδι από το `PORT_GAME_START` και πάνω, RCON = παιχνίδι +
  `PORT_RCON_OFFSET`, Bedrock από το `PORT_BEDROCK_START`), ελέγχονται για διαθεσιμότητα και δεσμεύονται στη
  βάση δεδομένων.
- **Τα όρια δίσκου** επιβάλλονται από το πάνελ επειδή το Docker δεν μπορεί να περιορίσει τη χρήση bind-mount: ο δείκτης
  αποθηκεύει στην κρυφή μνήμη τα μεγέθη ανά κατάλογο και οι λειτουργίες αύξησης δίσκου ελέγχονται με βάση αυτά.
- **Τα μυστικά** (κωδικοί RCON, κλειδιά API, μυστικά TOTP, διεύθυνση URL webhook Discord) κρυπτογραφούνται κατά την
  αποθήκευση με AES-256-GCM χρησιμοποιώντας ένα αποκλειστικό τυχαίο κλειδί στο `$DATA_DIR/.secret-key` (λειτουργία `0600`,
  αυτόματη δημιουργία). Είναι ανεξάρτητο από το `SESSION_SECRET`· ένα κλειδί που προέρχεται από το `SESSION_SECRET` διατηρείται ως εφεδρεία μόνο για αποκρυπτογράφηση για τιμές που γράφτηκαν πριν υπάρξει το αποκλειστικό κλειδί, και
  το `src/services/secretsMigration.js` τα επανακρυπτογραφεί κάτω από το αποκλειστικό κλειδί μία φορά κατά την εκκίνηση.
  Ένα `.secret-key` που υπάρχει αλλά δεν αναλύεται είναι ένα σοβαρό σφάλμα εκκίνησης (δεν δημιουργείται ποτέ σιωπηλά
  πάνω από αυτό). Τα Blueprints αφαιρούν όλα τα μυστικά κατά την εξαγωγή.

## Μορφές δεδομένων & καλωδίων

- **`data/panel.db`** - η βάση δεδομένων SQLite. Λαμβάνει στιγμιότυπα καθημερινά μέσω `VACUUM INTO` στο
  `data/backups/_panel/` (διατηρούνται τα 14 νεότερα)· το `PRAGMA integrity_check` εκτελείται κατά την εκκίνηση.
- **`data/.session-secret`** - το μυστικό αυτόματης δημιουργίας για υπογραφή cookie, που δημιουργείται κατά την πρώτη εκτέλεση εάν
  το `SESSION_SECRET` είναι ανενεργό. Η διαγραφή του περιστρέφει το μυστικό (που ακυρώνει τις συνεδρίες).
- **`data/.secret-key`** - το αποκλειστικό κλειδί κρυπτογράφησης κατά την αποθήκευση 32 byte (λειτουργία `0600`), αυτόματης δημιουργίας
  κατά την πρώτη εκτέλεση. Ανεξάρτητο από το `SESSION_SECRET`· η διαγραφή του καθιστά κάθε αποθηκευμένο διαπιστευτήριο
  μη αποκρυπτογραφήσιμο, οπότε ανήκει στα αντίγραφα ασφαλείας σας.
- **Blueprints (`.mcserver.zip`)** - ένα zip με ένα `manifest.json` που περιγράφει τη διαμόρφωση, τους πόρους, την
  καρφωμένη αναφορά πακέτου, τον κατάλογο επικάλυψης (διευθύνσεις URL πηγής + sha256), επιλεγμένα αρχεία διαμόρφωσης και
  προαιρετικά έναν κόσμο. Η εισαγωγή επαν-κατεβάζει και επαληθεύει με hash κάθε τροποποίηση και εκχωρεί νέες θύρες.
- **Κοντέινερ Docker** που δημιουργούνται από το πάνελ ονομάζονται και επισημαίνονται ώστε ο watcher να μπορεί να τα βρει·
  το πάνελ κατέχει τον πλήρη κύκλο ζωής τους.

## Ακολουθία εκκίνησης

1. `require('./instrument')` (η ραφή Sentry) πριν από οτιδήποτε άλλο, στη συνέχεια `require('./preflight')`
   για να αποτύχει καθαρά σε μια μη υποστηριζόμενη έκδοση Node.
2. Φόρτωση διαμόρφωσης· διασφάλιση/δημιουργία `.session-secret` **και** `.secret-key`.
3. `ensureDataRoot()` - δημιουργία της διάταξης `./data`, εκκαθάριση του `tmp/`.
4. Εκτέλεση μετεγκαταστάσεων βάσης δεδομένων, στη συνέχεια `PRAGMA integrity_check` (καταγράφει δυνατά, δείχνει στο `data/backups/_panel`
   σε περίπτωση αποτυχίας).
5. Επανακρυπτογράφηση τυχόν παλαιότερων μυστικών με κλειδί `SESSION_SECRET` κάτω από το `.secret-key` (`secretsMigration`).
6. Σπόρος αρχικών blueprints (φρουρούμενα).
7. Εκκίνηση του διακομιστή HTTP + WS. Σε ένα εκτεθειμένο bind, εκτύπωση του PIN `/setup` πρώτης εκτέλεσης.
8. Εγκατάσταση του φύλακα χρόνου εκτέλεσης μετά την εκκίνηση (πιάνει μη αναμενόμενα σφάλματα· το `MSM_EXIT_ON_FATAL=1` το καθιστά σκληρή έξοδο για επιβλεπόμενες αναπτύξεις).
9. Εκκίνηση υπηρεσιών παρασκηνίου: μεταβιβαστής WS, δείκτης αποθήκευσης, watchers σφαλμάτων + απογραφής, χρονοπρογραμματιστής,
   γεφυρα συμβάντων Discord, και ο **χρονοδιακόπτης καθημερινής συντήρησης** (εκκαθάριση παλαιών γραμμών αναλυτικών στοιχείων + στιγμιότυπο
   του `panel.db`).
10. Αρχικοποίηση Docker **στο παρασκήνιο**. Η διεπαφή χρήστη είναι πλήρως χρησιμοποιήσιμη ενώ ο διακομιστής είναι κάτω·
    οι λειτουργίες Docker ενεργοποιούνται όταν γίνει προσβάσιμος. Μόλις συνδεθεί, το `refreshStatuses({ boot })`
    επανασυμφωνεί τις αποθηκευμένες στην κρυφή μνήμη καταστάσεις, εκπέμπει ένα εφάπαξ συμβάν `offline-after-restart` για έναν διακομιστή που ήταν
    ενεργός πριν από την επανεκκίνηση του πάνελ και δεν θα επανέλθει, και ο βρόχος εκκίνησης ξεκινά
    διακομιστές `auto_start` συν ανακτά διακομιστές `auto_restart` που βρέθηκαν σε σφάλμα κατά τη διάρκεια της διακοπής
    (σεβόμενος την καθυστέρηση βρόχου σφαλμάτων).

> Η σειρά instrument-before-preflight είναι μια σκόπιμη ανταλλαγή: επιτρέπει σε μια μελλοντική καλωδίωση Sentry
> να επιδιορθώσει πρώτα τον χρόνο εκτέλεσης, με κόστος ένα ελαφρώς λιγότερο φιλικό μήνυμα σε ένα πραγματικά παλιό Node.

## Δημιουργία αγωγού

`pnpm run build` = `build:css` (Tailwind → `public/css/app.css`) + `build:js` (esbuild →
`public/dist/js/`, ESM με διαχωρισμό κώδικα). Το `postinstall` εκτελεί **μόνο CSS**. Τα `public/css/app.css`
και `public/dist/` είναι αντικείμενα build που αγνοούνται από το git· το στάδιο build του Dockerfile εκτελεί το πλήρες
`pnpm run build` και αντιγράφει το `public/` στην εικόνα χρόνου εκτέλεσης. Τα στατικά στοιχεία εξυπηρετούνται
με `immutable`/long-cache για αρχεία με δακτυλικό αποτύπωμα, short-cache για CSS/JS, και `no-cache` για HTML και
`/api`.
