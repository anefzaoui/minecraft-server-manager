Η σελίδα **Ενημερώσεις** παρακολουθεί τι είναι ξεπερασμένο σε όλους τους διακομιστές σας σε ένα μέρος:

- Εκδόσεις **Modpack** ([modpacks](/docs/modpacks/)) έναντι του Modrinth / CurseForge / του δείκτη κυκλοφορίας του GTNH.
- **Προσαρμοσμένο περιεχόμενο** που προσθέσατε εσείς - mods, datapacks, resource packs, plugins - το καθένα έναντι της πηγής του: Modrinth, CurseForge, Hangar, SpigotMC (Spiget) ή GitHub Releases. Οι αναζητήσεις στο GitHub χρησιμοποιούν επανεπιβεβαίωση ETag, οπότε οι καθημερινοί έλεγχοι ελάχιστα αγγίζουν το όριο ρυθμού του.
- **Απαρχαιωμένη εικόνα Docker**: η εικόνα κάθε εκτελούμενου κοντέινερ έναντι ενός πρόσφατα ληφθέντος tag (με αφαίρεση διπλοτύπων μεταξύ διακομιστών με το ίδιο tag), που προσφέρεται ως αναβάθμιση μόνο για επανδημιουργία.
- **Καρφίτσωμα εκδόσεων αυτόνομης λειτουργίας**: για έναν διακομιστή χωρίς διαχειριζόμενο πακέτο, ένα ρητό καρφίτσωμα `mc_version` έναντι του καταλόγου του Mojang, και μια ρητή μεταβλητή περιβάλλοντος `mc_version` (`PAPER_BUILD`, `FORGE_VERSION`, κ.λπ.) έναντι του μητρώου του φορτωτή. Οι εκδόσεις Paper προέρχονται από το τρέχον **Fill v3 API** του PaperMC (το παλιό endpoint v2 σταμάτησε να λαμβάνει νέες εκδόσεις Minecraft).

![Ενημερώσεις](/docs/images/updates.png)

## Πώς λειτουργεί

Το πάνελ ελέγχει τις καρφιτσωμένες εκδόσεις κάθε διακομιστή έναντι της πηγής upstream και παραθέτει οτιδήποτε έχει νεότερη κυκλοφορία. Ένας αντίστοιχος μετρητής εμφανίζεται επίσης στο πλακίδιο "Διαθέσιμες ενημερώσεις" του [dashboard](/docs/dashboard/).

Οι έλεγχοι εκτελούνται κατά παραγγελία και μπορούν να προγραμματιστούν ([Schedules](/docs/schedules/)). Η **πολιτική** ενημέρωσης είναι ανά διακομιστή: εσείς αποφασίζετε αν το πάνελ απλώς σας ειδοποιεί ή αν τα πάντα παραμένουν χειροκίνητα.

## Εφαρμογή μιας ενημέρωσης

Οι ενημερώσεις δεν είναι ποτέ σιωπηλές. Όταν επιλέγετε να αναβαθμίσετε ένα πακέτο, το πάνελ:

1. Δημιουργεί ένα **αντίγραφο ασφαλείας πριν την ενημέρωση** (ώστε να είναι αναστρέψιμο· διατηρούνται τα τελευταία 10 αντίγραφα ασφαλείας πριν την ενημέρωση ανά διακομιστή).
2. Επανακαρφιτσώνει την ακριβή νέα έκδοση.
3. Επανδημιουργεί το κοντέινερ, επαναπροσδιορίζοντας το περιβάλλον εκτέλεσης Java εάν χρειάζεται.
4. Παρακολουθεί την πρώτη εκκίνηση, με χρονικό όριο ανά πλατφόρμα.

Εάν δεν εκκινήσει υγιώς, γίνεται επαναφορά στο αντίγραφο ασφαλείας πριν την ενημέρωση. Ένας διακομιστής που παρακολουθεί σταθερές εκδόσεις δεν του προσφέρεται ποτέ μια beta, και ο σύνδεσμος του αρχείου καταγραφής αλλαγών οδηγεί στην πραγματική διαφορά ανά έκδοση όπου η πηγή την παρέχει. Μια αποτυχημένη ενημέρωση ενεργοποιεί επίσης μια [ειδοποίηση](/docs/integrations/) στο Discord εάν η ενσωμάτωση έχει ρυθμιστεί.
