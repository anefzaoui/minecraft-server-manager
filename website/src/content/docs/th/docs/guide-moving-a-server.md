การย้ายเวิลด์นั้นง่าย แต่การย้ายเซิร์ฟเวอร์ที่ผู้เล่นยังสามารถเข้าสู่ระบบได้ โดยที่สินค้าคงคลัง บ้าน และสิทธิ์ต่างๆ ยังคงอยู่เหมือนเดิม คือส่วนที่มักจะผิดพลาด ลำดับด้านล่างนี้จะทำให้ช่วงเวลาที่เซิร์ฟเวอร์ไม่พร้อมใช้งานสั้นลงเหลือเพียงไม่กี่นาที และยังคงมีทางย้อนกลับหากเครื่องใหม่ไม่เป็นไปตามที่คาดหวัง

## ตรวจสอบสต็อกก่อน

จดสิ่งเหล่านี้ไว้ก่อนที่คุณจะแตะต้องอะไรก็ตาม ทุกข้อเหล่านี้เคยทำให้การย้ายล้มเหลวอย่างสิ้นเชิงเมื่อถูกสันนิษฐานแทนที่จะตรวจสอบ:

- **เวอร์ชันและตัวโหลดของ Minecraft** อย่างถูกต้อง 1.20.1 NeoForge ไม่ใช่ 1.20.1 Forge
- **รายการม็อดหรือปลั๊กอินพร้อมเวอร์ชัน** เวิลด์จะไม่โหลดหากไม่มีม็อดที่สร้างขึ้น
- **เวอร์ชัน Java** ซึ่งตามหลังเวอร์ชัน Minecraft
- **`level-name`** จาก `server.properties` โฟลเดอร์เวิลด์มักจะไม่ได้ชื่อว่า `world`
- **โหมดออนไลน์** หากเซิร์ฟเวอร์เก่าทำงานด้วย `online-mode=false` และเซิร์ฟเวอร์ใหม่ทำงานด้วย `online-mode=true` หรือกลับกัน ผู้เล่นทุกคนจะได้รับ UUID ที่แตกต่างกัน และดังนั้นจึงได้รับสินค้าคงคลังใหม่ที่ว่างเปล่า นี่คือข้อผิดพลาดที่เจ็บปวดที่สุดเพียงข้อเดียวในหน้านี้
- **สิ่งใดก็ตามที่อยู่นอกโฟลเดอร์เซิร์ฟเวอร์** เช่น ฐานข้อมูล MySQL ของปลั๊กอิน

## คัดลอกขณะที่ยังทำงาน จากนั้นคัดลอกอีกครั้งขณะที่หยุดทำงาน

เคล็ดลับในการลดเวลาหยุดทำงานให้น้อยที่สุดคือการคัดลอกที่ใช้เวลานานก่อน

1. **ขณะที่เซิร์ฟเวอร์กำลังทำงาน** ให้คัดลอกไดเรกทอรีเซิร์ฟเวอร์ทั้งหมดไปยังเครื่องใหม่ บนเวิลด์ขนาดใหญ่อาจใช้เวลาหนึ่งชั่วโมง ไม่มีใครสังเกตเห็น เพราะไม่มีอะไรหยุดทำงาน
2. **ประกาศรีสตาร์ท จากนั้นหยุดเซิร์ฟเวอร์อย่างถูกต้อง** การหยุดทำงานอย่างราบรื่นจะทำให้เกมบันทึกเวิลด์ การฆ่ากระบวนการจะไม่ทำเช่นนั้น
3. **คัดลอกอีกครั้ง** เฉพาะไฟล์ที่เปลี่ยนแปลงเท่านั้นที่จะถูกย้ายในครั้งนี้ ดังนั้นจึงใช้เวลาเพียงไม่กี่วินาทีถึงนาที
4. **เริ่มทำงานบนเครื่องใหม่** บนพอร์ตที่ไม่ใช่สาธารณะหากทำได้ และเข้าร่วมด้วยตนเอง ตรวจสอบฐานที่คุณรู้จัก สินค้าคงคลังของคุณ และปลั๊กอินหรือม็อดโหลดขึ้นโดยไม่มีข้อผิดพลาด
5. **จากนั้น** ชี้ผู้เล่นไปที่เซิร์ฟเวอร์นั้น

`rsync -a --delete` เป็นเครื่องมือทั่วไปสำหรับขั้นตอนที่ 1 และ 3 รักษาการอนุญาตและเวลา: เวิลด์ที่คัดลอกโดยผู้ใช้ผิดคนคือเซิร์ฟเวอร์ที่จะไม่เริ่มทำงาน และข้อผิดพลาดจะไม่ระบุอย่างชัดเจน

## อย่าเพิ่งลบอันเก่า

เก็บเครื่องเก่าไว้ หยุดทำงานแต่ยังคงอยู่ อย่างน้อยสองสามวัน มันคือการย้อนกลับที่แท้จริงเพียงอย่างเดียว เก็บเครื่องให้ปิดอยู่ แทนที่จะเปิดทำงาน เพื่อไม่ให้ใครเข้าร่วมสำเนาที่ถูกทิ้งร้างโดยไม่ได้ตั้งใจและสร้างสิ่งต่างๆ ที่นั่นเป็นเวลาหนึ่งสัปดาห์

## ทำให้ที่อยู่รอดจากการย้าย

หากผู้เล่นเชื่อมต่อกับที่อยู่ IP เปล่า การย้ายทุกครั้งจะบังคับให้ผู้เล่นทุกคนแก้ไขรายการเซิร์ฟเวอร์ของตน และบางคนก็ไม่เคยทำ

ใช้ชื่อโฮสต์ที่คุณควบคุม ชี้ไปยังเซิร์ฟเวอร์ การย้ายจะกลายเป็นการเปลี่ยนแปลง DNS และที่อยู่ในไคลเอ็นต์ของทุกคนจะยังคงเดิม ลดค่า TTL (Time-to-Live) ของเรคคอร์ดลงหนึ่งวันก่อนการย้าย เพื่อให้การเปลี่ยนแปลงแพร่กระจายอย่างรวดเร็ว

หากคุณต้องการให้ผู้เล่นพิมพ์โดเมนเปล่าขณะที่เซิร์ฟเวอร์ทำงานบนพอร์ตที่ไม่ใช่มาตรฐาน เรคคอร์ด SRV จะทำเช่นนั้น กลไกเดียวกันกับที่โฮสต์เชิงพาณิชย์ใช้ในการแจกจ่าย `play.something.net`

## ตรวจสอบเครื่องใหม่ก่อนที่จะเชื่อถือ

สามสิ่งที่แตกต่างกันระหว่างโฮสต์และสร้างปัญหาหลังการย้าย:

- **ไฟร์วอลล์** พอร์ตเกมของคุณต้องเปิด และเฉพาะพอร์ตเกมของคุณเท่านั้น อย่าเปิดเผยแผงการจัดการหรือแผนที่สู่อินเทอร์เน็ตเพียงเพราะมันทำงานบน localhost
- **ความเร็ว Single-core** Minecraft ให้ความสำคัญกับความเร็วของคอร์เดียวมากกว่าจำนวนคอร์อย่างมาก แปดคอร์ที่ช้าจะให้ประสบการณ์ที่แย่กว่าสองคอร์ที่เร็ว
- **ดิสก์** เวิลด์บนที่เก็บข้อมูลแบบหมุนหรือโวลุ่มที่ใช้ร่วมกันอย่างหนักจะกระตุกระหว่างการโหลดชังก์

## ออกจากแผงควบคุมที่มีการจัดการ

หากคุณมาจากโฮสต์ที่ให้แผงควบคุมแก่คุณแทนที่จะเป็นเครื่อง ให้ค้นหาตัวดาวน์โหลดหรือตัวจัดการไฟล์ และนำไดเรกทอรีเซิร์ฟเวอร์ทั้งหมดไปแทนที่จะเป็นเพียงเวิลด์ รับไฟล์ jar ของปลั๊กอินและม็อดเอง ไม่ใช่รายการ: เวอร์ชันมีความสำคัญ และ "ล่าสุด" คือไฟล์ที่แตกต่างกันในเดือนหน้า

ตรวจสอบให้แน่ใจว่าการสำรองข้อมูลของคุณเป็นของคุณเอง การสำรองข้อมูลที่มีอยู่ภายในแผงควบคุมที่คุณกำลังจะจากไปเท่านั้น ไม่ใช่การสำรองข้อมูลที่คุณเป็นเจ้าของ

## ใน Minecraft Server Manager

ทั้งแผงควบคุมเป็นไดเรกทอรีเดียว การคัดลอกไปยังเครื่องอื่นและเริ่มแผงควบคุมที่นั่นจะนำเซิร์ฟเวอร์ เวิลด์ การสำรองข้อมูล และการตั้งค่าทั้งหมดมาด้วย ซึ่งทำให้การย้ายแผงควบคุมเองเป็นการคัดลอกมากกว่าการย้าย

สำหรับเซิร์ฟเวอร์เดียวแทนที่จะเป็นทั้งหมด บลูพริ้นท์จะบันทึกการกำหนดค่า ชุดม็อด และเวอร์ชันแพ็คที่ปักหมุด (และหากคุณเลือก มันจะบันทึกเวิลด์ที่ใช้งานอยู่) เป็นไฟล์ `.mcserver.zip` ไฟล์เดียวที่สามารถนำเข้าบนแผงควบคุมอื่นเพื่อสร้างเซิร์ฟเวอร์เดียวกันใหม่ เวิลด์สามารถดาวน์โหลดและติดตั้งแยกต่างหากได้เมื่อมีเพียงเวิลด์ที่ต้องการย้ายเท่านั้น

หากพอร์ตเกมที่เซิร์ฟเวอร์เคยใช้ถูกใช้งานอยู่แล้วบนเครื่องใหม่ หรือคุณต้องการทดสอบบนพอร์ตที่ไม่ใช่สาธารณะก่อน ให้เปลี่ยนที่ **Settings → Configuration**: การ์ด **Game Port** มี **Use Next Free Port** เซิร์ฟเวอร์ที่กำลังทำงานจะถามก่อนที่จะรีสตาร์ทบนพอร์ตใหม่ และหากไม่สามารถเริ่มทำงานที่นั่นได้ มันจะกลับไปใช้พอร์ตเดิม เปลี่ยนเป็นพอร์ตสาธารณะเมื่อคุณชี้ผู้เล่นไปที่เซิร์ฟเวอร์นั้น
