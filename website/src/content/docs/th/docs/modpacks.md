หน้า **Modpacks** (และแท็บ **From modpack** ใน [วิซาร์ดการสร้าง](/docs/servers/)) จะติดตั้ง modpack เป็นเซิร์ฟเวอร์ โดยจะ **ตรึงไว้กับเวอร์ชันแพ็กที่แน่นอนเสมอ** เพื่อให้การรีสตาร์ทไม่สามารถอัปเกรดแพ็กโดยไม่แจ้งให้ทราบได้

![Modpacks](/docs/images/modpacks.png)

## แพลตฟอร์มที่รองรับ

- **CurseForge** - ค้นหาหรือวาง URL ของแพ็ก จำเป็นต้องมี CurseForge API key สำหรับการค้นหาและแพ็กส่วนตัว (เพิ่มได้ที่ Settings → API keys)
- **Modrinth** - ค้นหาตามชื่อ
- **FTB** - Feed The Beast packs
- **GT New Horizons** - แพ็กผู้เชี่ยวชาญ 1.7.10 ติดตั้งจากดัชนีการเผยแพร่ของ GTNH เอง GTNH เลือก Java runtime ตามเวอร์ชันแพ็ก (2.8.0+ ทำงานบน **Java 25** ผ่านแพตช์ lwjgl3ify ที่รวมมาด้วย รุ่นเก่ากว่าทำงานบน Java 21 หรือ 17) และวิซาร์ดจะเพิ่ม RAM และดิสก์ของเซิร์ฟเวอร์ให้ถึงค่าต่ำสุดที่เหมาะสม
- **Custom zip** - ไม่ใช่แพ็กที่เผยแพร่เลย: อัปโหลด **CurseForge modpack export** (ไฟล์ zip ที่มี `manifest.json` ซึ่งแอป CurseForge สร้างขึ้นสำหรับชุด mod ที่เลือกด้วยตนเอง) หรือ **ไฟล์ zip ของ mod jars ใดๆ** แผงควบคุมจะประมวลผล manifest เป็นชุดผ่าน CurseForge API (หรือระบุ jar แต่ละรายการด้วย hash/fingerprint/metadata) แสดงตัวอย่างสิ่งที่เข้ากันได้ และติดตั้งทุกอย่างในงานเดียว - รวมถึงคอนฟิก `overrides/` ของแพ็ก หากคุณเลือก Mod ที่ผู้เขียนไม่อนุญาตให้ดาวน์โหลดอัตโนมัติจะแสดงรายการพร้อมลิงก์เบราว์เซอร์และช่องสำหรับอัปโหลดด้วยตนเองแทนที่จะทำให้การติดตั้งล้มเหลว

## การตรึงทำงานอย่างไร

เมื่อคุณเลือกแพ็ก แผงควบคุมจะประมวลผลเวอร์ชันที่แน่นอน บันทึกไว้ และติดตั้งเวอร์ชันนั้น ในหน้า **Updates** คุณจะได้รับแจ้งเมื่อมีเวอร์ชันใหม่พร้อมใช้งาน การอัปเกรดเป็นการดำเนินการที่ตั้งใจและได้รับการป้องกัน พร้อมการสำรองข้อมูลก่อนอัปเกรดและการย้อนกลับ เซิร์ฟเวอร์ที่ติดตามเวอร์ชันเสถียรจะไม่ได้รับข้อเสนอเวอร์ชันเบต้า

เซิร์ฟเวอร์ที่สร้างขึ้นบนเวอร์ชันแผงควบคุมที่เก่ามาก (ก่อน 0.9.7) อาจถูกปล่อยให้ _ไม่ถูกตรึง_ ซึ่งหมายความว่าอิมเมจคอนเทนเนอร์จะติดตั้งเวอร์ชันแพ็กล่าสุดอย่างเงียบๆ ทุกครั้งที่เริ่มทำงาน ตอนนี้แผงควบคุมจะซ่อมแซมสิ่งเหล่านี้เมื่อบูต: มันจะล็อคแต่ละรายการให้เป็นเวอร์ชันที่ติดตั้งอยู่จริง (อ่านจากบันทึกของแผงควบคุมเองหรือ manifest การติดตั้งของอิมเมจ ไม่ใช่ "ล่าสุด" ที่ประมวลผลใหม่) และบันทึกเหตุการณ์ หากไม่สามารถบอกได้ว่าติดตั้งอะไร หน้า Settings ของเซิร์ฟเวอร์จะแสดงคำเตือนขอให้คุณเลือกเวอร์ชันด้วยตนเอง และการพยายามบันทึกการกำหนดค่า modpack ที่ไม่ถูกตรึงจะถูกปฏิเสธทันที

## นโยบายการอัปเดต

เซิร์ฟเวอร์แต่ละเครื่องมีนโยบายการอัปเดตใน **Settings** และทั้งสามตัวเลือกมีความหมายตามที่กล่าวไว้:

- **Manual only** - จะไม่มีอะไรเปลี่ยนแปลงด้วยตัวเอง และเซิร์ฟเวอร์จะถูกแยกออกจากป้ายอัปเดตและหน้า Updates โดยสิ้นเชิง โหมด "ปล่อยฉันไว้คนเดียว": เหมาะสำหรับแพ็กที่ปรับแต่งด้วยตนเองหรือนำเข้าที่คุณไม่ต้องการให้แตะต้อง
- **Notify me** (ค่าเริ่มต้น) - การตรวจสอบรายวันจะแสดงอัปเดตที่พร้อมใช้งานเป็นป้ายและในหน้า Updates การนำไปใช้จะเป็นการคลิกของคุณเสมอ
- **Auto-update** - หลังจากการตรวจสอบรายวันตามกำหนด อัปเดต **แพ็ก** ที่รอดำเนินการจะถูกนำไปใช้ผ่านเส้นทางที่ได้รับการป้องกันเช่นเดียวกับการอัปเกรดด้วยตนเอง: การสำรองข้อมูลก่อนอัปเกรด การตรวจสอบสุขภาพ และการย้อนกลับอัตโนมัติหากเวอร์ชันใหม่ไม่สามารถบูตได้ อัปเดตที่จะย้ายเซิร์ฟเวอร์ไปยังเวอร์ชัน Minecraft ที่แตกต่างกันจะถูกข้ามเสมอด้วยเหตุการณ์แทน - การแปลงเวิลด์อย่างถาวรเป็นการตัดสินใจที่แผงควบคุมปฏิเสธที่จะทำเพื่อคุณ ปุ่ม "ตรวจสอบทันที" ด้วยตนเองจะตรวจสอบเท่านั้น จะไม่กระตุ้นการอัปเดตอัตโนมัติ

## การอัปเกรดแพ็ก

จากเซิร์ฟเวอร์ที่ถูกตรึง คุณสามารถอัปเกรดเป็นเวอร์ชันที่ใหม่กว่าได้ในครั้งเดียว แผงควบคุมจะสำรองข้อมูลก่อน สลับเวอร์ชันที่ตรึง สร้างคอนเทนเนอร์ใหม่ (ประมวลผล Java ใหม่หากเวอร์ชันใหม่ต้องการ runtime ที่แตกต่างกัน) และตรวจสอบการบูตครั้งแรก ด้วยหน้าต่างที่กว้างขวางสำหรับแพ็กขนาดใหญ่เช่น GTNH ที่ดาวน์โหลดข้อมูลสองสามกิกะไบต์และสร้างเวิลด์ที่มี mod หลายร้อยตัวเมื่อเริ่มต้นครั้งแรก
