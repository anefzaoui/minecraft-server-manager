เซิร์ฟเวอร์แต่ละเครื่องมีการผสานรวมภายใต้กลุ่ม **การตั้งค่า**: **Discord**, **หน้าสถานะ**สาธารณะ, **คำเชิญ**ในคลิกเดียว และแท็บ **แชทบอท**เสริม หน้านี้ครอบคลุม Discord (ส่วนอื่นๆ มีเอกสารและตัวช่วยตั้งค่าของตนเองในแผงควบคุม)

## การแจ้งเตือน Discord

แผงควบคุมจะส่งต่อเหตุการณ์ของเซิร์ฟเวอร์ไปยังช่อง Discord ผ่านเว็บฮุก ไม่ต้องใช้บอท ไม่ต้องใช้ OAuth

### การตั้งค่า

1. ใน Discord: **การตั้งค่าเซิร์ฟเวอร์ → การผสานรวม → เว็บฮุก → เว็บฮุกใหม่** เลือกช่องและคัดลอก URL ของเว็บฮุก
2. ในแผงควบคุม เปิดแท็บ **การตั้งค่า → Discord** ของเซิร์ฟเวอร์ วาง URL ลงใน **URL ของเว็บฮุก** เปิดการ์ด **เปิด** และ **บันทึก** URL จะถูกจัดเก็บแบบเข้ารหัส (ในที่เก็บข้อมูลขณะพักเดียวกันกับคีย์ API ของคุณ)
3. ใช้ **ส่งการทดสอบ** เพื่อยืนยันว่าทำงานได้

![การผสานรวม Discord](/docs/images/integrations-discord.png)

หากต้องการแทนที่ URL ที่จัดเก็บไว้ ให้วาง URL ใหม่แล้วบันทึก เว้นช่องว่างไว้เพื่อเก็บ URL ปัจจุบัน URL ที่จัดเก็บไว้จะแสดงแบบปิดบัง (โทเค็นจะถูกซ่อน)

### สิ่งที่ถูกส่ง

การแจ้งเตือนจะถูกจัดกลุ่มเป็นหมวดหมู่ที่สลับได้ ทั้งหมดเปิดอยู่ตามค่าเริ่มต้น

| หมวดหมู่           | เหตุการณ์                                              |
| ------------------ | ------------------------------------------------------ |
| **เริ่ม / หยุด**   | เซิร์ฟเวอร์เริ่มทำงาน, เซิร์ฟเวอร์หยุดทำงาน            |
| **การขัดข้อง**     | การขัดข้อง, ตรวจพบวงจรการขัดข้อง, รายงานการขัดข้องใหม่ |
| **การสำรองข้อมูล** | สร้างการสำรองข้อมูล, กู้คืนการสำรองข้อมูล              |
| **การอัปเดต**      | ใช้การอัปเดต, ยกเลิกการอัปเดต, การอัปเดตล้มเหลว        |
| **การเตะ / แบน**   | ผู้เล่นถูกเตะ, ผู้เล่นถูกแบน                           |
| **การแจ้งเตือน**   | สิ่งที่ทำให้เซิร์ฟเวอร์เสียหายอย่างเงียบๆ (ดูด้านล่าง) |

### หมวดหมู่การแจ้งเตือน

`การแจ้งเตือน` คือช่อง "บางอย่างต้องการคน" สำหรับเงื่อนไขที่เคยปรากฏในแผงควบคุมเท่านั้น:

| เหตุการณ์               | ความหมาย                                                                                                             |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `oom`                   | คอนเทนเนอร์ถูกหยุดเนื่องจากหน่วยความจำหมด                                                                            |
| `unhealthy`             | กระบวนการทำงานอยู่ แต่การตรวจสอบ `mc-health` ล้มเหลว: เซิร์ฟเวอร์ทำงานแต่เหมือนตาย                                   |
| `startup-stalled`       | ยังคงเริ่มทำงานหลังจากประมาณ 10 นาที โดยไม่มี "เสร็จสิ้น" ในบันทึก (พร้อมการวินิจฉัยว่าจะแก้ไขอะไร ที่ไหน เมื่อทราบ) |
| `stop-failed`           | การหยุดทำงานอย่างนุ่มนวลไม่สำเร็จ และคอนเทนเนอร์ยังคงทำงานอยู่                                                       |
| `schedule-failed`       | การรีสตาร์ท / การสำรองข้อมูล / คำสั่งตามกำหนดเวลาล้มเหลว                                                             |
| `quota-exceeded`        | โควต้าดิสก์โหมดเข้มงวดถูกละเมิดและเซิร์ฟเวอร์ถูกหยุด                                                                 |
| `offline-after-restart` | เซิร์ฟเวอร์ทำงานอยู่ก่อนที่แผงควบคุมจะรีสตาร์ท ตอนนี้ไม่ทำงาน และจะไม่เริ่มทำงานอัตโนมัติ                            |
| `crash-report`          | รายงานการขัดข้องใหม่ถูกบันทึกและแยกวิเคราะห์แล้ว                                                                     |
| `update-failed`         | การอัปเกรดที่ได้รับการป้องกันไม่สามารถทำงานได้อย่างมีสุขภาพดี                                                        |

### วิธีการส่งมอบทำงานอย่างไร

สะพานเบื้องหลังจะสำรวจ [บันทึกกิจกรรม](/docs/activity/) ทุกๆ 15 วินาที และส่งต่อแถวที่จับคู่ หากการ POST เว็บฮุกล้มเหลวชั่วคราว แถวนั้นจะถูกลองใหม่ในการสำรวจครั้งถัดไปแทนที่จะถูกทิ้งไป เว็บฮุกที่ไม่สามารถเข้าถึงได้อย่างถาวรจะถูกปิดเสียง (หนึ่งบรรทัดต่อชั่วโมง) หลังจากพยายามหลายครั้ง สะพานจะไม่เล่นเหตุการณ์ย้อนหลังก่อนที่แผงควบคุมจะเริ่มทำงาน
