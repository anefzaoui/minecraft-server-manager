เซิร์ฟเวอร์แต่ละเครื่องมีการผสานรวมภายใต้กลุ่ม **การตั้งค่า**: **Discord**, **หน้าสถานะ**สาธารณะ, **คำเชิญ**ในคลิกเดียว และแท็บ **แชทบอท** (เฉพาะผู้ดูแลระบบ) หน้าเว็บนี้ครอบคลุม Discord; [คำเชิญและหน้าสถานะ](/docs/invites-and-status-page/) ครอบคลุมสองรายการนั้น และ [แชทบอท](/docs/chatbot/) มีหน้าของตัวเอง

## การแจ้งเตือน Discord

แผงควบคุมจะส่งต่อเหตุการณ์ของเซิร์ฟเวอร์ไปยังช่อง Discord ผ่านเว็บฮุค ไม่ต้องใช้บอท ไม่ต้องใช้ OAuth

### การตั้งค่า

1. ใน Discord: **การตั้งค่าเซิร์ฟเวอร์ → การผสานรวม → เว็บฮุค → เว็บฮุคใหม่** เลือกช่องและคัดลอก URL ของเว็บฮุค
2. ในแผงควบคุม ให้เปิดแท็บ **Discord** ของเซิร์ฟเวอร์ **การตั้งค่า → Discord** วาง URL ลงใน **URL ของเว็บฮุค** เปิดการ์ด **เปิด** และ **บันทึก** URL จะถูกจัดเก็บแบบเข้ารหัส (ในที่จัดเก็บแบบพักเดียวกันกับคีย์ API ของคุณ)
3. ใช้ **ส่งการทดสอบ** เพื่อยืนยันว่าทำงานได้

![การผสานรวม Discord](/docs/images/integrations-discord.png)

หากต้องการแทนที่ URL ที่จัดเก็บไว้ ให้วาง URL ใหม่แล้วบันทึก เว้นช่องว่างไว้เพื่อคงค่าปัจจุบัน URL ที่จัดเก็บไว้จะแสดงแบบปิดบัง (โทเค็นจะถูกซ่อนไว้)

### สิ่งที่ถูกส่ง

การแจ้งเตือนจะถูกจัดกลุ่มเป็นหมวดหมู่ที่สลับได้ ทั้งหมดเปิดอยู่ตามค่าเริ่มต้น

| หมวดหมู่           | เหตุการณ์                                              |
| ------------------ | ------------------------------------------------------ |
| **เริ่ม / หยุด**   | เซิร์ฟเวอร์เริ่มทำงาน, เซิร์ฟเวอร์หยุดทำงาน            |
| **ข้อขัดข้อง**     | ข้อขัดข้อง, ตรวจพบวงจรข้อขัดข้อง, รายงานข้อขัดข้องใหม่ |
| **การสำรองข้อมูล** | สร้างการสำรองข้อมูล, กู้คืนการสำรองข้อมูล              |
| **การอัปเดต**      | ใช้การอัปเดต, ย้อนกลับการอัปเดต, การอัปเดตล้มเหลว      |
| **การเตะ / แบน**   | ผู้เล่นถูกเตะ, ผู้เล่นถูกแบน                           |
| **การแจ้งเตือน**   | สิ่งที่ทำให้เซิร์ฟเวอร์เสียโดยไม่ส่งเสียง (ดูด้านล่าง) |

### หมวดหมู่การแจ้งเตือน

`การแจ้งเตือน` คือช่อง "บางอย่างต้องการคน" สำหรับเงื่อนไขที่เคยเห็นได้เฉพาะในแผงควบคุมเท่านั้น:

| เหตุการณ์               | ความหมาย                                                                                                             |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `oom`                   | คอนเทนเนอร์ถูกหยุดเนื่องจากหน่วยความจำหมด                                                                            |
| `unhealthy`             | กระบวนการทำงานอยู่ แต่การตรวจสอบ `mc-health` ล้มเหลว: เซิร์ฟเวอร์ทำงานแต่เหมือนตาย                                   |
| `startup-stalled`       | ยังคงเริ่มทำงานหลังจากประมาณ 10 นาที โดยไม่มี "เสร็จสิ้น" ในบันทึก (พร้อมการวินิจฉัยว่าจะแก้ไขอะไร ที่ไหน เมื่อทราบ) |
| `stop-failed`           | การหยุดทำงานอย่างราบรื่นไม่สำเร็จ และคอนเทนเนอร์ยังคงทำงานอยู่                                                       |
| `schedule-failed`       | การรีสตาร์ท / สำรองข้อมูล / คำสั่งตามกำหนดเวลาล้มเหลว                                                                |
| `quota-exceeded`        | โควตาพื้นที่ดิสก์โหมดเข้มงวดถูกละเมิด และเซิร์ฟเวอร์ถูกหยุด                                                          |
| `offline-after-restart` | เซิร์ฟเวอร์ทำงานอยู่ก่อนที่แผงควบคุมจะรีสตาร์ท ตอนนี้ไม่ทำงาน และจะไม่เริ่มทำงานอัตโนมัติ                            |
| `port-change-failed`    | การเปลี่ยนแปลงพอร์ตล้มเหลว และเซิร์ฟเวอร์ไม่สามารถกลับไปใช้พอร์ตเดิมได้ จึงหยุดทำงาน                                 |
| `auto-restart-gave-up`  | เซิร์ฟเวอร์ที่ขัดข้องไม่ได้รับการรีสตาร์ทเนื่องจากการดำเนินการอื่นทำให้เซิร์ฟเวอร์ไม่ว่างนานเกินไป                   |

### วิธีการทำงานของการส่งมอบ

สะพานเบื้องหลังจะสำรวจ [บันทึกกิจกรรม](/docs/activity/) ทุกๆ 15 วินาที และส่งต่อแถวที่จับคู่ หากการโพสต์เว็บฮุคไม่สำเร็จชั่วคราว แถวนั้นจะถูกลองใหม่ในการสำรวจครั้งต่อไปแทนที่จะถูกละทิ้ง หลังจากลองล้มเหลวสองสามครั้ง แถวนั้นจะถูกข้ามไป และความล้มเหลวในการส่งมอบจะถูกบันทึกอย่างน้อยหนึ่งครั้งต่อชั่วโมงต่อเซิร์ฟเวอร์ หลังจากรีสตาร์ทแผงควบคุม สะพานจะส่งเหตุการณ์ที่ยังไม่ได้ส่งมอบ แต่ไม่เกินสองชั่วโมงย้อนหลัง เมื่อเริ่มทำงานครั้งแรก จะเริ่มจากเหตุการณ์ล่าสุด
