หน้า **การสำรองข้อมูล** คือภาพรวมของทุกการสำรองข้อมูลในระบบของคุณ พร้อมด้วยขนาด เหตุผล และอายุ

![การสำรองข้อมูล](/docs/images/backups.png)

## การสร้างการสำรองข้อมูล

จากแท็บ **การสำรองข้อมูล** ของเซิร์ฟเวอร์ (หรือผ่าน [กำหนดการ](/docs/schedules/)) คุณสามารถสร้างสแนปชอตของไดเรกทอรีเซิร์ฟเวอร์ทั้งหมดได้ในคลิกเดียว แผงควบคุมจะทำให้เวิลด์หยุดทำงานก่อน (`save-off` → `save-all`) บีบอัดข้อมูล จากนั้นเปิดใช้งานการบันทึกอีกครั้ง (`save-on`) ดังนั้นการสำรองข้อมูลจึงมีความสอดคล้องกันแม้ในขณะที่เซิร์ฟเวอร์กำลังทำงาน การบีบอัดจะทำงานในเธรดของเวิร์กเกอร์เบื้องหลัง เพื่อไม่ให้แผงควบคุมหยุดทำงาน การสำรองข้อมูลแต่ละรายการสามารถมีบันทึกได้

อาร์ไคฟ์แต่ละรายการจะถูก **ตรวจสอบความสมบูรณ์** ทันทีที่เขียน: แผงควบคุมจะเปิด zip อีกครั้งและอ่านไดเรกทอรี หากอาร์ไคฟ์เสียหายหรือไม่สามารถเปิดได้ จะถูกลบและการเรียกใช้การสำรองข้อมูลจะล้มเหลวทันที แทนที่จะเกิดปัญหาขึ้นในภายหลังเมื่อการกู้คืนเป็นสิ่งเดียวที่ขวางกั้นคุณจากการสูญเสียข้อมูล อาร์ไคฟ์ที่มีรายการเป็นศูนย์ (เซิร์ฟเวอร์ที่ไม่เคยเริ่มทำงาน) จะได้รับอนุญาต แต่จะถูกตั้งค่าสถานะในเหตุการณ์

เลือก **"ย่อเวิลด์หลังจากนั้นด้วย"** (ในแท็บการสำรองข้อมูล หรือในกำหนดการสำรองข้อมูล) เพื่อลบส่วนที่ไม่ค่อยได้เข้าชมหลังจากที่อาร์ไคฟ์ถูกเขียนอย่างปลอดภัยแล้ว (ดู **[การย่อเวิลด์](/docs/world-shrink/)**) การย่อขนาดจะทำงานเฉพาะเมื่อเซิร์ฟเวอร์หยุดทำงานเท่านั้น ในเซิร์ฟเวอร์ที่กำลังทำงาน การสำรองข้อมูลจะยังคงเกิดขึ้นและจะข้ามการย่อขนาด

![การสำรองข้อมูลเซิร์ฟเวอร์](/docs/images/server-backups.png)

## เหตุผลในการสำรองข้อมูล

การสำรองข้อมูลจะถูกติดแท็กตามเหตุผลที่ถูกสร้างขึ้น:

- **ด้วยตนเอง** - คุณคลิกปุ่ม
- **ตามกำหนดการ** - สร้างโดย [กำหนดการ](/docs/schedules/) เซิร์ฟเวอร์ใหม่แต่ละเครื่องจะได้รับการสำรองข้อมูลตามกำหนดการรายวันโดยอัตโนมัติ (สลับระหว่าง 02:00 ถึง 05:59) ดังนั้นเซิร์ฟเวอร์จะได้รับการคุ้มครองอัตโนมัติตั้งแต่วันแรก ไม่ใช่แค่ก่อนการอัปเดต
- **ก่อนอัปเดต** - สร้างขึ้นโดยอัตโนมัติก่อนการอัปเกรดแพ็ค ดังนั้นการอัปเกรดจึงสามารถย้อนกลับได้เสมอ
- **ก่อนกู้คืน** - สร้างขึ้นโดยอัตโนมัติก่อนการกู้คืนหรือการรีเซ็ตเวิลด์ เพื่อเป็นตาข่ายนิรภัยในกรณีที่การกู้คืนไม่เป็นไปตามที่คุณต้องการ

## การเก็บรักษา

การเก็บรักษาจะถูกจำกัด **ต่อเซิร์ฟเวอร์ ต่อเหตุผล**: รายการที่ใหม่ที่สุดในแต่ละกลุ่มจะถูกเก็บไว้ รายการที่เก่ากว่าจะถูกลบโดยอัตโนมัติหลังจากการสำรองข้อมูลที่สำเร็จแต่ละครั้ง:

| เหตุผล      | เก็บไว้ |
| ----------- | ------- |
| ตามกำหนดการ | 10      |
| ก่อนอัปเดต  | 10      |
| ด้วยตนเอง   | 20      |
| ก่อนกู้คืน  | 5       |

`ก่อนกู้คืน` มีพื้นที่เก็บข้อมูลขนาดเล็กของตัวเองโดยเฉพาะ เพื่อให้การสำรองข้อมูลความปลอดภัยอัตโนมัติไม่สามารถลบการสำรองข้อมูล `ด้วยตนเอง` ที่คุณเก็บไว้โดยเจตนาได้

เพดานเสริมสองแบบใช้เพิ่มเติมจากจำนวนต่อเหตุผล โดยทั้งสองอย่างปิดใช้งานตามค่าเริ่มต้น: **อายุสูงสุด** (การสำรองข้อมูลที่เก่ากว่า N วันจะถูกลบ ไม่ว่าเหตุผลใดก็ตาม) และ **ขนาดรวมสูงสุด** ต่อเซิร์ฟเวอร์ (การสำรองข้อมูลที่เก่าที่สุดจะถูกลบจนกว่าผลรวมจะพอดี โดยเริ่มจาก `ก่อนกู้คืน`) การสำรองข้อมูลที่ใหม่ที่สุดของเซิร์ฟเวอร์จะไม่ถูกลบโดยเพดานใดๆ สิ่งเหล่านี้ทั้งหมดสามารถเปลี่ยนแปลงได้ทั่วโลกในหน้าการตั้งค่า และเขียนทับต่อเซิร์ฟเวอร์ในแท็บการสำรองข้อมูล

การสำรองข้อมูลสามารถ **เปลี่ยนชื่อ** ได้จากรายการสำรองข้อมูล (ปุ่มเปลี่ยนชื่อในแต่ละแถว) อาร์ไคฟ์บนดิสก์และบันทึกของแผงควบคุมจะเคลื่อนย้ายไปด้วยกัน ดังนั้นการดาวน์โหลด การกู้คืน และการเก็บรักษาจะยังคงทำงานด้วยชื่อใหม่

![เปลี่ยนชื่อการสำรองข้อมูล](/docs/images/backup-rename.png)

> การเก็บรักษาจะถูกจำกัดโดยอัตโนมัติ แต่ไฟล์เก็บถาวรขนาดใหญ่ที่มีม็อดจะยังคงนับรวมกับ [โควต้าดิสก์](/docs/storage/) ของเซิร์ฟเวอร์ ดังนั้นโปรดจับตาดูผลรวมสำหรับแพ็คขนาดใหญ่

## การกู้คืน

การกู้คืนการสำรองข้อมูลจะหยุดเซิร์ฟเวอร์ (ตรวจสอบว่าคอนเทนเนอร์หยุดทำงานจริงก่อนที่จะแตะต้องไฟล์ใดๆ) สร้างการสำรองข้อมูลความปลอดภัย `ก่อนกู้คืน` แทนที่ **ไดเรกทอรีเซิร์ฟเวอร์ทั้งหมด** ด้วยสแนปชอต และปล่อยให้เซิร์ฟเวอร์หยุดทำงานเพื่อให้คุณเริ่มใหม่ เนื่องจากอัปเกรดแพ็คจะสร้างการสำรองข้อมูล `ก่อนอัปเดต` เสมอ คุณจึงสามารถย้อนกลับการอัปเกรดที่ผิดพลาดได้เสมอ

## ฐานข้อมูลของแผงควบคุมเอง

การสำรองข้อมูลเซิร์ฟเวอร์ครอบคลุมเฉพาะไดเรกทอรีเวิลด์ต่อเซิร์ฟเวอร์เท่านั้น ฐานข้อมูลของแผงควบคุมเอง (`panel.db` ซึ่งเก็บผู้ใช้ บทบาท ความลับ 2FA กำหนดการ หมุดแพ็ค และประวัติ) จะถูกสร้างสแนปชอตแยกต่างหากในตัวจับเวลาการบำรุงรักษารายวัน:

- `VACUUM INTO` จะเขียนสำเนาที่สอดคล้องกันและไม่แตกตัวเป็นชิ้นๆ ไปยัง `data/backups/_panel/`; **14** รายการล่าสุดจะถูกเก็บไว้
- เมื่อบูต แผงควบคุมจะรัน `PRAGMA integrity_check` และบันทึกข้อความดังหากล้มเหลว โดยชี้คุณไปยัง `data/backups/_panel` สำหรับสำเนาที่ถูกต้องล่าสุด

สำรองข้อมูลทั้งต้นไม้ `data/` (ซึ่งมี `.secret-key` ซึ่งเป็นคีย์การเข้ารหัสขณะพัก) และคุณได้สำรองข้อมูลทุกอย่างแล้ว
