หน้า **Updates** ติดตามสิ่งที่ล้าสมัยในทุกเซิร์ฟเวอร์ของคุณในที่เดียว:

- เวอร์ชัน **Modpack** ([modpacks](/docs/modpacks/)) เทียบกับ Modrinth / CurseForge / ดัชนีการเผยแพร่ GTNH
- **เนื้อหาที่กำหนดเอง** ที่คุณเพิ่มเอง (mods, datapacks, resource packs, plugins) แต่ละรายการเทียบกับแหล่งที่มา: Modrinth, CurseForge, Hangar, SpigotMC (Spiget) หรือ GitHub Releases การค้นหา GitHub ใช้การตรวจสอบ ETag ดังนั้นการตรวจสอบรายวันจึงแทบไม่กระทบต่อขีดจำกัดอัตรา
- **Docker image** ที่ล้าสมัย: ID ของ image ของคอนเทนเนอร์เซิร์ฟเวอร์แต่ละรายการเทียบกับแท็กที่ดึงมาใหม่ (ลดซ้ำซ้อนระหว่างเซิร์ฟเวอร์ที่มีแท็กเดียวกัน) นำเสนอเป็นการอัปเกรดที่ต้องสร้างใหม่เท่านั้น
- **การปักหมุดเวอร์ชันสแตนด์อโลน**: สำหรับเซิร์ฟเวอร์ที่ไม่มีแพ็กที่จัดการ การปักหมุด `mc_version` อย่างชัดเจนเทียบกับ manifest ของ Mojang และตัวแปรสภาพแวดล้อม env var ของ loader-build ที่ชัดเจน (`PAPER_BUILD`, `FORGE_VERSION` และอื่นๆ) เทียบกับ registry ของ loader การสร้าง Paper มาจาก **Fill v3 API** ปัจจุบันของ PaperMC (จุดสิ้นสุด v2 แบบเก่าหยุดรับเวอร์ชัน Minecraft ใหม่) บนเซิร์ฟเวอร์ที่มี mods เวอร์ชัน Minecraft ที่ใหม่กว่าจะถูกนำเสนอเมื่อ [การตรวจสอบเวอร์ชัน](#minecraft-version-compatibility) แสดงว่า mods ที่ติดตั้งทั้งหมดมี build สำหรับเวอร์ชันนั้น เซิร์ฟเวอร์ Forge ที่ปักหมุดจะได้รับ build ที่แนะนำของ Forge ไม่ใช่ build ที่เก่ากว่าที่ปักหมุดไว้ และเซิร์ฟเวอร์ที่ปักหมุดไว้กับ release จะไม่ได้รับ pre-release (ที่อยู่ใน beta อยู่แล้วสามารถรับ beta ที่ใหม่กว่าหรือ release ได้) การใช้ build ของ loader จะสำรองข้อมูลก่อนการอัปเดต การย้ายเซิร์ฟเวอร์ Forge หรือ NeoForge ไปยังเวอร์ชัน Minecraft ใหม่จะล้างหมายเลข build ของ loader ที่ปักหมุดไว้ เนื่องจาก build ถูกสร้างขึ้นสำหรับเวอร์ชัน Minecraft เดียว คำหลักเช่น `latest` จะยังคงอยู่ เนื่องจากจะติดตามเวอร์ชันด้วยตัวเอง หากต้องการเลือก build ที่เฉพาะเจาะจงด้วยตนเอง โปรดดูที่ [การเปลี่ยนเวอร์ชัน mod loader](#changing-the-mod-loader-version)

## วิธีการทำงาน

แผงควบคุมจะตรวจสอบเวอร์ชันที่ปักหมุดของเซิร์ฟเวอร์แต่ละรายการกับแหล่งข้อมูลต้นทางและแสดงรายการสิ่งที่ออกใหม่ การนับที่ตรงกันจะปรากฏบนไทล์ "Updates available" ของ [แดชบอร์ด](/docs/dashboard/)

การตรวจสอบจะทำงานทุกวันตาม [กำหนดการ](/docs/schedules/) เริ่มต้นและตามต้องการด้วย **Check All Now** **Ignore** ในแถวจะหยุดการนำเสนอเวอร์ชันนั้นๆ และจะมีการนำเสนอเวอร์ชันที่ใหม่กว่าอีกครั้ง นโยบายการอัปเดตเป็นแบบต่อเซิร์ฟเวอร์: แผงควบคุมจะปล่อยให้ทุกอย่างเป็นแบบแมนนวล (ค่าเริ่มต้น ซึ่งจะทำให้เซิร์ฟเวอร์ไม่อยู่ในหน้านี้) เพียงแจ้งให้คุณทราบ หรือใช้การอัปเดตแพ็กเอง ([update policy](/docs/modpacks/#update-policy))

## ความเข้ากันได้ของเวอร์ชัน Minecraft

เวอร์ชัน Minecraft ที่ใหม่กว่าไม่ใช่การอัปเกรดหาก mods ของคุณไม่สามารถไปด้วยกันได้ เซิร์ฟเวอร์แต่ละเครื่องมีแท็บ **Versions** ของตัวเอง (ภายใต้ Mods) ที่ตอบคำถามนั้น:

- เวอร์ชันที่เซิร์ฟเวอร์กำลังทำงานอยู่ และ **เวอร์ชันสูงสุดที่ mods ที่ติดตั้งทั้งหมดมี build สำหรับ**
- แถวที่ยุบได้หนึ่งแถวต่อเวอร์ชัน Minecraft ในอนาคต พร้อมจำนวน mods ที่พร้อมใช้งานและจำนวน mods ที่ยังไม่มีอะไรเผยแพร่ เปิดแถวเพื่อดูว่า mods ใดจะถูกทิ้งไว้ข้างหลัง และ mods ใดที่ใช้ได้

![Version compatibility](/docs/images/server-versions.png)

กด **Check Future Versions** เพื่อเรียกใช้ ไม่มีอะไรสแกนเอง: การตรวจสอบจะอ่าน jar ทุกไฟล์ในโฟลเดอร์ mods ของเซิร์ฟเวอร์และสอบถาม Modrinth และ CurseForge เกี่ยวกับแต่ละไฟล์ ดังนั้นจึงเกิดขึ้นเฉพาะเมื่อคุณร้องขอเท่านั้น ความคืบหน้าและผลลัพธ์บางส่วนจะถูกเขียนขณะดำเนินการ ดังนั้นการปิดหน้าหรือรีเฟรชจะไม่สูญเสียอะไร และการตรวจสอบที่ถูกขัดจังหวะโดยการรีสตาร์ทแผงควบคุมจะแจ้งให้ทราบและเสนอให้เรียกใช้อีกครั้ง ทุกสิ่งที่การตรวจสอบที่ถูกขัดจังหวะได้ดำเนินการไปแล้วจะถูกเก็บไว้ ดังนั้นการเรียกใช้อีกครั้งจะไม่ทำซ้ำงานนั้น

รายงานจะอธิบายเฉพาะเซิร์ฟเวอร์ที่สร้างขึ้นเท่านั้น เปลี่ยนเวอร์ชัน Minecraft, loader หรือ mods เอง (เพิ่มหนึ่ง, ลบหนึ่ง, อัปเดตหนึ่ง) และรายงานจะถูกทำเครื่องหมายว่าล้าสมัยและหยุดใช้งาน จนกว่าคุณจะเรียกใช้การตรวจสอบอีกครั้ง

Mods จะถูกระบุจากรายการไฟล์ของ modpack เองหากมี และมิฉะนั้นจะโดยเนื้อหาของไฟล์ วิธีเดียวกับที่ launcher ระบุ jar mods สองประเภทที่ไม่สามารถตอบได้ และไม่มีการคาดเดา:

- **ไม่สามารถระบุได้**: jar ที่สร้างด้วยมือหรือ build ส่วนตัวที่ไม่มี registry ใดรู้จัก
- **ไม่สามารถตรวจสอบได้**: mod จาก GitHub Releases, Hangar หรือ SpigotMC หรือ mod ที่โครงการถูกลบไป สิ่งเหล่านี้ไม่ได้เผยแพร่รายการว่า build ใดสำหรับเวอร์ชัน Minecraft ใด

ขณะที่อย่างใดอย่างหนึ่งถูกติดตั้ง แผงควบคุมจะไม่เสนอการอัปเดตเวอร์ชัน Minecraft แบบคลิกเดียวเลย เนื่องจากไม่สามารถบอกได้อย่างซื่อสัตย์ว่าอะไรจะพัง การใช้เวอร์ชันที่สูงกว่าที่ mods รองรับจะถูกปฏิเสธ และจะระบุ mods ที่บล็อก

Mods ที่คุณ **ปิดใช้งาน** จะไม่เกี่ยวข้อง: เซิร์ฟเวอร์จะไม่โหลด mods เหล่านั้น ดังนั้นการปิด mod จึงเป็นวิธีจริงในการข้ามตัวบล็อก การเปิดหรือปิด mod จะทำเครื่องหมายรายงานเพื่อตรวจสอบใหม่

นี่ครอบคลุมเซิร์ฟเวอร์ที่รัน mods: Fabric, Forge, NeoForge และ Quilt เซิร์ฟเวอร์ปลั๊กอินสไตล์ Paper จะคงพฤติกรรม release ล่าสุดแบบธรรมดาและไม่มีแท็บ Versions เนื่องจาก registry สองแห่งที่ปลั๊กอินมาจากนั้นไม่ได้เผยแพร่สิ่งที่การตรวจสอบสามารถอ่านได้

![A version opened, showing which mods would be left behind](/docs/images/server-versions-expanded.png)

การเปิดเวอร์ชันจะแสดง mods ที่ไม่มี build สำหรับเวอร์ชันนั้นก่อน (ตัวที่ตัดสินคำตอบ) และเก็บ mods ที่พร้อมใช้งานไว้หลังจากการคลิก แพ็กขนาดใหญ่จะโหลดหน้า mods ทีละหน้า ดังนั้นเซิร์ฟเวอร์ 300 mods จะเปิดเร็วเท่ากับเซิร์ฟเวอร์ 5 mods

## การเปลี่ยนเวอร์ชัน mod loader

แท็บ **Versions** ยังมีส่วน **Loader Version** แสดงให้เห็นว่าเซิร์ฟเวอร์ติดตั้ง Forge, NeoForge, Fabric หรือ Quilt build ใด และในกรณีที่สามารถเปลี่ยนแปลงได้ จะมีตัวเลือกให้สลับไปยัง build อื่น

- **เซิร์ฟเวอร์ Forge, NeoForge, Fabric หรือ Quilt** สามารถรัน build ที่เผยแพร่ได้ ตัวเลือกจะแสดง build ล่าสุดสำหรับเวอร์ชัน Minecraft ของเซิร์ฟเวอร์ โดยมี build ที่แนะนำและล่าสุดของ Forge กำกับไว้ **Other Build…** จะรับ build เก่ากว่าตามหมายเลข และ **Default** จะกลับไปให้เซิร์ฟเวอร์เลือก
- **Forge หรือ Fabric CurseForge modpack** จะติดตั้งเวอร์ชัน loader ที่ประกาศโดย manifest ของตัวเอง ดังนั้นวิธีปกติในการเปลี่ยนแปลงคือการอัปเดตแพ็ก เมื่อแพ็กเองแสดงเวอร์ชันที่ไม่ถูกต้อง (mod ภายในขอ Forge ที่ใหม่กว่าที่แพ็กติดตั้ง) ส่วนนี้สามารถแทนที่ได้ และ **The Modpack's Version** จะลบการแทนที่อีกครั้ง การอัปเดตแพ็กก็จะลบออกเช่นกัน เนื่องจากเวอร์ชันใหม่ประกาศ loader ของตัวเอง หากเวอร์ชันใหม่ยังคงแสดงเวอร์ชันที่ไม่ถูกต้อง ให้ตั้งค่าการแทนที่อีกครั้ง
- **NeoForge CurseForge modpack หรือ Modrinth modpack** จะแสดง loader แต่ไม่สามารถแทนที่ได้: image ของเซิร์ฟเวอร์จะใช้การแทนที่กับ Forge และ Fabric packs เท่านั้น Loader จะติดตามเวอร์ชันแพ็ก ดังนั้นให้ อัปเดตแพ็กแทน Loader ของ FTB pack ก็ไม่สามารถเปลี่ยนแปลงได้ที่นี่เช่นกัน ส่วนนี้มักจะไม่ปรากฏขึ้น เนื่องจากตัวติดตั้งของ FTB เองเก็บรักษาบันทึกที่แผงควบคุมไม่สามารถอ่านได้

แผงควบคุมจะตรวจสอบว่า build มีอยู่จริงก่อนที่จะถามอะไรคุณ build ของ Forge หรือ NeoForge ถูกสร้างขึ้นสำหรับเวอร์ชัน Minecraft เดียว ดังนั้นบนเซิร์ฟเวอร์ที่ติดตาม release ล่าสุด การปักหมุด build ก็จะทำให้เซิร์ฟเวอร์ยังคงอยู่ที่เวอร์ชัน Minecraft ที่กำลังทำงานอยู่ (การยืนยันจะแจ้งให้ทราบ) การเลือก **Default** หลังจากนั้นจะลบการปักหมุด แต่อย่าลืมเวอร์ชัน Minecraft นั้น เซิร์ฟเวอร์ที่ติดตาม release ล่าสุดอาจย้ายไปยัง Java image ที่แตกต่างกันเมื่อถูกสร้างใหม่ ซึ่งเป็นเวอร์ชันที่ต้องการ เซิร์ฟเวอร์ดังกล่าวที่ไม่เคยเริ่มทำงานมาก่อนจะถูกขอให้เริ่มทำงานก่อน เพื่อให้แผงควบคุมทราบเวอร์ชันนั้น Forge จะข้ามหมายเลข build (ไม่มี 47.4.14 ระหว่าง 47.4.13 และ 47.4.15) ดังนั้น mod ที่ "ต้องการ 47.4.14 หรือสูงกว่า" จะได้รับการตอบสนองโดย build ถัดไป และการปฏิเสธจะระบุชื่อ การเปลี่ยนแปลงจะสำรองข้อมูลก่อนการอัปเดต จากนั้นจึงสร้างเซิร์ฟเวอร์ใหม่ build ใหม่จะถูกติดตั้งในครั้งต่อไปที่เซิร์ฟเวอร์เริ่มทำงาน และส่วนนั้นจะแจ้งให้ทราบจนกว่าจะถึงตอนนั้น

## การยกเลิกการอัปเดต mod

ทุก build ที่ mod ถูกอัปเดตจากจะยังคงอยู่ในไลบรารีที่ใช้ร่วมกัน ดังนั้นการอัปเดตที่ทำให้เกิดปัญหาจะสามารถย้อนกลับได้ แถวของ mod ในแท็บ **Mods** จะมีปุ่ม **Revert** ที่จะคืนค่า build ก่อนหน้ากลับไป ไม่มีการดาวน์โหลด ดังนั้นจึงทำงานได้แม้ว่าโครงการจะถูกลบออกจาก registry แล้วก็ตาม build ที่คุณย้อนกลับไปจะหยุดการนำเสนอจนกว่าจะมีการปรากฏ build ที่ใหม่กว่า

![Revert a mod to the build it was updated from](/docs/images/mods-revert.png)

## การใช้การอัปเดต

การอัปเดตจะไม่เงียบเสมอไป เมื่อคุณเลือกที่จะอัปเกรดแพ็ก (หรือ [สลับไปยังเวอร์ชันอื่น](/docs/modpacks/#changing-the-pack-version) รวมถึงเวอร์ชันเก่ากว่า) แผงควบคุมจะ:

1. ทำการ **สำรองข้อมูลก่อนการอัปเดต** (เพื่อให้สามารถย้อนกลับได้ โดยค่าเริ่มต้นจะเก็บสำรองข้อมูลก่อนการอัปเดต 10 รายการล่าสุดต่อเซิร์ฟเวอร์ ดู [retention](/docs/backups/#retention))
2. ปักหมุดเวอร์ชันใหม่ที่แน่นอนอีกครั้ง
3. สร้างเซิร์ฟเวอร์ใหม่ โดยแก้ไข runtime ของ Java หากจำเป็น
4. ตรวจสอบการบูตครั้งแรก โดยมีงบประมาณเวลาต่อแพลตฟอร์ม

หากไม่สามารถบูตได้สำเร็จ คุณจะย้อนกลับไปยังข้อมูลสำรองก่อนการอัปเดต เซิร์ฟเวอร์ที่ติดตาม release อย่างเสถียรจะไม่ได้รับ beta และลิงก์ changelog จะชี้ไปยัง diff ต่อเวอร์ชันจริงที่แหล่งข้อมูลให้ไว้ การอัปเดตที่ล้มเหลวจะส่งการแจ้งเตือน Discord [alert](/docs/integrations/) หากมีการกำหนดค่าการรวมระบบ
