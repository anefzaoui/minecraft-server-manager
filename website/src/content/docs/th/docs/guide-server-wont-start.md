ทำงานตามรายการนี้ โดยเรียงลำดับตามความถี่ที่แต่ละรายการเป็นคำตอบ และสี่รายการแรกครอบคลุมส่วนใหญ่

## 1. อ่าน 20 บรรทัดสุดท้าย ไม่ใช่บรรทัดแรก

เลื่อนไปที่ **ส่วนท้าย** ของบันทึก Java stack trace จะถูกพิมพ์จากด้านในสุด ดังนั้นส่วนบนของข้อความจำนวนมากจึงเป็นส่วนที่น่าสนใจน้อยที่สุด สิ่งที่คุณต้องการคือบรรทัด `Caused by:` สุดท้ายและสิ่งที่ตามมา บรรทัดเดียวนี้มักจะบอกปัญหา

รูปทรงสองแบบจะบอกคุณว่าคุณอยู่ที่ไหน:

- `Exception in thread "main"` หรือเส้นทางรายงานข้อขัดข้องใกล้ส่วนท้าย หมายความว่าเกมล้มเหลวเอง
- บันทึกหยุดกลางคันโดยไม่มีข้อยกเว้นเลย หมายความว่ามีบางอย่างที่ทำให้กระบวนการหยุดทำงานจากภายนอก ไปที่ข้อ 3

## 2. UnsupportedClassVersionError หมายถึง Java ผิดเวอร์ชัน

```
java.lang.UnsupportedClassVersionError: net/minecraft/server/Main has been compiled
by a more recent version of the Java Runtime (class file version 65.0)
```

Class file 52 คือ Java 8, 60 คือ 16, 61 คือ 17, 65 คือ 21, 69 คือ 25 ข้อความหมายความว่าเซิร์ฟเวอร์ต้องการ Java ที่ใหม่กว่าที่กำลังทำงานอยู่ ตรงกันข้าม แพ็คเก่าบน Java ใหม่มักจะล้มเหลวด้วยข้อผิดพลาด mixin หรือ reflection แทน

| Minecraft version  | Java |
| ------------------ | ---- |
| 1.16.5 และเก่ากว่า | 8    |
| 1.17               | 16   |
| 1.18 และ 1.19      | 17   |
| 1.20 ถึง 1.20.4    | 17   |
| 1.20.5 ถึง 1.21.x  | 21   |
| 26.1 และใหม่กว่า   | 25   |

แพ็คเก่าต้องการ Java 8 จริงๆ เวอร์ชันใหม่กว่าไม่ได้ดีกว่าในกรณีนี้

## 3. รหัสออก 137 คือเคอร์เนล ไม่ใช่ mod

บันทึกหยุดกลางคัน ไม่มีรายงานข้อขัดข้อง และคอนเทนเนอร์รายงาน 137 นั่นคือการถูกฆ่าเนื่องจากหน่วยความจำไม่เพียงพอ: กระบวนการขอหน่วยความจำที่เครื่องไม่มี จึงถูกยุติ

เกือบตลอดเวลา Java heap ถูกตั้งค่าเป็นจำนวนเดียวกับหน่วยความจำของเครื่อง heap ต้องการหน่วยความจำของเครื่อง **ลบ** ค่าใช้จ่ายเพิ่มเติมของ JVM เอง ซึ่งอยู่ที่ 0.5 ถึง 1.5 GB บนเซิร์ฟเวอร์ที่มี mod ลดขนาด heap หรือเพิ่มขนาดเครื่อง [RAM ที่เซิร์ฟเวอร์ต้องการเท่าใด](/docs/guide-server-memory/) มีตัวเลข

## 4. EULA และพอร์ต

สองรายการคลาสสิกพร้อมวิธีแก้ไขแบบบรรทัดเดียว:

- `You need to agree to the EULA in order to run the server.` ตั้งค่า `eula=true` ใน `eula.txt` หรือด้วยตัวแปรสภาพแวดล้อมที่การตั้งค่าของคุณใช้
- `Address already in use` หรือ `FAILED TO BIND TO PORT` มีบางอย่างอื่นใช้พอร์ต 25565 อยู่ มักจะเป็นสำเนาของเซิร์ฟเวอร์เดียวกันที่ยังไม่หยุดทำงานอย่างสมบูรณ์ ค้นหาและหยุดมันแทนที่จะเปลี่ยนพอร์ต มิฉะนั้นคุณจะมีสองอัน

## 5. mod ขาด dependency

```
Mod X requires mod Y, which is missing
Fabric API is not installed
```

Mod Fabric ส่วนใหญ่ต้องการ Fabric API เป็นไฟล์แยก Mod Forge และ NeoForge จะแสดงรายการ dependencies ของตนเองในข้อผิดพลาด ติดตั้งเวอร์ชันที่ระบุ ไม่ใช่เวอร์ชันล่าสุด: "requires 0.91.x" หมายถึงบรรทัดนั้น และ 0.92 จะล้มเหลวในการตรวจสอบเดียวกัน

บางครั้ง dependency ที่ขาดหายไปคือตัวโหลดเอง:

```
Mod X requires forge 47.4.14 or above
Mod ID: 'forge', Requested by: 'x', Expected range: '[47.4.14,)', Actual version: '47.4.10'
```

การแก้ไขคือการอัปเดต build ของตัวโหลด ไม่ใช่ mod อื่น "47.4.14 or above" หมายถึง build ใดๆ ตั้งแต่ตรงนั้นขึ้นไป และ Forge ไม่ได้เผยแพร่ทุกหมายเลข ดังนั้น build ที่ต้องติดตั้งอาจเป็น build ถัดไป บน modpack ให้อัปเดตแพ็คก่อน: แพ็คที่มีเวอร์ชันตัวโหลดเก่าเกินไปสำหรับ mod ของตนถือเป็นข้อผิดพลาดสำหรับผู้เขียนที่จะแก้ไข

## 6. mod สำหรับตัวโหลดหรือเวอร์ชันผิด

jar สำหรับตัวโหลดอื่นจะไม่แจ้งข้อผิดพลาดอย่างสุภาพ คาดหวังข้อผิดพลาด mixin, `NoClassDefFoundError`, หรือข้อขัดข้องภายในคลาสที่คุณไม่เคยได้ยินมาก่อน ตรวจสอบหน้า jar: ตัวโหลดและเวอร์ชัน Minecraft ทั้งสองต้องตรงกันทุกประการ 1.20.1 และ 1.20.4 ถือเป็นเกมที่แตกต่างกันสำหรับ mod

## 7. โลกมาจากเวอร์ชันที่ใหม่กว่า

```
This world was created by a newer version of Minecraft
```

โลกจะอัปเกรดไปข้างหน้าเสมอและไม่เคยย้อนกลับ กู้คืนการสำรองข้อมูลก่อนการอัปเกรด หรือเรียกใช้เวอร์ชันที่โลกคาดหวัง ไม่มีเส้นทางดาวน์เกรดที่จะรักษา chunk ให้สมบูรณ์

## เมื่อเกิดข้อขัดข้องหลังจากทำงานได้ดีมาหลายสัปดาห์

คำถามที่แตกต่างกัน มักจะตอบต่างกัน:

- **เกิดข้อขัดข้องภายใต้ภาระงาน** โดยมี timings แสดงการหยุดชะงักนาน: garbage collection ดังนั้นให้ดูขนาด heap ก่อน mod
- **เกิดข้อขัดข้องที่จุดเดิมในโลก**: chunk เสียหายหรือ entity เสียหาย รายงานข้อขัดข้องมักจะระบุพิกัด
- **เกิดข้อขัดข้องทันทีหลังจากการอัปเดต**: mod ที่อัปเดตคือผู้ต้องสงสัย แม้ว่า trace จะชี้ไปที่อื่นก็ตาม ย้อนกลับและดู
- **เกิดข้อขัดข้องเมื่อรีสตาร์ท หลังจากที่เคยใช้งานได้ดีมาก่อน**: ตรวจสอบดิสก์ ดิสก์เต็มจะทำให้เกิดข้อผิดพลาดที่น่าตื่นตาและทำให้เข้าใจผิด

## การขอความช่วยเหลือที่ได้ผลจริง

โพสต์ **บันทึกทั้งหมด** ไม่ใช่บรรทัดสุดท้าย และบอกว่าคุณเปลี่ยนอะไรก่อนที่จะเกิดปัญหา วางไว้ในที่ที่ออกแบบมาสำหรับมัน เช่น [mclo.gs](https://mclo.gs) แทนที่จะเป็นในแชท รวมถึงเวอร์ชัน Minecraft, ตัวโหลด, แพ็คและเวอร์ชัน และปริมาณ heap ที่เซิร์ฟเวอร์มี รายงานที่มีข้อมูลสี่อย่างนี้จะได้รับคำตอบในหนึ่งการตอบกลับ หากไม่มีข้อมูลเหล่านั้น จะต้องใช้ห้าครั้ง

## ใน Minecraft Server Manager

ข้อขัดข้องจะถูกตรวจจับจากการออกของคอนเทนเนอร์เอง ดังนั้นเซิร์ฟเวอร์ที่ดับในตอนเช้ามืดจะถูกบันทึกพร้อมส่วนที่ตัดตอนมาจากบันทึก แทนที่จะพบในวันถัดไป ผู้ต้องสงสัยทั่วไปในหน้านี้ (EULA, Java ผิดเวอร์ชัน, โลกจากเวอร์ชันที่ใหม่กว่า, พอร์ตที่ใช้งานอยู่แล้ว, Java หมดหน่วยความจำ) จะถูกจดจำในบันทึกนั้นและระบุในรายการประวัติพร้อมวิธีแก้ไข และการรีสตาร์ทอัตโนมัติจะปล่อยให้สิ่งเหล่านั้นอยู่ตามลำพัง เนื่องจาก การรีสตาร์ทจะไม่แก้ไข รายงานข้อขัดข้องจะถูกแยกวิเคราะห์เมื่อมาถึง: ข้อยกเว้นจะถูกเน้น, stack สามารถยุบได้, และ mod ที่ปรากฏใน trace จะถูกระบุว่าเป็นผู้ต้องสงสัย

รายงานใดๆ สามารถแชร์ไปยัง mclo.gs จากการ์ดของมันเมื่อคุณต้องการความช่วยเหลือ (หลังจากการยืนยัน เนื่องจาก paste เป็นสาธารณะ) และเมนู **Download** ของคอนโซลมีไฟล์บันทึกทั้งหมดเป็น zip ไฟล์เดียว ดังนั้น "โพสต์บันทึกทั้งหมด" จึงเป็นการดาวน์โหลดแทนที่จะเป็นการขุดค้นทางโบราณคดี การถูกฆ่าเนื่องจากหน่วยความจำไม่เพียงพอจะถูกบันทึกเป็นการถูกฆ่าเนื่องจากหน่วยความจำไม่เพียงพอ ซึ่งช่วยประหยัดเวลาหนึ่งชั่วโมงในการตำหนิ mod หากมีสิ่งอื่นที่ต้องการพอร์ตจริงๆ การ์ด **Game Port** ใน **Settings → Configuration** จะย้ายเซิร์ฟเวอร์ไปยังพอร์ตที่ว่าง

ตัวโหลดที่เก่าเกินไปจะถูกเปลี่ยนจากแท็บ **Versions** ของเซิร์ฟเวอร์ ซึ่งจะตรวจสอบว่า build มีอยู่หรือไม่ และสำรองข้อมูลก่อนที่จะสร้างเซิร์ฟเวอร์ใหม่ ([การเปลี่ยนเวอร์ชันตัวโหลด mod](/docs/updates/#changing-the-mod-loader-version))
