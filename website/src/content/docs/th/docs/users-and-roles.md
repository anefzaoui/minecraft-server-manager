แผงควบคุมรองรับผู้ใช้หลายคน จัดการบัญชีได้ที่ **การตั้งค่า → ผู้ใช้**

![Users](/docs/images/settings-users.png)

## สามบทบาท

| บทบาท            | สามารถทำอะไรได้                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **ผู้ดูแลระบบ**  | ทุกอย่าง: จัดการผู้ใช้, คีย์ API, ไฟล์ส่วนกลาง, การตั้งค่า Docker ขั้นสูง และการดำเนินการเซิร์ฟเวอร์ทั้งหมด                                |
| **ผู้ดำเนินการ** | เรียกใช้และกำหนดค่าเซิร์ฟเวอร์ (เริ่ม/หยุด, คอนโซล, สำรองข้อมูล, โลก, ม็อด, การตั้งค่าส่วนใหญ่) แต่ไม่ใช่ส่วนที่มีเฉพาะผู้ดูแลระบบเท่านั้น |
| **ผู้ชม**        | อ่านอย่างเดียว ดูเซิร์ฟเวอร์และสถานะของเซิร์ฟเวอร์ แต่ไม่สามารถเปลี่ยนแปลงอะไรได้                                                          |

ผู้ใช้ทุกคน รวมถึงผู้ชม สามารถจัดการ [การยืนยันตัวตนสองปัจจัย](/docs/two-factor-authentication/) ของตนเองได้ เนื่องจากการปกป้องการเข้าสู่ระบบของคุณไม่ใช่การดำเนินการจัดการเซิร์ฟเวอร์

## เฉพาะผู้ดูแลระบบ และเหตุผล

บางสิ่งถูกจำกัดเฉพาะผู้ดูแลระบบโดยเจตนา:

- **การจัดการผู้ใช้, คีย์ API และไฟล์ส่วนกลาง**
- **[API สาธารณะ](/docs/public-api/)** - การเปิดใช้งาน `/api/v1` และการสร้าง, การกำหนดขอบเขต, หรือการเพิกถอนโทเค็น Bearer แบบอ่านอย่างเดียว
- **การตั้งค่า Docker ขั้นสูง** - ชื่อคอนเทนเนอร์ที่กำหนดเอง, การเผยแพร่พอร์ตเพิ่มเติม และการเมาท์แบบผูกติด การเมาท์แบบผูกติดสามารถแมปพาธโฮสต์ใดก็ได้เข้าไปในคอนเทนเนอร์ และเมื่อรวมกับการเข้าถึง Docker ของแผงควบคุมแล้ว จะมีสิทธิ์เทียบเท่า root บนโฮสต์ ฟิลด์เหล่านี้จะปรากฏเฉพาะสำหรับผู้ดูแลระบบเท่านั้น

ชื่อคอนเทนเนอร์ที่กำหนดเองไม่สามารถอยู่ในเนมสเปซ `msm-` ของแผงควบคุมได้ ดังนั้นคอนเทนเนอร์ที่ตั้งชื่อด้วยตนเองจะไม่สามารถซ้อนทับเซิร์ฟเวอร์อื่นและส่งคำสั่งหยุดหรือคำสั่งไปยังอินสแตนซ์ที่ไม่ถูกต้องได้

## การจัดการบัญชี

![Profile picture](/docs/images/profile-picture.png)

ผู้ดูแลระบบสามารถสร้างผู้ใช้, เปลี่ยนบทบาท, รีเซ็ตรหัสผ่าน และลบบัญชีได้จากตารางผู้ใช้ คอลัมน์ **2FA** แสดงว่าผู้ใช้แต่ละคนเปิดใช้งานการยืนยันตัวตนสองปัจจัยหรือไม่ ผู้ดูแลระบบสามารถ **รีเซ็ต** การยืนยันตัวตนสองปัจจัยของผู้ใช้อื่นได้ (ในกรณีที่โทรศัพท์หายและไม่มีรหัสสำรอง) แต่ไม่สามารถปิดใช้งานของตนเองได้หากไม่มีรหัสผ่าน ซึ่งกระบวนการบริการตนเองจะจัดการแทน

การเข้าสู่ระบบที่ล้มเหลวจะถูกจำกัดอัตราต่อบัญชี (ทั้งตัวนับต่อ IP และตัวนับทั่วทั้งบัญชี) เพื่อชะลอความพยายามในการเดารหัสผ่าน และขีดจำกัดเดียวกันนี้จะครอบคลุมขั้นตอนการป้อนรหัส 2FA ด้วย ดังนั้นรหัสผ่านที่ถูกต้องจึงไม่สามารถรีเซ็ตตัวนับก่อนที่จะเดารหัสได้ ด้านหน้าของสิ่งนั้นคือตัวจำกัดคำขอต่อ IP ของไคลเอ็นต์ที่หยาบกว่าบนจุดสิ้นสุดการเข้าสู่ระบบ / 2FA / การตั้งค่า ซึ่งสามารถปรับแต่งได้ผ่าน `RATE_LIMIT_AUTH_PER_15MIN` (ค่าเริ่มต้น 100; หากอยู่หลังพร็อกซีผกผัน ให้ตั้งค่า `TRUST_PROXY` เพื่อให้ใช้ IP จริงของไคลเอ็นต์)
