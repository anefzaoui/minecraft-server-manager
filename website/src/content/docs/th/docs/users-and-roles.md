แผงควบคุมรองรับผู้ใช้หลายคน จัดการบัญชีได้ที่ **การตั้งค่า → ผู้ใช้**

![ผู้ใช้](/docs/images/settings-users.png)

## สามบทบาท

| บทบาท              | ค่าเริ่มต้นสำหรับทุกเซิร์ฟเวอร์                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| **ผู้ดูแลระบบ**    | ทุกอย่าง: จัดการผู้ใช้, คีย์ API, ไฟล์ส่วนกลาง, การตั้งค่า Docker ขั้นสูงเพิ่มเติม, และการดำเนินการเซิร์ฟเวอร์ทั้งหมด               |
| **ผู้ดำเนินการ**   | เรียกใช้และกำหนดค่าเซิร์ฟเวอร์ (เริ่ม/หยุด, คอนโซล, สำรองข้อมูล, โลก, ม็อด, การตั้งค่าส่วนใหญ่) แต่ไม่ใช่ส่วนของผู้ดูแลระบบเท่านั้น |
| **ผู้สังเกตการณ์** | อ่านอย่างเดียว ดูเซิร์ฟเวอร์และสถานะของเซิร์ฟเวอร์ แต่ไม่สามารถเปลี่ยนแปลงใดๆ ได้                                                   |

ผู้ใช้ทุกคน รวมถึงผู้สังเกตการณ์ สามารถจัดการ [การยืนยันตัวตนแบบสองปัจจัย](/docs/two-factor-authentication/) ของตนเองได้ เพราะการปกป้องการเข้าสู่ระบบของตนเองไม่ใช่การดำเนินการจัดการเซิร์ฟเวอร์

บทบาทคือค่า **เริ่มต้น** สำหรับทุกเซิร์ฟเวอร์ หากต้องการให้สิทธิ์ที่แตกต่างกันแก่บุคคลในเซิร์ฟเวอร์เดียว ให้ใช้สิทธิ์ต่อเซิร์ฟเวอร์ด้านล่าง

## สิทธิ์ต่อเซิร์ฟเวอร์

หน้า **สิทธิ์** (ในแถบด้านข้าง หรือ **สิทธิ์เซิร์ฟเวอร์** ใต้ **การตั้งค่า → ผู้ใช้**) แสดงตาราง: ผู้ดำเนินการและผู้สังเกตการณ์แต่ละคนอยู่ด้านข้าง เซิร์ฟเวอร์แต่ละเครื่องอยู่ด้านบน คลิกที่ช่องเพื่อตัดสินใจว่าผู้ใช้นั้นสามารถทำอะไรได้ในเซิร์ฟเวอร์นั้นๆ ผู้ดูแลระบบไม่อยู่ในรายการเพราะพวกเขามีทุกอย่างเสมอ

![สิทธิ์](/docs/images/settings-permissions.png)

แต่ละช่องคือชุดสิทธิ์:

| สิทธิ์          | สิ่งที่อนุญาตบนเซิร์ฟเวอร์นั้น                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------- |
| **ดู**          | ดูเซิร์ฟเวอร์ สถานะ, ผลลัพธ์คอนโซล, ผู้เล่น, ประวัติ, และสถิติ                                          |
| **ควบคุม**      | เริ่ม, หยุด, รีสตาร์ท, ฆ่า, และสร้างเซิร์ฟเวอร์ใหม่                                                     |
| **คอนโซล**      | เรียกใช้คำสั่งคอนโซลและการดำเนินการด่วนของโลก ส่งข้อความแชท และจัดการคำสั่งแชท                          |
| **ผู้เล่น**     | ไล่ออก, แบน, เพิ่มในรายการที่อนุญาต, ให้สิทธิ์ผู้ดำเนินการ, และแก้ไขบันทึกของผู้เล่น                    |
| **เนื้อหา**     | ติดตั้งและลบม็อด, ปลั๊กอิน, แพ็ค, โลก, ดาต้าแพ็ค, และแก้ไขรายการสิ่งของ                                 |
| **สำรองข้อมูล** | สร้าง, กู้คืน, ดาวน์โหลด, และลบข้อมูลสำรอง                                                              |
| **ไฟล์**        | เรียกดู, แก้ไข, อัปโหลด, และดาวน์โหลดไฟล์เซิร์ฟเวอร์, บันทึกที่เก็บถาวร, และชุดบันทึก; ส่งออกพิมพ์เขียว |
| **การตั้งค่า**  | เปลี่ยนการตั้งค่าเซิร์ฟเวอร์, คุณสมบัติ, การผสานรวม, ไอคอน, และอัปเกรดเวอร์ชัน                          |
| **ลบ**          | ลบเซิร์ฟเวอร์                                                                                           |

![ตัวแก้ไขสิทธิ์](/docs/images/permissions-editor.png)

ใต้ตาราง **สิ่งที่สิทธิ์แต่ละรายการครอบคลุม** จะขยายแต่ละสิทธิ์ออกเป็นสิ่งที่บุคคลสามารถทำได้ สิ่งที่ไม่รวมอยู่ด้วย และเส้นทางแผงควบคุมที่แน่นอนที่ปลดล็อก รายการสุดท้ายนี้จะถูกตรวจสอบกับโค้ดที่กำลังทำงานโดยชุดทดสอบ

![การอ้างอิงสิทธิ์](/docs/images/permissions-reference.png)

บนโทรศัพท์ ตารางจะซ้อนกันเป็นบัตรต่อผู้ใช้ โดยมีแถวต่อเซิร์ฟเวอร์

<p align="center">
  <img src="/docs/images/mobile/permissions.png" alt="สิทธิ์บนโทรศัพท์" width="180">
</p>

ชิ้นส่วนต่างๆ ทำงานร่วมกันอย่างไร:

- **บทบาทคือค่าเริ่มต้น** ผู้ดำเนินการจะเริ่มต้นด้วยสิทธิ์ทุกอย่างในทุกเซิร์ฟเวอร์ ผู้สังเกตการณ์จะเริ่มต้นด้วยสิทธิ์ "ดู" เท่านั้น ช่องที่มีข้อความจางๆ (คำแนะนำจะบอกว่า "ค่าเริ่มต้นของบทบาท") ไม่เคยถูกเปลี่ยนแปลง
- **ช่องจะเขียนทับบทบาทสำหรับเซิร์ฟเวอร์นั้นเท่านั้น** ให้สิทธิ์ "ควบคุม" และ "คอนโซล" แก่ผู้สังเกตการณ์ในเซิร์ฟเวอร์เดียว แล้วพวกเขาจะสามารถเรียกใช้ได้ ในขณะที่เซิร์ฟเวอร์อื่นๆ ทั้งหมดจะยังคงเป็นแบบอ่านอย่างเดียวสำหรับพวกเขา นำสิทธิ์ "ลบ" ออกจากผู้ดำเนินการในเซิร์ฟเวอร์หลักของคุณ แล้วพวกเขายังคงมีทุกอย่างอื่นในนั้น
- **ทุกสิทธิ์รวมถึง "ดู"** คุณไม่สามารถดำเนินการกับเซิร์ฟเวอร์ที่คุณมองไม่เห็นได้
- **ปิดทุกอย่างเพื่อซ่อนเซิร์ฟเวอร์** เซิร์ฟเวอร์นั้นจะหายไปจากแถบด้านข้าง, แดชบอร์ด, ข้อมูลสำรอง, ตารางเวลา, กิจกรรม, การอัปเดต, ชุดม็อด, สถานะสด, งานที่กำลังทำงาน, และพิมพ์เขียวของผู้ใช้นั้นๆ และไลบรารีโลกจะหยุดตั้งชื่อเซิร์ฟเวอร์นั้น ลิงก์โดยตรง, การเรียก API, หรือซ็อกเก็ตคอนโซลจะตอบว่า "ไม่พบ" เช่นเดียวกับเซิร์ฟเวอร์ที่ไม่มีอยู่จริง
- **การดำเนินการทั่วทั้งแผงยังคงเป็นไปตามบทบาท** การสร้างเซิร์ฟเวอร์ (รวมถึงการโคลน), พื้นที่จัดเก็บ, ผู้ใช้, คีย์ API, การตั้งค่าส่วนกลาง, และตารางเวลากระจายทั่วทั้งแผงไม่ใช่ต่อเซิร์ฟเวอร์ ดังนั้นผู้สังเกตการณ์ที่มีสิทธิ์ในบางเซิร์ฟเวอร์ก็ยังไม่สามารถทำสิ่งเหล่านั้นได้ ผู้ดำเนินการจะยังคงสร้างเซิร์ฟเวอร์และตารางเวลากระจายทั่วทั้งแผงได้ ส่วนพื้นที่จัดเก็บ, ผู้ใช้, คีย์ API, และการตั้งค่าส่วนกลางเป็นของผู้ดูแลระบบเท่านั้น
- **ตารางเวลาจะตามเซิร์ฟเวอร์** การรีสตาร์ท, สำรองข้อมูล, หรือคำสั่งที่ตั้งเวลาไว้บนเซิร์ฟเวอร์ต้องการสิทธิ์ที่ตรงกันในเซิร์ฟเวอร์นั้น (ควบคุม, สำรองข้อมูล, หรือคอนโซล) ไม่ว่าบทบาทจะเป็นอะไรก็ตาม
- **พิมพ์เขียวก็ตามเซิร์ฟเวอร์เช่นกัน** การส่งออกเซิร์ฟเวอร์เป็นพิมพ์เขียวต้องการสิทธิ์ "ไฟล์" ในเซิร์ฟเวอร์นั้น เพราะไฟล์เก็บถาวรจะบรรจุไฟล์ของเซิร์ฟเวอร์นั้น พิมพ์เขียวที่ส่งออกจากเซิร์ฟเวอร์ที่บุคคลมองไม่เห็นก็จะถูกซ่อนจากพวกเขาเช่นกัน
- **ส่วนของผู้ดูแลระบบเท่านั้นที่จะยังคงเป็นของผู้ดูแลระบบเท่านั้น** ในทุกเซิร์ฟเวอร์: แชทบอท, การเก็บรักษาข้อมูลสำรอง, และการตั้งค่า Docker ขั้นสูงเพิ่มเติม

ทุกการเปลี่ยนแปลงจะถูกเขียนลงในบันทึกกิจกรรมพร้อมระบุว่าใครเปลี่ยนแปลงอะไร รายการเหล่านั้นจะแสดงให้ผู้ดูแลระบบเท่านั้น การลบผู้ใช้จะลบแถวของผู้ใช้นั้น การลบเซิร์ฟเวอร์จะเก็บแถวของผู้ใช้ไว้ ดังนั้นเซิร์ฟเวอร์ที่ถูกซ่อนจากใครบางคนจะยังคงถูกซ่อนในประวัติและข้อมูลสำรองที่เก็บไว้

การติดตั้งที่มีอยู่จะยังคงทำงานต่อไปโดยไม่มีการเปลี่ยนแปลง: จนกว่าผู้ดูแลระบบจะแก้ไขช่อง ผู้ใช้ทุกคนจะมีสิทธิ์ที่บทบาทของพวกเขามอบให้ก่อนหน้านี้ทุกประการ

## เฉพาะผู้ดูแลระบบ และเหตุผล

บางสิ่งถูกจำกัดไว้สำหรับผู้ดูแลระบบโดยเจตนา:

- **การจัดการผู้ใช้, พื้นที่จัดเก็บ, การตั้งค่าส่วนกลาง, คีย์ API, และไฟล์ส่วนกลาง**
- **[API สาธารณะ](/docs/public-api/)**: การเปิดใช้งาน `/api/v1` และการสร้าง, การกำหนดขอบเขต, หรือการเพิกถอนโทเค็น Bearer แบบอ่านอย่างเดียว
- **การตั้งค่า Docker ขั้นสูงเพิ่มเติม**: ชื่อคอนเทนเนอร์ที่กำหนดเอง, การเผยแพร่พอร์ตเพิ่มเติม, และ bind mounts bind mount สามารถจับคู่เส้นทางโฮสต์ใดๆ เข้ากับคอนเทนเนอร์ได้ และเมื่อรวมกับการเข้าถึง Docker ของแผงควบคุมแล้ว นั่นก็เทียบเท่ากับสิทธิ์ root บนโฮสต์ ช่องเหล่านี้จะปรากฏเฉพาะสำหรับผู้ดูแลระบบเท่านั้น

ชื่อคอนเทนเนอร์ที่กำหนดเองก็ไม่สามารถอยู่ในเนมสเปซ `msm-` ของแผงควบคุมได้ ดังนั้นคอนเทนเนอร์ที่ตั้งชื่อด้วยตนเองจึงไม่สามารถซ้อนทับเซิร์ฟเวอร์อื่นและส่งคำสั่งหยุดหรือคำสั่งไปยังอินสแตนซ์ที่ไม่ถูกต้องได้

## การจัดการบัญชี

![รูปโปรไฟล์](/docs/images/profile-picture.png)

ผู้ดูแลระบบสามารถสร้างผู้ใช้, เปลี่ยนบทบาท, รีเซ็ตรหัสผ่าน, และลบบัญชีได้จากตารางผู้ใช้ คอลัมน์ **2FA** จะแสดงว่าผู้ใช้เปิดใช้งานการยืนยันตัวตนแบบสองปัจจัยหรือไม่ ผู้ดูแลระบบสามารถรีเซ็ต 2FA ของผู้ใช้อื่นได้ด้วย **รีเซ็ต 2FA** ในเมนูการดำเนินการของผู้ใช้นั้น (สำหรับกรณีที่ทำโทรศัพท์และรหัสสำรองหาย) แต่ไม่สามารถปิดใช้งาน 2FA ของตนเองได้หากไม่มีรหัสผ่าน ซึ่งการไหลของบริการตนเองจะจัดการแทน

การเข้าสู่ระบบที่ล้มเหลวจะถูกจำกัดอัตราต่อบัญชี (ทั้งตัวนับต่อ IP และตัวนับทั่วทั้งบัญชี) เพื่อชะลอความพยายามในการเดารหัสผ่าน และข้อจำกัดเดียวกันนี้จะครอบคลุมขั้นตอนโค้ด 2FA เพื่อให้รหัสผ่านที่ถูกต้องไม่สามารถรีเซ็ตตัวนับก่อนที่จะเดาโค้ดได้ ก่อนหน้านั้นคือตัวจำกัดคำขอต่อ IP ของไคลเอ็นต์ที่หยาบกว่าบนจุดสิ้นสุดการเข้าสู่ระบบ / 2FA / การตั้งค่า ซึ่งสามารถปรับแต่งได้ผ่าน `RATE_LIMIT_AUTH_PER_15MIN` (ค่าเริ่มต้น 100; หากอยู่หลังพร็อกซีผกผัน ให้ตั้งค่า `TRUST_PROXY` เพื่อให้ใช้ IP ไคลเอ็นต์จริง)
