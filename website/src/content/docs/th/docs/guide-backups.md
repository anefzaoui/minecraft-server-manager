เซิร์ฟเวอร์ส่วนใหญ่มีการสำรองข้อมูล แต่มีเพียงไม่กี่แห่งที่มีการสำรองข้อมูลที่ใช้งานได้จริง และความแตกต่างนี้จะถูกค้นพบในวันที่เลวร้ายที่สุดเท่านั้น สิ่งสามอย่างที่แยกความแตกต่างระหว่างการสำรองข้อมูลที่ใช้งานได้และใช้งานไม่ได้คือ: การคัดลอกที่สอดคล้องกัน, การเก็บไว้ในที่อื่น และมีคนเคยเรียกคืนข้อมูลนั้นอย่างน้อยหนึ่งครั้ง

## คัดลอกโลกขณะที่ไม่มีการเขียน

เซิร์ฟเวอร์ที่กำลังทำงานจะเขียนไฟล์ภูมิภาคอย่างต่อเนื่อง หากคุณคัดลอกไฟล์เหล่านั้นในขณะที่กำลังเขียน คุณจะได้ไฟล์ที่ครึ่งหนึ่งเก่าและครึ่งหนึ่งใหม่ ซึ่งอาจไม่สามารถโหลดได้ หรือโหลดมาแล้วมีช่องว่างในพื้นดินตรงที่ฐานของผู้เล่นเคยอยู่ สิ่งนี้จะไม่แจ้งเตือนคุณ เพราะการคัดลอกสำเร็จ

มีสองวิธีที่ถูกต้องในการคัดลอกข้อมูล:

1. **หยุดเซิร์ฟเวอร์**, คัดลอก, แล้วเริ่มใหม่ วิธีนี้ง่าย ตรงไปตรงมา และไม่เป็นที่นิยมเนื่องจากต้องหยุดให้บริการ
2. **สั่งให้เกมหยุดเขียนก่อน** รันคำสั่ง `save-off`, จากนั้น `save-all flush`, รอจนเสร็จ, คัดลอก, แล้วรัน `save-on` โลกจะสมบูรณ์และเงียบในช่วงเวลาของการคัดลอก

อย่าข้ามไปคัดลอกโดยตรง การสร้างสแนปชอตในระดับระบบไฟล์หรือระดับโวลุ่มจะใช้ได้ก็ต่อเมื่อเป็นแบบอะตอมมิกจริงๆ และการใช้ `cp -r` ในขณะที่ผู้เล่นกำลังวางบล็อกนั้นไม่ใช่วิธีที่ถูกต้อง

## สำรองข้อมูลมากกว่าแค่โลก

การกู้คืนโลกเพียงอย่างเดียวจะทำให้คุณได้ภูมิประเทศ แต่สูญเสียเซิร์ฟเวอร์ไป คุณยังต้องการ:

- `server.properties` และไฟล์อื่นๆ ที่ตั้งค่ากฎ
- ไฟล์ jar ของม็อดหรือปลั๊กอิน ในเวอร์ชันที่ถูกต้องที่กำลังทำงานอยู่ โลกจะไม่สามารถโหลดได้หากไม่มีม็อดที่สร้างบล็อกเหล่านั้น
- ข้อมูลผู้เล่น รวมถึง `whitelist.json`, `ops.json` และโฟลเดอร์สถิติและการพัฒนา
- เวอร์ชันของแพ็ก หากมาจากแพ็ก การจดบันทึกไว้ก็ถือว่าเพียงพอแล้ว

การตรวจสอบความถูกต้องของการสำรองข้อมูลที่เร็วที่สุด: คุณสามารถสร้างเซิร์ฟเวอร์นี้ใหม่บนเครื่องที่ว่างเปล่าจากไฟล์เก็บถาวรเพียงอย่างเดียวได้หรือไม่? หากคำตอบต้องขึ้นต้นด้วยประโยคที่ว่า "และจากนั้นฉันจะติดตั้งใหม่" นั่นไม่ใช่การสำรองข้อมูลที่สมบูรณ์

## การคัดลอกครั้งเดียวบนดิสก์เดียวกันไม่ใช่การสำรองข้อมูล

การสำรองข้อมูลที่เก็บไว้ในเครื่องที่มันปกป้องครอบคลุมความล้มเหลวเพียงอย่างเดียว: คุณลบอะไรบางอย่างไป มันไม่ครอบคลุมถึงดิสก์เสีย, ผู้ให้บริการระงับบัญชี, หรือข้อผิดพลาดที่ลบทั้งไดเรกทอรี

ทำให้ง่ายเข้าไว้ดีกว่าสมบูรณ์แบบ:

- การคัดลอกภายในเครื่องหนึ่งครั้ง สำหรับกรณีทั่วไป เช่น ผู้เล่นก่อกวน หรือการอัปเดตที่ผิดพลาด
- การคัดลอกอีกครั้งในที่อื่น เครื่องอื่น, ที่เก็บข้อมูลแบบอ็อบเจกต์, หรือ NAS ที่บ้านดึงข้อมูลทุกคืนผ่าน SSH
- ประวัติเพียงพอที่จะรอดพ้นจากปัญหาที่คุณสังเกตไม่ทันที การเสียหายมักจะถูกพบในภายหลังหลายวัน และหากคุณเก็บสำเนาสำรองไว้สามวัน คุณก็อาจจะเขียนทับสำเนาที่ดีไปแล้ว

การสำรองข้อมูลรายวันเจ็ดครั้ง บวกกับรายสัปดาห์สี่ครั้ง ครอบคลุมเหตุการณ์จริงเกือบทั้งหมดและใช้พื้นที่น้อยมาก

## ทดสอบการกู้คืนก่อนที่คุณจะต้องการ

เลือกสำเนาสำรอง, กู้คืนไปยังเซิร์ฟเวอร์สำรอง, แล้วเข้าร่วม นั่นคือการทดสอบทั้งหมด ใช้เวลาสิบห้านาที และสามารถจับข้อผิดพลาดคลาสสิกทั้งหมดได้: ไฟล์เก็บถาวรขาดโฟลเดอร์ม็อด, โลกที่ต้องการเวอร์ชันที่คุณไม่ได้ใช้งานอีกต่อไป, สิทธิ์ที่ทำให้ไฟล์ไม่สามารถอ่านได้, การอัปโหลดที่เสียหาย

ทำครั้งเดียวเมื่อคุณตั้งค่าการสำรองข้อมูล และอีกครั้งหลังจากมีการเปลี่ยนแปลงครั้งใหญ่กับเซิร์ฟเวอร์

## ขนาด และวิธีรักษามันให้เหมาะสม

โลกขยายใหญ่ขึ้นเพราะผู้เล่นสำรวจ โลกที่ผู้เล่นบินไปเป็นระยะทางหมื่นบล็อกในแนวเส้นตรง จะเก็บทุกชิ้นส่วนตามแนวเส้นนั้นไปตลอด และชิ้นส่วนส่วนใหญ่เหล่านั้นจะไม่มีวันถูกเยี่ยมชมอีก

สามคันโยก, เรียงตามลำดับของผลตอบแทนที่ได้:

1. **ตัดแต่งชิ้นส่วนที่ไม่ได้เยี่ยมชม** เครื่องมือที่ตัดตามเวลาที่เข้าถึงล่าสุดมักจะลบส่วนใหญ่ของโลกที่เดินทางบ่อยออกไปโดยไม่มีผลกระทบที่มองเห็นได้ในการเล่น
2. **บีบอัดอย่างเหมาะสม** ไฟล์ภูมิภาคบีบอัดได้ดี; ไฟล์เก็บถาวรของไฟล์เหล่านั้นไม่ได้รับประโยชน์จากอะไรที่แปลกใหม่
3. **อย่าเก็บสำเนาทุกชั่วโมงไว้เป็นเวลาหนึ่งปี** การเก็บรักษาดีกว่าการบีบอัด

## ใน Minecraft Server Manager

การสำรองข้อมูลใช้วิธี `save-off`, flush, copy, `save-on` และการหยุดหรือรีสตาร์ทที่ร้องขอระหว่างการสำรองข้อมูลจะถูกปฏิเสธจนกว่าการคัดลอกจะเสร็จสิ้น แทนที่จะแข่งกับมัน ไฟล์เก็บถาวรครอบคลุมไดเรกทอรีเซิร์ฟเวอร์ทั้งหมด ดังนั้นม็อด การกำหนดค่า และข้อมูลผู้เล่นจะเดินทางไปพร้อมกับโลก

การสำรองข้อมูลสามารถทำงานตามกำหนดเวลาควบคู่ไปกับการรีสตาร์ทและคำสั่ง และเซิร์ฟเวอร์ใหม่ทุกเครื่องจะเริ่มต้นด้วยกำหนดการสำรองข้อมูลรายวัน จำนวนครั้งที่เก็บรักษาจะนับแต่ละประเภทแยกกัน ดังนั้นสำเนาตามกำหนดการสิบชุดที่สะสมอยู่เองไม่สามารถผลักดันสำเนาที่คุณทำด้วยตนเองก่อนการเปลี่ยนแปลงที่มีความเสี่ยงออกไปได้ และข้อจำกัดด้านอายุและขนาดจะถูกนำมาใช้ ผู้ดูแลระบบสามารถเปลี่ยนแปลงทั้งหมดได้ในหน้าการตั้งค่า หรือต่อเซิร์ฟเวอร์ในแท็บการสำรองข้อมูล การกู้คืนจะใช้สำเนาสำรองใหม่ก่อน ดังนั้นการกู้คืนไปยังจุดเวลาที่ไม่ถูกต้องจึงสามารถย้อนกลับได้ โลกสามารถถูกย่อขนาดได้ด้วยตัวเองหรือเป็นส่วนหนึ่งของการสำรองข้อมูล ซึ่งเป็นคันโยกที่มีความสำคัญมากที่สุดสำหรับขนาด

แผงควบคุมทั้งหมด รวมถึงการสำรองข้อมูลทุกรายการ จะอยู่ภายใต้ไดเรกทอรีเดียว การคัดลอกไดเรกทอรีนั้นไปยังที่อื่นคือครึ่งหนึ่งของเรื่องราวที่อยู่นอกเครื่อง และมันเป็นสิ่งเดียวที่คุณต้องคัดลอกโดยเจตนา
