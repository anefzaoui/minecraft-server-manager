این پنل چندکاربره است. مدیریت حساب‌ها را در بخش **Settings → Users** انجام دهید.

![کاربران](/docs/images/settings-users.png)

## سه نقش موجود

| نقش          | پیش‌فرض برای هر سرور                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| **admin**    | همه چیز: مدیریت کاربران، کلیدهای API، فایل‌های سراسری، تنظیمات پیشرفته Docker و تمامی عملیات‌های سرور.           |
| **operator** | اجرا و پیکربندی سرورها (شروع/توقف، کنسول، پشتیبان‌گیری، دنیاها، مادها، اکثر تنظیمات)، اما نه بخش‌های مخصوص مدیر. |
| **viewer**   | فقط خواندنی. مشاهده سرورها و وضعیت آن‌ها، بدون امکان ایجاد تغییرات.                                              |

هر کاربر، از جمله کاربر با نقش viewer، می‌تواند [تأیید هویت دو مرحله‌ای](/docs/two-factor-authentication/) خود را مدیریت کند، زیرا محافظت از حساب کاربری شخصی، یک عملیات مدیریتی سرور محسوب نمی‌شود.

یک نقش، **پیش‌فرض** برای هر سرور است. برای اعطای دسترسی‌های متفاوت به یک شخص در یک سرور خاص، از مجوزهای مخصوص هر سرور که در ادامه آمده استفاده کنید.

## مجوزهای مخصوص هر سرور

صفحه **Permissions** (در نوار کناری، یا **Server Permissions** در بخش **Settings → Users**) یک جدول را نمایش می‌دهد: تمام اپراتورها و مشاهده‌گرها در ستون سمت راست و تمام سرورها در ردیف بالا. روی یک سلول کلیک کنید تا تعیین کنید آن کاربر در آن سرور خاص چه کارهایی می‌تواند انجام دهد. مدیران (Admins) در این لیست نیستند زیرا همیشه به همه چیز دسترسی دارند.

![مجوزها](/docs/images/settings-permissions.png)

هر سلول مجموعه‌ای از مجوزهاست:

| مجوز         | آنچه در آن سرور مجاز است                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| **View**     | مشاهده سرور، وضعیت آن، خروجی کنسول، بازیکنان، تاریخچه و آمار.                                             |
| **Power**    | شروع، توقف، راه‌اندازی مجدد، کشتن (kill) و بازسازی سرور.                                                  |
| **Console**  | اجرای دستورات کنسول و عملیات سریع دنیا، ارسال چت و مدیریت دستورات چت.                                     |
| **Players**  | اخراج (kick)، مسدود کردن (ban)، لیست سفید (whitelist)، اپراتور کردن (op) و ویرایش یادداشت‌های بازیکنان.   |
| **Content**  | نصب و حذف مادها، پلاگین‌ها، پک‌ها، دنیاها، دیتاپک‌ها و ویرایش اینونتوری‌ها.                               |
| **Backups**  | ایجاد، بازیابی، دانلود و حذف پشتیبان‌ها.                                                                  |
| **Files**    | مرور، ویرایش، آپلود و دانلود فایل‌های سرور، لاگ‌های آرشیو شده و بسته‌های لاگ؛ خروجی گرفتن از بلوپرینت‌ها. |
| **Settings** | تغییر تنظیمات سرور، ویژگی‌ها، یکپارچه‌سازی‌ها، آیکون و ارتقای نسخه‌ها.                                    |
| **Delete**   | حذف سرور.                                                                                                 |

![ویرایشگر مجوز](/docs/images/permissions-editor.png)

در زیر جدول، بخش **What Each Permission Covers** هر مجوز را باز می‌کند تا نشان دهد شخص چه کاری می‌تواند انجام دهد، چه چیزی شامل آن نمی‌شود و دقیقاً چه مسیرهایی (routes) در پنل باز می‌شوند. لیست آخر توسط مجموعه تست‌ها با کد در حال اجرا بررسی می‌شود.

![مرجع مجوزها](/docs/images/permissions-reference.png)

در گوشی، این جدول به صورت کارت‌های تکی برای هر کاربر و ردیف‌های مجزا برای هر سرور نمایش داده می‌شود.

<p align="center">
  <img src="/docs/images/mobile/permissions.png" alt="مجوزها در گوشی" width="180">
</p>

نحوه عملکرد اجزا در کنار هم:

- **نقش، پیش‌فرض است.** یک اپراتور با تمام مجوزها در هر سرور شروع می‌کند؛ یک مشاهده‌گر فقط با مجوز View شروع می‌کند. سلولی که با متن کم‌رنگ نمایش داده شده (و راهنمای آن "Role default" است) هرگز تغییر نکرده است.
- **یک سلول، نقش را فقط برای همان سرور بازنویسی می‌کند.** به یک مشاهده‌گر در یک سرور خاص مجوز Power و Console بدهید تا بتواند آن را اجرا کند، در حالی که سایر سرورها برای او همچنان فقط‌خواندنی باقی می‌مانند. مجوز Delete را از یک اپراتور در سرور اصلی خود بگیرید تا بقیه دسترسی‌هایش حفظ شود.
- **هر مجوز شامل View است.** شما نمی‌توانید روی سروری که نمی‌بینید، عملیاتی انجام دهید.
- **همه چیز را خاموش کنید تا یک سرور مخفی شود.** سرور از نوار کناری، داشبورد، پشتیبان‌ها، زمان‌بندی‌ها، فعالیت‌ها، به‌روزرسانی‌ها، مادپک‌ها، وضعیت زنده، وظایف در حال اجرا و بلوپرینت‌های آن کاربر ناپدید می‌شود و کتابخانه دنیاها دیگر نام آن را نمایش نمی‌دهد. لینک مستقیم، فراخوانی API یا سوکت کنسول پاسخ "not found" می‌دهند، درست مانند سروری که وجود ندارد.
- **عملیات‌های سراسری پنل همچنان از نقش پیروی می‌کنند.** ایجاد سرور (شامل کلون کردن)، فضای ذخیره‌سازی، کاربران، کلیدهای API، تنظیمات سراسری و زمان‌بندی‌های کل پنل، مخصوص یک سرور نیستند؛ بنابراین مشاهده‌گری که روی برخی سرورها مجوز دارد، همچنان نمی‌تواند هیچ‌کدام از این کارها را انجام دهد. اپراتورها امکان ایجاد سرور و زمان‌بندی‌های کل پنل را حفظ می‌کنند؛ فضای ذخیره‌سازی، کاربران، کلیدهای API و تنظیمات سراسری فقط در اختیار مدیران است.
- **زمان‌بندی‌ها از سرور پیروی می‌کنند.** یک راه‌اندازی مجدد، پشتیبان‌گیری یا دستور زمان‌بندی شده در یک سرور، به مجوز مربوطه در آن سرور (Power، Backups یا Console) نیاز دارد، فارغ از اینکه نقش کاربر چیست.
- **بلوپرینت‌ها نیز از سرور پیروی می‌کنند.** خروجی گرفتن از یک سرور به عنوان بلوپرینت به مجوز Files در آن سرور نیاز دارد، زیرا آرشیو شامل فایل‌های آن است. بلوپرینتی که از سروری که کسی نمی‌تواند ببیند صادر شده باشد، برای او نیز مخفی است.
- **بخش‌های مخصوص مدیر، در هر سروری فقط برای مدیر باقی می‌مانند:** چت‌بات، نگهداری پشتیبان‌ها و تنظیمات پیشرفته Docker.

هر تغییر در لاگ فعالیت با ذکر اینکه چه کسی چه چیزی را تغییر داده ثبت می‌شود؛ این ورودی‌ها فقط برای مدیران قابل مشاهده است. حذف یک کاربر، ردیف‌های مربوط به او را پاک می‌کند. حذف یک سرور، ردیف‌های آن را نگه می‌دارد، بنابراین سروری که از دید کسی مخفی شده، در تاریخچه و پشتیبان‌های حفظ‌شده‌اش همچنان مخفی می‌ماند.

نصب‌های موجود بدون تغییر به کار خود ادامه می‌دهند: تا زمانی که یک مدیر سلولی را ویرایش نکند، هر کاربر دقیقاً همان دسترسی‌هایی را دارد که نقش او قبلاً تعیین کرده بود.

## بخش‌های مخصوص مدیر و دلیل آن

چند مورد به عمد فقط برای مدیران محدود شده است:

- **مدیریت کاربران، فضای ذخیره‌سازی، تنظیمات سراسری، کلیدهای API و فایل‌های سراسری.**
- **[API عمومی](/docs/public-api/)**: فعال‌سازی `/api/v1` و ایجاد، محدودسازی یا ابطال توکن‌های Bearer فقط‌خواندنی آن.
- **تنظیمات پیشرفته Docker**: نام کانتینر سفارشی، انتشار پورت‌های اضافی و bind mountها. یک bind mount می‌تواند هر مسیر میزبان را به داخل کانتینر نگاشت کند و در ترکیب با دسترسی Docker پنل، این عملاً به معنای دسترسی ریشه (root) روی میزبان است. این فیلدها فقط برای مدیران ظاهر می‌شوند.

نام‌های کانتینر سفارشی نیز نمی‌توانند در فضای نام `msm-` خود پنل باشند، بنابراین یک کانتینر با نام دستی هرگز نمی‌تواند جایگزین کانتینر سرور دیگری شود و دستورات یا توقف را به اشتباه به نمونه دیگری هدایت کند.

## مدیریت حساب‌ها

![تصویر پروفایل](/docs/images/profile-picture.png)

مدیران می‌توانند از جدول کاربران، کاربر ایجاد کنند، نقش‌ها را تغییر دهند، رمز عبور را بازنشانی کنند و حساب‌ها را حذف کنند. ستون **2FA** نشان می‌دهد که آیا هر کاربر تأیید هویت دو مرحله‌ای را فعال کرده است یا خیر؛ یک مدیر می‌تواند 2FA کاربر دیگری را با گزینه **Reset 2FA** در منوی عملیات آن کاربر بازنشانی کند (برای مواردی که گوشی و کدهای پشتیبان گم شده‌اند)، اما هرگز نمی‌تواند 2FA خود را بدون رمز عبور غیرفعال کند، که این کار از طریق جریان سلف‌سرویس انجام می‌شود.

تلاش‌های ناموفق برای ورود به سیستم برای هر حساب محدود شده است (هم شمارنده برای هر IP و هم شمارنده سراسری حساب) تا سرعت حملات brute-force کاهش یابد، و همین محدودیت شامل مرحله کد 2FA نیز می‌شود تا یک رمز عبور صحیح نتواند شمارنده را قبل از حدس زدن کد بازنشانی کند. در مقابل آن، یک محدودکننده درخواست بر اساس IP کلاینت در نقاط پایانی ورود / 2FA / راه‌اندازی قرار دارد که از طریق `RATE_LIMIT_AUTH_PER_15MIN` قابل تنظیم است (پیش‌فرض 100؛ اگر پشت پروکسی معکوس هستید، `TRUST_PROXY` را تنظیم کنید تا بر اساس IP واقعی کلاینت عمل کند).
