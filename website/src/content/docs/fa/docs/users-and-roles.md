این پنل چندکاربره است. حساب‌های کاربری را در بخش **تنظیمات → کاربران** مدیریت کنید.

![کاربران](/docs/images/settings-users.png)

## سه نقش موجود

| نقش                    | قابلیت‌ها                                                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **مدیر (admin)**       | همه کارها: مدیریت کاربران، کلیدهای API، فایل‌های سراسری، تنظیمات پیشرفته Docker و تمامی عملیات مربوط به سرور.                |
| **اپراتور (operator)** | اجرا و پیکربندی سرورها (شروع/توقف، کنسول، پشتیبان‌گیری، دنیاها، مادها، اکثر تنظیمات)، اما دسترسی به بخش‌های مختص مدیر ندارد. |
| **بیننده (viewer)**    | فقط خواندنی. مشاهده سرورها و وضعیت آن‌ها، بدون امکان ایجاد تغییرات.                                                          |

هر کاربر، حتی بیننده، می‌تواند [احراز هویت دو مرحله‌ای](/docs/two-factor-authentication/) خود را مدیریت کند، زیرا محافظت از حساب کاربری شخصی، یک عملیات مدیریتی سرور محسوب نمی‌شود.

## بخش‌های مختص مدیر و دلیل آن

چند مورد به دلایل امنیتی فقط برای مدیران در دسترس است:

- **مدیریت کاربران، کلیدهای API و فایل‌های سراسری.**
- **[API عمومی](/docs/public-api/)** - فعال‌سازی `/api/v1` و ایجاد، تعیین محدوده یا ابطال توکن‌های Bearer با دسترسی فقط خواندنی.
- **تنظیمات پیشرفته Docker** - نام سفارشی کانتینر، انتشار پورت‌های اضافی و bind mountها. یک bind mount می‌تواند هر مسیری از میزبان (host) را به داخل کانتینر نگاشت کند که در ترکیب با دسترسی پنل به Docker، عملاً به معنای دسترسی ریشه (root) روی میزبان است. این فیلدها فقط برای مدیران نمایش داده می‌شوند.

همچنین نام‌های سفارشی کانتینر نمی‌توانند در فضای نام `msm-` خودِ پنل قرار بگیرند، بنابراین یک کانتینر با نام دستی هرگز نمی‌تواند جایگزین کانتینر سرور دیگری شود و باعث ارسال دستور توقف یا سایر دستورات به نمونه اشتباه گردد.

## مدیریت حساب‌ها

![تصویر پروفایل](/docs/images/profile-picture.png)

مدیران می‌توانند از جدول کاربران، حساب کاربری ایجاد کنند، نقش‌ها را تغییر دهند، رمز عبور را بازنشانی کنند و حساب‌ها را حذف نمایند. ستون **2FA** نشان می‌دهد که آیا هر کاربر احراز هویت دو مرحله‌ای را فعال کرده است یا خیر؛ یک مدیر می‌تواند 2FA کاربر دیگری را **بازنشانی** کند (برای مواقعی که گوشی و کدهای پشتیبان گم شده‌اند)، اما هرگز نمی‌تواند 2FA خود را بدون رمز عبور غیرفعال کند، که این مورد توسط فرآیند سلف‌سرویس مدیریت می‌شود.

تلاش‌های ناموفق برای ورود به سیستم برای هر حساب محدود شده است (هم بر اساس IP و هم یک شمارنده کلی برای حساب) تا سرعت حملات brute-force کاهش یابد. همین محدودیت برای مرحله کد 2FA نیز اعمال می‌شود تا نتوان با وارد کردن رمز عبور صحیح، شمارنده را قبل از حدس زدن کد بازنشانی کرد. در لایه بالاتر، یک محدودکننده درخواست کلی‌تر بر اساس IP کلاینت برای نقاط پایانی ورود / 2FA / راه‌اندازی وجود دارد که از طریق `RATE_LIMIT_AUTH_PER_15MIN` قابل تنظیم است (مقدار پیش‌فرض 100؛ اگر پشت یک پروکسی معکوس هستید، `TRUST_PROXY` را تنظیم کنید تا محدودیت بر اساس IP واقعی کلاینت اعمال شود).
