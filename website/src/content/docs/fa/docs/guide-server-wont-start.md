این لیست را به ترتیب کار کنید. ترتیب آن بر اساس فراوانی هر مورد به عنوان پاسخ است و چهار مورد اول بیشتر موارد را پوشش می‌دهند.

## ۱. بیست خط آخر را بخوانید، نه خط اول

به **انتهای** لاگ اسکرول کنید. یک ردپای پشته جاوا (Java stack trace) ابتدا از داخلی‌ترین قسمت چاپ می‌شود، بنابراین بالای دیوار متن کمترین بخش جالب است. چیزی که شما می‌خواهید آخرین خط `Caused by:` و هر چیزی است که بعد از آن می‌آید. این خط معمولاً مشکل را نام می‌برد.

دو شکل به شما می‌گویند کجا هستید:

- `Exception in thread "main"` یا مسیری به گزارش خرابی (crash report) در انتهای لاگ به این معنی است که خود بازی با شکست مواجه شده است.
- توقف ساده لاگ در وسط خط، بدون هیچ استثنایی، به این معنی است که چیزی فرآیند را از بیرون کشته است. به بخش ۳ بروید.

## ۲. UnsupportedClassVersionError به معنی جاوا اشتباه است

```
java.lang.UnsupportedClassVersionError: net/minecraft/server/Main has been compiled
by a more recent version of the Java Runtime (class file version 65.0)
```

فایل کلاس ۵۲ جاوا ۸ است، ۶۰ نسخه ۱۶، ۶۱ نسخه ۱۷، ۶۵ نسخه ۲۱ و ۶۹ نسخه ۲۵ است. این پیام به این معنی است که سرور به جاوا جدیدتری نسبت به آنچه در حال اجرا است نیاز دارد؛ برعکس آن، یک بسته قدیمی روی جاوا جدید، معمولاً با خطای mixin یا reflection خطا می‌گیرد.

| نسخه ماینکرافت     | جاوا |
| ------------------ | ---- |
| ۱.۱۶.۵ و قبل از آن | ۸    |
| ۱.۱۷               | ۱۶   |
| ۱.۱۸ و ۱.۱۹        | ۱۷   |
| ۱.۲۰ تا ۱.۲۰.۴     | ۱۷   |
| ۱.۲۰.۵ تا ۱.۲۱.x   | ۲۱   |
| ۲۶.۱ و بعد از آن   | ۲۵   |

بسته‌های قدیمی واقعاً به جاوا ۸ نیاز دارند. نسخه جدیدتر در اینجا بهتر نیست.

## ۳. کد خروج ۱۳۷ مربوط به هسته (kernel) است، نه یک ماد

لاگ در وسط جمله متوقف می‌شود، هیچ گزارش خرابی وجود ندارد و کانتینر کد ۱۳۷ را گزارش می‌دهد. این یک خطای خارج از حافظه (out-of-memory kill) است: فرآیند حافظه‌ای را درخواست کرده که ماشین نداشته است، بنابراین خاتمه یافته است.

تقریباً همیشه هیپ جاوا (Java heap) برابر با حافظه ماشین تنظیم شده است. هیپ به حافظه ماشین **منهای** سربار خود JVM نیاز دارد که در سرورهای ماد شده بین ۰.۵ تا ۱.۵ گیگابایت است. هیپ را کم کنید یا ماشین را ارتقا دهید. [مقدار رم مورد نیاز سرور](/docs/guide-server-memory/) اعداد را دارد.

## ۴. EULA و پورت

دو مورد کلاسیک با راه‌حل‌های تک‌خطی:

- `You need to agree to the EULA in order to run the server.` مقدار `eula=true` را در `eula.txt` یا با متغیر محیطی که تنظیمات شما استفاده می‌کند، تنظیم کنید.
- `Address already in use` یا `FAILED TO BIND TO PORT`. چیزی دیگر پورت ۲۵۵۶۵ را اشغال کرده است، اغلب یک نسخه قبلی از همین سرور که هرگز به طور کامل متوقف نشده است. آن را پیدا کرده و متوقف کنید به جای تغییر پورت، در غیر این صورت دو سرور خواهید داشت.

## ۵. یک ماد وابستگی خود را ندارد

```
Mod X requires mod Y, which is missing
Fabric API is not installed
```

بیشتر مادهای Fabric به Fabric API به عنوان یک فایل جداگانه نیاز دارند. مادهای Forge و NeoForge وابستگی‌های خود را در خود خطا لیست می‌کنند. نسخه نام‌برده را نصب کنید، نه جدیدترین نسخه را: "requires 0.91.x" به این معنی است که آن خط، و نسخه 0.92 همان بررسی را با شکست مواجه می‌کند.

گاهی اوقات وابستگی گمشده خود بارگذارنده (loader) است:

```
Mod X requires forge 47.4.14 or above
Mod ID: 'forge', Requested by: 'x', Expected range: '[47.4.14,)', Actual version: '47.4.10'
```

راه‌حل، ساخت جدیدتری از بارگذارنده است، نه یک ماد متفاوت. "47.4.14 or above" به معنی هر ساختی از آن به بعد است، و Forge هر عددی را منتشر نمی‌کند، بنابراین ساخت قابل نصب ممکن است ساخت بعدی باشد. در یک بسته‌ی ماد (modpack)، ابتدا بسته را به‌روزرسانی کنید: بسته‌ای که نسخه بارگذارنده‌ی آن برای مادهایش قدیمی است، یک اشکال برای نویسنده‌ی آن است که باید رفع کند.

## ۶. یک ماد برای بارگذارنده یا نسخه اشتباه است

یک فایل jar برای بارگذارنده‌ی متفاوت به طور مؤدبانه شکست نمی‌خورد. انتظار یک خطای mixin، یک `NoClassDefFoundError`، یا خرابی در کلاسی که هرگز نشنیده‌اید را داشته باشید. به صفحه فایل jar مراجعه کنید: بارگذارنده و نسخه ماینکرافت هر دو باید دقیقاً مطابقت داشته باشند. از نظر مادها، ۱.۲۰.۱ و ۱.۲۰.۴ بازی‌های متفاوتی هستند.

## ۷. دنیا از نسخه جدیدتری است

```
This world was created by a newer version of Minecraft
```

دنیاها به جلو ارتقا می‌یابند و هرگز به عقب برنمی‌گردند. پشتیبان‌گیری قبل از ارتقا را بازیابی کنید، یا نسخه‌ای را اجرا کنید که دنیا انتظار دارد. هیچ مسیر تنزل درجه‌ای که قطعات (chunks) را سالم نگه دارد وجود ندارد.

## وقتی بعد از هفته‌ها اجرا شدن خوب، خراب شد

سوال متفاوتی است، معمولاً پاسخ متفاوتی دارد:

- **تحت بار خراب شد**، با زمان‌بندی‌هایی که مکث‌های طولانی را نشان می‌دهد: جمع‌آوری زباله (garbage collection)، بنابراین قبل از مادها به اندازه هیپ نگاه کنید.
- **در نقطه مشابهی از دنیا خراب شد**: یک قطعه خراب یا یک موجودیت شکسته. گزارش خرابی معمولاً مختصات را نام می‌برد.
- **درست بعد از به‌روزرسانی خراب شد**: مادی که به‌روزرسانی شده مظنون است، حتی اگر ردپا به جای دیگری اشاره کند. آن را برگردانید و ببینید.
- **در راه‌اندازی مجدد خراب شد، در حالی که قبلاً خوب بود**: دیسک را بررسی کنید. یک دیسک پر، خطاهای دیدنی و گمراه‌کننده‌ای ایجاد می‌کند.

## دریافت کمکی که واقعاً کمک می‌کند

**کل لاگ** را پست کنید، نه خط آخر، و بگویید قبل از خراب شدن چه چیزی را تغییر دادید. آن را در جایی که برای آن طراحی شده است، مانند [mclo.gs](https://mclo.gs)، بچسبانید، نه در چت. نسخه ماینکرافت، بارگذارنده، بسته و نسخه آن، و مقدار هیپ سرور را شامل شود. گزارشی با این چهار واقعیت در یک پاسخ پاسخ داده می‌شود؛ بدون آن‌ها پنج پاسخ طول می‌کشد.

## در Minecraft Server Manager

خرابی‌ها از خروج خود کانتینر تشخیص داده می‌شوند، بنابراین سروری که در ساعت سه صبح از کار می‌افتد با بخش لاگ خود ثبت می‌شود به جای اینکه روز بعد پیدا شود. مظنونان معمول در این صفحه (EULA، جاوا اشتباه، دنیایی از نسخه جدیدتر، پورتی که از قبل استفاده شده، اتمام حافظه جاوا) در آن لاگ تشخیص داده شده و در ورودی تاریخچه با کاری که باید در مورد آن‌ها انجام شود، نام‌گذاری می‌شوند، و راه‌اندازی مجدد خودکار آن‌ها را نادیده می‌گیرد، زیرا راه‌اندازی مجدد آن‌ها را اصلاح نخواهد کرد. گزارش‌های خرابی هنگام دریافت تجزیه و تحلیل می‌شوند: استثنا برجسته می‌شود، پشته قابل جمع شدن است، و مادهایی که در ردپا ظاهر می‌شوند به عنوان مظنون لیست می‌شوند.

هر گزارشی را می‌توان از کارت مربوطه به mclo.gs به اشتراک گذاشت زمانی که به کمک نیاز دارید (پس از تأیید، زیرا چسباندن عمومی است)، و منوی **Download** کنسول تمام فایل‌های لاگ را به صورت یک فایل زیپ دارد، بنابراین "پست کردن کل لاگ" یک دانلود است تا یک پروژه باستان‌شناسی. یک خطای خارج از حافظه به عنوان یک خطای خارج از حافظه ثبت می‌شود، که یک ساعت معمول سرزنش یک ماد را ذخیره می‌کند. اگر چیز دیگری واقعاً به پورت نیاز دارد، کارت **Game Port** در **Settings → Configuration** سرور را به یک پورت آزاد منتقل می‌کند.

بارگذارنده‌ای که خیلی قدیمی است از طریق تب **Versions** سرور تغییر می‌کند، که بررسی می‌کند ساخت وجود دارد و قبل از بازسازی سرور یک پشتیبان تهیه می‌کند ([تغییر نسخه بارگذارنده ماد](/docs/updates/#changing-the-mod-loader-version)).
