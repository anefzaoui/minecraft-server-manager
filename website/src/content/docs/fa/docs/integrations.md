هر سرور، یکپارچه‌سازی‌های خود را در گروه **تنظیمات** دارد: **Discord**، یک **صفحه وضعیت** عمومی، **دعوت‌نامه‌های** تک‌کلیکی، و تب اختیاری **چت‌بات** (فقط مدیران). این صفحه به Discord می‌پردازد؛ [دعوت‌نامه‌ها و صفحه وضعیت](/docs/invites-and-status-page/) آن دو را پوشش می‌دهد، و [چت‌بات](/docs/chatbot/) صفحه مخصوص خود را دارد.

## اعلان‌های Discord

پنل رویدادهای سرور را از طریق یک وب‌هوک به یک کانال Discord ارسال می‌کند. بدون ربات، بدون OAuth.

### راه‌اندازی

۱. در Discord: **Server Settings → Integrations → Webhooks → New Webhook**. کانال را انتخاب کرده و URL وب‌هوک را کپی کنید.
۲. در پنل، تب **Settings → Discord** سرور را باز کنید، URL را در **Webhook URL** پیست کنید، کارت را **روشن** کنید، و **Save** را بزنید. URL به صورت رمزنگاری شده ذخیره می‌شود (در همان محل ذخیره‌سازی در حالت استراحت که کلیدهای API شما ذخیره می‌شوند).
۳. از **Send Test** برای تأیید کارکرد آن استفاده کنید.

![Discord integration](/docs/images/integrations-discord.png)

برای جایگزینی یک URL ذخیره شده، یک URL جدید پیست کرده و ذخیره کنید؛ فیلد را خالی بگذارید تا مورد فعلی حفظ شود. URL ذخیره شده به صورت ماسک شده نمایش داده می‌شود (توکن پنهان است).

### چه چیزی ارسال می‌شود

اعلان‌ها به دسته‌های قابل فعال/غیرفعال کردن گروه‌بندی شده‌اند. همه به طور پیش‌فرض روشن هستند.

| دسته                   | رویدادها                                                                |
| ---------------------- | ----------------------------------------------------------------------- |
| **شروع / توقف**        | سرور شروع شد، سرور متوقف شد                                             |
| **خرابی‌ها**           | خرابی، تشخیص حلقه خرابی، گزارش خرابی جدید                               |
| **پشتیبان‌گیری‌ها**    | پشتیبان‌گیری ایجاد شد، پشتیبان‌گیری بازیابی شد                          |
| **به‌روزرسانی‌ها**     | به‌روزرسانی اعمال شد، به‌روزرسانی بازگردانده شد، به‌روزرسانی ناموفق بود |
| **اخراج / مسدود کردن** | بازیکن اخراج شد، بازیکن مسدود شد                                        |
| **هشدارها**            | مواردی که به آرامی سرور را خراب می‌کنند (در زیر ببینید)                 |

### دسته هشدارها

`Alerts` کانال "چیزی نیاز به دخالت انسان دارد" است، برای شرایطی که قبلاً فقط در پنل قابل مشاهده بودند:

| رویداد                  | معنی                                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------------------- |
| `oom`                   | کانتینر به دلیل اتمام حافظه متوقف شد.                                                          |
| `unhealthy`             | پروسه بالا است اما پروب `mc-health` ناموفق است: یک سرور زنده اما مرده.                         |
| `startup-stalled`       | هنوز در حال شروع است پس از حدود ۱۰ دقیقه بدون "Done" در لاگ‌ها (با تشخیص مشکل، در صورت امکان). |
| `stop-failed`           | توقف عادی مؤثر نبود و کانتینر هنوز در حال اجرا است.                                            |
| `schedule-failed`       | یک ریستارت / پشتیبان‌گیری / دستور زمان‌بندی شده ناموفق بود.                                    |
| `quota-exceeded`        | سهمیه دیسک حالت سختگیرانه فعال شد و سرور متوقف شد.                                             |
| `offline-after-restart` | سرور قبل از ریستارت پنل فعال بود، اکنون نیست، و به طور خودکار راه‌اندازی مجدد نخواهد شد.       |
| `port-change-failed`    | تغییر پورت ناموفق بود و سرور نتوانست به پورت قبلی خود بازگردد، بنابراین از کار افتاده است.     |
| `auto-restart-gave-up`  | یک سرور خراب به دلیل اینکه اقدام دیگری آن را بیش از حد مشغول نگه داشت، راه‌اندازی مجدد نشد.    |

### نحوه تحویل

یک پل پس‌زمینه هر ۱۵ ثانیه [لاگ رویداد](/docs/activity/) را بررسی کرده و ردیف‌های نگاشت شده را ارسال می‌کند. اگر ارسال وب‌هوک به طور موقت ناموفق باشد، آن ردیف در بررسی‌های بعدی مجدداً تلاش می‌شود به جای حذف شدن؛ پس از چند تلاش ناموفق، ردیف نادیده گرفته می‌شود و شکست‌های تحویل حداکثر یک بار در ساعت برای هر سرور ثبت می‌شوند. پس از ریستارت پنل، پل رویدادهایی را که هنوز تحویل نداده است ارسال می‌کند، اما هرگز بیش از دو ساعت به عقب برنمی‌گردد؛ در اولین اجرای خود از جدیدترین رویداد شروع می‌کند.
