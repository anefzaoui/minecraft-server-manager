هر سرور یکپارچه‌سازی‌های خود را در گروه **تنظیمات** (Settings) مدیریت می‌کند: **Discord**، یک **صفحه وضعیت** (Status Page) عمومی، **دعوت‌نامه‌های** تک‌کلیکی و تب اختیاری **چت‌بات** (Chatbot). این صفحه به Discord می‌پردازد (سایر موارد دارای مستندات و راهنماهای راه‌اندازی اختصاصی در پنل هستند).

## اعلان‌های Discord

پنل رویدادهای سرور را از طریق یک وب‌هوک (webhook) به کانال Discord ارسال می‌کند. بدون نیاز به بات یا OAuth.

### راه‌اندازی

1. در Discord: به مسیر **Server Settings → Integrations → Webhooks → New Webhook** بروید. کانال مورد نظر را انتخاب کرده و URL وب‌هوک را کپی کنید.
2. در پنل، تب **Settings → Discord** سرور را باز کنید، URL را در قسمت **Webhook URL** جای‌گذاری کنید، کارت را **روشن** (on) کرده و **ذخیره** (Save) کنید. این URL به صورت رمزنگاری‌شده ذخیره می‌شود (در همان محل ذخیره‌سازی امن که کلیدهای API شما قرار دارند).
3. برای اطمینان از عملکرد صحیح، از گزینه **Send test** استفاده کنید.

![یکپارچه‌سازی Discord](/docs/images/integrations-discord.png)

برای جایگزینی یک URL ذخیره‌شده، URL جدید را وارد و ذخیره کنید؛ برای حفظ URL فعلی، فیلد را خالی بگذارید. URL ذخیره‌شده به صورت ماسک‌شده (توکن مخفی است) نمایش داده می‌شود.

### چه مواردی ارسال می‌شود

اعلان‌ها در دسته‌بندی‌های قابل تغییر (toggleable) گروه‌بندی شده‌اند. همه آن‌ها به صورت پیش‌فرض فعال هستند.

| دسته‌بندی          | رویدادها                                                               |
| ------------------ | ---------------------------------------------------------------------- |
| **شروع / توقف**    | سرور شروع شد، سرور متوقف شد                                            |
| **کرش‌ها**         | کرش، تشخیص حلقه کرش، گزارش کرش جدید                                    |
| **بک‌آپ‌ها**       | بک‌آپ ایجاد شد، بک‌آپ بازیابی شد                                       |
| **به‌روزرسانی‌ها** | به‌روزرسانی اعمال شد، به‌روزرسانی بازگردانی شد، به‌روزرسانی ناموفق بود |
| **اخراج / بن**     | بازیکن اخراج شد، بازیکن بن شد                                          |
| **هشدارها**        | مواردی که بی‌سروصدا باعث خرابی سرور می‌شوند (در زیر ببینید)            |

### دسته‌بندی هشدارها (Alerts)

`Alerts` کانالی برای مواردی است که «نیاز به مداخله انسانی دارند»؛ یعنی شرایطی که قبلاً فقط در پنل قابل مشاهده بودند:

| رویداد                  | معنا                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `oom`                   | کانتینر به دلیل کمبود حافظه (RAM) متوقف شد.                                                                          |
| `unhealthy`             | پردازش در حال اجراست اما بررسی `mc-health` با شکست مواجه شده: سروری که زنده است اما کار نمی‌کند.                     |
| `startup-stalled`       | پس از حدود ۱۰ دقیقه هنوز در حال شروع است و عبارت "Done" در لاگ‌ها دیده نمی‌شود (با تشخیص علت احتمالی در صورت امکان). |
| `stop-failed`           | توقف نرم (graceful stop) عمل نکرده و کانتینر همچنان در حال اجراست.                                                   |
| `schedule-failed`       | یک ری‌استارت / بک‌آپ / دستور زمان‌بندی‌شده با شکست مواجه شد.                                                         |
| `quota-exceeded`        | سهمیه دیسک در حالت سخت‌گیرانه (strict-mode) پر شده و سرور متوقف شد.                                                  |
| `offline-after-restart` | سرور قبل از ری‌استارت پنل فعال بود، اکنون نیست و به صورت خودکار شروع نخواهد شد.                                      |
| `crash-report`          | یک گزارش کرش جدید ثبت و تحلیل شد.                                                                                    |
| `update-failed`         | ارتقای محافظت‌شده (guarded upgrade) به وضعیت سالم نرسید.                                                             |

### نحوه ارسال

یک پل پس‌زمینه، [لاگ رویدادها](/docs/activity/) را هر ۱۵ ثانیه بررسی کرده و ردیف‌های نگاشت‌شده را ارسال می‌کند. اگر یک درخواست POST وب‌هوک به صورت موقت با شکست مواجه شود، آن ردیف در بررسی‌های بعدی دوباره تلاش می‌شود و حذف نمی‌گردد؛ وب‌هوکی که به طور دائم غیرقابل دسترس باشد، پس از چند تلاش، بی‌صدا (mute) می‌شود (یک خط لاگ در هر ساعت). این پل هرگز رویدادهای پیش از شروع به کار پنل را دوباره پخش نمی‌کند.
