**모드팩** 페이지(및 [생성 마법사](/docs/servers/)의 **모드팩으로 만들기** 탭)는 모드팩을 서버로 설치하며, 항상 **정확한 팩 버전에 고정**되어 있어 다시 시작해도 팩이 조용히 업그레이드되는 것을 방지합니다.

![Modpacks](/docs/images/modpacks.png)

## 지원되는 플랫폼

- **CurseForge**: 이름으로 검색합니다. CurseForge API 키가 필요합니다 (**설정 → API 키**에서 추가).
- **Modrinth**: 이름으로 검색합니다.
- **FTB**: Feed The Beast 팩, API를 통해서만 가능합니다 (숫자 팩 ID와 명시적인 버전 ID 필요). 패널은 아직 FTB 팩의 업데이트를 확인하지 않습니다.
- **GT New Horizons**: 1.7.10 전문가 팩, GTNH 자체 릴리스 인덱스에서 설치됩니다. GTNH는 팩 버전에 따라 Java 런타임을 선택합니다 (2.8.0+는 번들 lwjgl3ify 패치를 통해 **Java 25**에서 실행, 이전 릴리스는 Java 21 또는 17에서 실행). 마법사는 서버의 RAM과 디스크를 합리적인 최소값으로 조정합니다.
- **사용자 지정 zip**: 게시된 팩이 아닙니다. **CurseForge 모드팩 내보내기**(CurseForge 앱이 선택한 모드 세트에 대해 생성하는 `manifest.json`이 포함된 zip), **Modrinth `.mrpack`**, 또는 **모드 jar 파일의 모든 zip**을 업로드합니다. 패널은 매니페스트를 일괄 처리하거나(또는 각 jar 파일을 해시/지문/메타데이터로 식별), 설치 가능한 것을 미리 보고, 선택 사항으로 팩의 `overrides/` 설정을 포함하여 모든 것을 한 번에 설치합니다. 자동 다운로드를 허용하지 않는 모드는 설치 실패 대신 브라우저 링크와 수동 업로드 슬롯으로 표시됩니다.

## 고정 기능 작동 방식

팩을 선택하면 패널이 정확한 버전을 확인하고 기록한 다음 설치합니다. **업데이트** 페이지에서 새 버전이 사용 가능한 경우 알려줍니다(서버의 [업데이트 정책](#update-policy)이 **수동만**이 아닌 경우). 업그레이드는 사전 업데이트 백업 및 롤백을 포함한 의도적이고 안전한 작업입니다. 안정 버전 추적 서버에는 베타 버전이 제공되지 않습니다. 서버 자체의 **버전** 탭은 질문의 나머지 절반을 답합니다. 즉, 실제 모드가 따를 수 있는 향후 Minecraft 버전은 무엇인지 ([업데이트](/docs/updates/#minecraft-version-compatibility)).

모드 로더 버전도 팩과 함께 제공됩니다. 서버는 팩이 선언한 Forge, NeoForge 또는 Fabric 빌드를 설치합니다. Forge 또는 Fabric CurseForge 팩이 모드에 비해 너무 오래된 버전을 선언하는 경우, 팩이 수정될 때까지 **버전** 탭에서 이를 재정의할 수 있습니다. 팩 업데이트는 새 버전이 자체 버전을 선언하므로 재정의를 제거합니다 ([모드 로더 버전 변경](/docs/updates/#changing-the-mod-loader-version)).

매우 오래된 패널 버전(0.9.7 이전)에서 생성된 서버는 _고정되지 않은_ 상태로 남을 수 있습니다. 이는 컨테이너 이미지가 시작될 때마다 최신 팩 버전을 조용히 설치한다는 의미입니다. 패널은 이제 부팅 시 이를 복구합니다. 각 서버를 실제로 설치된 버전(패널 자체 기록 또는 이미지의 설치 매니페스트에서 읽음, 새로 확인된 "최신" 아님)에 고정하고 이벤트를 기록합니다. 설치된 버전을 알 수 없는 경우 서버의 설정 페이지에 경고와 함께 **버전 선택…** 버튼(CurseForge, Modrinth 및 GTNH 팩)이 표시되며, 이는 [버전 선택기](#changing-the-pack-version)를 엽니다. 고정되지 않은 모드팩 구성을 저장하려는 시도는 즉시 거부됩니다.

## 업데이트 정책

각 서버에는 **설정 → 구성** 탭에 **업데이트 정책** 카드가 있으며, 세 가지 옵션 모두 말 그대로 의미합니다.

- **수동만** (기본값): 아무것도 자동으로 변경되지 않으며 서버는 업데이트 배지 및 업데이트 페이지에서 완전히 제외됩니다. "날 내버려 둬" 모드: 수동으로 조정하거나 가져온 팩에 이상적이며 절대 건드리지 않으려는 경우. 버전 고정은 하지 않습니다: [**버전 변경…**](#changing-the-pack-version)은 모든 정책에서 작동합니다. 새 버전에 대한 알림을 받고 한 번의 클릭으로 적용하려면 **알림 받기**를 선택합니다.
- **알림 받기**: 매일 확인 시 사용 가능한 업데이트가 배지로 표시되고 업데이트 페이지에 나타납니다. 적용은 항상 사용자의 클릭으로 이루어집니다.
- **자동 업데이트**: 예약된 일일 확인 후, 보류 중인 **팩** 업데이트는 수동 업그레이드와 동일한 안전 경로를 통해 적용됩니다. 사전 업데이트 백업, 상태 모니터링, 새 버전이 부팅에 실패할 경우 자동 롤백. 서버를 다른 Minecraft 버전으로 이동하는 업데이트는 항상 이벤트로 건너뜁니다. 월드를 영구적으로 변환하는 것은 패널이 사용자를 대신하여 결정하지 않는 결정입니다. 수동 **지금 확인** 버튼은 확인만 하고 자동 업데이트를 트리거하지 않습니다.

## 팩 업그레이드

고정된 서버에서 한 번의 작업으로 최신 버전으로 업그레이드할 수 있습니다. 패널은 먼저 백업을 수행하고, 고정된 버전을 교체하고, 서버를 다시 빌드하고(새 버전이 다른 런타임을 필요로 하는 경우 Java 재확인), 첫 번째 부팅을 모니터링합니다. GTNH와 같이 몇 기가바이트를 다운로드하고 첫 번째 시작 시 수백 개의 모드로 월드를 빌드하는 대형 팩을 위한 충분한 시간이 주어집니다.

## 팩 버전 변경

특정 버전을 실행하려면(최신 또는 이전 버전), 서버의 **개요** 탭에 있는 팩 카드에서 **버전 변경…**을 사용합니다. **모드팩** 페이지에서 설치된 팩 카드를 열면 동일한 선택 사항이 제공됩니다. 드롭다운에서 버전을 선택하고 **이 버전으로 전환**을 클릭합니다. 둘 다 서버의 **콘텐츠** 권한이 필요하며, CurseForge, Modrinth 및 GTNH 팩에서 사용할 수 있습니다(FTB 팩에는 아직 버전 목록이 없습니다). 목록에는 CurseForge 및 Modrinth의 최신 25개 버전과 모든 GTNH 릴리스가 표시됩니다.

전환은 업그레이드와 동일한 안전 경로를 거칩니다. 사전 업데이트 백업, 새 고정, 다시 빌드 및 모니터링되는 첫 번째 부팅. 서버가 정상적으로 시작되지 않으면 한 번의 클릭으로 롤백됩니다. 사용자 지정 모드는 그대로 유지되며, 비활성화된 팩 모드와 팩의 다른 설치 설정(강제 포함된 모드, 무시할 파일, 추가 프로젝트)도 마찬가지입니다. 다른 팩을 설치하면 해당 설정이 새로 시작됩니다. 해당 설정은 제작된 팩에만 의미가 있기 때문입니다.

각 버전은 마지막으로 저장한 월드 버전과 비교하여 실행되는 Minecraft 버전과 함께 나열됩니다.

- **동일한 Minecraft 버전**: 일반 확인 후 전환합니다. 이전 팩 버전으로 돌아가면 해당 버전에 없는 모드의 블록과 아이템이 누락될 수 있으므로, 어느 쪽이든 백업은 백업 탭에 유지됩니다.
- **최신 Minecraft 버전**: 월드가 영구적으로 변환된다는 경고와 함께 확인 후 허용됩니다. 먼저 수행된 백업이 이전 월드로 돌아갈 수 있는 유일한 방법입니다.
- **이전 Minecraft 버전**: 사용할 수 없습니다. Minecraft는 마지막으로 저장한 버전보다 이전 버전의 월드를 로드할 수 없으므로, 패널은 부팅 시 충돌하는 서버를 남겨두는 대신 거부합니다.
