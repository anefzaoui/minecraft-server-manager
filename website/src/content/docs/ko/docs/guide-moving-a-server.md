월드를 옮기는 것은 쉽습니다. 하지만 플레이어가 계속 접속할 수 있고, 인벤토리, 홈, 권한이 그대로 유지되는 서버를 옮기는 것은 문제가 발생하는 부분입니다. 아래 순서를 따르면 다운타임을 몇 분으로 줄이고, 새 머신이 실망스러울 경우 되돌아갈 방법을 유지할 수 있습니다.

## 먼저 현황 파악하기

무언가를 건드리기 전에 다음 사항들을 기록해 두세요. 이 중 하나라도 제대로 확인하지 않고 추측했다가 마이그레이션이 잘못된 경우가 많았습니다.

- **정확한 Minecraft 버전 및 로더.** 1.20.1 NeoForge는 1.20.1 Forge와 다릅니다.
- **버전이 포함된 모드 또는 플러그인 목록.** 해당 모드가 없으면 월드를 로드할 수 없습니다.
- **Java 버전.** Minecraft 버전에 따라 달라집니다.
- **`server.properties`의 `level-name`.** 월드 폴더 이름이 항상 `world`인 것은 아닙니다.
- **온라인 모드.** 이전 서버가 `online-mode=false`로 실행되었고 새 서버가 `true`로 실행되거나 그 반대의 경우, 모든 플레이어는 다른 UUID를 받게 되어 완전히 새로운 빈 인벤토리를 갖게 됩니다. 이 페이지에서 가장 고통스러운 실수입니다.
- **서버 폴더 외부에서 실행되는 것.** 예를 들어 플러그인의 MySQL 데이터베이스 등.

## 실행 중에 복사하고, 중지한 후 다시 복사하기

짧은 다운타임의 비결은 느린 복사를 먼저 하는 것입니다.

1. **서버가 실행 중일 때**, 전체 서버 디렉토리를 새 머신으로 복사합니다. 월드가 크면 한 시간이 걸릴 수도 있습니다. 아무도 눈치채지 못합니다. 왜냐하면 아무것도 중지되지 않았기 때문입니다.
2. **재시작을 공지하고 서버를 제대로 중지합니다.** 정상적으로 종료하면 게임이 월드를 플러시합니다. 프로세스를 강제 종료하면 그렇지 않습니다.
3. **다시 복사합니다.** 이번에는 변경된 파일만 이동하므로 몇 초에서 몇 분이 걸립니다.
4. **새 머신에서 서버를 시작합니다.** 가능하다면 비공개 포트로 시작하고 직접 접속하여 확인합니다. 익숙한 건축물, 자신의 인벤토리, 그리고 모드나 플러그인이 오류 없이 로드되었는지 확인합니다.
5. **그런 다음** 플레이어들에게 새 서버 주소를 안내합니다.

`rsync -a --delete`가 1단계와 3단계에 일반적으로 사용되는 도구입니다. 권한과 타임스탬프를 유지하세요. 잘못된 사용자로 복사된 월드는 시작되지 않는 서버를 만들고, 오류 메시지도 명확하지 않을 수 있습니다.

## 아직 이전 서버를 삭제하지 마세요

이전 머신은 최소 며칠 동안 중지된 상태로 그대로 두세요. 이것이 유일한 실제 롤백 방법입니다. 실수로 버려진 복사본에 접속하여 일주일 동안 작업하는 것을 방지하기 위해 실행 중인 상태보다는 전원을 꺼두세요.

## 주소가 이동 후에도 유지되도록 하기

플레이어가 IP 주소로 직접 접속하는 경우, 모든 이동마다 플레이어들이 서버 목록을 편집해야 하며, 일부는 절대 그렇게 하지 않습니다.

직접 제어하는 호스트 이름을 서버에 연결하여 사용하세요. 이렇게 하면 이동은 DNS 변경만으로 이루어지며, 모든 플레이어의 클라이언트 주소는 동일하게 유지됩니다. 변경 사항이 빠르게 전파되도록 이동 하루 전에 레코드의 TTL(Time-To-Live)을 낮추세요.

서버가 비표준 포트에서 실행되는 동안 플레이어가 기본 도메인을 입력하도록 하려면 SRV 레코드를 사용하세요. 상용 호스트가 `play.something.net`을 제공하는 데 사용하는 것과 동일한 메커니즘입니다.

## 새 머신을 신뢰하기 전에 확인하기

호스트마다 다르며 이동 후에 문제가 되는 세 가지 사항:

- **방화벽.** 게임 포트가 열려 있어야 하며, 게임 포트만 열려 있어야 합니다. 로컬호스트에서 작동했다고 해서 관리 패널이나 맵을 인터넷에 노출하지 마세요.
- **단일 코어 속도.** Minecraft는 코어 수보다 단일 코어의 속도에 훨씬 더 신경 씁니다. 8개의 느린 코어는 2개의 빠른 코어보다 성능이 떨어집니다.
- **디스크.** 스핀 디스크 또는 과도하게 공유된 볼륨의 월드는 청크 로딩 중에 끊길 수 있습니다.

## 관리형 패널에서 이전하기

제어판을 제공하는 호스트에서 이전하는 경우, 다운로드 또는 파일 관리자를 찾아 월드뿐만 아니라 전체 서버 디렉토리를 가져오세요. 모드 및 플러그인 JAR 파일 자체를 가져오세요. 목록만으로는 안 됩니다. 버전이 중요하며, "최신"은 다음 달에 다른 파일이 됩니다.

백업도 제대로 소유하고 있는지 확인하세요. 떠나는 패널 내부에만 존재하는 백업은 소유한 백업이 아닙니다.

## Minecraft Server Manager에서

전체 패널이 하나의 디렉토리입니다. 이를 다른 머신으로 복사하고 거기서 패널을 시작하면 모든 서버, 월드, 백업 및 설정이 함께 이전되므로 패널 자체를 옮기는 것은 마이그레이션이 아닌 복사 작업이 됩니다.

모든 서버가 아닌 하나의 서버를 위해, 청사진은 서버 구성, 모드 세트 및 고정된 팩 버전을 단일 `.mcserver.zip` 파일로 캡처합니다. 이 파일은 다른 패널에서 가져와 동일한 서버를 다시 구축하는 데 사용할 수 있습니다. 월드만 이동해야 하는 경우 월드를 별도로 다운로드하고 설치할 수 있습니다.

서버가 사용했던 게임 포트가 새 머신에서 이미 사용 중이거나 먼저 비공개 포트에서 테스트하고 싶다면, **설정 → 구성**에서 변경하세요. **게임 포트** 카드에는 **다음 사용 가능한 포트 사용** 옵션이 있습니다. 실행 중인 서버는 새 포트에서 다시 시작하기 전에 확인을 요청하며, 거기서 시작할 수 없으면 이전 포트로 돌아갑니다. 플레이어들에게 새 서버를 안내할 때 공개 포트로 전환하세요.
