**백업** 페이지는 모든 서버의 스냅샷을 크기, 이유, 생성 시점과 함께 보여줍니다.

![백업](/docs/images/backups.png)

## 백업 생성하기

서버의 **백업** 탭(또는 [예약된 작업](/docs/schedules/)을 통해)에서 클릭 한 번으로 전체 서버 디렉터리를 스냅샷할 수 있습니다. 패널은 월드를 먼저 안정화시킨 후(`save-off` → `save-all`), 데이터를 압축하고 다시 저장(`save-on`)을 활성화하므로 실행 중인 서버에서도 일관된 백업이 가능합니다. 압축은 백그라운드 워커 스레드에서 실행되어 패널 작동을 방해하지 않습니다. 각 백업에는 메모를 추가할 수 있습니다.

모든 아카이브는 작성되는 즉시 **무결성 검사**를 거칩니다. 패널은 zip 파일을 다시 열어 디렉터리를 읽습니다. 손상되었거나 열 수 없는 아카이브는 삭제되며, 복원 시점에 문제가 발견되는 대신 백업 호출이 즉시 실패합니다. 서버가 시작된 적이 없는 경우의 빈 아카이브는 허용되지만 이벤트에 플래그가 지정됩니다.

**"월드 축소도 함께 진행"**을 선택하면(백업 탭 또는 백업 예약에서) 아카이브가 안전하게 작성된 후 방문 빈도가 낮은 청크를 제거합니다(**[월드 축소](/docs/world-shrink/)** 참조). 축소는 서버가 중지된 동안에만 실행되며, 실행 중인 서버에서는 백업이 수행되고 축소는 건너뜁니다.

![서버 백업](/docs/images/server-backups.png)

## 백업 이유

백업은 생성된 이유에 따라 태그가 지정됩니다.

- **수동**: 버튼을 클릭했습니다.
- **예약됨**: [예약된 작업](/docs/schedules/)에 의해 생성되었습니다. 모든 새 서버에는 자동으로 일일 예약 백업이 제공됩니다(02:00~05:59 사이에 분산됨). 따라서 서버는 첫날부터 자동 백업을 받을 수 있으며, 업데이트 직전에만 백업되는 것이 아닙니다.
- **업데이트 전**: 팩 업그레이드 전에 자동으로 생성되어 업그레이드를 항상 되돌릴 수 있습니다.
- **복원 전**: 복원 또는 월드 초기화 직전에 자동으로 생성되어 복원이 예상과 다를 경우 안전망 역할을 합니다.

## 보존 정책

보존은 **서버별, 이유별**로 제한됩니다. 각 그룹에서 가장 최신 백업이 유지되며, 성공적인 백업 후 오래된 백업은 자동으로 정리됩니다.

| 이유        | 유지 개수 |
| ----------- | --------- |
| 예약됨      | 10        |
| 업데이트 전 | 10        |
| 수동        | 20        |
| 복원 전     | 5         |

`복원 전`은 별도의 작은 공간을 가지므로 자동 안전 백업이 수동으로 보관한 백업을 삭제하는 것을 방지합니다.

각 이유별 개수 외에 두 가지 선택적 상한선이 적용되며, 둘 다 기본적으로 비활성화되어 있습니다. **최대 보존 기간**(이유에 관계없이 N일보다 오래된 백업은 정리됨) 및 **서버당 최대 총 크기**(총 크기에 맞을 때까지 가장 오래된 백업이 정리됨, `복원 전` 백업이 먼저 정리됨). 서버의 가장 최신 백업은 이 상한선에 의해 정리되지 않습니다. 이 모든 설정은 설정 페이지에서 전역적으로 변경할 수 있으며, 서버 백업 탭에서 서버별로 재정의할 수 있습니다.

백업은 백업 목록에서 **이름을 변경**할 수 있습니다(각 행의 이름 변경 버튼). 디스크의 아카이브와 패널의 기록이 함께 이동하므로 다운로드, 복원 및 보존은 새 이름으로 계속 작동합니다.

![백업 이름 변경](/docs/images/backup-rename.png)

> 보존 정책은 자동으로 제한되지만, 대규모 모드 팩 아카이브는 여전히 서버의 [디스크 할당량](/docs/storage/)에 포함되므로 대규모 팩의 총량을 주시해야 합니다.

## 복원하기

백업을 복원하면 서버가 중지되고(파일을 건드리기 전에 컨테이너가 실제로 중지되었는지 확인), `복원 전` 안전 백업을 수행하고, **전체 서버 디렉터리**를 스냅샷으로 교체한 후, 다시 시작할 수 있도록 중지된 상태로 둡니다. 팩 업그레이드는 항상 `업데이트 전` 백업을 먼저 수행하므로, 잘못된 업그레이드는 항상 되돌릴 수 있습니다.

## 패널 자체 데이터베이스

서버 백업은 서버별 월드 디렉터리만 포함합니다. 패널 자체 데이터베이스(`panel.db`, 사용자, 역할, 2FA 비밀번호, 예약, 팩 고정 및 기록 포함)는 일일 유지 관리 타이머에 별도로 스냅샷됩니다.

- `VACUUM INTO`는 `data/backups/_panel/`에 일관되고 조각 모음된 복사본을 작성합니다. 가장 최신 **14개**가 유지됩니다.
- 부팅 시 패널은 `PRAGMA integrity_check`를 실행하고 실패하면 크게 기록하여 `data/backups/_panel`에서 최신 유효 복사본을 가리킵니다.

전체 `data/` 트리를 백업하면(여기에는 암호화 키인 `.secret-key`도 포함됨) 모든 것을 백업한 것입니다.
