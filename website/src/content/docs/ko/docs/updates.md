**업데이트** 페이지는 한 곳에서 모든 서버의 최신 상태가 아닌 항목들을 추적합니다:

- **모드팩** 버전 ([모드팩](/docs/modpacks/)) 대 Modrinth / CurseForge / GTNH 릴리스 인덱스.
- 직접 추가한 **사용자 지정 콘텐츠** - 모드, 데이터팩, 리소스팩, 플러그인 - 각 소스 대: Modrinth, CurseForge, Hangar, SpigotMC (Spiget) 또는 GitHub 릴리스. GitHub 조회는 ETag 재검증을 사용하므로, 일일 검사는 속도 제한에 거의 영향을 주지 않습니다.
- **Docker 이미지** 최신성: 실행 중인 각 컨테이너의 이미지 ID 대 새로 가져온 태그 (동일한 태그의 서버 간 중복 제거), 재생성 전용 업그레이드로 제공됩니다.
- **독립 실행형 버전 고정**: 관리되는 팩이 없는 서버의 경우, 명시적인 `mc_version` 고정 대 Mojang의 매니페스트, 그리고 명시적인 로더 빌드 환경 변수 (`PAPER_BUILD`, `FORGE_VERSION` 등) 대 로더 레지스트리. Paper 빌드는 PaperMC의 현재 **Fill v3 API**에서 제공됩니다 (레거시 v2 엔드포인트는 새 Minecraft 버전을 더 이상 받지 않습니다).

## 작동 방식

패널은 각 서버의 고정된 버전을 업스트림 소스와 비교하여 더 새로운 릴리스가 있는 항목을 나열합니다. 일치하는 개수는 [대시보드](/docs/dashboard/)의 "업데이트 가능" 타일에도 표시됩니다.

검사는 요청 시 실행되며 예약될 수 있습니다 ([예약](/docs/schedules/)). 업데이트 **정책**은 서버별로 적용됩니다: 패널이 알림만 보내도록 할지, 아니면 모든 것을 수동으로 유지할지 결정합니다.

## 업데이트 적용

업데이트는 절대 자동으로 이루어지지 않습니다. 팩 업그레이드를 선택하면 패널은 다음을 수행합니다:

1. **업데이트 전 백업**을 생성합니다 (되돌릴 수 있도록; 서버당 마지막 10개의 업데이트 전 백업이 보관됩니다).
2. 정확한 새 버전을 다시 고정합니다.
3. 컨테이너를 재생성하고, 필요한 경우 Java 런타임을 다시 확인합니다.
4. 플랫폼별 시간 제한 내에서 첫 번째 부팅을 모니터링합니다.

정상적으로 시작되지 않으면, 업데이트 전 백업으로 롤백됩니다. 안정 버전 추적 서버에는 베타 버전이 절대 제공되지 않으며, 변경 로그 링크는 소스에서 제공하는 실제 버전별 차이점으로 연결됩니다. 업데이트 실패 시 Discord [알림](/docs/integrations/) 통합이 구성된 경우 알림이 발송됩니다.
