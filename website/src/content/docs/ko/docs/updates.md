**업데이트** 페이지는 한 곳에서 모든 서버의 최신 상태가 아닌 것들을 추적합니다:

- **모드팩** 버전 ([모드팩](/docs/modpacks/)) 대 Modrinth / CurseForge / GTNH 릴리스 인덱스.
- 직접 추가한 **사용자 지정 콘텐츠** (모드, 데이터팩, 리소스팩, 플러그인) 각각의 소스 대조: Modrinth, CurseForge, Hangar, SpigotMC (Spiget) 또는 GitHub Releases. GitHub 조회는 ETag 재검증을 사용하므로 일일 검사로는 속도 제한에 거의 영향을 주지 않습니다.
- **Docker 이미지** 최신성: 각 서버 컨테이너의 이미지 ID 대 새로 가져온 태그 (동일한 태그의 서버 간 중복 제거), 재빌드 전용 업그레이드로 제공됩니다.
- **독립 실행형 버전 고정**: 관리되는 팩이 없는 서버의 경우, 명시적인 `mc_version` 고정을 Mojang의 매니페스트에 대해, 그리고 명시적인 로더 빌드 환경 변수 (`PAPER_BUILD`, `FORGE_VERSION` 등)를 로더의 레지스트리에 대해 고정합니다. Paper 빌드는 PaperMC의 현재 **Fill v3 API**에서 가져옵니다 (레거시 v2 엔드포인트는 더 이상 새 Minecraft 버전을 받지 않습니다). 모드가 있는 서버에서는 새 Minecraft 버전이 제공되기 전에 [버전 확인](#minecraft-version-compatibility)을 통해 설치된 모든 모드에 대한 빌드가 있는지 확인합니다. 고정된 Forge 서버에는 Forge의 권장 빌드가 제공되며, 고정된 빌드보다 오래된 빌드는 제공되지 않으며, 릴리스에 고정된 서버에는 프리릴리스가 제공되지 않습니다 (베타 버전에 이미 있는 경우 더 새 베타 또는 릴리스가 제공될 수 있습니다). 로더 빌드를 적용하려면 먼저 업데이트 전 백업을 수행합니다. Forge 또는 NeoForge 서버를 새 Minecraft 버전으로 이동하면 고정된 로더 빌드 번호가 지워집니다. 빌드는 하나의 Minecraft 버전에 대해 만들어지기 때문입니다. `latest`와 같은 키워드는 버전 자체를 따르므로 유지됩니다. 특정 빌드를 직접 선택하려면 [모드 로더 버전 변경](#changing-the-mod-loader-version)을 참조하세요.

## 작동 방식

패널은 각 서버의 고정된 버전을 업스트림 소스와 비교하여 새 릴리스가 있는 항목을 나열합니다. 일치하는 개수도 [대시보드](/docs/dashboard/)의 "업데이트 가능" 타일에 표시됩니다.

검사는 기본 [일정](/docs/schedules/)에 따라 매일 실행되며, **지금 모두 확인**으로 수동 실행할 수 있습니다. 행의 **무시**는 해당 특정 버전을 더 이상 제공하지 않도록 합니다. 새 버전이 나오면 다시 제공됩니다. 업데이트 **정책**은 서버별로 적용됩니다: 패널은 모든 것을 수동으로 유지하고 (기본값, 이 경우 서버가 이 페이지에 표시되지 않음), 알림만 보내거나, 팩 업데이트를 직접 적용합니다 ([업데이트 정책](/docs/modpacks/#update-policy)).

## Minecraft 버전 호환성

모드가 함께 이동할 수 없다면 새 Minecraft 버전은 업그레이드가 아닙니다. 각 서버에는 자체 **버전** 탭 (모드 아래)이 있으며, 이 질문에 답합니다:

- 서버가 현재 실행 중인 버전과 **설치된 모든 모드에 대한 빌드가 있는 가장 높은 버전**.
- 향후 Minecraft 버전별로 접을 수 있는 행이 있으며, 준비된 모드 수와 아직 게시되지 않은 모드 수를 표시합니다. 행을 열면 어떤 모드가 남겨질 것이고 어떤 모드가 괜찮은지 볼 수 있습니다.

![버전 호환성](/docs/images/server-versions.png)

**향후 버전 확인**을 눌러 실행합니다. 아무것도 자동으로 스캔되지 않습니다: 검사는 서버의 모드 폴더에 있는 각 jar 파일을 읽고 각 파일에 대해 Modrinth와 CurseForge에 문의하므로, 요청할 때만 발생합니다. 진행 상황과 부분 결과가 기록되므로 페이지를 닫거나 새로고침해도 아무것도 손실되지 않으며, 패널 재시작으로 중단된 검사는 그렇게 표시하고 다시 실행할 수 있도록 제안합니다. 중단된 검사가 이미 처리한 모든 내용은 유지되므로 다시 실행해도 해당 작업이 다시 수행되지 않습니다.

보고서는 해당 서버에 대해서만 설명합니다. Minecraft 버전, 로더 또는 모드 자체 (추가, 제거, 업데이트)를 변경하면 보고서가 최신이 아닌 것으로 표시되고 다시 실행할 때까지 사용되지 않습니다.

모드는 모드팩 자체의 파일 목록에서 식별되거나, 그렇지 않으면 파일 내용으로, 런처가 jar 파일을 인식하는 방식과 동일하게 식별됩니다. 두 가지 유형의 모드는 답변할 수 없으며 추측하지 않습니다:

- **식별할 수 없음**: 수동으로 빌드되었거나 레지스트리에서 인식하지 못하는 비공개 빌드입니다.
- **확인할 수 없음**: GitHub Releases, Hangar 또는 SpigotMC의 모드이거나 프로젝트가 삭제된 모드입니다. 이들은 각 빌드가 어떤 Minecraft 버전에 대한 것인지에 대한 목록을 게시하지 않습니다.

둘 중 하나라도 설치되어 있으면 패널은 한 번의 클릭으로 Minecraft 버전 업데이트를 전혀 제공하지 않습니다. 무엇이 깨질지 정직하게 말할 수 없기 때문입니다. 모드가 지원하는 것보다 높은 버전을 적용하는 것은 거부되며, 이를 차단하는 모드의 이름을 명시합니다.

**비활성화**된 모드는 영향을 주지 않습니다: 서버는 이를 로드하지 않으므로 모드를 끄는 것은 차단기를 통과하는 실제 방법입니다. 모드를 켜거나 끄면 보고서가 다시 확인되도록 표시됩니다.

이는 모드를 실행하는 서버에 적용됩니다: Fabric, Forge, NeoForge 및 Quilt. Paper 스타일 플러그인 서버는 일반적인 최신 릴리스 동작을 유지하며 버전 탭이 없습니다. 플러그인이 오는 두 레지스트리가 확인할 수 있는 것을 게시하지 않기 때문입니다.

![열린 버전, 어떤 모드가 남겨질지 보여줌](/docs/images/server-versions-expanded.png)

버전을 열면 빌드가 없는 모드가 먼저 나열되고 (결정을 내리는 모드), 준비된 모드는 클릭 뒤에 숨겨집니다. 큰 팩은 한 번에 한 페이지의 모드를 로드하므로 300개 모드 서버도 5개 모드 서버만큼 빠르게 열립니다.

## 모드 로더 버전 변경

**버전** 탭에는 **로더 버전** 카드도 있습니다. 서버에 설치된 Forge, NeoForge, Fabric 또는 Quilt 빌드를 표시하고, 변경 가능한 경우 다른 빌드로 전환할 수 있는 선택기를 제공합니다.

- **Forge, NeoForge, Fabric 또는 Quilt 서버**는 게시된 모든 빌드를 실행할 수 있습니다. 선택기에는 서버의 Minecraft 버전에 대한 최근 빌드가 나열되며, Forge의 권장 및 최신 빌드가 표시됩니다. **다른 빌드…**은 번호로 이전 빌드를 입력할 수 있으며, **기본값**은 서버가 선택하도록 되돌립니다.
- **Forge 또는 Fabric CurseForge 모드팩**은 자체 매니페스트가 선언하는 로더 버전을 설치하므로, 일반적으로 변경하는 방법은 팩을 업데이트하는 것입니다. 팩 자체에 잘못된 버전이 나열된 경우 (내부 모드가 팩이 설치하는 것보다 최신 Forge를 요청하는 경우), 카드를 사용하여 이를 재정의할 수 있으며, **모드팩의 버전**은 다시 제거합니다. 팩을 업데이트해도 제거됩니다. 새 버전이 자체 로더를 선언하기 때문입니다. 새 버전에도 잘못된 버전이 나열되면 재정의를 다시 설정하세요.
- **NeoForge CurseForge 모드팩 또는 Modrinth 모드팩**은 로더를 표시하지만 재정의할 수 없습니다: 서버 이미지는 Forge 및 Fabric 팩에만 재정의를 적용합니다. 로더는 팩 버전을 따르므로 대신 팩을 업데이트하세요. FTB 팩의 로더는 여기서도 변경할 수 없습니다. 해당 카드는 일반적으로 나타나지 않습니다. FTB 자체 설치 프로그램이 패널이 읽지 못하는 기록을 유지하기 때문입니다.

패널은 요청하기 전에 빌드가 존재하는지 확인합니다. Forge 또는 NeoForge 빌드는 하나의 Minecraft 버전에 대해 만들어지므로, 최신 릴리스를 따르는 서버에서는 이를 고정하면 서버가 현재 실행 중인 Minecraft 버전에도 유지됩니다 (확인 메시지에 표시됨). 이후 **기본값**을 선택하면 고정은 제거되지만 해당 Minecraft 버전은 유지됩니다. 최신 릴리스를 따르던 서버는 재빌드 시 다른 Java 이미지로 이동할 수도 있습니다. 해당 버전이 필요하기 때문입니다. 아직 시작되지 않은 서버는 먼저 시작하도록 요청받습니다. 그래야 패널이 해당 버전을 알 수 있습니다. Forge는 빌드 번호를 건너뜁니다 (47.4.13과 47.4.15 사이에 47.4.14가 없음). 따라서 "47.4.14 이상 필요"라는 모드는 다음 빌드로 만족되며, 거부 시 해당 빌드의 이름을 명시합니다. 변경은 업데이트 전 백업을 수행한 다음 서버를 재빌드합니다. 새 빌드는 다음번 서버 시작 시 설치되며, 그때까지 카드가 그렇게 표시됩니다.

## 모드 업데이트 취소

모드가 업데이트되기 전의 모든 빌드는 공유 라이브러리에 남아 있으므로, 업데이트로 인해 문제가 발생한 경우 되돌릴 수 있습니다. **모드** 탭의 모드 행에는 **되돌리기** 버튼이 있어 이전 빌드를 복원합니다. 다운로드가 없으므로 프로젝트가 해당 레지스트리에서 삭제된 경우에도 작동합니다. 되돌린 빌드는 더 새 빌드가 나타날 때까지 제공되지 않습니다.

![모드를 업데이트 전 빌드로 되돌리기](/docs/images/mods-revert.png)

## 업데이트 적용

업데이트는 절대 조용히 이루어지지 않습니다. 팩을 업그레이드하거나 ([다른 버전으로 전환](/docs/modpacks/#changing-the-pack-version)하는 경우, 이전 버전 포함), 패널은 다음을 수행합니다:

1. **업데이트 전 백업**을 수행합니다 (되돌릴 수 있도록; 기본적으로 서버당 마지막 10개의 업데이트 전 백업이 유지됩니다. [보존](/docs/backups/#retention) 참조).
2. 정확한 새 버전을 다시 고정합니다.
3. 서버를 재빌드하고, 필요한 경우 Java 런타임을 다시 해석합니다.
4. 플랫폼별 시간 제한 내에서 첫 번째 부팅을 모니터링합니다.

정상적으로 시작되지 않으면 업데이트 전 백업으로 롤백합니다. 안정적인 서버는 베타 버전을 제공받지 않으며, 변경 로그 링크는 소스에서 제공하는 실제 버전별 diff를 가리킵니다. 실패한 업데이트는 통합이 구성된 경우 Discord [알림](/docs/integrations/)을 발생시킵니다.
