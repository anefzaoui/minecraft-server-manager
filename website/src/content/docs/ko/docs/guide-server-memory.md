간단히 말해, 실제로 플레이할 서버의 경우:

| 실행 중인 것                            | Java 힙 | 머신에 할당 |
| --------------------------------------- | ------- | ----------- |
| Vanilla 또는 Paper, 최대 10명 플레이어  | 2 GB    | 4 GB        |
| 플러그인이 있는 Paper, 10~30명 플레이어 | 4 GB    | 6 GB        |
| 가벼운 모드 팩, 40~80개 모드            | 4 GB    | 6 GB        |
| 대규모 키친 싱크 팩, 150~300개 모드     | 6~8 GB  | 10 GB       |
| GregTech New Horizons 및 유사한 괴물    | 8~12 GB | 16 GB       |

하나가 아닌 두 개의 숫자입니다. 대부분의 가이드에서 건너뛰는 부분이며, 사람들이 4GB 서버를 구매하고 Java에 4GB를 할당한 다음 서버가 죽는 것을 지켜보는 이유입니다.

## 힙과 머신은 다른 숫자입니다

Java 힙 (`-Xmx`)은 게임 자체가 월드, 엔티티 및 모드 데이터에 사용할 수 있는 메모리 양입니다. 머신 또는 컨테이너는 해당 힙 **과** Java가 필요로 하는 나머지 모든 것(클래스 메타데이터, 스레드 스택, 가비지 컬렉터 장부, 네트워크 버퍼 및 JVM 자체)을 보유해야 합니다. 모드 서버의 경우 이러한 오버헤드는 대략 0.5~1.5GB입니다.

힙이 머신의 메모리와 같으면 Java가 해당 오버헤드를 사용하려고 할 때 커널이 서버를 종료합니다. Docker에서는 종료 코드 137로 표시되고 로그에는 아무것도 표시되지 않습니다. 프로세스가 문장 중간에 사라집니다. 사람들은 보통 모드를 탓합니다.

안전한 규칙: **힙에 25%를 더하고 최소 1GB의 여유 공간을 확보하세요.** 8GB 힙에는 10GB 머신이 필요합니다.

## RAM이 많다고 성능이 향상되는 것은 아닙니다

Minecraft는 대부분의 작업에서 단일 스레드에 의해 제한됩니다. 40개 모드 팩에 16GB를 제공한다고 해서 청크 생성이 더 빨라지는 것은 아닙니다. 오히려 각 가비지 컬렉션 일시 중지 시간이 더 길어집니다. 30초마다 버벅거리는 서버는 메모리가 부족해서가 아니라 힙이 너무 많아서일 수 있습니다.

다음과 같은 경우에만 힙을 늘리세요.

- 로그에 `java.lang.OutOfMemoryError: Java heap space`가 표시될 때.
- 타이밍에서 가비지 컬렉션 일시 중지와 함께 "따라잡을 수 없습니다! 서버가 과부하되었습니까?" 메시지가 반복될 때.
- 메모리 사용량이 최대치까지 올라가 몇 시간 동안 고정될 때.

## 온라인 플레이어가 없을 때 서버가 12GB를 사용하는 이유

그렇게 설정했기 때문입니다. 두 가지 기본값이 충돌합니다.

1. 일반적인 Docker 이미지에서는 시작 힙을 최대 힙과 동일하게 설정하므로 `-Xms`와 `-Xmx`가 모두 귀하의 숫자입니다. Java는 메모리를 늘리는 대신 미리 확보합니다.
2. 인기 있는 Aikar 플래그 세트에는 시작 시 힙의 모든 페이지를 순회하여 페이지가 실제로 할당되도록 하는 `-XX:+AlwaysPreTouch`가 포함됩니다. 이는 나중에 일시 중지 시간을 줄이기 위해 부팅 시간을 늘리고 유휴 상태의 메모리 사용량을 늘리는 절충입니다.

Paper 1.21.1에서 4GB 컨테이너에 2GB 힙을 사용하고 월드 로딩이 완료된 후 3분 동안 샘플링한 결과:

| 구성                               | 상주 메모리 |
| ---------------------------------- | ----------- |
| 플래그 없음                        | 2.60 GiB    |
| Aikar 플래그                       | 2.59 GiB    |
| `AlwaysPreTouch` 없는 Aikar 플래그 | 1.95 GiB    |
| 512MB 시작 힙이 있는 Aikar 플래그  | 1.38 GiB    |
| 512MB 시작 힙이 없는 플래그        | 1.25 GiB    |

따라서 유휴 상태에서 12GB를 "사용"하는 서버는 미리 터치된 12GB 힙이지 메모리 누수가 아닙니다. 모니터링은 올바르게 읽고 있지만 숫자가 보이는 것과 같지 않습니다.

정직한 유휴 상태 수치를 원하면 시작 힙을 최대 힙보다 낮게 설정하세요. 초기에는 몇 번의 컬렉션이 더 발생합니다. 프레임 시간을 일정하게 유지하고 싶다면 그대로 두고 그래프를 보는 것을 멈추세요.

## 플레이어는 생각보다 덜 중요합니다

플레이어 수를 10명에서 20명으로 두 배로 늘리는 것은 모드를 50개 추가하는 것보다 훨씬 적은 비용이 듭니다. 플레이어는 주로 엔티티와 로드된 청크를 추가하며, 이는 완만하게 확장됩니다. 모드는 클래스 데이터, 레지스트리, 월드 생성 기능 및 자체 캐시를 추가하며, 이는 그렇지 않습니다. 먼저 모드 팩 크기를 고려한 다음 모드 서버의 경우 일반 플레이어당 약 100~200MB를 추가하세요.

뷰 거리는 다른 중요한 요소입니다. 12개 청크에서 8개 청크로 줄이면 바쁜 서버에서 1GB를 절약할 수 있으며 플레이에서는 거의 눈에 띄지 않습니다.

## Minecraft Server Manager에서

각 서버에는 **Java 힙**과 **컨테이너 메모리 제한**이라는 두 개의 별도 필드가 있습니다. 이는 두 가지 질문이 다르기 때문입니다. 생성 마법사는 컨테이너 제한을 힙보다 50% 높게 설정하며, 패널은 컨테이너 제한이 힙보다 높지 않은 서버를 저장하지 않습니다. 해당 조합은 오류 메시지 대신 종료 코드 137로 끝나기 때문입니다.

서버의 메모리 미터는 컨테이너가 실제로 사용하고 있는 것을 보여주며, 힙이 미리 확보된 경우 메모리 누수로 읽히지 않도록 메모가 표시됩니다. 메모리 부족으로 커널이 종료한 서버는 미스터리한 충돌이 아닌 기록에 정확히 그렇게 기록됩니다.
