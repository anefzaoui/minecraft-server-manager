## 서버 생성

마법사 창을 열려면 **서버 생성**(상단 표시줄)을 클릭하거나 **서버 생성** 카드를 클릭하세요.

![서버 생성](/docs/images/create-wizard.png)

마법사는 관리자가 언제든지 변경할 수 있는 설정 페이지의 **새 서버 기본값**에서 Java 힙 및 디스크 할당량을 미리 채웁니다. 새 서버는 CPU 제한도 여기서 가져옵니다.

![새 서버 기본값](/docs/images/settings-defaults.png)

다음 항목을 선택합니다.

- **이름**(및 선택적 설명, 아이콘, 강조 색상). 서버 그룹을 정리하기 위한 태그는 나중에 서버 설정에서 추가됩니다.
- **서버 유형**: **바닐라** 탭의 바닐라, 페이퍼 또는 퍼퍼. 모드 서버의 경우 **모드에서** 탭에서 로더(패브릭, 포지, 네오포지 또는 퀼트), Minecraft 버전 및 로더 빌드(최신 또는 특정 버전)를 선택한 다음 모드를 검색할 수 있습니다.
- **Minecraft 버전**: `LATEST`, 스냅샷 또는 특정 버전(베타 및 알파 포함).
- **게임 포트**: 사용 가능한 포트가 제안됩니다. 원격 콘솔(RCON)은 기본적으로 1000이 높은 포트를 사용합니다. 나중에 변경할 수 있습니다( [게임 포트 변경](#changing-the-game-port) 참조).
- **리소스**: Java 힙(컨테이너 메모리 제한은 이보다 50% 높게 설정됨) 및 디스크 할당량.

**고급 옵션**은 서버 이미지에서 지원하는 나머지 모든 설정을 열고 추가 환경 변수 및(관리자의 경우) 고급 Docker 설정을 제공합니다.

모드팩을 선호하시나요? **모드팩에서** 탭은 대신 CurseForge, Modrinth 또는 GT New Horizons 팩을 설치하거나( [모드팩](/docs/modpacks/) 참조) **업로드한 사용자 지정 zip**을 사용합니다. Modrinth `.mrpack`, CurseForge 모드팩 내보내기(`manifest.json`) 또는 모드 jar의 zip 파일입니다. 매니페스트(또는 식별된 jar 전체의 다수결)는 로더와 Minecraft 버전을 채우고 모든 모드는 하나의 작업으로 설치됩니다. **청사진에서** 탭에서 저장된 [청사진](/docs/blueprints/)으로 시작할 수도 있습니다.

패널은 선택한 버전에 적합한 Java 런타임을 자동으로 선택하고, 이미지를 가져오고, 컨테이너를 생성하고, 모두 하나의 양식에서 시작합니다.

## 단일 서버

![플레이어](/docs/images/players.png)

서버를 열면 탭 형식의 작업 공간이 나타납니다.

- **개요**: 플레이어와 공유할 주소, 설명, 실시간 사용량 및 온라인 상태인 사용자.
- **콘솔**: 실시간 로그 스트림 및 명령 입력, 게임 내 채팅 및 [채팅 명령](/docs/console-and-chat/).
- **플레이어**: 명단, 재고 및 통계.
- **모드**: 설치된 모드 목록, [모드 브라우저](/docs/modpacks/) 및 콘텐츠 업데이트. 모드 서버의 경우 **버전** 하위 탭에서 모드의 빌드가 향후 Minecraft 버전에 대해 확인되는지 확인합니다( [업데이트](/docs/updates/#minecraft-version-compatibility) ).
- **월드**: [월드, 실시간 지도 및 파일 관리자](/docs/worlds-and-files/).
- **백업**: 이 서버의 [스냅샷 및 복원](/docs/backups/).
- **모니터링**: 서버별 기록 및 실시간 메트릭, 충돌 보고서 포함(아래 참조).
- **설정**: **구성**(서버 실행에 대한 모든 것) 및 [통합](/docs/integrations/) (Discord, 상태 페이지, 초대, 관리자의 경우 챗봇).

시작, 중지 및 다시 시작 컨트롤은 모든 탭 위의 헤더에 있습니다. 각 탭에서 수행할 수 있는 작업은 해당 서버의 [권한](/docs/users-and-roles/#per-server-permissions)에 따라 다르며, 예를 들어 **파일** 하위 탭에는 파일 권한이 필요하고 콘솔 명령을 보내려면 콘솔 권한이 필요합니다.

![서버 개요](/docs/images/server-overview.png)

**월드 컨트롤** 레일은 모든 탭에 걸쳐 이동합니다. 게임 내 시계, 날씨, 토글 칩으로 된 일반적인 게임 규칙 및 나머지 규칙에 대한 "모든 월드 규칙 보기".

![월드 컨트롤](/docs/images/world-controls.png)

**모니터링 → 실시간**은 TPS 및 초당 밀리초, 충돌(지난 24시간 및 7일), 메모리 부족 종료, 자동 다시 시작을 포함한 상태 및 안정성 카드, 월드별 크기를 보여줍니다.

![실시간 모니터링](/docs/images/monitoring-live.png)

## 서버 설정

**설정 → 구성**은 전체 구성 표면입니다. 이름, 설명, MOTD, 아이콘, 색상 및 태그, 리소스, 게임 포트, 업데이트 정책, 패널 부팅 시 시작 및 충돌 시 자동 다시 시작, 서버 이미지에서 지원하는 모든 환경 변수, 고급 Docker 설정, 청사진 내보내기, 복제, 다시 빌드 및 삭제. 서버를 다시 빌드해야만 적용되는 변경 사항은 즉시 저장되고 대기합니다. **변경 사항 적용** 버튼이 서버 헤더에 나타나며 다음번 서버 시작 시에도 적용됩니다.

**충돌 시 자동 다시 시작**은 충돌한 서버를 다시 시작하며, 시도 사이에 더 오래 기다립니다(5, 10, 20초). 10분 내에 3번 시도 후 중지됩니다. EULA, 잘못된 Java, 최신 버전의 월드, 사용 중인 포트, 메모리 부족, 누락된 CurseForge 키와 같이 패널이 설정 문제로 인식하는 충돌은 건너뜁니다. 이러한 문제는 먼저 수정해야 합니다. 다른 작업이 서버와 관련되어 있는 경우(백업, 복원, 포트 변경), 최대 30분 동안 기다리고, 누군가 서버를 중지하거나 시작하면 즉시 포기합니다.

직접 설정 변경은 항상 다시 시작 시에도 유지됩니다. **월드 컨트롤** 레일로 PvP 또는 난이도를 변경하거나, **플레이어** 탭에서 화이트리스트를 토글하거나, **파일** 편집기에서 `server.properties`를 편집하면 해당 환경 변수(설정된 경우)가 제거되고 다음 시작 시 컨테이너 이미지에서 다시 적용되는 대신 디스크의 값이 우선하도록 서버가 다시 빌드되도록 표시됩니다.

![서버 설정](/docs/images/server-settings.png)

**메모리 미터 정보.** "RAM(Java 힙)"은 Java에 시작 및 최대 힙으로 모두 전달되며, Java는 Aikar / MeowIce 플래그 사전 설정 유무에 관계없이 제공된 힙을 첫 1분 내에 채웁니다. 따라서 메모리 미터는 힙 크기 근처에서 안정화되고 아무도 플레이하지 않을 때도 그대로 유지됩니다. 미터의 눈금은 힙이 컨테이너 제한 내에서 어디에 있는지 표시하고, 그 아래의 메모는 그렇게 말합니다. 메모리가 실제 사용량을 따르도록 하려면 설정 → 구성의 리소스 카드(또는 마법사의 고급 옵션)에서 **초기 힙**을 512MB와 같이 더 작게 설정하십시오. 2GB 힙에서 측정 결과 유휴 사용량이 2.6GB에서 약 1.3GB로 줄었습니다. Java는 힙 외부에서도 메모리가 필요합니다(바닐라의 경우 약 0.5GB, 대형 모드팩의 경우 1.5~2GB). 컨테이너 제한의 여유 공간이 이를 위한 것입니다. 수치는 README의 "두 가지 메모리 제한"을 참조하십시오.

> **고급 Docker 설정**(컨테이너 이름, Docker 네트워크, 추가 포트 매핑 및 추가 볼륨 바인딩)은 **관리자 전용**입니다. 바인드 마운트와 패널의 Docker 액세스는 호스트에서 루트 권한과 동일하기 때문입니다. [사용자 및 역할](/docs/users-and-roles/)을 참조하십시오.

### 게임 포트 변경

**설정 → 구성**의 **게임 포트** 카드는 언제든지 서버를 다른 포트로 이동시키며, 자체 **포트 저장** 버튼이 있습니다. **다음 사용 가능한 포트 사용**은 가장 낮은 사용 가능한 포트를 선택하고, 카드는 입력한 포트를 저장하기 전에 확인합니다. RCON은 항상 게임 포트보다 1000 높은 곳에 위치합니다(기본 오프셋). 관리자는 1024부터 어떤 포트든 선택할 수 있습니다. 다른 모든 사용자는 첫 번째 게임 포트(기본값 25565)부터 시작하는 포트를 선택합니다. 저장하면 변경 사항이 즉시 적용됩니다. 중지된 서버는 단순히 이동하고, 실행 중인 서버는 먼저 확인한 후 새 포트에서 다시 시작합니다(월드는 먼저 저장되고 플레이어는 새 포트에서 다시 연결됩니다). 새 포트에서 서버를 시작할 수 없으면 이전 포트로 돌아갑니다. 다른 변경 사항이 **변경 사항 적용**을 기다리는 동안에는 포트 변경이 거부되므로 먼저 해당 변경 사항을 적용하십시오. 포트 변경에는 해당 서버의 설정 권한이 필요합니다.

## 충돌 보고서 및 mclo.gs 분석

충돌 보고서(`crash-reports/*.txt` 및 JVM `hs_err_pid*.log` 파일)는 자동으로 수집되어 예외 및 의심되는 모드가 포함된 한 줄 요약으로 구문 분석되고 **모니터링 → 기록**에 나열됩니다.

![충돌 보고서 카드](/docs/images/crash-mclogs-card.png)

각 보고서 카드는 내장 뷰어(접기/펼치기 섹션 및 강조 표시된 예외 포함), 스택 추적 복사, 다운로드 및 두 가지 [mclo.gs](https://mclo.gs) 작업을 제공합니다.

- **mclo.gs에 공유**는 보고서를 공개 페이스트로 게시하고 링크를 복사합니다. 모드 작성자 및 지원 Discord에서 요청하는 정확한 것입니다. 링크는 보고서에 기억되므로 아무것도 두 번 업로드되지 않습니다.
- **분석**은 페이스트에 대한 mclo.gs의 자동화된 인사이트를 실행합니다. 알려진 문제와 제안된 수정 사항(누락된 종속성, 버전 불일치, 일반적인 모드 충돌)이 패널에 직접 렌더링됩니다.

![mclo.gs 인사이트](/docs/images/crash-insights.png)

두 작업 모두 명시적인 확인 뒤에 있으며, 페이스트는 공개적이기 때문입니다. 충돌 보고서에는 플레이어 이름과 전체 모드 목록이 포함될 수 있습니다. 패널은 자체적으로 아무것도 업로드하지 않습니다.
