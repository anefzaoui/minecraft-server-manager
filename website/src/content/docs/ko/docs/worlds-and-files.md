## 월드

**월드** 페이지는 서버의 월드 데이터를 관리합니다: 활성 월드를 전환하거나, 월드를 업로드하거나, 다운로드할 수 있습니다.

![월드](/docs/images/worlds.png)

## 파일 관리자

서버의 **월드** 섹션 아래에 있는 **파일** 탭은 해당 서버의 데이터 디렉토리를 위한 완전한 브라우저 내 파일 관리자입니다. 파일 목록을 보고, 읽고, 편집하고, 만들고, 이름을 바꾸고, 이동하고, 복사하고, 삭제하고, 업로드할 수 있습니다. SSH를 통해 일반적으로 수행하는 모든 작업을 브라우저에서 할 수 있습니다.

![파일 관리자](/docs/images/server-files.png)

텍스트 파일은 2MB 제한이 있는 편집기에서 열립니다. 더 큰 파일은 다운로드할 수 있습니다. 업로드는 여러 파일을 한 번에 처리합니다.

### 샌드박스 내 유지

모든 파일 작업은 서버 자체의 데이터 디렉토리로 제한됩니다. 패널은 각 경로를 확인하고 벗어나려는 모든 것을 거부합니다: `..` 탐색, 절대 경로, 심지어 디렉토리 외부를 가리키는 심볼릭 링크(존재하지 않는 끊어진 링크 포함)도 마찬가지입니다. 모드나 플러그인이 파일 관리자를 속여 호스트의 다른 곳을 읽거나 쓰게 만들 수 없습니다.

## 모드

모드 서버의 경우, **모드** 탭(서버 사이드바의 자체 그룹)은 모드 세트를 관리합니다: 모드를 검색하고 추가하고 설치된 모드를 확인합니다. 모드 및 팩 업데이트는 [업데이트](/docs/updates/) 페이지에 표시됩니다.

### 모드 추가

![모드](/docs/images/mods.png)

네 가지 방법으로 추가할 수 있으며, 모두 모드 탭 도구 모음에서 가능합니다:

- **모드 검색** - **Modrinth 또는 CurseForge**를 검색합니다 (CurseForge 칩은 설정 → API 키 아래에 API 키가 저장되면 나타납니다). 플러그인 서버의 경우 **Hangar**(PaperMC 자체 플러그인 레지스트리) 및 **SpigotMC**(Spiget의 CDN 프록시를 통해)도 검색할 수 있습니다 - 둘 다 키가 필요 없습니다. 모든 결과는 서버의 로더 및 Minecraft 버전에 맞게 필터링됩니다. Quilt 서버는 Quilt가 Fabric 모드를 실행하기 때문에 Fabric 태그가 지정된 빌드도 자동으로 표시합니다. 이미 서버에 있는 결과에는 **설치됨** 배지가 표시됩니다. CurseForge 작성자가 자동 다운로드를 허용하지 않거나 SpigotMC 리소스가 외부에서 호스팅되는 경우, 패널은 이를 미리 알려주고 설치 중에 실패하는 대신 **페이지 열기** + **jar 업로드** 경로를 제공합니다.

  ![Hangar 검색](/docs/images/mods-search-hangar.png)

- **zip 가져오기** - 하나의 버튼, 세 가지 모양, 자동 감지:
  - **Modrinth 모드팩 (`.mrpack`)**: 고정된 모든 파일은 해시 조회를 통해 Modrinth 프로젝트로 다시 정규화됩니다 (따라서 가져온 모드는 실제 이름, 아이콘을 유지하고 업데이트 확인 가능하게 유지됩니다. Modrinth가 모르는 파일은 팩 자체 URL에서 설치됩니다). 다운로드 중에 팩의 sha512 체크섬과 비교하여 확인되고, 적합한 결과와 함께 미리 보기가 제공됩니다. 클라이언트 전용 파일은 눈에 띄게 건너뛰고, 두 오버라이드 트리 (`overrides/`, 그 다음 `server-overrides/` - 서버별 복사본이 우선)를 적용할 수 있습니다.

    ![mrpack 가져오기](/docs/images/mrpack-import.png)

  - **CurseForge 모드팩 내보내기 zip** (CurseForge 앱이 생성하는 zip, `manifest.json` 포함): 고정된 모든 모드는 일괄 처리되고, 경고와 함께 미리 보기가 제공됩니다 (이 서버에 잘못된 로더/MC, 더 이상 CurseForge에 없는 파일, 수동 다운로드가 필요한 모드). 실제 진행 상황과 함께 설치됩니다. 팩의 `overrides/` (설정, 스크립트)도 선택적으로 적용할 수 있습니다 - 덮어쓰여질 모든 파일은 먼저 서버 폴더 내의 `.import-backups/<타임스탬프>/`로 백업됩니다.
  - 직접 수집한 **jar 파일의 일반 zip**: 각 jar 파일은 식별됩니다 (Modrinth 해시 일치 → CurseForge 지문 → jar 자체 메타데이터). 그리고 서버와 비교하여 판단됩니다 - _적합 / 잘못된 로더 / 잘못된 MC 버전 / 이미 설치됨 / 식별되지 않음_ - 따라서 설치 전에 실제로 필요한 것을 선택할 수 있습니다.
- **링크로 추가** - 거의 모든 것을 붙여넣을 수 있습니다: Modrinth, CurseForge, Hangar 또는 SpigotMC 프로젝트 페이지, GitHub 저장소 또는 릴리스 URL (단순 `owner/repo`도 작동합니다 - GitHub 설치는 최신 안정 릴리스를 선호하며 `-sources`/`-javadoc` 사이드카 jar는 건너뜁니다), 단순 Modrinth 슬러그 또는 모든 직접 `.jar` URL. 패널은 서버의 로더 및 MC 버전에 맞는 올바른 빌드를 확인합니다.

  ![링크로 추가](/docs/images/mods-add-by-link.png)

- **jar 업로드** (검색 대체 또는 보류 중인 다운로드 해결 프로그램에서) - 업로드된 jar 파일은 동일한 방식으로 식별되므로 실제 이름, 버전, 아이콘을 유지하고 업데이트 확인 가능하게 됩니다.

모든 레지스트리 설치는 **다운로드 중에 체크섬이 확인됩니다**: 스트림은 레지스트리가 게시하는 가장 강력한 다이제스트(sha512 → sha256 → sha1 → md5)와 비교하여 확인되며, 불일치가 발생하면 아무것도 서버에 착륙하기 전에 중단됩니다.

전체 zip 파일(`.mrpack` 포함)은 **서버를 생성**할 수도 있습니다: 마법사의 _모드팩에서_ 탭에서 업로드하면 팩 매니페스트(또는 식별된 jar 파일 간의 다수결)가 로더, Minecraft 버전 및 로더 빌드를 채웁니다.
