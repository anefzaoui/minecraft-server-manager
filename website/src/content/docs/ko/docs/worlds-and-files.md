## 월드

**월드** 페이지는 모든 저장된 월드를 한곳에 모아둔 월드 라이브러리입니다. **월드 업로드**는 `.zip` 또는 `.tar` 아카이브를 받아 그 안에 있는 월드를 자동으로 찾고, **라이브러리에 저장**은 서버의 라이브 월드를 스냅샷으로 저장합니다(서버가 실행 중일 때도 작동합니다). 각 라이브러리 월드는 **설치 대상…**을 통해 어떤 서버로든 다운로드하거나 설치할 수 있습니다. 설치는 서버의 월드를 교체하거나(서버는 중지되어야 하며, 현재 월드는 먼저 백업됩니다) 옆에 추가하여 나중에 활성화할 수 있습니다. 모든 설치 전에 호환성 검사가 실행됩니다.

서버 자체의 **월드 → 월드** 탭에는 해당 서버에 있는 월드 목록이 표시됩니다. 여기에서 다른 월드를 활성화하거나(서버가 중지된 상태에서), 월드를 다운로드, 복제, 이름 변경 또는 [축소](/docs/world-shrink/)하거나, 다른 서버로 복사하거나, 비활성 월드를 삭제하거나, 새 시드, 보관된 시드 또는 사용자 지정 시드로 활성 월드를 재설정할 수 있습니다(안전 백업이 먼저 제공됩니다). 동일한 라이브러리가 아래에 있으며, **여기에 설치** 버튼이 있습니다.

## 파일 관리자

서버의 **월드** 섹션 아래에 있는 **파일** 탭은 해당 서버의 데이터 디렉토리를 위한 완전한 인브라우저 파일 관리자입니다. 파일 목록 보기, 읽기, 편집, 이름 변경, 이동, 복사, 삭제, 업로드, 폴더 생성, 그리고 **파일에서 찾기**를 통해 폴더 내 파일의 텍스트를 검색하는 등 SSH를 통해 일반적으로 수행하는 모든 작업을 브라우저에서 할 수 있습니다.

![파일 관리자](/docs/images/server-files.png)

텍스트 파일은 8MB 제한이 있는 편집기에서 열리며, 더 큰 파일은 다운로드할 수 있습니다. 업로드는 한 번에 최대 20개의 파일을 허용합니다.

### 샌드박스 내 유지

모든 파일 작업은 서버 자체의 데이터 디렉토리로 제한됩니다. 패널은 각 경로를 확인하고 `..` 탐색, 절대 경로, 심지어 디렉토리 외부를 가리키는 심볼릭 링크(아직 존재하지 않는 매달린 링크 포함)와 같이 벗어날 수 있는 모든 것을 거부합니다. 모드나 플러그인은 파일 관리자를 속여 호스트의 다른 곳을 읽거나 쓰도록 링크를 심을 수 없습니다.

## 모드

모드 및 플러그인 서버의 경우, **모드** 탭(서버 사이드바의 자체 그룹)은 모드 세트를 관리합니다: 모드를 찾아 추가하고, 설치된 모드를 확인합니다. 각 설치된 모드의 행에서 업데이트(또는 해당 업데이트 무시), [되돌리기](/docs/updates/#undoing-a-mod-update), 비활성화 또는 제거할 수 있으며, **모두 업데이트**는 한 번의 재시작으로 사용 가능한 모든 업데이트를 적용합니다. 모드 및 팩 업데이트는 [업데이트](/docs/updates/) 페이지에도 표시됩니다.

### 모드 추가

![모드](/docs/images/mods.png)

모드 탭 도구 모음에서 네 가지 방법으로 추가할 수 있습니다:

- **모드 검색**: **Modrinth 또는 CurseForge**를 검색하고(CurseForge 칩은 **설정 → API 키**에 API 키가 저장되면 나타납니다), 플러그인 서버에서는 **Hangar**(PaperMC 자체 플러그인 레지스트리) 및 **SpigotMC**(Spiget의 CDN 프록시를 통해)도 검색할 수 있으며, 둘 다 키가 필요 없습니다. **데이터팩** 탭은 Modrinth의 데이터팩을 검색합니다. 모든 것은 서버의 로더 및 Minecraft 버전에 따라 필터링됩니다(체크박스는 호환되지 않는 것으로 나열된 빌드도 자신의 위험 부담으로 표시합니다). Quilt 서버는 Fabric 모드를 실행하므로 Fabric 태그가 지정된 빌드도 자동으로 표시됩니다. 서버에 이미 있는 결과는 **설치됨** 배지를 표시합니다. CurseForge 작성자가 자동 다운로드를 허용하지 않거나(또는 SpigotMC 리소스가 외부에서 호스팅되는 경우), 패널은 미리 알려주고 설치 도중 실패하는 대신 **CurseForge 열기**(또는 **SpigotMC 열기**) + **Jar 업로드** 경로를 제공합니다.

  ![Hangar 검색](/docs/images/mods-search-hangar.png)

- **Zip 가져오기**: 하나의 버튼, 세 가지 형태, 자동 감지:
  - **Modrinth 모드팩(`.mrpack`)**: 모든 고정된 파일은 해시 조회를 통해 Modrinth 프로젝트로 다시 정규화됩니다(따라서 가져온 모드는 실제 이름, 아이콘을 유지하고 업데이트 확인이 가능하며, Modrinth가 알지 못하는 파일은 팩 자체의 URL에서 설치됩니다). 다운로드하는 동안 팩의 sha512 체크섬과 비교하여 확인되고, 적합성 판정으로 미리 보기가 제공됩니다. 클라이언트 전용 파일은 눈에 띄게 건너뛰어지고, 두 개의 오버라이드 트리(`overrides/`, 그 다음 `server-overrides/`; 서버별 복사본이 우선합니다)를 적용할 수 있습니다.

    ![mrpack 가져오기](/docs/images/mrpack-import.png)

  - **CurseForge 모드팩 내보내기**(CurseForge 앱이 `manifest.json`과 함께 생성하는 zip): 모든 고정된 모드는 일괄적으로 해결되고, 경고(이 서버에 맞지 않는 로더/MC, CurseForge에 더 이상 없는 파일, 수동 다운로드가 필요한 모드)와 함께 미리 보기가 제공되며, 실제 진행 상황과 함께 설치됩니다. 팩의 `overrides/`(설정, 스크립트)도 선택적으로 적용할 수 있습니다. 덮어쓰여질 파일은 먼저 서버 폴더 내의 `.import-backups/<timestamp>/`에 백업됩니다.
  - **직접 수집한 jar 파일의 일반 zip**: 각 jar는 식별되고(Modrinth 해시 일치 → CurseForge 지문 → jar 자체 메타데이터) 서버에 대해 판단됩니다(_적합 / 잘못된 로더 / 잘못된 MC 버전 / 이미 설치됨 / 식별되지 않음_). 따라서 실제로 설치하기 전에 어떤 것이 속하는지 선택할 수 있습니다.
- **URL로 추가**: 거의 모든 것을 붙여넣을 수 있습니다: Modrinth, CurseForge, Hangar 또는 SpigotMC 프로젝트 페이지, GitHub 저장소 또는 릴리스 URL(단순한 `owner/repo`도 작동하며, GitHub 설치는 최신 안정 릴리스를 선호하고 `-sources`/`-javadoc` 사이드카 jar는 건너뜁니다), 단순한 Modrinth 슬러그 또는 모든 직접 `.jar` URL. 패널은 서버의 로더 및 MC 버전에 맞는 빌드를 해결합니다.

  ![링크로 추가](/docs/images/mods-add-by-link.png)

- **Jar 업로드**(검색 대체 또는 보류 중인 다운로드 해결사에서): 업로드된 jar는 동일한 방식으로 식별되므로 실제 이름, 버전, 아이콘을 유지하고 업데이트 확인이 가능해집니다.

모든 레지스트리 설치는 **다운로드하는 동안 체크섬으로 확인됩니다**: 스트림은 레지스트리가 게시하는 가장 강력한 다이제스트(sha512 → sha256 → sha1 → md5)와 비교하여 확인되며, 불일치가 발생하면 서버에 아무것도 도착하기 전에 중단됩니다.

전체 zip(`.mrpack` 포함)으로도 **서버를 생성**할 수 있습니다: 마법사의 **모드팩에서** 탭에서 업로드하면 팩 매니페스트(또는 식별된 jar 파일들의 다수결)가 로더, Minecraft 버전 및 로더 빌드를 채웁니다.
