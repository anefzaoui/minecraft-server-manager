패널은 다중 사용자입니다. 계정 관리는 **설정 → 사용자**에서 할 수 있습니다.

![Users](/docs/images/settings-users.png)

## 세 가지 역할

| 역할                 | 모든 서버에서 기본값                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------- |
| **관리자(admin)**    | 모든 것: 사용자, API 키, 전역 파일, 고급 Docker 재정의, 모든 서버 작업 관리.                |
| **운영자(operator)** | 서버 실행 및 구성(시작/중지, 콘솔, 백업, 월드, 모드, 대부분의 설정), 관리자 전용 영역 제외. |
| **보기(viewer)**     | 읽기 전용. 서버 및 상태 확인 가능, 변경 불가.                                               |

보기(viewer)를 포함한 모든 사용자는 자신의 [2단계 인증](/docs/two-factor-authentication/)을 관리할 수 있습니다. 이는 자신의 로그인을 보호하는 것이 서버 관리 작업이 아니기 때문입니다.

역할은 모든 서버의 **기본값**입니다. 특정 서버에서 다른 권한을 부여하려면 아래의 서버별 권한을 사용하세요.

## 서버별 권한

**권한(Permissions)** 페이지(사이드바 또는 **설정 → 사용자** 아래의 **서버 권한**)에는 표가 표시됩니다. 한쪽에는 모든 운영자 및 보기 사용자가, 다른 쪽에는 모든 서버가 나열됩니다. 셀을 클릭하여 해당 사용자가 해당 서버에서 수행할 수 있는 작업을 결정합니다. 관리자는 항상 모든 것을 가지고 있으므로 목록에 없습니다.

![Permissions](/docs/images/settings-permissions.png)

각 셀은 권한 집합입니다.

| 권한                  | 해당 서버에서 허용하는 작업                                                              |
| --------------------- | ---------------------------------------------------------------------------------------- |
| **보기(View)**        | 서버, 상태, 콘솔 출력, 플레이어, 기록 및 통계 보기.                                      |
| **전원(Power)**       | 서버 시작, 중지, 다시 시작, 종료 및 다시 빌드.                                           |
| **콘솔(Console)**     | 콘솔 명령 및 월드 빠른 작업 실행, 채팅 전송, 채팅 명령 관리.                             |
| **플레이어(Players)** | 플레이어 추방, 차단, 화이트리스트 추가, 운영자 지정, 플레이어 노트 편집.                 |
| **콘텐츠(Content)**   | 모드, 플러그인, 팩, 월드, 데이터팩 설치 및 제거, 인벤토리 편집.                          |
| **백업(Backups)**     | 백업 생성, 복원, 다운로드 및 삭제.                                                       |
| **파일(Files)**       | 서버 파일, 아카이브된 로그 및 로그 번들 탐색, 편집, 업로드 및 다운로드; 청사진 내보내기. |
| **설정(Settings)**    | 서버 설정, 속성, 통합, 아이콘 변경, 버전 업그레이드.                                     |
| **삭제(Delete)**      | 서버 삭제.                                                                               |

![Permission editor](/docs/images/permissions-editor.png)

표 아래의 **각 권한이 적용되는 범위**를 클릭하면 각 권한이 허용하는 작업, 포함되지 않는 내용, 그리고 해당 권한이 잠금 해제하는 정확한 패널 경로가 자세히 설명됩니다. 마지막 목록은 테스트 스위트에서 실행 중인 코드와 비교하여 확인됩니다.

![Permission reference](/docs/images/permissions-reference.png)

휴대폰에서는 표가 사용자별 카드 하나로 쌓이고, 각 카드에는 서버별 행이 표시됩니다.

조각들이 어떻게 맞춰지는가:

- **역할은 기본값입니다.** 운영자는 모든 서버의 모든 권한으로 시작하며, 보기 사용자는 보기 권한만 가지고 시작합니다. 희미한 텍스트로 표시된 셀(툴팁에 "역할 기본값"이라고 표시됨)은 변경된 적이 없습니다.
- **셀은 해당 서버에 대해서만 역할을 재정의합니다.** 보기 사용자에게 한 서버에서 전원 및 콘솔 권한을 부여하면 해당 서버를 실행할 수 있지만, 다른 모든 서버는 해당 사용자에게 읽기 전용으로 유지됩니다. 주 서버에서 운영자의 삭제 권한을 제거해도 해당 서버의 다른 모든 권한은 유지됩니다.
- **모든 권한에는 보기가 포함됩니다.** 볼 수 없는 서버에서는 아무 작업도 할 수 없습니다.
- **모든 것을 끄면 서버가 숨겨집니다.** 해당 사용자의 사이드바, 대시보드, 백업, 예약, 활동, 업데이트, 모드팩, 실시간 상태, 실행 중인 작업 및 청사진에서 사라지며, 월드 라이브러리에서 해당 서버 이름이 더 이상 표시되지 않습니다. 직접 링크, API 호출 또는 콘솔 소켓은 존재하지 않는 서버와 마찬가지로 "찾을 수 없음"으로 응답합니다.
- **패널 전체 작업은 여전히 역할을 따릅니다.** 서버 생성(복제 포함), 스토리지, 사용자, API 키, 전역 설정 및 패널 전체 예약은 서버별이 아니므로 일부 서버에서 권한이 있는 보기 사용자는 이러한 작업을 수행할 수 없습니다. 운영자는 서버 생성 및 패널 전체 예약을 유지합니다. 스토리지, 사용자, API 키 및 전역 설정은 관리자 전용입니다.
- **예약은 서버를 따릅니다.** 서버에 대한 예약된 다시 시작, 백업 또는 명령은 해당 서버에서 일치하는 권한(전원, 백업 또는 콘솔)이 필요하며, 역할에 관계없이 적용됩니다.
- **청사진도 서버를 따릅니다.** 서버를 청사진으로 내보내려면 해당 서버에 파일 권한이 필요합니다. 아카이브가 파일을 포함하기 때문입니다. 보이지 않는 서버에서 내보낸 청사진은 해당 사용자에게도 숨겨집니다.
- **관리자 전용 영역은 모든 서버에서 관리자 전용으로 유지됩니다.** 챗봇, 백업 보존 및 고급 Docker 재정의.

모든 변경 사항은 활동 로그에 누가 무엇을 변경했는지 기록되며, 이 항목은 관리자에게만 표시됩니다. 사용자 삭제는 해당 사용자의 행을 제거합니다. 서버 제거는 해당 행을 유지하므로, 숨겨진 서버는 기록 및 보관된 백업에서도 계속 숨겨집니다.

기존 설치는 변경 없이 계속 작동합니다. 관리자가 셀을 편집할 때까지 모든 사용자는 역할이 이전에 부여한 권한을 정확히 가집니다.

## 관리자 전용 및 그 이유

몇 가지 사항은 의도적으로 관리자에게만 제한됩니다.

- **사용자 관리, 스토리지, 전역 설정, API 키 및 전역 파일.**
- **[공개 API](/docs/public-api/)**: `/api/v1` 활성화 및 읽기 전용 Bearer 토큰 생성, 범위 지정 또는 취소.
- **고급 Docker 재정의**: 사용자 지정 컨테이너 이름, 추가 포트 게시, 바인드 마운트. 바인드 마운트는 호스트의 모든 경로를 컨테이너로 매핑할 수 있으며, 패널의 Docker 액세스와 결합하면 호스트에 대한 루트 권한과 동일합니다. 이러한 필드는 관리자에게만 표시됩니다.

사용자 지정 컨테이너 이름은 패널 자체의 `msm-` 네임스페이스에 있을 수 없으므로, 수동으로 이름이 지정된 컨테이너는 다른 서버의 컨테이너를 가리거나 잘못된 인스턴스로 중지 또는 명령을 전달할 수 없습니다.

## 계정 관리

![Profile picture](/docs/images/profile-picture.png)

관리자는 사용자 테이블에서 사용자를 생성하고, 역할을 변경하고, 비밀번호를 재설정하고, 계정을 삭제할 수 있습니다. **2FA** 열은 각 사용자의 2단계 인증 활성화 여부를 보여줍니다. 관리자는 해당 사용자의 작업 메뉴에서 **2FA 재설정**을 사용하여 다른 사용자의 2FA를 재설정할 수 있습니다(전화 분실 및 백업 코드의 경우). 그러나 비밀번호 없이는 자신의 2FA를 비활성화할 수 없으며, 이는 셀프 서비스 흐름에서 처리됩니다.

로그인 실패는 계정당 속도 제한(IP별 및 계정 전역 카운터 모두)되어 무차별 대입 공격 시도를 늦춥니다. 동일한 제한은 2FA 코드 단계에도 적용되므로 올바른 비밀번호로도 코드 추측 전에 카운터를 재설정할 수 없습니다. 그 앞에는 로그인 / 2FA / 설정 엔드포인트에 더 거친 클라이언트 IP별 요청 제한기가 있으며, `RATE_LIMIT_AUTH_PER_15MIN`(기본값 100)으로 조정할 수 있습니다(리버스 프록시 뒤에 있는 경우 `TRUST_PROXY`를 설정하여 실제 클라이언트 IP를 기준으로 키를 지정).
