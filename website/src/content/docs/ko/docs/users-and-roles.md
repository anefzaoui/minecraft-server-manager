패널은 다중 사용자입니다. 계정 관리는 **설정 → 사용자**에서 할 수 있습니다.

![사용자](/docs/images/settings-users.png)

## 세 가지 역할

| 역할                 | 할 수 있는 작업                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------- |
| **관리자(admin)**    | 모든 작업: 사용자, API 키, 전역 파일, 고급 Docker 재정의, 모든 서버 작업 관리.               |
| **운영자(operator)** | 서버 실행 및 구성 (시작/중지, 콘솔, 백업, 월드, 모드, 대부분의 설정), 관리자 전용 영역 제외. |
| **보기(viewer)**     | 읽기 전용. 서버 및 상태 확인 가능, 변경 불가.                                                |

보기(viewer)를 포함한 모든 사용자는 자신의 [2단계 인증](/docs/two-factor-authentication/)을 관리할 수 있습니다. 이는 자체 로그인 보호가 서버 관리 작업이 아니기 때문입니다.

## 관리자 전용 기능 및 이유

몇 가지 기능은 의도적으로 관리자에게만 제한됩니다:

- **사용자 관리, API 키, 전역 파일.**
- **[공개 API](/docs/public-api/)** - `/api/v1` 활성화 및 읽기 전용 Bearer 토큰 생성, 범위 지정 또는 취소.
- **고급 Docker 재정의** - 사용자 지정 컨테이너 이름, 추가 포트 게시, 바인드 마운트. 바인드 마운트는 모든 호스트 경로를 컨테이너에 매핑할 수 있으며, 패널의 Docker 액세스와 결합하면 사실상 호스트의 루트 권한과 같습니다. 이 필드는 관리자에게만 표시됩니다.

사용자 지정 컨테이너 이름은 패널 자체의 `msm-` 네임스페이스에 있을 수 없으므로, 수동으로 이름이 지정된 컨테이너는 다른 서버의 컨테이너를 가리거나 잘못된 인스턴스로 중지 또는 명령을 보내지 않습니다.

## 계정 관리

![프로필 사진](/docs/images/profile-picture.png)

관리자는 사용자 테이블에서 사용자를 생성하고, 역할을 변경하고, 비밀번호를 재설정하고, 계정을 삭제할 수 있습니다. **2FA** 열은 각 사용자의 2단계 인증 활성화 여부를 보여줍니다. 관리자는 다른 사용자의 2FA를 재설정할 수 있지만 (전화 분실 및 백업 코드의 경우), 자체 비밀번호 없이는 자신의 2FA를 비활성화할 수 없습니다. 이는 자체 서비스 흐름에서 처리됩니다.

로그인 실패는 계정당 속도 제한됩니다 (IP별 및 계정 전역 카운터 모두). 이를 통해 무차별 대입 공격을 늦출 수 있으며, 동일한 제한이 2FA 코드 단계에도 적용되어 올바른 비밀번호가 코드 추측 전에 카운터를 재설정할 수 없습니다. 이 앞에는 로그인 / 2FA / 설정 엔드포인트에 대한 더 거친 클라이언트 IP별 요청 제한기가 있으며, `RATE_LIMIT_AUTH_PER_15MIN` (기본값 100)으로 조정할 수 있습니다 (리버스 프록시 뒤에서는 `TRUST_PROXY`를 설정하여 실제 클라이언트 IP를 기준으로 키를 지정).
