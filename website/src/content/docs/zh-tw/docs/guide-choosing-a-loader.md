請根據玩家想安裝的內容來選擇，而不是根據聽起來最快的選項。

| 您想要                                   | 運行此選項         | 玩家安裝   |
| ---------------------------------------- | ------------------ | ---------- |
| 生存模式與朋友同樂，沒有特別之處         | Vanilla            | 無         |
| 公共伺服器，包含等級、領地和管理功能     | Paper              | 無         |
| 來自 CurseForge 或 Modrinth 的特定模組包 | 照說明內容         | 模組包     |
| 您自己正在建構的現代模組包               | Fabric 或 NeoForge | 相同的模組 |
| 1.7 至 1.12 時代的舊模組包               | Forge              | 相同的模組 |

這對大多數人來說就是全部的決定了。本頁的其餘部分在解釋原因。

## 外掛程式 (Plugins) 與模組 (Mods) 並非相同

這是其他一切區分的基礎。

**外掛程式 (Plugins)** 僅在伺服器上運行。Paper、Spigot 和 Bukkit 會載入它們。玩家使用普通的
未修改客戶端加入，並且不會察覺。任何本質上與規則、權限、經濟、
領地、小遊戲或管理相關的功能都是外掛程式，這也是為什麼幾乎所有公共伺服器都運行 Paper 的原因。

**模組 (Mods)** 會改變遊戲本身：新的方塊、新的維度、新的機器。客戶端必須載入
與伺服器相同的模組，否則它無法理解伺服器傳達的內容。加入
模組化伺服器的任何人必須先安裝模組包。

一個伺服器無法有意義地同時是兩者。存在混合專案，它們將外掛程式 API 附加到模組載入器上，
它們可以正常運作，直到它們失效為止，通常發生在最糟糕的時刻。如果您同時需要兩者，請運行一個代理伺服器，
在其後面連接一個模組化伺服器和一個外掛程式伺服器，而不是一個混合伺服器。

## 外掛程式方面

**Paper** 是預設的選擇。它是 Spigot 的一個分支，經過多年的效能優化，並提供了一個
設定檔來處理幾乎所有曾讓管理員感到困擾的行為。來自 Bukkit 時代的 Vanilla 外掛程式
大多仍然可以運行。

**Purpur** 是 Paper 的一個分支，提供更多選項，包括遊戲玩法相關的開關。如果您想要
那些特定的設定，請選擇它；否則請選擇 Paper。

**Vanilla** 在重點是未經修改的遊戲時才值得運行。它在有多個玩家時速度較慢，
並且沒有權限系統，因此管理是手動的。

Paper 預設會更改一些 Vanilla 行為，以提高效能。如果影片中的紅石裝置在您的伺服器上無法運作，
這通常是原因，而且通常是可以透過設定解決的。

## 模組方面

**Fabric** 體積小，能在幾天內更新到新的 Minecraft 版本，並支援大多數現代
效能模組。幾乎所有 Fabric 模組都需要 Fabric API，這是一個獨立的下載。
如果您的目標是擁有少量生活品質模組的快速伺服器，那麼這是您的選擇。

**NeoForge** 是舊的 Forge 生態系統目前用於處理當前版本的所在地。它在 1.20.1 版本期間從
Forge 分離出來，大多數為 1.20.2 及更高版本建構的大型模組包都以它為目標。如果您今天開始建構一個新的重量級模組包，那麼這是您的選擇。

**Forge** 仍然主宰著過去。1.7.10、1.12.2 和 1.16.5 時代的任何內容，這包含了許多深受喜愛的模組包，都是 Forge，而且將永遠如此。請為那些情況保留它。

**Quilt** 是 Fabric 的一個分支，可以運行大多數 Fabric 模組。它的存在有其充分的理由，但如果您沒有特別的理由選擇它，請選擇 Fabric。

一個載入器的模組無法在另一個載入器上運行。標示為 Fabric 的模組頁面意味著是 Fabric。

## 如果您正在安裝模組包，由模組包決定

不要自行選擇。模組包會列出其載入器和確切的 Minecraft 版本，兩者都必須匹配。
在這裡，「差不多」是不存在的：「差不多」是不行的：1.20.1 的模組包無法在 1.20.4 上運行，而 1.20.1 的 NeoForge
模組包也無法在 1.20.1 的 Forge 上運行。

請透過其 ID 或連結安裝模組包，而不是手動挑選模組，並固定版本。模組包會更新，
而在遊戲過程中發生的更新可能會導致世界損壞。

## 使用哪個 Java 版本

Minecraft 的要求會隨著遊戲版本而變動，運行錯誤的版本會產生一個無用的
`UnsupportedClassVersionError` 而不是清晰的訊息。

| Minecraft 版本    | Java |
| ----------------- | ---- |
| 1.16.5 及更早版本 | 8    |
| 1.17              | 16   |
| 1.18 和 1.19      | 17   |
| 1.20 至 1.20.4    | 17   |
| 1.20.5 至 1.21.x  | 21   |
| 26.1 及更新版本   | 25   |

舊的模組包確實需要 Java 8；這是軟體中少數幾個最新版本反而錯誤的地方之一。

## 在 Minecraft Server Manager 中

建立精靈會詢問您想運行什麼，並從上表選擇 Java 版本，因此意外的不匹配情況永遠不會發生。Vanilla、Paper 和 Purpur 在其 **Vanilla** 標籤頁上；
**From Mods** 標籤頁接受 Fabric、Forge、NeoForge 或 Quilt，並可選擇 Minecraft 版本和載入器版本（最新版，或您固定的版本）。從 CurseForge、Modrinth 或 GT New Horizons 安裝模組包會將其固定到確切的版本。升級僅在您套用時發生（或在每日檢查後，如果伺服器的更新政策是 **自動更新**），總是會先備份，並且可以回滾。

模組瀏覽器知道伺服器運行哪個載入器，並據此過濾提供的內容，因此 Fabric jar 不會意外地進入 NeoForge 伺服器。
