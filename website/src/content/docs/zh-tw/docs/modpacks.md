**模組包 (Modpacks)** 頁面（以及[創建嚮導](/docs/servers/)中的**從模組包創建**標籤頁）會將模組包安裝為伺服器，並始終**固定到確切的包版本**，因此重新啟動永遠不會在您不知情的情況下升級模組包。

![Modpacks](/docs/images/modpacks.png)

## 支援的平台

- **CurseForge**: 按名稱搜尋。需要 CurseForge API 金鑰（在**設定 → API 金鑰**下添加）。
- **Modrinth**: 按名稱搜尋。
- **FTB**: Feed The Beast 包，僅透過 API（需要數字包 ID 和明確的版本 ID）。目前面板還不會檢查 FTB 包是否有更新。
- **GT New Horizons**: 1.7.10 的專家包，從 GTNH 自有的發行索引安裝。GTNH 為每個包版本選擇其 Java 運行時（2.8.0+ 版本透過捆綁的 lwjgl3ify 修補程式運行在**Java 25**上，較舊版本運行在 Java 21 或 17 上），並且嚮導會將伺服器的 RAM 和磁碟空間提升到合理的最低要求。
- **自訂 zip**: 並非已發佈的包。上傳一個**CurseForge 模組包匯出檔**（CurseForge 應用程式為手動選擇的模組集生成的包含 `manifest.json` 的 zip 檔）、一個**Modrinth `.mrpack`**，或**任何模組 jar 檔的 zip**。面板會批量解析資訊清單（或透過雜湊/指紋/元數據識別每個 jar 檔），預覽可行的內容，並一次性安裝所有內容，如果您選擇加入，還包括包的 `overrides/` 設定檔。作者不允許自動下載的模組會列出瀏覽器連結和手動上傳欄位，而不是導致安裝失敗。

## 固定版本的工作原理

當您選擇一個包時，面板會解析確切的版本，記錄下來，然後安裝該版本。在**更新**頁面上，當有新版本可用時會通知您（除非伺服器的[更新政策](#update-policy)是**僅手動**）；升級是一個經過深思熟慮、有保護措施的操作，包含更新前的備份和回滾。穩定版追蹤伺服器永遠不會提供測試版。伺服器自身的**版本**標籤頁回答了另一半問題：它實際擁有的模組可以跟隨哪些未來的 Minecraft 版本（[更新](/docs/updates/#minecraft-version-compatibility)）。

模組載入器版本也隨包一起提供：伺服器安裝包聲明的 Forge、NeoForge 或 Fabric 版本。如果一個 Forge 或 Fabric CurseForge 包聲明了一個對其自身模組來說過舊的版本，則**版本**標籤頁可以覆蓋它，直到包被修復；包更新會移除覆蓋，因為新版本會聲明自己的版本（[變更模組載入器版本](/docs/updates/#changing-the-mod-loader-version)）。

在非常舊的面板版本（0.9.7 之前）上創建的伺服器可能會處於_未固定_狀態，這意味著容器映像在每次啟動時都會悄悄安裝最新的包版本。面板現在會在啟動時修復這些伺服器：它將每個伺服器固定到實際安裝的版本（從面板自己的記錄或映像的安裝資訊清單中讀取，絕不會是新解析的“最新”版本），並記錄一個事件。如果它無法確定已安裝的版本，伺服器的設定頁面會顯示一個警告，並帶有一個**選擇版本…**按鈕（適用於 CurseForge、Modrinth 和 GTNH 包），該按鈕會打開[版本選擇器](#changing-the-pack-version)；任何嘗試儲存未固定模組包配置的行為都會被直接拒絕。

## 更新政策

每個伺服器在其**設定 → 設定**標籤頁上都有一個**更新政策**卡片，所有三個選項都如其字面意思：

- **僅手動**（預設值）：一切都不會自行更改，伺服器完全不會出現在更新徽章和更新頁面上。「別管我」模式：非常適合您從不想被修改的手動調整或匯入的包。它不會鎖定版本：[**變更版本…**](#changing-the-pack-version) 在所有政策下都有效。要接收新版本通知並一鍵套用，請選擇**通知我**。
- **通知我**: 每日檢查會在更新頁面上顯示可用的更新作為徽章；套用更新始終需要您的點擊。
- **自動更新**: 在每日排定的檢查後，待處理的**包**更新將透過與手動升級相同的保護路徑套用：更新前的備份、健康狀況監控以及在新版本啟動失敗時自動回滾。會將伺服器移至不同 Minecraft 版本的更新將始終被跳過並記錄一個事件：將世界永久轉換是一個面板拒絕為您做出的決定。手動的**立即檢查**按鈕僅檢查；它們從不觸發自動更新。

## 升級模組包

從已固定的伺服器，您可以一次性升級到更新的版本。面板會先進行備份，交換固定版本，重建伺服器（如果新版本需要不同的運行時則重新解析 Java），並監控首次啟動，對於像 GTNH 這樣下載數 GB 數據並在首次啟動時建立數百個模組的世界的大型包，會有一個寬裕的緩衝時間。

## 變更模組包版本

要運行特定版本，無論是較新還是較舊，請使用伺服器**總覽**標籤頁上模組包卡片的**變更版本…**。在**模組包**頁面上，打開已安裝包的卡片會提供相同的選擇：在下拉選單中選擇一個版本，然後點擊**切換到此版本**。兩者都需要伺服器的**內容**權限，並且兩者都適用於 CurseForge、Modrinth 和 GTNH 包（FTB 包目前還沒有版本列表）。列表顯示 CurseForge 和 Modrinth 的 25 個最新版本，以及 GTNH 的所有發行版本。

切換過程與升級過程相同，都經過保護路徑：更新前的備份、新的固定版本、重建以及受監控的首次啟動，如果伺服器未能正常啟動，則提供一鍵回滾。您的自訂模組將被保留，您禁用的包模組以及包的其他安裝設定（強制加入的模組、要忽略的檔案、額外項目）也會被保留。安裝不同的包會重設這些設定，因為它們僅對其所屬的包才有意義。

每個版本都會列出其運行的 Minecraft 版本，並與您的世界最後儲存的版本進行比較：

- **相同的 Minecraft 版本**: 在正常確認後切換。返回到較舊的包版本可能會導致該版本沒有的模組掉落方塊和物品，因此無論如何，備份都會保留在備份標籤頁中。
- **較新的 Minecraft 版本**: 允許在確認警告世界已被永久轉換後進行。首次採取的備份是返回舊世界的唯一方法。
- **較舊的 Minecraft 版本**: 不可用。Minecraft 無法載入比上次儲存它的版本更舊的版本來儲存的世界，因此面板會拒絕操作，而不是留下一個啟動時崩潰的伺服器。
