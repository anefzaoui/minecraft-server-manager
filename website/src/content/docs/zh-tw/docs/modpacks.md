**模組包 (Modpacks)** 頁面（以及 [創建嚮導](/docs/servers/) 中的 **從模組包創建** 選項卡）會將模組包安裝為伺服器，並始終**固定到確切的模組包版本**，因此重新啟動永遠不會在您不知情的情況下升級模組包。

![Modpacks](/docs/images/modpacks.png)

## 支援的平台

- **CurseForge** - 搜尋或貼上模組包的 URL。搜尋和私人模組包需要 CurseForge API 金鑰（在「設定」→「API 金鑰」下添加）。
- **Modrinth** - 按名稱搜尋。
- **FTB** - Feed The Beast 模組包。
- **GT New Horizons** - 1.7.10 專家級模組包，從 GTNH 自有的發行索引安裝。GTNH 會為每個模組包版本選擇其 Java 運行時（2.8.0+ 版本透過內建的 lwjgl3ify 修補程式運行在 **Java 25** 上，較舊版本運行在 Java 21 或 17 上），並且創建嚮導會將伺服器的 RAM 和磁碟空間提升到合理的最低要求。
- **自訂 zip** - 並非已發佈的模組包：上傳 **CurseForge 模組包匯出檔**（CurseForge 應用程式為手動選擇的模組集合生成的包含 `manifest.json` 的 zip 檔）或**任何模組 jar 檔的 zip 檔**。面板會透過 CurseForge API 大量解析資訊清單（或透過雜湊/指紋/元數據識別每個 jar 檔），預覽符合條件的內容，並一次性安裝所有內容——如果您選擇加入，還包括模組包的 `overrides/` 設定檔。作者不允許自動下載的模組會顯示瀏覽器連結和手動上傳欄位，而不是導致安裝失敗。

## 固定如何運作

當您選擇一個模組包時，面板會解析確切版本，記錄下來，然後進行安裝。在「**更新**」頁面上，系統會告知您何時有新版本可用；升級是一個經過深思熟慮且有保護措施的操作，包含更新前的備份和回滾。穩定追蹤的伺服器永遠不會提供 Beta 版本。

在非常舊的面板版本（0.9.7 之前）上創建的伺服器可能會處於_未固定_狀態，這意味著容器映像在每次啟動時都會悄悄安裝最新的模組包版本。面板現在會在啟動時修復這些伺服器：它會將每個伺服器鎖定到實際安裝的版本（從面板自己的記錄或映像的安裝資訊清單中讀取，絕不會是新解析的「最新」版本），並記錄一個事件。如果它無法確定已安裝的版本，伺服器的「設定」頁面會顯示警告，要求您手動選擇版本，並且任何嘗試儲存未固定的模組包設定的操作都會被直接拒絕。

## 更新政策

每個伺服器在「**設定**」中都有一個更新政策，所有三個選項都名副其實：

- **僅手動** - 永遠不會自動變更，伺服器完全不會出現在更新徽章和「更新」頁面上。「讓我一個人待著」模式：非常適合您從未想過要變更的手動調整或匯入的模組包。
- **通知我**（預設） - 每日檢查會在「更新」頁面上顯示可用的更新作為徽章；套用更新始終需要您的點擊。
- **自動更新** - 在排定的每日檢查後，待處理的**模組包**更新將透過與手動升級相同的保護路徑套用：更新前的備份、健康監控，以及在新版本啟動失敗時自動回滾。會將伺服器更新到不同 Minecraft 版本的更新一律會被跳過並記錄一個事件——永久轉換世界是一個面板拒絕為您做出的決定。手動的「立即檢查」按鈕僅執行檢查；它們不會觸發自動更新。

## 升級模組包

從已固定的伺服器，您可以一次性升級到更新的版本。面板會先進行備份，交換固定的版本，重新建立容器（如果新版本需要不同的運行時，則重新解析 Java），並監控首次啟動，對於像 GTNH 這樣下載數 GB 資料並在首次啟動時建立數百個模組的世界的大型模組包，會提供一個寬裕的監控時間窗口。
