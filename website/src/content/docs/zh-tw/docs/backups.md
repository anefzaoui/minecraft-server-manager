**備份**頁面顯示您所有伺服器中的快照，包含大小、原因和時間，可依伺服器和原因篩選。

![備份](/docs/images/backups.png)

## 建立備份

從伺服器的「**備份**」標籤頁（或透過[排程](/docs/schedules/)）即可一鍵快照整個伺服器目錄。面板會先靜止世界（`save-off` → `save-all`），壓縮資料，然後重新啟用儲存（`save-on`），因此即使在執行中的伺服器上，備份也是一致的。壓縮在背景執行緒中進行，不會延遲面板。透過 API 啟動的備份可以附帶備註。

每個封存檔在寫入時都會進行**完整性檢查**：面板會重新開啟 zip 檔並讀取其目錄。損壞或無法開啟的封存檔會被刪除，備份呼叫會立即失敗，而不是在數月後還原時才發現問題。零項目封存檔（從未啟動過的伺服器）是允許的，但會在事件中標記。

勾選「**之後也壓縮世界**」（在備份標籤頁或備份排程中），在封存檔安全寫入後移除很少訪問的區塊（參見 **[壓縮世界](/docs/world-shrink/)**）。壓縮僅在伺服器停止時執行；在執行中的伺服器上，備份仍會進行，壓縮則會被略過。

![伺服器備份](/docs/images/server-backups.png)

## 備份原因

備份會依據建立原因進行標記：

- **手動**：您點擊「**立即備份**」。將伺服器的活躍世界替換為資料庫中的某個世界時，也會先進行一次 `manual` 備份。
- **排程**：由[排程](/docs/schedules/)建立。每個新伺服器也會自動建立每日排程備份（介於凌晨 02:00 至 05:59 之間輪流執行），因此伺服器從第一天起就有自動保護，而不僅僅是在更新前。
- **更新前**：在套件升級或 Minecraft 版本變更前自動建立，因此升級總是可逆的。
- **還原前**：在還原或重設世界前自動建立，作為安全網，以防還原不如預期。

## 保留策略

保留策略**依伺服器、依原因**設有上限：每個群組中最新的備份會被保留，較舊的備份會在每次成功備份後自動刪除：

| 原因   | 預設保留數量 |
| ------ | ------------ |
| 排程   | 10           |
| 更新前 | 10           |
| 手動   | 20           |
| 還原前 | 5            |

`pre-restore`（在面板中稱為安全備份）有自己的獨立空間，精確地確保自動安全備份永遠不會取代您刻意保留的 `manual` 備份。

除了每個原因的數量上限外，還有兩個可選的總體上限，兩者預設均關閉：**最大年齡**（超過 N 天的備份將被刪除，無論其原因為何）和每個伺服器的**最大總大小**（將刪除最舊的備份直到總大小符合要求：優先刪除安全備份，然後是排程備份，最後是其他備份）。伺服器最新的備份永遠不會被這兩個上限刪除。

### 變更設定

管理員可在「**設定**」頁面的「**備份保留**」卡片中設定全域策略（「**填入預設值**」會將上述預設值重新填入表單，準備儲存）。伺服器可在任一項六個值上有所不同：開啟其「**備份**」標籤頁並展開「**此伺服器的保留策略**」。除非該伺服器設定了某個欄位，否則該欄位將為空白，空白欄位將遵循全域值（顯示在欄位內）。因此，伺服器可以例如保留 3 個排程備份，而其他所有設定則使用全域值；清除欄位會將其恢復為全域值。

![設定中的備份保留卡片](/docs/images/settings-retention.png)

![伺服器備份標籤頁上的此伺服器的保留策略](/docs/images/server-retention.png)

儲存本身不會刪除任何內容。如果新的限制會導致現有備份超出上限，面板會列出每個伺服器將刪除多少種備份、釋放多少空間以及最舊備份的年齡。它還會說明在這次變更之前伺服器是否已經超出其限制（例如，在先前「**從下次備份開始**」之後），因為立即套用會修剪所有超出限制的備份，而不僅僅是這次編輯新增的。然後會詢問如何套用：

- **立即移除**：精確刪除剛列出的備份，不多也不少：期間建立的備份將等待下次修剪。從設定頁面來看，正在進行還原、備份或類似操作的伺服器將被跳過，並在下次備份後進行修剪；在伺服器自己的備份標籤頁上，會要求您在該操作完成後重試。在刪除伺服器舊備份時（通常是幾秒鐘），該伺服器上的其他操作必須等待：在此期間發生的排程備份或啟動將每分鐘重試一次（最多 30 分鐘），崩潰的伺服器將在完成後約 20 秒內重新啟動（最多 30 分鐘），而在此期間發生的排程重啟或停止將被跳過，直到下一個排程時間。
- **從下次備份開始**：暫時保留它們；每個伺服器將在其下次建立備份時修剪其備份，一如既往。

![列出新限制將刪除內容的對話方塊](/docs/images/retention-preview.png)

正在還原的備份在還原期間永遠不會被移除：保留策略會忽略它（並且不會刪除其他備份來為它騰出空間），並且在還原完成前無法手動刪除它。

相同的設定可透過腳本作為管理 API 端點使用：`GET`/`POST /api/backups/retention` 和 `/api/servers/:id/backups/retention`。全域值不能為 `null`。對於伺服器，`null` 值（或 `""`）會移除該特定鍵，使其遵循全域值；`{ "reset": true }` 會移除所有伺服器特定的設定。在這兩個路徑下，`POST …/preview` 會報告變更將刪除什麼內容而不實際刪除（`backups`、`bytes`、`servers` 和每個伺服器的 `byServer` 細節），`POST …/apply` 會立即套用儲存的策略並回覆全域的 `{ deleted, skipped }`（`skipped` 計算忙碌的伺服器）或單一伺服器的 `{ deleted }`。發送預覽的 `{ "token": "..." }`（保留 10 分鐘）或其 `{ "ids": [...] }` 僅刪除這些備份；如果兩者都沒有，則刪除所有超出限制的備份。對忙碌伺服器的單一伺服器套用會回覆 409。

備份可以從備份列表中**重新命名**（每行的重新命名按鈕）。磁碟上的封存檔和面板的記錄會一起移動，因此下載、還原和保留策略都能繼續使用新名稱。

![重新命名備份](/docs/images/backup-rename.png)

> 保留策略會自動限制數量，但大型的模組化封存檔仍會計入伺服器的[磁碟配額](/docs/storage/)，因此請留意大型套件的總容量。

## 還原

還原備份會停止伺服器（在觸碰任何檔案前驗證容器確實已停止），建立一個 `pre-restore` 安全備份，將**整個伺服器目錄**替換為快照，並保持伺服器停止狀態，以便您重新啟動。封存檔會先解壓縮到旁邊，直到完全解壓縮後才會進行交換，因此部分失敗的還原會保持現有檔案不變。由於套件升級總是先進行 `pre-update` 備份，因此您總是能夠回滾失敗的升級。

## 面板本身的資料庫

伺服器備份僅涵蓋伺服器自身的資料夾。面板本身的資料庫（`panel.db`，包含使用者、角色、2FA 密碼、排程、套件釘選和歷史記錄）會在每日維護計時器中單獨快照：

- `VACUUM INTO` 會將一致、無碎片的副本寫入資料夾中的 `backups/_panel/`；最新的 **14** 個副本會被保留。
- 啟動時，面板會執行 `PRAGMA integrity_check`，如果失敗會大聲記錄，並指向 `backups/_panel` 以取得最新的良好副本。

備份整個資料夾（其中也包含 `.secret-key`，即靜態加密金鑰），您就備份了所有內容。
