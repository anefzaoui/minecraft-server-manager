**備份**頁面顯示您所有伺服器的快照，包含大小、原因和時間。

![備份](/docs/images/backups.png)

## 建立備份

從伺服器的「**備份**」標籤頁（或透過[排程](/docs/schedules/)）中，您可以一鍵快照整個伺服器目錄。面板會先將世界靜止 (`save-off` → `save-all`)，壓縮資料，然後重新啟用儲存 (`save-on`)，因此即使在執行中的伺服器上，備份也是一致的。壓縮在背景執行緒中進行，不會延遲面板。每個備份都可以附帶一個備註。

每個壓縮檔在寫入時都會進行**完整性檢查**：面板會重新開啟壓縮檔並讀取其目錄。損壞或無法開啟的壓縮檔會被刪除，備份呼叫會立即失敗，而不是在數月後還原時才發現問題。零項目壓縮檔（從未啟動過的伺服器）是允許的，但會在事件中標記。

勾選「**之後也壓縮世界**」（在備份標籤頁或備份排程中），在壓縮檔安全寫入後移除很少訪問的區塊（請參閱**[壓縮世界](/docs/world-shrink/)**）。壓縮僅在伺服器停止時執行；在執行中的伺服器上，備份仍會進行，而壓縮會被跳過。

![伺服器備份](/docs/images/server-backups.png)

## 備份原因

備份會根據建立原因進行標記：

- **手動** - 您點擊了按鈕。
- **排程** - 由[排程](/docs/schedules/)建立。每個新伺服器也會自動建立一個每日排程備份（在 02:00 至 05:59 之間輪替），因此伺服器從第一天起就有自動保護，而不僅僅是在更新前。
- **更新前** - 在套件升級前自動建立，因此升級總是可逆的。
- **還原前** - 在還原或世界重設前自動建立，作為安全網，以防還原不如您預期。

## 保留策略

保留策略是**針對每個伺服器、每個原因**設定上限：會保留每個群組中最新的備份，較舊的備份會在每次成功備份後自動刪除：

| 原因   | 保留數量 |
| ------ | -------- |
| 排程   | 10       |
| 更新前 | 10       |
| 手動   | 20       |
| 還原前 | 5        |

`還原前`有自己的獨立空間，正是為了確保自動安全備份永遠不會覆蓋您刻意保留的 `手動` 備份。

除了每個原因的數量上限外，還有兩個可選的總體上限，兩者預設均關閉：**最大年齡**（超過 N 天的備份將被刪除，無論其原因為何）和每個伺服器的**最大總大小**（將刪除最舊的備份，直到總大小符合要求，優先刪除 `還原前` 的備份）。伺服器最新的備份永遠不會被這兩個上限刪除。所有這些都可以在「設定」頁面上進行全域更改，並在伺服器的「備份」標籤頁上進行覆蓋。

備份可以從備份列表中**重新命名**（每行的重新命名按鈕）。磁碟上的壓縮檔和面板的記錄會一起移動，因此下載、還原和保留策略會繼續使用新名稱。

![重新命名備份](/docs/images/backup-rename.png)

> 保留策略會自動限制數量，但大型的模組化壓縮檔仍計入伺服器的[磁碟配額](/docs/storage/)，因此請留意大型套件的總大小。

## 還原

還原備份會停止伺服器（在觸碰任何檔案前驗證容器確實已停止），建立一個 `還原前` 的安全備份，將**整個伺服器目錄**替換為快照，然後保持停止狀態讓您重新啟動。由於套件升級總是先進行 `更新前` 備份，因此您總是能夠回滾失敗的升級。

## 面板自身的資料庫

伺服器備份僅涵蓋每個伺服器的世界目錄。面板自身的資料庫（`panel.db`，包含使用者、角色、2FA 密碼、排程、套件釘選和歷史記錄）會在每日維護計時器中單獨快照：

- `VACUUM INTO` 會將一個一致、無碎片的副本寫入 `data/backups/_panel/`；會保留最新的 **14** 個。
- 啟動時，面板會執行 `PRAGMA integrity_check`，如果失敗會發出響亮的日誌，並指向 `data/backups/_panel` 以取得最新的良好副本。

備份整個 `data/` 目錄樹（它也包含 `.secret-key`，即靜態加密金鑰），您就備份了所有內容。
