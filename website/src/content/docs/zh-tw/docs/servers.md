## 建立伺服器

點擊（頂部欄）的「建立伺服器」或「建立伺服器」卡片以開啟精靈。

![建立伺服器](/docs/images/create-wizard.png)

精靈會預先填入「設定」頁面上的「新伺服器預設值」中的記憶體、CPU 和磁碟配額欄位，管理員可以隨時更改這些設定。

![新伺服器預設值](/docs/images/settings-defaults.png)

您可以選擇：

- **名稱**（以及可選的圖示、強調色和標籤，用於組織您的伺服器群組）。
- **伺服器類型** - 原版、Paper、Fabric、Forge、NeoForge 等，每種都會在後端對應到正確的 itzg 映像檔。
- **Minecraft 版本** - `LATEST`、快照或特定版本。
- **資源** - RAM（堆積）、容器記憶體限制、CPU 和磁碟配額。

偏好模組包？「從模組包」標籤頁會改為安裝 CurseForge、Modrinth、FTB 或 GT New Horizons 模組包（請參閱 [模組包](/docs/modpacks/)），或使用您上傳的**自訂 zip 檔案**：CurseForge 模組包匯出檔 (`manifest.json`) 或任何包含模組 jar 檔的 zip 檔。資訊清單（或識別出的 jar 檔中的多數投票）會填入載入器和 Minecraft 版本，所有模組都會在一個任務中安裝。您也可以從已儲存的 [藍圖](/docs/blueprints/) 開始。

面板會自動為您的版本選擇一個合理的 Java 執行階段，拉取映像檔，建立容器，並（可選地）啟動它，所有這些都來自同一個表單。

## 伺服器列表

「伺服器」頁面會列出您的所有伺服器，包含狀態和快速統計資訊。

![伺服器列表](/docs/images/servers-list.png)

## 單一伺服器

![玩家](/docs/images/players.png)

開啟伺服器後，您會進入一個分頁工作區：

- **概覽** - 狀態、即時統計、上線時間以及主要的啟動/停止/重新啟動控制項。
- **主控台** - 即時日誌串流和指令輸入，以及遊戲內聊天（[詳細資訊](/docs/console-and-chat/)）。
- **玩家** - 在線玩家，以及他們的物品欄、統計資料和 [聊天指令](/docs/console-and-chat/)。
- **模組** - 已安裝的模組列表、[模組瀏覽器](/docs/modpacks/) 和內容更新。
- **世界** - [世界、即時地圖和檔案管理器](/docs/worlds-and-files/)。
- **備份** - 此伺服器的 [快照和還原](/docs/backups/)。
- **監控** - 每個伺服器的歷史記錄和即時指標，包括當機報告（見下文）。
- **設定** - 關於伺服器如何運行的所有內容，以及 [整合功能](/docs/integrations/)（Discord、狀態頁面、邀請、聊天機器人）。

![伺服器概覽](/docs/images/server-overview.png)

「世界控制項」導軌會顯示在每個分頁上：遊戲內時鐘、天氣、常見的遊戲規則切換按鈕，以及用於其餘規則的「顯示所有世界規則」。

![世界控制項](/docs/images/world-controls.png)

「監控 → 即時」顯示 TPS 和每毫秒滴答數，一個健康與穩定性卡片顯示過去 24 小時 / 7 天的當機和重新啟動次數，以及每個世界的磁碟空間使用量。

![即時監控](/docs/images/monitoring-live.png)

## 伺服器設定

「設定」標籤頁是完整的設定介面：重新命名、資源、更新政策、自動啟動/自動重新啟動、環境變數和進階 Docker 覆寫。會影響容器運行方式的欄位會清楚標示需要重新啟動。

![伺服器設定](/docs/images/server-settings.png)

**關於記憶體計量器。** 「RAM (Java 堆積)」會作為 Java 的起始和最大堆積大小傳遞，Java 會在第一分鐘內填滿其獲得的堆積，無論是否使用 Aikar / MeowIce 標誌預設值。因此，記憶體計量器會穩定在堆積大小左右並保持在那裡，即使沒有玩家在玩；計量器上的刻度標記了堆積在容器限制下的位置，下方的說明也會如此說明。如果您希望記憶體使用量跟隨實際使用情況，請設定較小的「初始堆積」（進階設定）：在我們的測試中，一個 2 GB 的堆積將閒置使用量從 2.6 GB 降低到約 1.3 GB。Java 在堆積之外還需要記憶體（原版約 0.5 GB，大型模組包約 1.5 至 2 GB），這就是容器限制預留空間的用途。請參閱 README 中的「兩個記憶體限制」以了解詳細數字。

> 進階 Docker 覆寫欄位（自訂容器名稱、額外連接埠和綁定掛載，以及原始覆寫）僅限**管理員**使用，因為綁定掛載加上面板的 Docker 存取權相當於主機的 root 權限。請參閱 [使用者與角色](/docs/users-and-roles/)。

## 當機報告與 mclo.gs 分析

當機報告（`crash-reports/*.txt` 和 JVM `hs_err_pid*.log` 檔案）會被自動拾取，解析成單行摘要，包含例外情況和疑似的模組，並列在「監控 → 歷史記錄」下：

![當機報告卡片](/docs/images/crash-mclogs-card.png)

每個報告卡片都提供內建檢視器（包含可摺疊區段和高亮顯示的例外情況）、複製堆疊追蹤、下載，以及兩個 [mclo.gs](https://mclo.gs) 操作：

- **分享到 mclo.gs** 會將報告發佈為公開貼文並複製連結 - 這正是模組作者和支援 Discord 所要求的。連結會被記住，因此不會重複上傳任何內容。
- **分析** 會在貼文中運行 mclo.gs 的自動化洞察：已知的問題和建議的修復（遺失的依賴項、版本不符、常見的模組衝突），直接顯示在面板中。

![mclo.gs 洞察](/docs/images/crash-insights.png)

這兩個操作都位於明確的確認提示之後，因為貼文是公開的：當機報告可能包含玩家名稱和您的完整模組列表。面板永遠不會自行上傳任何內容。
