大多數伺服器都有備份。但很少有備份是真正可用的，而這種差異往往只會在最糟糕的時候才被發現。它們之間有三個關鍵點：備份必須是**一致的**，它必須**儲存在別處**，而且**有人至少測試過還原**。

## 複製未寫入中的世界

正在運行的伺服器會持續寫入區域檔案。如果在寫入過程中複製它們，你將得到一個一半舊一半新的檔案，這將導致無法載入，或者載入後出現一個大洞，裡面曾經是你玩家的基地。沒有任何警告，因為複製操作本身是成功的。

有兩種正確的複製方法：

1.  **停止伺服器**，複製，然後重新啟動。簡單、直接，但因為停機時間而不受歡迎。
2.  **先讓遊戲停止寫入**。執行 `save-off`，然後 `save-all flush`，等待其完成，複製，然後執行 `save-on`。在複製期間，世界是完整且靜默的。

切勿跳過前面的步驟直接複製。如果檔案系統或磁碟區層級的快照是真正原子性的，那麼它是可以的，但在玩家放置方塊時執行 `cp -r` 則不行。

## 備份的不只是世界

僅還原世界只會找回地形，卻會失去伺服器。你還需要：

- `server.properties`，以及任何其他設定規則的檔案。
- 模組或插件的 jar 檔案，必須是當時運行的確切版本。沒有創建了其方塊的模組，世界將無法載入。
- 玩家資料，包括 `whitelist.json`、`ops.json` 以及統計資料和進度資料夾。
- 如果來自整合包，則需要整合包的版本。記錄下來即可。

對任何備份進行最快速的健全性檢查：你能僅憑備份檔案在全新的機器上重建這個伺服器嗎？如果答案需要以「然後我會重新安裝」開頭的句子，那它就不是一個完整的備份。

## 儲存在同一顆硬碟上的備份不算備份

保護它所在的機器上的備份，只能應對一種故障：你刪除了某些東西。它無法應對硬碟損壞、服務供應商暫停帳戶，或刪除整個目錄的錯誤操作。

保持簡單而非追求完美：

- 一個本地備份，用於常見情況，例如有人惡意破壞或糟糕的更新。
- 一個儲存在別處的備份。另一台機器、物件儲存，或透過 SSH 每晚拉取的家用 NAS。
- 足夠的歷史記錄，以應對你沒有立即注意到的問題。損壞通常在幾天後才被發現，如果你只保留三天的備份，你可能已經覆蓋了好的備份。

七個每日備份加上四個每週備份，幾乎可以應對所有實際的事件，而且佔用的空間非常少。

## 在需要之前測試還原

選擇一個備份，將其還原到一個備用伺服器，然後加入。這就是整個測試，只需十五分鐘，就能捕捉到所有常見的失敗情況：備份檔案遺漏了模組資料夾、世界需要一個你不再運行的版本、權限導致檔案無法讀取、上傳損壞。

在設定備份時進行一次，在伺服器有任何重大變更後再進行一次。

## 大小，以及如何保持合理

世界會因為玩家探索而擴大。一個玩家直線飛行了十萬格的世界，會永遠攜帶沿途的所有區塊，而其中大部分區塊可能再也不會被訪問。

有三個方法，按效果大小排序：

1.  **修剪未訪問的區塊**。通常會根據最後修改時間來修剪的工具，可以在一個經常被遊覽的世界中移除大部分區塊，而不會對遊戲產生可見的影響。
2.  **正確壓縮**。區域檔案本身壓縮效果很好；對它們的歸檔進行額外的壓縮收益不大。
3.  **不要保留一年的每小時備份**。保留比壓縮更重要。

## 在 Minecraft Server Manager 中

備份採用 `save-off`、flush、複製、`save-on` 的流程，如果在備份過程中請求停止或重啟，將會被拒絕，直到複製完成為止，而不是與之競爭。歸檔涵蓋了整個伺服器目錄，因此模組、設定和玩家資料會與世界一起移動。

備份可以與重啟和命令一起按計劃運行，並且每個新伺服器都會預設每日備份計劃。保留計數會分開計算，因此自動累積的十個計劃備份不會覆蓋你在進行風險變更前手動執行的備份，並且還會應用年齡和大小上限。管理員可以在「設定」頁面或伺服器各自的「備份」標籤頁中更改所有這些設定。還原會先取得最新的備份，因此還原到錯誤的時間點本身是可以撤銷的。世界可以單獨縮小，或作為備份的一部分進行縮小，這是對大小影響最大的關鍵。

整個面板，包括每一個備份，都位於一個目錄下。將該目錄複製到別處是離機備份的一半，而且這也是你唯一需要複製的東西。
