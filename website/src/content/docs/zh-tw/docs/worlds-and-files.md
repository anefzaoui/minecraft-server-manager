## 世界

**世界**頁面是世界庫：所有已儲存的世界集中於一處。**上傳世界**會接受 `.zip` 或 `.tar` 封存檔，並自動尋找其中的世界；**儲存至庫**則能快照伺服器正在執行的世界（即使伺服器正在運行也能正常工作）；而庫中的每個世界都可以透過**安裝至…**下載或安裝到任何伺服器。安裝時，可以選擇替換伺服器現有的世界（伺服器必須停止，且現有世界會先被備份），或將其與現有世界並存，以便稍後啟用。每次安裝前都會進行相容性檢查。

伺服器自身的**世界 → 世界**標籤頁會列出該伺服器上的世界。從那裡您可以啟用另一個世界（伺服器需停止）、下載、複製、重新命名或[壓縮](/docs/world-shrink/)世界、將其複製到另一個伺服器、刪除非活動世界，以及使用新的、保留的或自訂的種子重置活動世界（會先提供安全備份）。下方同樣是世界庫，並有**安裝至此**按鈕。

![Worlds](/docs/images/worlds.png)

## 檔案管理器

在伺服器的**世界**區塊下，**檔案**標籤頁是一個完整的瀏覽器內檔案管理器，用於管理該伺服器資料目錄下的檔案。您可以列出、讀取、編輯、重新命名、移動、複製、刪除和上傳檔案，建立資料夾，並在資料夾下的檔案中搜尋文字，使用**在檔案中尋找**功能：所有您平常透過 SSH 操作的功能，現在都能在瀏覽器中完成。

![File manager](/docs/images/server-files.png)

文字檔案會在編輯器中開啟，有 8 MB 的限制；較大的檔案可以下載。上傳功能一次最多可接受 20 個檔案。

### 保持在沙盒內

所有檔案操作都限制在伺服器自身的資料目錄內。面板會解析每個路徑並拒絕任何試圖逃離目錄的操作：例如 `..` 遞迴遍歷、絕對路徑，甚至是連結到目錄外的符號連結（包括尚未存在的懸空連結）。模組或外掛程式無法透過連結來誘騙檔案管理器讀取或寫入主機上的其他位置。

## 模組

對於安裝了模組和外掛程式的伺服器，**模組**標籤頁（位於伺服器側邊欄的獨立群組）用於管理模組集：瀏覽和新增模組，以及查看已安裝的模組。對於已安裝的每個模組，您可以更新它（或忽略該更新）、[復原](/docs/updates/#undoing-a-mod-update)它、停用它或移除它；**全部更新**則能一次性套用所有可用更新並重新啟動伺服器。模組和模組包的更新也會出現在[更新](/docs/updates/)頁面上。

### 新增模組

![Mods](/docs/images/mods.png)

有四種方式可以新增模組，全部從模組標籤頁的工具列進行：

- **搜尋模組**：搜尋**Modrinth 或 CurseForge**（當在**設定 → API 金鑰**中儲存了 API 金鑰後，會出現 CurseForge 選項），對於外掛程式伺服器，還可以搜尋**Hangar**（PaperMC 自有的外掛程式註冊中心）和**SpigotMC**（透過 Spiget 的 CDN 代理），這兩者都無需金鑰。**資料包**標籤頁會搜尋 Modrinth 上的資料包。所有搜尋結果都會根據伺服器的載入器和 Minecraft 版本進行篩選（一個核取方塊也會顯示未列為相容的建置版本，但風險自負）；Quilt 伺服器也會自動顯示標記為 fabric 的建置版本，因為 Quilt 可以運行 Fabric 模組。結果中已安裝在伺服器上的模組會顯示**已安裝**標籤。如果 CurseForge 作者不允許自動下載（或 SpigotMC 資源託管在站外），面板會提前告知並提供**開啟 CurseForge**（或**開啟 SpigotMC**）+ **上傳 Jar** 的路徑，而不是在安裝過程中失敗。

  ![Hangar search](/docs/images/mods-search-hangar.png)

- **匯入 Zip**：一個按鈕，三種格式，自動偵測：
  - **Modrinth 模組包 (`.mrpack`)**：所有釘選的檔案都會透過雜湊查找，重新對應回其 Modrinth 專案（因此匯入的模組會保留真實名稱、圖示，並保持可更新狀態；Modrinth 未知的檔案會從模組包自身的 URL 安裝），下載時會根據模組包的 sha512 校驗和進行驗證，並顯示適合度評估。僅限客戶端的檔案會被明顯跳過，並且可以套用覆蓋樹（`overrides/`，然後是 `server-overrides/`；伺服器特定的副本優先）。

    ![mrpack import](/docs/images/mrpack-import.png)

  - **CurseForge 模組包匯出檔**（CurseForge 應用程式產生的 zip 檔，包含 `manifest.json`）：所有釘選的模組都會被批量解析，並顯示警告（載入器/MC 版本與此伺服器不符、檔案已不在 CurseForge 上、需要手動下載的模組），然後以實際進度進行安裝。模組包的 `overrides/`（設定檔、腳本）也可以選擇性套用；任何會被覆蓋的檔案都會先備份到伺服器資料夾內的 `.import-backups/<timestamp>/`。
  - **您自行收集的 jar 檔案的純 zip**：每個 jar 檔案都會被識別（Modrinth 雜湊比對 → CurseForge 指紋 → jar 檔案自身的元數據），並與伺服器進行比對（符合 / 載入器錯誤 / MC 版本錯誤 / 已安裝 / 無法識別），因此您可以在任何檔案安裝前選擇真正需要的。
- **透過 URL 新增**：貼上幾乎任何內容：Modrinth、CurseForge、Hangar 或 SpigotMC 的專案頁面、GitHub 儲存庫或發行版 URL（僅輸入 `owner/repo` 也可以；GitHub 安裝會優先選擇最新的穩定版本，並跳過 `-sources`/`-javadoc` 的輔助 jar）、一個純粹的 Modrinth slug，或任何直接的 `.jar` URL。面板會解析適合伺服器載入器和 MC 版本的正確建置版本。

  ![Add by link](/docs/images/mods-add-by-link.png)

- **上傳 Jar**（來自搜尋備用方案或待下載解析器）：上傳的 jar 檔案會以相同方式識別，因此它們會保留真實名稱、版本、圖示，並變得可更新。

所有註冊中心的安裝都會在下載時進行**校驗和驗證**：串流會與註冊中心發布的最強雜湊演算法（sha512 → sha256 → sha1 → md5）進行比對，如果雜湊不符，則會在任何檔案落地伺服器前中止。

整個 zip 檔案（包括 `.mrpack`）也可以用來**建立伺服器**：在設定精靈的**從模組包建立**標籤頁中，上傳 zip 檔案，模組包的資訊檔（或根據識別出的 jar 檔案進行多數投票）將會填入載入器、Minecraft 版本和載入器版本。
