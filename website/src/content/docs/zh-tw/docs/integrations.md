每個伺服器在其 **設定** 群組下都包含其整合功能：**Discord**、公開的 **狀態頁面**、一鍵 **邀請**，以及可選的 **聊天機器人** 標籤頁（僅限管理員）。本頁面介紹 Discord；[邀請與狀態頁面](/docs/invites-and-status-page/) 涵蓋了這兩者，而[聊天機器人](/docs/chatbot/) 則有其專屬頁面。

## Discord 通知

面板透過 webhook 將伺服器事件轉發到 Discord 頻道。無需機器人，無需 OAuth。

### 設定

1. 在 Discord 中：**伺服器設定 → 整合 → Webhooks → 新增 Webhook**。選擇頻道並複製 webhook URL。
2. 在面板中，開啟伺服器的 **設定 → Discord** 標籤頁，將 URL 貼到 **Webhook URL** 欄位，開啟該卡片，然後點擊 **儲存**。URL 會被加密儲存（與您的 API 金鑰儲存在相同的位置）。
3. 使用 **傳送測試** 來確認設定是否正常運作。

![Discord 整合](/docs/images/integrations-discord.png)

若要替換已儲存的 URL，請貼上新的 URL 並儲存；若要保留目前的 URL，請將欄位留空。儲存的 URL 會以遮罩形式顯示（權杖會被隱藏）。

### 發送內容

通知會被分組到可切換的類別中。預設情況下，所有類別都已啟用。

| 類別          | 事件                                   |
| ------------- | -------------------------------------- |
| **啟動/停止** | 伺服器已啟動，伺服器已停止             |
| **崩潰**      | 發生崩潰，偵測到崩潰循環，新的崩潰報告 |
| **備份**      | 已建立備份，已還原備份                 |
| **更新**      | 已套用更新，已回滾更新，更新失敗       |
| **踢出/封鎖** | 玩家被踢出，玩家被封鎖                 |
| **警報**      | 那些悄悄讓伺服器損壞的事件（見下文）   |

### 警報類別

`警報` 是「需要人工介入」的頻道，用於處理過去只能在面板中看到的狀況：

| 事件                    | 意義                                                                     |
| ----------------------- | ------------------------------------------------------------------------ |
| `oom`                   | 容器因記憶體不足而停止。                                                 |
| `unhealthy`             | 程序仍在運行，但 `mc-health` 探針失敗：伺服器處於運行但無效的狀態。      |
| `startup-stalled`       | 啟動約 10 分鐘後仍未在日誌中出現「完成」訊息（並附有診斷說明，若已知）。 |
| `stop-failed`           | 正常停止未能生效，容器仍在運行。                                         |
| `schedule-failed`       | 排定的重新啟動/備份/命令失敗。                                           |
| `quota-exceeded`        | 嚴格模式磁碟配額被觸發，伺服器已停止。                                   |
| `offline-after-restart` | 在面板重新啟動前伺服器是啟動的，但現在沒有，且不會自動啟動。             |
| `port-change-failed`    | 連接埠變更失敗，且伺服器無法恢復到舊的連接埠，因此已關閉。               |
| `auto-restart-gave-up`  | 由於另一項操作佔用了過長時間，崩潰的伺服器未能重新啟動。                 |

### 傳送機制

背景橋接器每 15 秒輪詢一次[事件日誌](/docs/activity/)，並轉發對應的記錄。如果 webhook 的 POST 請求暫時失敗，該記錄將在後續輪詢中重試，而不是丟失；在幾次失敗嘗試後，該記錄將被跳過，並且每個伺服器每小時最多記錄一次傳送失敗。面板重新啟動後，橋接器會傳送尚未傳送的事件，但最多只回溯兩小時；在其首次運行時，它會從最新的事件開始。
