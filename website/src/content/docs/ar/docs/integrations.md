يحمل كل خادم تكاملاته تحت مجموعة **الإعدادات**: **Discord**، و**صفحة الحالة** العامة، و**الدعوات** بنقرة واحدة، وعلامة التبويب الاختيارية **Chatbot** (للمسؤولين فقط). تغطي هذه الصفحة Discord؛ [الدعوات وصفحة الحالة](/docs/invites-and-status-page/) تغطي هذين العنصرين، و[الـ Chatbot](/docs/chatbot/) له صفحته الخاصة.

## إشعارات Discord

يقوم اللوحة بإعادة توجيه أحداث الخادم إلى قناة Discord عبر خطاف ويب (webhook). لا يوجد بوت، ولا OAuth.

### الإعداد

1. في Discord: **إعدادات الخادم ← التكاملات ← خطافات الويب ← خطاف ويب جديد**. اختر القناة وانسخ عنوان URL لخطاف الويب.
2. في اللوحة، افتح علامة التبويب **Discord** في **إعدادات** الخادم، الصق عنوان URL في **عنوان URL لخطاف الويب**، قم بتشغيل البطاقة **تشغيل**، ثم **حفظ**. يتم تخزين عنوان URL بشكل مشفر (في نفس مخزن الراحة الذي تُخزن فيه مفاتيح API الخاصة بك).
3. استخدم **إرسال اختبار** للتأكد من أنه يعمل.

![تكامل Discord](/docs/images/integrations-discord.png)

لاستبدال عنوان URL مخزن، الصق عنوان URL جديدًا واحفظ؛ اترك الحقل فارغًا للاحتفاظ بالعنوان الحالي. يتم عرض عنوان URL المخزن بشكل مقنع (يتم إخفاء الرمز المميز).

### ما الذي يتم إرساله

يتم تجميع الإشعارات في فئات قابلة للتبديل. كلها قيد التشغيل افتراضيًا.

| الفئة               | الأحداث                                              |
| ------------------- | ---------------------------------------------------- |
| **بدء / إيقاف**     | بدأ الخادم، توقف الخادم                              |
| **الأعطال**         | عطل، تم اكتشاف حلقة عطل، تقرير عطل جديد              |
| **النسخ الاحتياطي** | تم إنشاء نسخة احتياطية، تم استعادة نسخة احتياطية     |
| **التحديثات**       | تم تطبيق التحديث، تم التراجع عن التحديث، فشل التحديث |
| **الطرد / الحظر**   | تم طرد لاعب، تم حظر لاعب                             |
| **تنبيهات**         | الأشياء التي تترك الخادم معطلاً بصمت (انظر أدناه)    |

### فئة التنبيهات

`التنبيهات` هي قناة "شيء ما يحتاج إلى تدخل بشري"، للحالات التي كانت مرئية فقط في اللوحة سابقًا:

| الحدث                   | المعنى                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| `oom`                   | تم إيقاف الحاوية بسبب نفاد الذاكرة.                                                                     |
| `unhealthy`             | العملية قيد التشغيل ولكن فحص `mc-health` يفشل: خادم مباشر ولكنه معطل.                                   |
| `startup-stalled`       | لا يزال قيد البدء بعد حوالي 10 دقائق بدون "تم" في السجلات (مع تشخيص لما يجب إصلاحه، حيثما كان معروفًا). |
| `stop-failed`           | لم يتم تطبيق إيقاف سلس وظلت الحاوية قيد التشغيل.                                                        |
| `schedule-failed`       | فشل إعادة تشغيل / نسخة احتياطية / أمر مجدول.                                                            |
| `quota-exceeded`        | تم تجاوز حصة القرص في الوضع الصارم وتم إيقاف الخادم.                                                    |
| `offline-after-restart` | كان الخادم قيد التشغيل قبل إعادة تشغيل اللوحة، ولكنه ليس كذلك الآن، ولن تتم إعادة تشغيله تلقائيًا.      |
| `port-change-failed`    | فشل تغيير المنفذ ولم يتمكن الخادم من العودة إلى منفذه القديم، لذا فهو معطل.                             |
| `auto-restart-gave-up`  | لم تتم إعادة تشغيل خادم معطل لأن إجراءً آخر أبقاه مشغولاً لفترة طويلة جدًا.                             |

### كيفية عمل التسليم

يقوم جسر خلفي بالاستطلاع الدوري لسجل النشاط [log النشاط](/docs/activity/) كل 15 ثانية ويعيد توجيه الصفوف المعينة. إذا فشل نشر خطاف الويب بشكل عابر، تتم إعادة محاولة هذا الصف في عمليات الاستطلاع اللاحقة بدلاً من إسقاطه؛ بعد عدة محاولات فاشلة، يتم تخطي الصف، ويتم تسجيل فشل التسليم مرة واحدة على الأكثر في الساعة لكل خادم. بعد إعادة تشغيل اللوحة، يرسل الجسر الأحداث التي لم يتم تسليمها بعد، ولكن لا يزيد عن ساعتين إلى الوراء؛ عند تشغيله الأول يبدأ من أحدث حدث.
