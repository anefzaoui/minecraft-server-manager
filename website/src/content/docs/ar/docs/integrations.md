يحمل كل خادم تكاملاته تحت مجموعة **الإعدادات**: **Discord**، و**صفحة الحالة** العامة، و**الدعوات** بنقرة واحدة، وعلامة التبويب الاختيارية **Chatbot**. تغطي هذه الصفحة Discord (الآخرون لديهم مستنداتهم ومساعدي الإعداد الخاصة بهم في اللوحة).

## إشعارات Discord

تقوم اللوحة بإعادة توجيه أحداث الخادم إلى قناة Discord عبر خطاف ويب (webhook). لا يوجد روبوت، ولا OAuth.

### الإعداد

1. في Discord: **إعدادات الخادم ← التكاملات ← خطافات الويب ← خطاف ويب جديد**. اختر القناة وانسخ عنوان URL لخطاف الويب.
2. في اللوحة، افتح علامة التبويب **الإعدادات ← Discord** للخادم، الصق عنوان URL في **عنوان URL لخطاف الويب**، قم بتشغيل البطاقة **تشغيل**، ثم **حفظ**. يتم تخزين عنوان URL بشكل مشفر (في نفس مخزن "at-rest" الخاص بمفاتيح API الخاصة بك).
3. استخدم **إرسال اختبار** للتأكد من أنه يعمل.

![تكامل Discord](/docs/images/integrations-discord.png)

لاستبدال عنوان URL مخزن، الصق عنوانًا جديدًا واحفظ؛ اترك الحقل فارغًا للاحتفاظ بالعنوان الحالي. يتم عرض عنوان URL المخزن بشكل مقنع (يتم إخفاء الرمز المميز).

### ما الذي يتم إرساله

يتم تجميع الإشعارات في فئات قابلة للتبديل. كلها قيد التشغيل افتراضيًا.

| الفئة               | الأحداث                                              |
| ------------------- | ---------------------------------------------------- |
| **بدء / إيقاف**     | بدأ الخادم، توقف الخادم                              |
| **الأعطال**         | عطل، تم اكتشاف حلقة أعطال، تقرير عطل جديد            |
| **النسخ الاحتياطي** | تم إنشاء نسخة احتياطية، تم استعادة نسخة احتياطية     |
| **التحديثات**       | تم تطبيق التحديث، تم التراجع عن التحديث، فشل التحديث |
| **الطرد / الحظر**   | تم طرد لاعب، تم حظر لاعب                             |
| **التنبيهات**       | الأشياء التي تترك الخادم معطلاً بهدوء (انظر أدناه)   |

### فئة التنبيهات

`التنبيهات` هي قناة "شيء ما يحتاج إلى تدخل بشري"، للحالات التي كانت مرئية فقط في اللوحة سابقًا:

| الحدث                   | المعنى                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| `oom`                   | تم إيقاف الحاوية بسبب نفاد الذاكرة.                                                                          |
| `unhealthy`             | العملية قيد التشغيل ولكن فحص `mc-health` يفشل: خادم مباشر ولكنه معطل.                                        |
| `startup-stalled`       | لا يزال قيد البدء بعد حوالي 10 دقائق دون ظهور "تم" في السجلات (مع تشخيص لما يجب إصلاحه، حيثما يكون معروفًا). |
| `stop-failed`           | لم يتم تطبيق إيقاف سلس ولا تزال الحاوية قيد التشغيل.                                                         |
| `schedule-failed`       | فشل إعادة تشغيل / نسخة احتياطية / أمر مجدول.                                                                 |
| `quota-exceeded`        | تم تجاوز حصة القرص في الوضع الصارم وتم إيقاف الخادم.                                                         |
| `offline-after-restart` | كان الخادم قيد التشغيل قبل إعادة تشغيل اللوحة، ولكنه ليس كذلك الآن، ولن يتم تشغيله تلقائيًا.                 |
| `crash-report`          | تم التقاط وتحليل تقرير عطل جديد.                                                                             |
| `update-failed`         | لم يأت ترقية محمية بصحة جيدة.                                                                                |

### كيف يعمل التسليم

يقوم جسر خلفي بفحص [سجل النشاط](/docs/activity/) كل 15 ثانية ويعيد توجيه الصفوف المعينة. إذا فشل طلب POST لخطاف الويب بشكل عابر، تتم إعادة محاولة هذا الصف في عمليات المسح اللاحقة بدلاً من إسقاطه؛ يتم كتم صوت خطاف ويب غير قابل للوصول بشكل دائم (سطر سجل واحد في الساعة) بعد عدة محاولات. لا يعيد الجسر تشغيل الأحداث من قبل بدء تشغيل اللوحة.
