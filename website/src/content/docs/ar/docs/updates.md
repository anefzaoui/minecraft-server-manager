تقوم صفحة **التحديثات** بتتبع ما هو قديم عبر أسطولك في مكان واحد:

- إصدارات **Modpack** ([modpacks](/docs/modpacks/)) مقابل Modrinth / CurseForge / فهرس إصدارات GTNH.
- **المحتوى المخصص** الذي أضفته بنفسك - تعديلات، حزم بيانات، حزم موارد، إضافات - كل منها مقابل مصدره: Modrinth، CurseForge، Hangar، SpigotMC (Spiget)، أو GitHub Releases. تستخدم عمليات البحث في GitHub إعادة التحقق من ETag، لذا فإن عمليات التحقق اليومية بالكاد تلمس حد المعدل الخاص بها.
- تقادم **صورة Docker**: معرف الصورة لكل حاوية قيد التشغيل مقابل علامة تم سحبها حديثًا (تم إلغاء تكرارها عبر الخوادم التي تستخدم نفس العلامة)، يتم تقديمها كترقية قابلة لإعادة الإنشاء فقط.
- **تثبيتات الإصدارات المستقلة**: لخادم بدون حزمة مُدارة، تثبيت صريح لـ `mc_version` مقابل بيان Mojang، ومتغير بيئة تثبيت مُحمل صريح (`PAPER_BUILD`، `FORGE_VERSION`، وما شابه) مقابل سجل المُحمل. تأتي إصدارات Paper من واجهة برمجة تطبيقات **Fill v3 API** الحالية لـ PaperMC (نقطة النهاية القديمة v2 توقفت عن تلقي إصدارات Minecraft الجديدة).

## كيف يعمل

يقوم اللوحة بفحص الإصدارات المثبتة لكل خادم مقابل المصدر الأصلي ويسرد أي شيء يحتوي على إصدار أحدث. يظهر أيضًا عدد مطابق في بلاطة "التحديثات المتاحة" في [لوحة التحكم](/docs/dashboard/).

تجري عمليات التحقق عند الطلب ويمكن جدولتها ([Schedules](/docs/schedules/)). سياسة التحديث هي لكل خادم: أنت تقرر ما إذا كانت اللوحة تخبرك فقط، أو تترك كل شيء يدويًا.

## تطبيق تحديث

التحديثات ليست صامتة أبدًا. عندما تختار ترقية حزمة، تقوم اللوحة بما يلي:

1. تأخذ **نسخة احتياطية قبل التحديث** (بحيث يمكن التراجع عنها؛ يتم الاحتفاظ بآخر 10 نسخ احتياطية قبل التحديث لكل خادم).
2. تعيد تثبيت الإصدار الجديد الدقيق.
3. تعيد إنشاء الحاوية، مع إعادة حل وقت تشغيل Java إذا لزم الأمر.
4. تراقب التشغيل الأول، مع ميزانية وقت لكل منصة.

إذا لم يتم تشغيله بشكل صحيح، فإنك تتراجع إلى النسخة الاحتياطية قبل التحديث. لا يتم أبدًا تقديم خادم يتتبع الإصدارات المستقرة إلى إصدار تجريبي، ويرتبط رابط سجل التغييرات بالفرق الحقيقي لكل إصدار حيث يوفره المصدر. يؤدي فشل التحديث أيضًا إلى تشغيل تنبيه Discord [alert](/docs/integrations/) إذا تم تكوين التكامل.
