Minecraft Server Manager הוא יישום Node.js יחיד-תהליך, המרונדר בצד השרת. הוא מנהל
שרתי Minecraft שרצים כקונטיינרים של Docker באמצעות ה-
[itzg/docker-minecraft-server](https://github.com/itzg/docker-minecraft-server) image, ומתקשר עם
Docker daemon דרך ה-API שלו (לעולם לא על ידי הרצת פקודות `docker` חיצוניות).

## מבנה זמן ריצה

- **Express + Handlebars** מרנדרים דפים בצד השרת. אין SPA; ה-JS בדפדפן ב-`public/js/`
  הוא שיפור הדרגתי שנכתב ידנית. שלב esbuild (`pnpm run build:js`) מאגד ומכווץ אותו לתוך `public/dist/js/`; האפליקציה מגישה את החבילה הזו כשהיא קיימת ואת המקור הגולמי אחרת, כך שגם הרצה בפיתוח ללא בנייה עובדת.
- **`node:sqlite`** (מובנה ב-Node; הפאנל דורש Node ≥ 24) הוא מסד הנתונים - סינכרוני,
  ללא מודולים מקוריים, במצב WAL. מריץ מיגרציות גרסאות קטן (`src/db/migrations/*`) מופעל
  בעת האתחול. הצהרות מוכנות נשמרות במטמון ב-`src/db/index.js` עם מפתח המבוסס על טקסט ה-SQL.
- **`ws`** נושא את זרמי הקונסול והסטטיסטיקות החיים. שניהם **מתווכים**: אחד upstream
  `docker logs --follow` (או `docker stats`) לשרת, מפורק פעם אחת ומופץ לכל
  טאב מחובר, במקום אחד upstream לכל צופה. מתווך הקונסול שומר מאגר השהייה קטן לטאבים מצטרפים מאוחר ומסיר מנוי שחיבור ה-socket שלו נופל רחוק מדי במקום
  להאט את הזרם המשותף.
- **dockerode** היא הדרך היחידה שבה האפליקציה מתקשרת עם Docker. נקודת הקצה מזוהה אוטומטית לפי פלטפורמה
  (pipe בשם ב-Windows לעומת socket ב-Unix).
- **כל המצב המתמשך חי תחת ספרייה אחת** (`$DATA_DIR`, ברירת מחדל `./data`). העתקת ספרייה זו מעבירה את כל הפאנל.

## שכבות

תלויות זורמות בכיוון אחד:

```
                 ┌─────────────────────────────┐
   HTTP  ───────▶│  web/routes/*  (+ middleware)│   מנתח ומאמת קלט, מעצב תגובות
                 └──────────────┬──────────────┘
                                │
                 ┌──────────────▼──────────────┐
                 │         services/*          │   לוגיקת תחום (הפונקציונליות בפועל)
                 └───┬─────────┬─────────┬─────┘
                     │         │         │
        ┌────────────▼──┐ ┌────▼────┐ ┌──▼──────────┐
        │   docker/*    │ │  db/*   │ │  storage/*  │   תשתית
        └───────────────┘ └─────────┘ └─────────────┘
```

- **`web/routes/`** - ראוטר אחד לכל תחום (`servers`, `players`, `worlds`, `crashes`, `blueprints`,
  `files`, …), נטען ב-`web/app.js`. ראוטרים מאמתים עם zod, קוראים לשירות, ומחזירים JSON
  או מרנדרים תצוגה. לוגיקת עסקים לא שייכת לכאן. שני ראוטרים נטענים ב**אזור הציבורי**, לפני `requireAuth`: `routes/status.js` (דפי סטטוס HTML לשרת, אופציונלי) ו-`routes/apiV1.js` (`/api/v1`, API JSON לקריאה בלבד המאומת באמצעות טוקן Bearer שהונפק על ידי מנהל מ-`services/apiTokens.js`, כבוי אלא אם מופעל בהגדרות; ראה `docs/public-api.md`).
- **`services/`** - לב האפליקציה. כל שירות אחראי על תחום אחד ועשוי להיות תלוי ב-
  תשתית ובשירותים אחרים.
- **`docker/`** - עטיפות dockerode: `connect` (זיהוי נקודת קצה + בריאות daemon), `containers`
  (יצירה/הפעלה/עצירה/יצירה מחדש עם bind mounts, מגבלות זיכרון/CPU, ותוויות), `logs`, `stats`,
  `images`, ו-`watcher` שהופך אירועי Docker להיסטוריה + זיהוי קריסות.
- **`db/`** - עטיפת SQLite ומריץ המיגרציות.
- **`storage/`** - אתחול `./data`, **שומר הנתיבים** (`safeJoin`, עמוד השדרה של בטיחות קבצים),
  ומדד הגודל ברקע + אכיפת מכסות.

חוצי שכבות:

- **`config/`** - תצורת סביבה בתוספת **קטלוג השדות**: מקור האמת היחיד להגדרות
  שרת. כל משתנה סביבה של itzg מקוטלג (תווית, עזרה, סוג, יחידה, ברירת מחדל,
  אימות, סעיף, דגלי סכנה). האשף, טפסי ההגדרות, ואימות zod כולם נגזרים ממנו, כך שחשיפת הגדרה חדשה היא שינוי נתונים, לא אינסטלציה חדשה של UI.
- **`events/`** - `recordEvent()` היא נקודת הכניסה היחידה ליומן ההיסטוריה; אירועי מחזור חיים גם
  לוכדים קטעי יומן קונטיינר ל-`data/logs/<id>/events/`.
- **`ws/`** - WebSockets מאומתים לקונסול + סטטיסטיקות (אימות עוגיית סשן בעת שדרוג, בדיקת `Origin` לחסימת חטיפת אתרים בין אתרים), מתווכים לשרת (ראה "מבנה זמן ריצה").
- **`logger.js` + `instrument.js`** - `require('./logger')(label)` מחזיר לוגר
  [Pino](https://getpino.io) לכל מודול; רמה מ-`LOG_LEVEL`, `makeFailureThrottle()` שומר לולאת רקע שנכשלת באופן קבוע בשורה אחת של לוג בתוספת שורה "התאושש".
  `src/utils/logSanitize.js` מסיר מפתחות בצורת פרטי התחברות וטוקני webhook מהמטא-נתונים המובנים; `src/config/logLevel.js` הוא רשימת ההיתרים המשותפת לרמה (נשמר בנפרד כדי למנוע מחזור require עם `config`). `src/instrument.js` הוא תפר Sentry רדום, נטען ראשון ב-`src/server.js`. `src/web/middleware/requestLog.js` כותב שורת access-log אחת לכל בקשה
  (מדלג על `/healthz` ונכסים סטטיים). ESLint אוכף `no-console` תחת `src/**`, עם
  `preflight.js`, `instrument.js`, ו-`config/index.js` פטורים (הם רצים לפני שהלוגר קיים).
- **הגבלת קצב** - `src/web/middleware/rateLimit.js` מציב `express-rate-limit` לפני `/api`
  (`RATE_LIMIT_API_PER_MIN`, ברירת מחדל 1200) ופוסטים של כניסה / 2FA / הגדרה
  (`RATE_LIMIT_AUTH_PER_15MIN`, ברירת מחדל 100); `0` משבית מגביל. הוא מקודד לפי `req.ip`, כך ש-`TRUST_PROXY` חשוב מאחורי פרוקסי. ל-`/api/v1` יש מגביל משלו לכל טוקן
  (`RATE_LIMIT_PUBLIC_API_PER_MIN`, ברירת מחדל 120), מקודד לפי hash של טוקן ה-Bearer עם גיבוי IP. מונה רך נפרד לכל חשבון ב-
  `src/web/middleware/auth.js` מטפל בנעילת כניסה (לפי IP ולכלל החשבון, דועך).

## התנהגויות תחום מפתח

- **Modpacks תמיד מקובעים.** ה-image משדרג אוטומטית pack לא מקובעים בכל הפעלה מחדש, כך שהפאנל פותר "latest" למזהה גרסה קונקרטי בזמן ההתקנה ומקבע אותו. שדרוגים הם זרימה מתוזמרת מפורשת (`updates/`): תצוגה מקדימה → גיבוי לפני עדכון → עצירה חלקה → re-pin →
  יצירה מחדש → ניטור בריאות → גלגול לאחור בלחיצה אחת.
- **שכבת ה-mod המותאמת אישית** מנוהלת על ידי הפאנל: mods שנוספו על ידי המשתמש נוחתים בספרייה המנוטרלת כפילויות ומקושרים קשיחים לשרת כך שהם שורדים עדכוני pack. השבתה מודעת לסוג.
- **פורטים** מוקצים מסכמה בסיסית (משחק מ-`PORT_GAME_START` ומעלה, RCON = משחק +
  `PORT_RCON_OFFSET`, Bedrock מ-`PORT_BEDROCK_START`), נבדקים לזמינות, ונשמרים ב-
  DB.
- **מכסות דיסק** נאכפות על ידי הפאנל מכיוון ש-Docker לא יכול להגביל שימוש ב-bind-mount: המדד
  שומר במטמון גדלים לכל ספרייה ופעולות גידול דיסק נסגרות על פיהם.
- **סודות** (סיסמאות RCON, מפתחות API, סודות TOTP, כתובת ה-webhook של Discord) מוצפנים במנוחה
  עם AES-256-GCM באמצעות מפתח אקראי ייעודי ב-`$DATA_DIR/.secret-key` (מצב `0600`,
  נוצר אוטומטית). הוא בלתי תלוי ב-`SESSION_SECRET`; מפתח נגזר מ-`SESSION_SECRET` נשמר כגיבוי ללא הצפנה עבור ערכים שנכתבו לפני שהמפתח הייעודי היה קיים, ו-
  `src/services/secretsMigration.js` מצפין מחדש את אלה תחת המפתח הייעודי פעם אחת בעת האתחול.
  `.secret-key` קיים אך אינו ניתן לפענוח הוא שגיאת אתחול קשה (הוא לעולם לא נוצר מחדש בשקט
  מעל). Blueprints מסירים את כל הסודות בעת ייצוא.

## פורמטי נתונים וחוטים

- **`data/panel.db`** - מסד הנתונים SQLite. מצולם מדי יום באמצעות `VACUUM INTO` ל-
  `data/backups/_panel/` (14 האחרונים נשמרים); `PRAGMA integrity_check` מופעל בעת האתחול.
- **`data/.session-secret`** - הסוד לחתימת עוגיות שנוצר אוטומטית, נוצר בהרצה הראשונה אם
  `SESSION_SECRET` אינו מוגדר. מחיקתו מסובבת את הסוד (מה שפוסל סשנים).
- **`data/.secret-key`** - מפתח ההצפנה הייעודי במנוחה בגודל 32 בתים (מצב `0600`), נוצר אוטומטית
  בהרצה הראשונה. בלתי תלוי ב-`SESSION_SECRET`; מחיקתו הופכת כל פרטי התחברות מאוחסנים
  לבלתי ניתנים לפענוח, כך שהוא שייך לגיבויים שלך.
- **Blueprints (`.mcserver.zip`)** - קובץ zip עם `manifest.json` המתאר תצורה, משאבים, הפניה ל-pack מקובע, מניפסט שכבת-על (כתובות URL מקור + sha256), קבצי תצורה נבחרים, ואופציונלית עולם. הייבוא מוריד מחדש ומוודא hash של כל mod ומקצה פורטים חדשים.
- **קונטיינרים של Docker** שנוצרו על ידי הפאנל נקראים ומסומנים כך שה-watcher יוכל למצוא אותם;
  הפאנל הבעלים של מחזור החיים המלא שלהם.

## רצף אתחול

1. `require('./instrument')` (תפר ה-Sentry) לפני כל דבר אחר, ואז `require('./preflight')`
   כדי להיכשל בבירור בגרסת Node לא נתמכת.
2. טען תצורה; ודא/צור `.session-secret` **ו-** `.secret-key`.
3. `ensureDataRoot()` - צור את מבנה `./data`, נקה את `tmp/`.
4. הרץ מיגרציות DB, ואז `PRAGMA integrity_check` (רושם בקול רם, מצביע על `data/backups/_panel`
   במקרה של כשל).
5. הצפן מחדש סודות ישנים המקודדים לפי `SESSION_SECRET` תחת `.secret-key` (`secretsMigration`).
6. זרע blueprints התחלתיים (מוגן).
7. הפעל את שרת ה-HTTP + WS. ב-bind חשוף, הדפס את ה-PIN של `/setup` להרצה ראשונה.
8. התקן את שומר זמן הריצה לאחר האתחול (לוכד תקלות שלא נתפסו; `MSM_EXIT_ON_FATAL=1` גורם לו לצאת קשה עבור פריסות מפוקחות).
9. הפעל שירותי רקע: מתווך WS, מדד אחסון, מנטרי קריסות + מלאי, מתזמן,
   גשר אירועי Discord, ו**טיימר תחזוקה יומי** (מנקה שורות אנליטיקה ישנות + מצלם
   את `panel.db`).
10. אתחל את Docker **ברקע**. ה-UI שמיש לחלוטין בזמן שה-daemon למטה;
    תכונות Docker נדלקות כשהוא הופך לנגיש. לאחר החיבור, `refreshStatuses({ boot })`
    מיישר מצבים שמורים במטמון, פולט אירוע `offline-after-restart` חד-פעמי עבור שרת שהיה פעיל לפני שהפאנל הופעל מחדש ולא יוחזר, ולולאת האתחול מתחילה
    שרתים ב-`auto_start` ומשחזר שרתים ב-`auto_restart` שנמצאו קרוסים במהלך ההפסקה
    (תוך כיבוד backoff של לולאת קריסה).

> סדר instrument-before-preflight הוא פשרה מכוונת: הוא מאפשר לחוט Sentry עתידי
> לתקן את זמן הריצה תחילה, במחיר הודעה פחות ידידותית על גרסת Node עתיקה באמת.

## צינור בנייה

`pnpm run build` = `build:css` (Tailwind → `public/css/app.css`) + `build:js` (esbuild →
`public/dist/js/`, ESM עם חלוקת קוד). `postinstall` מריץ **CSS בלבד**. `public/css/app.css`
ו-`public/dist/` הם ארטיפקטים של בנייה המוזנחים ב-git; שלב בניית ה-Dockerfile מריץ את ה-`pnpm run build` המלא
ומעתיק את `public/` לתמונת זמן הריצה. נכסים סטטיים מוגשים
`immutable`/long-cache עבור קבצים עם טביעת אצבע, short-cache עבור CSS/JS, ו-`no-cache` עבור HTML ו-`/api`.
