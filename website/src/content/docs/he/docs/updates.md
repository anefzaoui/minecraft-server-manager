דף **עדכונים** עוקב אחר מה מיושן בכל הצי שלך במקום אחד:

- גרסאות **Modpack** ([modpacks](/docs/modpacks/)) מול Modrinth / CurseForge / אינדקס השחרור של GTNH.
- **תוכן מותאם אישית** שהוספת בעצמך - מודים, datapacks, חבילות משאבים, פלאגינים - כל אחד מול המקור שלו: Modrinth, CurseForge, Hangar, SpigotMC (Spiget), או GitHub Releases. בדיקות GitHub משתמשות באימות מחדש של ETag, כך שבדיקות יומיות בקושי נוגעות במגבלת הקצב שלה.
- עדכניות של **תמונת Docker**: מזהה התמונה של כל קונטיינר פועל מול תג שנמשך טרי (מנוטרל כפילויות בין שרתים באותו תג), מוצע כשדרוג הדורש יצירה מחדש בלבד.
- **נעצי גרסאות עצמאיות**: עבור שרת ללא חבילה מנוהלת, נעץ `mc_version` מפורש מול המניפסט של Mojang, ומשתנה סביבה מפורש של loader-build (`PAPER_BUILD`, `FORGE_VERSION`, וכדומה) מול הרישום של ה-loader. בניות Paper מגיעות מ-PaperMC **API v3 Fill** הנוכחי (נקודת הקצה הישנה v2 הפסיקה לקבל גרסאות Minecraft חדשות).

![Updates](/docs/images/updates.png)

## איך זה עובד

הפאנל בודק את הגרסאות הנעוצות של כל שרת מול מקור ה-upstream ומפרט כל דבר עם שחרור חדש יותר. ספירה תואמת מופיעה גם באריח "עדכונים זמינים" ב[לוח המחוונים](/docs/dashboard/).

בדיקות רצות לפי דרישה וניתן לתזמן אותן ([Schedules](/docs/schedules/)). **מדיניות** העדכון היא לשרת בודד: אתה מחליט אם הפאנל רק מודיע לך, או משאיר הכל ידני.

## החלת עדכון

עדכונים לעולם אינם שקטים. כאשר אתה בוחר לשדרג חבילה, הפאנל:

1. מבצע **גיבוי לפני עדכון** (כך שניתן לבטל אותו; 10 גיבויי טרום-עדכון אחרונים לשרת נשמרים).
2. מחדש את הנעץ של הגרסה החדשה המדויקת.
3. יוצר מחדש את הקונטיינר, ופותר מחדש את זמן הריצה של Java במידת הצורך.
4. מנטר את ההפעלה הראשונה, עם תקציב זמן לכל פלטפורמה.

אם הוא לא עולה במצב תקין, אתה חוזר לגיבוי שלפני העדכון. שרת במעקב יציב לעולם לא יוצע לו בטא, וקישור ליומן השינויים מצביע על ההבדל האמיתי לגרסה ספציפית היכן שהמקור מספק אותו. עדכון שנכשל גם מפעיל [התראה](/docs/integrations/) ב-Discord אם האינטגרציה מוגדרת.
