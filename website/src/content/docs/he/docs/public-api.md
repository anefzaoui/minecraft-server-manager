API קטן מבוסס HTTP לקריאה בלבד, המאפשר אחזור סטטוס של שרתים מחוץ לפאנל: לוח מחוונים לסטטוס, מנטר זמינות, בוט Discord, כלל אוטומציה ביתית. הוא מוגש על ידי הפאנל עצמו ומחזיר את אותם נתונים חיים שהדפים של הפאנל מציגים (מהמטמון בזיכרון), כך שפנייה אליו לעולם לא נוגעת ב-Docker.

הוא **כבוי עד שמנהל מערכת ישתמש בו** ונתון **לשליטת מנהל**. שום דבר לא נחשף עד שקיים טוקן.

## הפעלת ה-API

**הגדרות → API ציבורי → מפתח חדש**. תנו לו שם, בחרו מה הוא יכול לראות (כל השרתים, או קבוצה ספציפית), ואופציונלית תאריך תפוגה. המפתח המלא (טוקן Bearer) מוצג **פעם אחת**, בחלון דיאלוג; העתיקו אותו כעת, מכיוון שרק קידומת קצרה נשמרת לאחר מכן, לצורך זיהוי ברשימה.

![Public API settings](/docs/images/settings-public-api.png)

יצירת המפתח הראשון מפעילה את ה-API באופן אוטומטי (המתג **אפשר לאפליקציות חיצוניות לקרוא סטטוס** הוא בקרת השהייה: כבו אותו כדי להפסיק את ההגשה מבלי לבטל מפתחות כלשהם). בטלו מפתח מאותה טבלה בכל עת; לקוחות המשתמשים בו מאבדים גישה באופן מיידי.

טוקנים מאוחסנים כגיבוב SHA-256 (לעולם לא בטקסט רגיל), שורדים הפעלה מחדש של הפאנל, וחַיִּים יותר מהשרתים שהם מוגדרים עבורם (שרת שנמחק פשוט יוסר מתוצאות אותו טוקן).

## אימות

שלחו את הטוקן כאישור Bearer:

```
Authorization: Bearer msm_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

אין קובצי Cookie ו-**אין CORS**: זה מיועד לקריאות משרת-לשרת ומה-CLI, לא לאפליקציות דפדפן ממקור אחר. אם הפאנל נמצא מאחורי proxy הפוך, ודאו שה-proxy מעביר את הכותרת `Authorization`.

כשלונות מחזירים `401` עם `{ "ok": false, "error": "..." }`. כל דבר שאינו `GET` (או `HEAD`) מחזיר `405`. נתיבים לא ידועים מחזירים `404`. כאשר ה-API מושבת, כל נתיב מחזיר `404`.

## הגבלת קצב

כל טוקן מקבל תקציב משלו, `RATE_LIMIT_PUBLIC_API_PER_MIN` (ברירת מחדל `120` בקשות לדקה; `0` מבטל את המגבלה). חריגה מהמגבלה מחזירה `429`. בקשות שלעולם אינן מציגות טוקן תקין (חסר, פגום, מבוטל, או פג תוקף) מוגבלות בנפרד לפי כתובת IP של הלקוח פי חמישה מהמספר הזה, כך שסריקות אינן יכולות לעקוף את התקציב על ידי סיבוב טוקנים.

## נקודות קצה (Endpoints)

### `GET /api/v1/servers`

כל השרתים שהטוקן מוגדר עבורם.

```json
{
  "ok": true,
  "total": 1,
  "online": 1,
  "servers": [
    {
      "id": "srv_ab12cd34",
      "name": "SMP",
      "type": "PAPER",
      "state": "running",
      "cpuPct": 18.4,
      "memoryMb": 2048,
      "memoryLimitMb": 4096,
      "uptimeSeconds": 11722,
      "players": { "online": 3, "max": 20 }
    }
  ]
}
```

### `GET /api/v1/servers/:id`

שרת אחד, אותו אובייקט תחת מפתח `server`. מחזיר `404` עבור מזהה לא ידוע **וגם** עבור שרת שהטוקן אינו מוגדר עבורו (אין "אורקל קיום"), ו-`400` עבור מזהה פגום.

## שדות תגובה

| שדה             | משמעות                                                                                 |
| --------------- | -------------------------------------------------------------------------------------- |
| `total`         | כמה שרתים גלויים לטוקן זה (לאחר סינון ההיקף שלו).                                      |
| `online`        | כמה מהם במצב: `running`.                                                               |
| `id`            | מזהה שרת יציב (`srv_...`).                                                             |
| `name`          | שם תצוגה.                                                                              |
| `type`          | סוג שרת itzg (`PAPER`, `FABRIC`, `AUTO_CURSEFORGE`, ...).                              |
| `state`         | `running`, `starting`, `stopped`, או `crashed` - סיכום יציב של הסטטוס הפנימי של הפאנל. |
| `cpuPct`        | אחוז שימוש ב-CPU לאחרונה, או `null` כאשר השרת אינו פועל.                               |
| `memoryMb`      | זיכרון תושב ב-MB, או `null`.                                                           |
| `memoryLimitMb` | מגבלת זיכרון מוגדרת של הקונטיינר ב-MB, או `null`.                                      |
| `uptimeSeconds` | שניות מאז שהקונטיינר הופעל, או `null`.                                                 |
| `players`       | `{ online, max }`, או `null` עד שהשרת מדווח על רשימת שחקנים.                           |

## דוגמה

```sh
curl -s https://panel.example.com/api/v1/servers \
  -H "Authorization: Bearer $MSM_TOKEN" | jq
```
