עבוד לפי הרשימה הזו. היא מסודרת לפי התדירות שבה כל אחד מהם הוא התשובה, והארבעה הראשונים מכסים את רובם.

## 1. קרא את עשרים השורות האחרונות, לא הראשונות

גלול ל**סוף** הלוג. ערימת שגיאות Java (stack trace) מודפסת מבפנים החוצה, כך שבראש קיר הטקסט נמצא החלק הכי פחות מעניין. מה שאתה רוצה זה השורה האחרונה של `Caused by:` וכל מה שבא אחריה. שורה בודדת זו בדרך כלל מציינת את הבעיה.

שני סימנים אומרים לך איפה אתה נמצא:

- `Exception in thread "main"` או נתיב של דוח קריסה ליד הסוף פירושו שהמשחק עצמו נכשל.
- הלוג פשוט נעצר באמצע שורה, ללא שגיאה כלל, פירושו שמשהו הרג את התהליך מבחוץ. קפוץ לנקודה 3.

## 2. UnsupportedClassVersionError פירושו Java שגויה

```
java.lang.UnsupportedClassVersionError: net/minecraft/server/Main has been compiled
by a more recent version of the Java Runtime (class file version 65.0)
```

קובץ מחלקה 52 הוא Java 8, 60 הוא 16, 61 הוא 17, 65 הוא 21, 69 הוא 25. ההודעה פירושה שהשרת צריך Java חדשה יותר ממה שהוא פועל עליה; ההפך, חבילה ישנה על Java חדשה, בדרך כלל נכשלת עם שגיאת mixin או reflection במקום.

| גרסת Minecraft   | Java |
| ---------------- | ---- |
| 1.16.5 ומעלה     | 8    |
| 1.17             | 16   |
| 1.18 ו-1.19      | 17   |
| 1.20 עד 1.20.4   | 17   |
| 1.20.5 עד 1.21.x | 21   |
| 26.1 ומעלה       | 25   |

חבילות ישנות באמת צריכות Java 8. חדש יותר אינו טוב יותר כאן.

## 3. קוד יציאה 137 הוא הליבה, לא מוד

הלוג נעצר באמצע משפט, אין דוח קריסה, והקונטיינר מדווח על 137. זוהי הרג בגלל חוסר זיכרון (out-of-memory kill): התהליך ביקש זיכרון שהמכונה לא היה לה, ולכן הוא הופסק.

כמעט תמיד ערימת ה-Java (heap) הוגדרה לאותו מספר כמו הזיכרון של המכונה. הערימה צריכה את הזיכרון של המכונה **פחות** התקורה של ה-JVM עצמו, שהיא 0.5 עד 1.5 GB בשרת עם מודים. הורד את הערימה, או הגדל את המכונה. [כמה RAM שרת צריך](/docs/guide-server-memory/) מכיל את המספרים.

## 4. ה-EULA והפורט

שני קלאסיקות עם תיקונים של שורה אחת:

- `You need to agree to the EULA in order to run the server.` הגדר `eula=true`, בקובץ `eula.txt` או עם משתנה הסביבה שההגדרה שלך משתמשת בו.
- `Address already in use` או `FAILED TO BIND TO PORT`. משהו אחר מחזיק את 25565, לעיתים קרובות עותק קודם של אותו שרת שמעולם לא נעצר לחלוטין. מצא אותו ועצור אותו במקום לשנות את הפורט, אחרת תמצא את עצמך עם שניים.

## 5. למוד חסר תלות

```
Mod X requires mod Y, which is missing
Fabric API is not installed
```

מודים של Fabric דורשים ברובם את Fabric API כקובץ נפרד. מודים של Forge ו-NeoForge מפרטים את התלויות שלהם בשגיאה עצמה. התקן את הגרסה שצויינה, לא את החדשה ביותר: "דורש 0.91.x" פירושו השורה הזו, ו-0.92 ייכשל באותו בדיקה.

לפעמים התלות החסרה היא המטעין עצמו:

```
Mod X requires forge 47.4.14 or above
Mod ID: 'forge', Requested by: 'x', Expected range: '[47.4.14,)', Actual version: '47.4.10'
```

התיקון הוא גרסת מטעין חדשה יותר, לא מוד אחר. "47.4.14 או מעלה" פירושו כל גרסה משם והלאה, ו-Forge לא מפרסם כל מספר, כך שהגרסה להתקנה עשויה להיות הבאה בתור. בחבילת מודים, עדכן את החבילה קודם: חבילה שהגרסת המטעין שלה ישנה מדי עבור המודים שלה היא באג למפתח שלה לתקן.

## 6. מוד מיועד למטעין או גרסה שגויה

קובץ JAR למטעין אחר לא נכשל בנימוס. צפה לשגיאת mixin, `NoClassDefFoundError`, או קריסה בתוך מחלקה שמעולם לא שמעת עליה. בדוק את דף ה-jar: המטעין וגרסת ה-Minecraft חייבים להתאים בדיוק. 1.20.1 ו-1.20.4 הם משחקים שונים מבחינת מודים.

## 7. העולם מגרסה חדשה יותר

```
This world was created by a newer version of Minecraft
```

עולמות משדרגים קדימה ולעולם לא אחורה. שחזר את הגיבוי מלפני השדרוג, או הפעל את הגרסה שהעולם מצפה לה. אין דרך לרדת בגרסה שתשמור על החלקים (chunks) שלמים.

## כשזה קרס אחרי שהיה תקין במשך שבועות

שאלה שונה, בדרך כלל תשובה שונה:

- **זה קרס תחת עומס**, עם מדידות שמראות השהיות ארוכות: איסוף זבל (garbage collection), אז הסתכל על גודל הערימה לפני המודים.
- **זה קרס באותה נקודה בעולם**: חלק (chunk) פגום או ישות שבורה. דוח הקריסה בדרך כלל מציין קואורדינטות.
- **זה קרס מיד אחרי עדכון**: המוד שהתעדכן הוא החשוד, גם אם המעקב מצביע למקום אחר. החזר אותו ובדוק.
- **זה קרס בהפעלה מחדש, אחרי שהיה תקין קודם**: בדוק את הדיסק. דיסק מלא מייצר שגיאות מרהיבות ומטעות.

## קבלת עזרה שעוזרת באמת

פרסם את **כל הלוג**, לא את השורה האחרונה, וספר מה שינית לפני שהוא נשבר. הדבק אותו במקום המיועד לכך, כמו [mclo.gs](https://mclo.gs), במקום בצ'אט. כלול את גרסת ה-Minecraft, המטעין, החבילה והגרסה שלה, וכמה heap יש לשרת. דיווח עם ארבעת הפרטים האלה מקבל תשובה בתגובה אחת; בלעדיהם זה לוקח חמש.

## ב-Minecraft Server Manager

קריסות מזוהות מיציאת הקונטיינר עצמו, כך ששרת שמת בשלוש לפנות בוקר נרשם עם קטע הלוג שלו במקום להימצא למחרת. החשודים הרגילים בדף זה (ה-EULA, ה-Java השגויה, עולם מגרסה חדשה יותר, פורט שכבר בשימוש, Java שנגמר לה הזיכרון) מזוהים בלוג הזה ומצוינים בכניסת ההיסטוריה עם מה לעשות לגביהם, והפעלה מחדש אוטומטית משאירה אותם לבד, מכיוון שהפעלה מחדש לא תתקן אותם. דוחות קריסה מנותחים עם הגעתם: השגיאה מודגשת, ערימת השגיאות ניתנת לכיווץ, ומודים שמופיעים במעקב רשומים כחשודים.

כל דיווח ניתן לשיתוף ל-mclo.gs מכרטיס שלו כשאתה זקוק לעזרה (לאחר אישור, מכיוון שההדבקה פומבית), ובתפריט **הורדה** של הקונסולה יש את כל קבצי הלוג כ-zip אחד, כך ש"פרסם את כל הלוג" הוא הורדה במקום פרויקט ארכיאולוגיה. הרג בגלל חוסר זיכרון נרשם כהרג בגלל חוסר זיכרון, מה שחוסך את השעה הרגילה של האשמת מוד. אם משהו אחר באמת זקוק לפורט, כרטיס **Game Port** ב-**Settings → Configuration** מעביר את השרת לפורט פנוי.

מטעין ישן מדי משתנה דרך לשונית **Versions** של השרת, שבודקת שהגרסה קיימת ולוקחת גיבוי לפני שהיא בונה מחדש את השרת ([שינוי גרסת מטעין המודים](/docs/updates/#changing-the-mod-loader-version)).
