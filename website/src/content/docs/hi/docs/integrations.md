प्रत्येक सर्वर **सेटिंग्स** समूह के अंतर्गत अपने इंटीग्रेशन रखता है: **Discord**, एक सार्वजनिक **स्टेटस पेज**, एक-क्लिक **आमंत्रण**, और वैकल्पिक **चैटबॉट** टैब (केवल एडमिन के लिए)। यह पृष्ठ Discord को कवर करता है; [आमंत्रण और स्टेटस पेज](/docs/invites-and-status-page/) उन दोनों को कवर करता है, और [चैटबॉट](/docs/chatbot/) का अपना पृष्ठ है।

## Discord सूचनाएं

पैनल वेबहुक के माध्यम से सर्वर इवेंट्स को एक Discord चैनल पर फॉरवर्ड करता है। कोई बॉट नहीं, कोई OAuth नहीं।

### सेटअप

1. Discord में: **सर्वर सेटिंग्स → इंटीग्रेशन → वेबहुक → नया वेबहुक**। चैनल चुनें और वेबहुक URL कॉपी करें।
2. पैनल में, सर्वर का **सेटिंग्स → Discord** टैब खोलें, URL को **वेबहुक URL** में पेस्ट करें, कार्ड को **चालू** करें, और **सहेजें**। URL एन्क्रिप्टेड रूप से संग्रहीत है (उसी एट-रेस्ट स्टोर में जैसे आपकी API कुंजियाँ)।
3. यह पुष्टि करने के लिए **टेस्ट भेजें** का उपयोग करें कि यह काम करता है।

![Discord इंटीग्रेशन](/docs/images/integrations-discord.png)

संग्रहीत URL को बदलने के लिए, एक नया पेस्ट करें और सहेजें; वर्तमान URL को बनाए रखने के लिए फ़ील्ड को खाली छोड़ दें। संग्रहीत URL को मास्क्ड (टोकन छिपा हुआ) दिखाया गया है।

### क्या भेजा जाता है

सूचनाओं को टॉगल करने योग्य श्रेणियों में बांटा गया है। सभी डिफ़ॉल्ट रूप से चालू हैं।

| श्रेणी         | इवेंट्स                                                            |
| -------------- | ------------------------------------------------------------------ |
| **शुरू / बंद** | सर्वर शुरू हुआ, सर्वर बंद हुआ                                      |
| **क्रैश**      | क्रैश, क्रैश लूप का पता चला, नई क्रैश रिपोर्ट                      |
| **बैकअप**      | बैकअप बनाया गया, बैकअप बहाल किया गया                               |
| **अपडेट**      | अपडेट लागू किया गया, अपडेट वापस लिया गया, अपडेट विफल रहा           |
| **किक / बैन**  | खिलाड़ी को किक किया गया, खिलाड़ी को बैन किया गया                   |
| **अलर्ट**      | वे चीजें जो चुपचाप एक सर्वर को टूटा हुआ छोड़ देती हैं (नीचे देखें) |

### अलर्ट श्रेणी

`अलर्ट` "कुछ के लिए मानव हस्तक्षेप की आवश्यकता है" चैनल है, उन स्थितियों के लिए जो पहले केवल पैनल में दिखाई देती थीं:

| इवेंट                   | अर्थ                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| `oom`                   | मेमोरी खत्म होने के कारण कंटेनर बंद कर दिया गया था।                                                        |
| `unhealthy`             | प्रक्रिया चालू है लेकिन `mc-health` प्रोब विफल हो रहा है: एक लाइव लेकिन मृत सर्वर।                         |
| `startup-stalled`       | लॉग में "Done" के बिना ~10 मिनट के बाद भी शुरू हो रहा है (ठीक करने के लिए निदान के साथ, जहां एक ज्ञात हो)। |
| `stop-failed`           | एक ग्रेसफुल स्टॉप प्रभावी नहीं हुआ और कंटेनर अभी भी चल रहा है।                                             |
| `schedule-failed`       | एक निर्धारित रीस्टार्ट / बैकअप / कमांड विफल हो गया।                                                        |
| `quota-exceeded`        | स्ट्रिक्ट-मोड डिस्क कोटा ट्रिप हुआ और सर्वर बंद कर दिया गया।                                               |
| `offline-after-restart` | पैनल रीस्टार्ट होने से पहले सर्वर चालू था, अब नहीं है, और ऑटो-स्टार्ट नहीं होगा।                           |
| `port-change-failed`    | पोर्ट परिवर्तन विफल हो गया और सर्वर को उसके पुराने पोर्ट पर वापस नहीं लाया जा सका, इसलिए वह डाउन है।       |
| `auto-restart-gave-up`  | क्रैश हुए सर्वर को रीस्टार्ट नहीं किया गया क्योंकि कोई अन्य क्रिया उसे बहुत लंबे समय तक व्यस्त रख रही थी।  |

### डिलीवरी कैसे काम करती है

एक बैकग्राउंड ब्रिज हर 15 सेकंड में [इवेंट लॉग](/docs/activity/) को पोल करता है और मैप की गई पंक्तियों को फॉरवर्ड करता है। यदि कोई वेबहुक POST अस्थायी रूप से विफल हो जाता है, तो वह पंक्ति बाद के पोल पर पुनः प्रयास की जाती है बजाय इसके कि वह छूट जाए; कुछ असफल प्रयासों के बाद पंक्ति को छोड़ दिया जाता है, और प्रति सर्वर प्रति घंटे एक बार से अधिक डिलीवरी विफलताएं लॉग नहीं की जाती हैं। पैनल रीस्टार्ट के बाद ब्रिज उन इवेंट्स को भेजता है जिन्हें उसने अभी तक डिलीवर नहीं किया है, लेकिन कभी भी दो घंटे से अधिक पीछे नहीं; अपने पहले रन पर यह सबसे नए इवेंट से शुरू होता है।
