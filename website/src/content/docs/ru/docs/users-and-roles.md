Панель является многопользовательской. Управляйте учетными записями в разделе **Настройки → Пользователи**.

![Пользователи](/docs/images/settings-users.png)

## Три роли

| Роль         | По умолчанию на каждом сервере                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **admin**    | Все: управление пользователями, ключами API, глобальными файлами, расширенными настройками Docker и всеми действиями сервера.                         |
| **operator** | Запуск и настройка серверов (запуск/остановка, консоль, резервные копии, миры, моды, большинство настроек), но не области только для администраторов. |
| **viewer**   | Только для чтения. Просмотр серверов и их статуса, но без внесения изменений.                                                                         |

Каждый пользователь, включая наблюдателя, может управлять своей [двухфакторной аутентификацией](/docs/two-factor-authentication/), потому что защита собственного входа в систему не является действием по управлению сервером.

Роль является **по умолчанию** для каждого сервера. Чтобы предоставить кому-либо другие права на одном сервере, используйте разрешения для каждого сервера ниже.

## Разрешения для каждого сервера

Страница **Разрешения** (в боковой панели или **Разрешения сервера** в разделе **Настройки → Пользователи**) показывает сетку: каждый оператор и наблюдатель по вертикали, каждый сервер по горизонтали. Нажмите на ячейку, чтобы решить, что этот пользователь может делать на этом конкретном сервере. Администраторы не перечислены, потому что у них всегда есть все.

![Разрешения](/docs/images/settings-permissions.png)

Каждая ячейка представляет собой набор разрешений:

| Разрешение   | Что оно позволяет на этом сервере                                                                                       |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **View**     | Просмотр сервера, его статуса, вывода консоли, игроков, истории и статистики.                                           |
| **Power**    | Запуск, остановка, перезапуск, принудительное завершение и пересборка сервера.                                          |
| **Console**  | Выполнение консольных команд и быстрых действий с миром, отправка сообщений в чат и управление командами чата.          |
| **Players**  | Кик, бан, добавление в белый список, выдача OP и редактирование заметок об игроках.                                     |
| **Content**  | Установка и удаление модов, плагинов, пакетов, миров, датапаков и редактирование инвентаря.                             |
| **Backups**  | Создание, восстановление, загрузка и удаление резервных копий.                                                          |
| **Files**    | Просмотр, редактирование, загрузка и скачивание файлов сервера, архивированных логов и пакетов логов; экспорт чертежей. |
| **Settings** | Изменение настроек сервера, свойств, интеграций, значка и обновление версий.                                            |
| **Delete**   | Удаление сервера.                                                                                                       |

![Редактор разрешений](/docs/images/permissions-editor.png)

Под сеткой **Что охватывает каждое разрешение** раскрывает каждое разрешение на то, что человек может делать, что не включено, и точные маршруты панели, которые оно разблокирует. Этот последний список проверяется на соответствие работающему коду набором тестов.

![Справочник разрешений](/docs/images/permissions-reference.png)

На телефоне сетка складывается в одну карточку на пользователя, с одной строкой на сервер.

Как части сочетаются друг с другом:

- **Роль является значением по умолчанию.** Оператор начинает со всеми разрешениями на каждом сервере; наблюдатель начинает только с разрешения View. Ячейка с бледным текстом (ее всплывающая подсказка говорит "Роль по умолчанию") никогда не изменялась.
- **Ячейка переопределяет роль только для этого сервера.** Дайте наблюдателю Power и Console на одном сервере, и он сможет им управлять, в то время как все остальные серверы останутся для него только для чтения. Отнимите Delete у оператора на вашем основном сервере, и он сохранит все остальное там.
- **Каждое разрешение включает View.** Вы не можете действовать на сервере, который не можете видеть.
- **Отключите все, чтобы скрыть сервер.** Он исчезнет из боковой панели этого пользователя, панели управления, резервных копий, расписаний, активности, обновлений, модпаков, живого статуса, запущенных задач и чертежей, а библиотека миров перестанет его называть. Прямая ссылка, вызов API или сокет консоли ответят "не найдено", так же, как и для несуществующего сервера.
- **Действия по всей панели по-прежнему следуют роли.** Создание серверов (включая клонирование), хранилище, пользователи, ключи API, глобальные настройки и расписания по всей панели не являются специфичными для сервера, поэтому наблюдатель с разрешениями на некоторых серверах по-прежнему не может выполнять ни одно из этих действий. Операторы сохраняют создание сервера и расписания по всей панели; хранилище, пользователи, ключи API и глобальные настройки доступны только администраторам.
- **Расписания следуют за сервером.** Запланированный перезапуск, резервное копирование или команда на сервере требуют соответствующего разрешения там (Power, Backups или Console), независимо от роли.
- **Чертежи также следуют за сервером.** Экспорт сервера в виде чертежа требует наличия Files там, потому что архив содержит его файлы. Чертеж, экспортированный с сервера, который кто-то не может видеть, также скрыт от него.
- **Области только для администраторов остаются только для администраторов** на каждом сервере: чат-бот, хранение резервных копий и расширенные переопределения Docker.

Каждое изменение записывается в журнал активности с указанием того, кто что изменил; эти записи показываются только администраторам. Удаление пользователя удаляет его строки. Удаление сервера сохраняет их, поэтому сервер, скрытый от кого-то, остается скрытым в его истории и сохраненных резервных копиях.

Существующие установки продолжают работать без изменений: пока администратор не отредактирует ячейку, у каждого пользователя есть ровно то, что давала ему его роль раньше.

## Только для администраторов, и почему

Некоторые вещи специально ограничены для администраторов:

- **Управление пользователями, хранилище, глобальные настройки, ключи API и глобальные файлы.**
- **[Публичный API](/docs/public-api/)**: включение `/api/v1` и создание, определение области или отзыв его токенов Bearer только для чтения.
- **Расширенные переопределения Docker**: пользовательское имя контейнера, дополнительные публикации портов и монтирование томов. Монтирование тома может сопоставить любой путь хоста с контейнером, и в сочетании с доступом панели к Docker это фактически root на хосте. Эти поля появляются только для администраторов.

Пользовательские имена контейнеров также не могут находиться в собственном пространстве имен панели `msm-`, поэтому контейнер, названный вручную, никогда не сможет затенить другой сервер и перенаправить остановку или команду на неправильный экземпляр.

## Управление учетными записями

![Изображение профиля](/docs/images/profile-picture.png)

Администраторы могут создавать пользователей, изменять роли, сбрасывать пароли и удалять учетные записи из таблицы пользователей. Столбец **2FA** показывает, включена ли двухфакторная аутентификация для каждого пользователя; администратор может сбросить 2FA другого пользователя с помощью **Сбросить 2FA** в меню действий этого пользователя (для случая утерянного телефона и резервных кодов), но никогда не отключит свою собственную без своего пароля, что вместо этого обрабатывается потоком самообслуживания.

Неудачные попытки входа в систему ограничены по скорости для каждой учетной записи (как счетчик для каждого IP, так и глобальный счетчик для учетной записи), чтобы замедлить атаки методом перебора, и то же ограничение распространяется на шаг кода 2FA, чтобы правильный пароль не мог сбросить счетчик до угадывания кода. Перед этим находится более грубый ограничитель запросов для каждого клиентского IP на конечных точках входа / 2FA / настройки, настраиваемый через `RATE_LIMIT_AUTH_PER_15MIN` (по умолчанию 100; за обратным прокси-сервером установите `TRUST_PROXY`, чтобы он использовал реальный IP клиента).
