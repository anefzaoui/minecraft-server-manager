Панель поддерживает несколько пользователей. Управляйте учетными записями в разделе **Настройки → Пользователи**.

![Пользователи](/docs/images/settings-users.png)

## Три роли

| Роль              | Что можно делать                                                                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **администратор** | Всё: управлять пользователями, API-ключами, глобальными файлами, расширенными переопределениями Docker и всеми действиями с сервером.                     |
| **оператор**      | Запускать и настраивать серверы (старт/стоп, консоль, резервные копии, миры, моды, большинство настроек), но не области, доступные только администратору. |
| **наблюдатель**   | Только чтение. Просматривать серверы и их статус, но не вносить никаких изменений.                                                                        |

Каждый пользователь, включая наблюдателя, может управлять своей собственной [двухфакторной аутентификацией](/docs/two-factor-authentication/), поскольку защита собственного входа не является действием по управлению сервером.

## Только для администраторов, и почему

Некоторые функции намеренно ограничены для администраторов:

- **Управление пользователями, API-ключами и глобальными файлами.**
- **[Публичный API](/docs/public-api/)** — включение `/api/v1` и создание, ограничение области действия или отзыв его токенов Bearer только для чтения.
- **Расширенные переопределения Docker** — пользовательское имя контейнера, дополнительные опубликованные порты и привязки монтирования. Привязка монтирования может сопоставить любой путь хоста с контейнером, и в сочетании с доступом панели к Docker это фактически дает права root на хосте. Эти поля отображаются только для администраторов.

Пользовательские имена контейнеров также не могут находиться в собственном пространстве имен `msm-` панели, поэтому контейнер с вручную заданным именем никогда не сможет перекрыть другой сервер и направить команду остановки или другую команду не на тот экземпляр.

## Управление учетными записями

![Изображение профиля](/docs/images/profile-picture.png)

Администраторы могут создавать пользователей, изменять роли, сбрасывать пароли и удалять учетные записи из таблицы пользователей. Столбец **2FA** показывает, включена ли у каждого пользователя двухфакторная аутентификация; администратор может **сбросить** 2FA другого пользователя (в случае утери телефона и резервных кодов), но никогда не может отключить свою собственную без пароля, что вместо этого обрабатывается в потоке самообслуживания.

Неудачные попытки входа ограничиваются по частоте для каждой учетной записи (как по IP-адресу, так и глобально для учетной записи), чтобы замедлить попытки перебора паролей, и тот же лимит распространяется на шаг ввода кода 2FA, поэтому правильный пароль не может сбросить счетчик перед угадыванием кода. Перед этим стоит более грубый ограничитель запросов по IP-адресу клиента для конечных точек входа / 2FA / настройки, который можно настроить с помощью `RATE_LIMIT_AUTH_PER_15MIN` (по умолчанию 100; при использовании обратного прокси установите `TRUST_PROXY`, чтобы он использовал реальный IP-адрес клиента).
