Каждый сервер имеет свои интеграции в группе **Настройки**: **Discord**, публичная **Страница статуса**, **Приглашения** в один клик и опциональная вкладка **Чат-бот**. Эта страница охватывает Discord (остальные имеют свою документацию и помощников по настройке в панели).

## Уведомления Discord

Панель пересылает события сервера в канал Discord через вебхук. Без бота, без OAuth.

### Настройка

1. В Discord: **Настройки сервера → Интеграции → Вебхуки → Новый вебхук**. Выберите канал и скопируйте URL вебхука.
2. В панели откройте вкладку сервера **Настройки → Discord**, вставьте URL в поле **Webhook URL**, включите карточку **on** и нажмите **Сохранить**. URL хранится в зашифрованном виде (в том же хранилище в состоянии покоя, что и ваши API-ключи).
3. Используйте **Send test**, чтобы убедиться, что всё работает.

![Интеграция Discord](/docs/images/integrations-discord.png)

Чтобы заменить сохраненный URL, вставьте новый и сохраните; оставьте поле пустым, чтобы сохранить текущий. Сохраненный URL отображается маскированным (токен скрыт).

### Что отправляется

Уведомления сгруппированы по категориям с возможностью переключения. Все включены по умолчанию.

| Категория           | События                                                      |
| ------------------- | ------------------------------------------------------------ |
| **Старт / стоп**    | Сервер запущен, сервер остановлен                            |
| **Сбои**            | Сбой, обнаружен цикл сбоев, новый отчёт о сбое               |
| **Резервные копии** | Создана резервная копия, восстановлена резервная копия       |
| **Обновления**      | Применено обновление, отменено обновление, ошибка обновления |
| **Кики / баны**     | Игрок кикнут, игрок забанен                                  |
| **Оповещения**      | То, что тихо оставляет сервер неработоспособным (см. ниже)   |

### Категория Оповещения

`Alerts` — это канал "что-то требует внимания человека" для условий, которые ранее были видны только в панели:

| Событие                 | Значение                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `oom`                   | Контейнер был остановлен из-за нехватки памяти.                                                                               |
| `unhealthy`             | Процесс запущен, но проверка `mc-health` не проходит: сервер работает, но мёртв.                                              |
| `startup-stalled`       | Сервер всё ещё запускается примерно через 10 минут без сообщения "Done" в логах (с диагностикой проблемы, если она известна). |
| `stop-failed`           | Корректная остановка не удалась, и контейнер всё ещё работает.                                                                |
| `schedule-failed`       | Сбой запланированного перезапуска / резервного копирования / команды.                                                         |
| `quota-exceeded`        | Сработал строгий лимит дискового пространства, и сервер был остановлен.                                                       |
| `offline-after-restart` | Сервер был запущен до перезапуска панели, теперь нет, и автозапуск не будет выполнен.                                         |
| `crash-report`          | Новый отчёт о сбое был захвачен и разобран.                                                                                   |
| `update-failed`         | Защищённое обновление не привело к работоспособному состоянию.                                                                |

### Как работает доставка

Фоновый мост опрашивает [журнал событий](/docs/activity/) каждые 15 секунд и пересылает сопоставленные строки. Если POST-запрос к вебхуку временно не удался, эта строка будет повторно отправлена при последующих опросах, а не потеряна; постоянно недоступный вебхук будет заглушен (одна строка лога в час) после нескольких попыток. Мост никогда не воспроизводит события, произошедшие до запуска панели.
