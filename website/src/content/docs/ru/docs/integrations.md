Каждый сервер имеет свои интеграции в группе **Настройки**: **Discord**, общедоступная **Страница состояния**, **Приглашения** в один клик и необязательная вкладка **Чат-бот** (только для администраторов). Эта страница посвящена Discord; [приглашения и страница состояния](/docs/invites-and-status-page/) охватывают эти два пункта, а [чат-бот](/docs/chatbot/) имеет свою собственную страницу.

## Уведомления Discord

Панель пересылает события сервера в канал Discord через вебхук. Никаких ботов, никакого OAuth.

### Настройка

1. В Discord: **Настройки сервера → Интеграции → Вебхуки → Новый вебхук**. Выберите канал и скопируйте URL вебхука.
2. В панели откройте вкладку сервера **Настройки → Discord**, вставьте URL в поле **URL вебхука**, включите карточку **вкл.** и нажмите **Сохранить**. URL сохраняется в зашифрованном виде (в том же хранилище в состоянии покоя, что и ваши API-ключи).
3. Используйте **Отправить тест**, чтобы убедиться, что все работает.

![Интеграция Discord](/docs/images/integrations-discord.png)

Чтобы заменить сохраненный URL, вставьте новый и сохраните; оставьте поле пустым, чтобы сохранить текущий. Сохраненный URL отображается маскированным (токен скрыт).

### Что отправляется

Уведомления сгруппированы по категориям с возможностью переключения. Все включено по умолчанию.

| Категория           | События                                                      |
| ------------------- | ------------------------------------------------------------ |
| **Старт / стоп**    | Сервер запущен, сервер остановлен                            |
| **Сбои**            | Сбой, обнаружен цикл сбоев, новый отчет о сбое               |
| **Резервные копии** | Создана резервная копия, восстановлена резервная копия       |
| **Обновления**      | Применено обновление, отменено обновление, ошибка обновления |
| **Кики / баны**     | Игрок кикнут, игрок забанен                                  |
| **Оповещения**      | То, что тихо оставляет сервер неработоспособным (см. ниже)   |

### Категория Оповещения

`Оповещения` — это канал "что-то требует вмешательства человека", для условий, которые раньше были видны только в панели:

| Событие                 | Значение                                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| `oom`                   | Контейнер был остановлен из-за нехватки памяти.                                                            |
| `unhealthy`             | Процесс запущен, но проверка `mc-health` не проходит: сервер жив, но мертв.                                |
| `startup-stalled`       | Запуск задерживается около 10 минут без сообщения "Done" в логах (с указанием причины, если она известна). |
| `stop-failed`           | Корректная остановка не удалась, и контейнер все еще работает.                                             |
| `schedule-failed`       | Сбой запланированного перезапуска / резервного копирования / команды.                                      |
| `quota-exceeded`        | Превышена квота диска в строгом режиме, и сервер был остановлен.                                           |
| `offline-after-restart` | Сервер был запущен до перезапуска панели, теперь не запущен и не будет автоматически запущен.              |
| `port-change-failed`    | Изменение порта не удалось, и сервер не смог вернуться на старый порт, поэтому он остановлен.              |
| `auto-restart-gave-up`  | Сбойный сервер не был перезапущен, потому что другое действие слишком долго удерживало его занятым.        |

### Как работает доставка

Фоновый мост опрашивает [журнал событий](/docs/activity/) каждые 15 секунд и пересылает соответствующие записи. Если POST-запрос вебхука временно не удается, эта запись повторяется при последующих опросах, а не теряется; после нескольких неудачных попыток запись пропускается, и сбои доставки регистрируются не чаще одного раза в час на сервер. После перезапуска панели мост отправляет события, которые еще не были доставлены, но не более чем за два часа назад; при самом первом запуске он начинает с новейшего события.
