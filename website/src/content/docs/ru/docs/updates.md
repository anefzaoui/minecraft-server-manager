Страница **Обновления** отслеживает устаревшие компоненты на всех ваших серверах в одном месте:

- Версии **модпаков** ([модпаки](/docs/modpacks/)) по сравнению с Modrinth / CurseForge / индексом релизов GTNH.
- **Пользовательский контент**, который вы добавили сами — моды, датапаки, ресурспаки, плагины — каждый по сравнению с его источником: Modrinth, CurseForge, Hangar, SpigotMC (Spiget) или GitHub Releases. Поиск по GitHub использует повторную проверку ETag, поэтому ежедневные проверки почти не задевают лимит запросов.
- Устаревание **Docker-образа**: ID образа каждого запущенного контейнера по сравнению со свежезагруженным тегом (дедуплицируется между серверами с одинаковым тегом), предлагается как обновление, требующее только пересоздания.
- **Фиксация версий для автономных серверов**: для сервера без управляемого модпака — явная фиксация `mc_version` по манифесту Mojang и явная переменная окружения для сборки загрузчика (`PAPER_BUILD`, `FORGE_VERSION` и т.п.) по реестру загрузчика. Сборки Paper берутся из текущего **Fill v3 API** от PaperMC (устаревшая конечная точка v2 перестала получать новые версии Minecraft).

## Как это работает

Панель проверяет закрепленные версии каждого сервера по отношению к внешнему источнику и перечисляет все, что имеет новый релиз. Соответствующий счетчик также появляется на плитке "Доступны обновления" на [главной странице](/docs/dashboard/).

Проверки выполняются по запросу и могут быть запланированы ([Расписания](/docs/schedules/)). **Политика** обновлений настраивается для каждого сервера: вы решаете, будет ли панель просто уведомлять вас или оставлять все вручную.

## Применение обновления

Обновления никогда не происходят автоматически. Когда вы выбираете обновление модпака, панель:

1. Создает **резервную копию перед обновлением** (чтобы можно было откатить изменения; сохраняются последние 10 резервных копий перед обновлением для каждого сервера).
2. Перезакрепляет точную новую версию.
3. Пересоздает контейнер, при необходимости переопределяя среду выполнения Java.
4. Отслеживает первый запуск с временным бюджетом для каждой платформы.

Если сервер не запускается корректно, происходит откат к резервной копии перед обновлением. Серверу, отслеживающему стабильные версии, никогда не будет предложена бета-версия, а ссылка на журнал изменений ведет к реальному различию для конкретной версии, если источник его предоставляет. Неудачное обновление также отправляет [оповещение](/docs/integrations/) в Discord, если интеграция настроена.
