Страница **Обновления** отслеживает устаревшее ПО на всех ваших серверах в одном месте:

- Версии **сборки модов** ([сборки модов](/docs/modpacks/)) по сравнению с Modrinth / CurseForge / индексом релизов GTNH.
- **Пользовательский контент**, который вы добавили сами (моды, datapacks, ресурспаки, плагины), каждый по сравнению с его источником: Modrinth, CurseForge, Hangar, SpigotMC (Spiget) или GitHub Releases. Поиск по GitHub использует повторную проверку ETag, поэтому ежедневные проверки почти не затрагивают его лимит запросов.
- Устаревание **Docker-образа**: идентификатор образа каждого серверного контейнера по сравнению со свежезагруженным тегом (дедуплицируется между серверами с одинаковым тегом), предлагается как обновление, требующее только пересборки.
- **Фиксация версий**: для сервера без управляемой сборки — явная фиксация `mc_version` по манифесту Mojang и явная переменная окружения для загрузчика (`PAPER_BUILD`, `FORGE_VERSION` и т.п.) по реестру загрузчика. Сборки Paper берутся из текущего **Fill v3 API** PaperMC (устаревшая конечная точка v2 перестала получать новые версии Minecraft). На сервере с модами новая версия Minecraft предлагается только после того, как [проверка версий](#minecraft-version-compatibility) покажет, что каждый установленный мод имеет для нее сборку. Сервер с зафиксированной версией Forge получает рекомендуемую сборку Forge, никогда не сборку старше той, к которой он привязан, а сервер, привязанный к релизу, никогда не получает пре-релиз (уже находящийся на бета-версии может получить новую бета-версию или релиз). Применение сборки загрузчика сначала создает резервную копию перед обновлением. Перемещение сервера Forge или NeoForge на новую версию Minecraft очищает номер сборки загрузчика, так как сборка делается для одной версии Minecraft; ключевое слово, такое как `latest`, сохраняется, поскольку оно само следует за версией. Чтобы выбрать конкретную сборку самостоятельно, см. [изменение версии загрузчика модов](#changing-the-mod-loader-version).

## Как это работает

Панель проверяет зафиксированные версии каждого сервера по отношению к внешнему источнику и перечисляет все, что имеет новый релиз. Соответствующий счетчик также появляется на плитке "Доступны обновления" на [панели управления](/docs/dashboard/).

Проверки выполняются ежедневно по расписанию по умолчанию [расписанию](/docs/schedules/) и по запросу с помощью **Проверить все немедленно**. **Игнорировать** в строке прекращает предложение этой конкретной версии; более новая версия будет предложена снова. **Политика** обновлений настраивается для каждого сервера: панель оставляет все вручную (по умолчанию, что также не отображает сервер на этой странице), только уведомляет вас, или сама применяет обновления сборки ([политика обновлений](/docs/modpacks/#update-policy)).

## Совместимость версий Minecraft

Новая версия Minecraft не является обновлением, если ваши моды не могут перейти на нее. Каждый сервер имеет свою собственную вкладку **Версии** (в разделе Моды), которая отвечает на этот вопрос:

- Версия, которую сервер запускает сейчас, и **самая высокая версия, для которой каждый установленный мод имеет сборку**.
- Одна сворачиваемая строка для каждой будущей версии Minecraft, с указанием, сколько модов готовы и сколько еще не имеют опубликованных сборок. Откройте строку, чтобы увидеть, какие моды останутся позади, а какие в порядке.

![Version compatibility](/docs/images/server-versions.png)

Нажмите **Проверить будущие версии**, чтобы запустить ее. Ничего не сканируется само по себе: проверка считывает каждый jar-файл в папке модов сервера и запрашивает Modrinth и CurseForge по каждому из них, поэтому это происходит только тогда, когда вы просите. Ход выполнения и частичные результаты записываются по мере выполнения, поэтому закрытие страницы или обновление ничего не теряет, а проверка, прерванная перезапуском панели, сообщает об этом и предлагает повторить. Все, что прерванная проверка уже выяснила, сохраняется, поэтому повторный запуск не повторяет эту работу.

Отчет описывает только сервер, для которого он был создан. Измените версию Minecraft, загрузчик или сами моды (добавьте один, удалите один, обновите один), и отчет будет помечен как устаревший и перестанет использоваться до тех пор, пока вы снова не запустите проверку.

Моды идентифицируются из собственного списка файлов сборки модов, если он есть, а в противном случае — по содержимому файла, так же, как лаунчер распознает jar-файл. Два типа модов не могут быть определены, и ни один из них не угадывается:

- **Не удалось идентифицировать**: собранный вручную jar-файл или частная сборка, которую не распознает ни один реестр.
- **Не удалось проверить**: мод из GitHub Releases, Hangar или SpigotMC, или мод, проект которого был удален. Они не публикуют список того, для какой версии Minecraft предназначена каждая сборка.

Пока установлен один из них, панель вообще не будет предлагать обновление версии Minecraft в один клик, потому что она не может честно сказать, что сломается. Применение версии выше поддерживаемой модами отклоняется и указывает моды, которые ее блокируют.

**Отключенные** вами моды не участвуют: сервер их не загружает, поэтому отключение мода — реальный способ обойти блокировщик. Включение или отключение мода помечает отчет для повторной проверки.

Это касается серверов, на которых работают моды: Fabric, Forge, NeoForge и Quilt. Серверы плагинов в стиле Paper сохраняют обычное поведение последнего релиза и не имеют вкладки "Версии", потому что два из реестров, откуда берутся плагины, ничего не публикуют, что проверка могла бы прочитать.

![A version opened, showing which mods would be left behind](/docs/images/server-versions-expanded.png)

Открытие версии сначала перечисляет моды без сборки для нее (те, которые определяют ответ), а готовые моды скрывает за кликом. Большие сборки загружают страницу модов за раз, поэтому сервер с 300 модами открывается так же быстро, как и с пятью модами.

## Изменение версии загрузчика модов

На вкладке **Версии** также есть карточка **Версия загрузчика**. Она показывает, какая сборка Forge, NeoForge, Fabric или Quilt установлена на сервере, и, где ее можно изменить, — селектор для переключения на другую.

- **Сервер Forge, NeoForge, Fabric или Quilt** может запускать любую опубликованную сборку. Селектор перечисляет последние сборки для версии Minecraft сервера, с метками рекомендуемой и последней сборки Forge. **Другая сборка…** принимает любую более старую по ее номеру, а **По умолчанию** возвращает управление серверу.
- **Сборка модов Forge или Fabric CurseForge** устанавливает версию загрузчика, указанную в ее манифесте, поэтому обычный способ изменить ее — обновить сборку. Когда сама сборка указывает неверную версию (мод внутри нее запрашивает более новый Forge, чем устанавливает сборка), карточка может переопределить ее, а **Версия сборки модов** снова удаляет переопределение. Обновление сборки также удаляет его, потому что новая версия объявляет свой собственный загрузчик. Если новая версия по-прежнему указывает неверную, установите переопределение снова.
- **Сборка модов NeoForge CurseForge или сборка модов Modrinth** отображает свой загрузчик, но не может быть переопределена: образ сервера применяет переопределение только к сборкам Forge и Fabric. Ее загрузчик следует за версией сборки, поэтому вместо этого обновите сборку. Загрузчик сборки FTB также нельзя изменить здесь. Его карточка обычно не появляется, потому что собственный установщик FTB ведет записи, которые панель не читает.

Панель проверяет существование сборки, прежде чем что-либо вам предлагать. Сборка Forge или NeoForge делается для одной версии Minecraft, поэтому на сервере, который следует последнему релизу, фиксация одной также сохраняет сервер на текущей версии Minecraft (подтверждение говорит об этом). Выбор **По умолчанию** после этого удаляет фиксацию, но сохраняет эту версию Minecraft. Сервер, который следовал последнему релизу, также может перейти на другой Java-образ при пересборке, тот, который нужен этой версии. Такой сервер, который никогда не запускался, просит сначала запуститься один раз, чтобы панель знала эту версию. Forge пропускает номера сборок (между 47.4.13 и 47.4.15 нет 47.4.14), поэтому мод, который "требует 47.4.14 или выше", удовлетворяется следующей сборкой вверх, и отказ указывает на нее. Изменение требует резервной копии перед обновлением, затем пересборки сервера. Новая сборка устанавливается при следующем запуске сервера, и карточка сообщает об этом до тех пор.

## Отмена обновления мода

Каждая сборка, из которой обновляется мод, остается в общей библиотеке, поэтому обновление, которое что-то ломает, обратимо. Строка мода на вкладке **Моды** получает кнопку **Отменить**, которая возвращает предыдущую сборку. Загрузки нет, поэтому она работает, даже если проект с тех пор был удален из реестра. Сборка, от которой вы отказались, перестает предлагаться до появления более новой.

## Применение обновления

Обновления никогда не бывают бесшумными. Когда вы выбираете обновление сборки (или [переключение на другую версию](/docs/modpacks/#changing-the-pack-version), включая старые), панель:

1. Создает **резервную копию перед обновлением** (чтобы ее можно было отменить; по умолчанию сохраняется последние 10 резервных копий перед обновлением для каждого сервера, см. [хранение](/docs/backups/#retention)).
2. Перефиксирует точную новую версию.
3. Пересобирает сервер, при необходимости перерешая среду выполнения Java.
4. Отслеживает первый запуск с бюджетом времени на платформу.

Если он не запускается нормально, вы откатываетесь к резервной копии перед обновлением. Сервер, отслеживающий стабильные версии, никогда не получает бета-версии, а ссылка на журнал изменений указывает на реальное сравнение версий там, где источник предоставляет его. Неудачное обновление также отправляет [оповещение](/docs/integrations/) Discord, если интеграция настроена.
