Эта версия добавляет настраиваемого администратором чат-бота для каждого управляемого сервера Minecraft. Он подключается к конечной точке чат-завершений, совместимой с OpenAI, включая Ollama на другом хосте локальной сети. Каждый сервер имеет свою собственную конечную точку, модель, имя вызова, персону, политику транскрипции, сообщения для привлечения внимания и политику управления. По умолчанию используется вызов `@wizard`, а персоной по умолчанию является древний, игривый волшебник из мира игры; оба настраиваются.

![Настройки чат-бота](/docs/images/integrations-chatbot.png)

## Опыт игрока

- Любой игрок может использовать `@wizard <сообщение>` (или настроенный вызов) для общения и получения детерминированной помощи по рецептам ванильной игры с учетом версии Minecraft.
- Приветствия при входе и настраиваемая одноразовая проверка во время игрового сеанса напоминают игрокам о доступности чат-бота. `@wizard chat` открывает короткое окно для участия в беседе; `@wizard bye` закрывает его.
- **Обычные пользователи** могут использовать включенные функции для себя/мира. **Контроллеры функций** могут выполнять отдельно проверенные действия, влияющие на другого онлайн-игрока. Игроки, не входящие ни в одну из этих групп, могут только общаться.
- Самостоятельные подарки для обычных пользователей используют разрешенный список предметов. Контроллеры могут дарить другому игроку любой действительный ванильный или модифицированный предмет с пространством имен, при условии соблюдения лимита количества и других мер безопасности функций.

![Транскрипты чат-бота](/docs/images/chatbot-transcripts.png)

## Дизайн и безопасность

Конфигурация и транскрипты доступны только администраторам. Модель никогда не получает необработанный RCON или произвольное выполнение команд. Сообщение раскрывает только один фиксированный инструмент, соответствующий его явному намерению; код сервера проверяет авторизацию, аргументы, флаги, количества, время восстановления и точные имена онлайн-игроков перед выполнением существующей операции службы. Селекторы Minecraft отклоняются, межпользовательские действия не могут быть нацелены на вызывающего абонента, функции начинаются в режиме симуляции, и каждое предпринятое действие регистрируется. Неподдерживаемые модели вызова инструментов возвращаются к обычному общению.

Ответы ограничены для чата Minecraft. Известные ванильные рецепты берутся из прилагаемых данных рецептов с учетом версий и отображаются в виде стабильных строк 2x2/3x3; LLM не доверяют в создании макетов рецептов. Неизвестные или модифицированные рецепты направляют игрока в JEI/REI вместо предоставления вымышленного ответа.

## Основные файлы реализации

- `src/services/wizard.js`: конфигурация для каждого сервера, запросы, совместимые с OpenAI, обработка чата, привлечение внимания, хранение транскриптов и ограничения ответов.
- `src/services/wizardPowers.js`: проверки ролей, схемы инструментов, специфичные для намерений, проверка, выполнение, время восстановления и аудит функций.
- `src/services/wizardRecipes.js`: детерминированный поиск рецептов с учетом версий и форматирование сетки. Данные рецептов и предметов поступают из прилагаемого пакета [`minecraft-data`](https://github.com/PrismarineJS/minecraft-data). (Более ранний черновик этого документа указывал на папку `src/data/recipes/`, которая никогда не была зафиксирована; такой папки нет, и данные находятся в пакете. См. "Зависимости".)
- `src/analytics/ingest.js`: пересылает разобранные входы, выходы и чат игроков чат-боту.
- `src/web/routes/wizard.js`, `public/js/pages/integrations.js` и `views/partials/server/integrations.hbs`: API администратора и пользовательский интерфейс интеграций для каждого сервера.
- `src/db/migrations/011_wizard_chat.js` по `019_wizard_power_controllers.js`: постоянная схема.
- `test/wizard.test.js`: тесты авторизации, границ инструментов, хранения, привлечения внимания и поведения чата.

Внутренние имена маршрутов/модулей/таблиц `wizard` сохраняются для совместимости с обновлениями и API; "chatbot" — это пользовательский термин продукта. Аналогично, сохраненное поле `power_testers_json` соответствует группе **Обычные пользователи** в пользовательском интерфейсе.

## Зависимости (`minecraft-data`)

Помощь по рецептам использует пакет `minecraft-data`. Он занимает много места на диске (около 429 МБ в установленном виде) и поставляется внутри производственного образа, поскольку является зависимостью времени выполнения, а не разработки. Мы оставляем его намеренно, чтобы помощь по рецептам работала в автономном режиме для каждого выпуска Minecraft без сетевых вызовов.

Примечания для того, кто будет смотреть это дальше (человек или ИИ), чтобы размер не стал сюрпризом:

- В настоящее время используется только Java (`pc`) данные. `wizardRecipes.js` читает `minecraftData.versions.pc` и таблицы рецептов, предметов и блоков для каждой версии. Файлы, которые он фактически использует, составляют около 15 МБ для каждой версии pc.
- Около 330 МБ пакета составляют `data/bedrock`, и здесь пока ничего не читается. Мы оставляем его намеренно. Если панель когда-либо добавит поддержку Minecraft Bedrock, данные рецептов и предметов Bedrock уже будут здесь, поэтому функция рецептов сможет расшириться, чтобы охватить серверы Bedrock без добавления новой зависимости. Начните с `minecraftData.versions.bedrock` и следуйте той же структуре, что и путь pc.
- Если размер когда-либо придется уменьшить до появления поддержки Bedrock, в этом репозитории уже есть шаблон для этого. `src/services/itemRegistry.js` извлекает файлы `minecraft-data` из CDN jsDelivr, когда они ему нужны, и кэширует их в `api_cache`. Либо этот подход, либо небольшая подборка файлов из `src/data/recipes/`, охватывающая несколько распространенных версий, значительно уменьшит размер образа.

## Локальное хранилище и ручная проверка

Все настройки и сохраненные транскрипты хранятся в базе данных SQLite панели по адресу `/data/panel.db` внутри контейнера панели. При стандартном монтировании Compose путь хоста будет `${DATA_DIR_HOST}/panel.db` (например, `/opt/msm/data/panel.db`). Соответствующие таблицы: `wizard_configs`, `wizard_transcripts` и `wizard_outreach`; аудиты функций — это строки в таблице `events` с типом `wizard-power`. Необязательный ключ API LLM зашифрован AES-256-GCM с использованием `SESSION_SECRET` панели, обычно сохраняемого как `${DATA_DIR_HOST}/.session-secret`.

Сделайте резервную копию базы данных и остановите панель перед прямым редактированием SQLite, чтобы ее WAL обрабатывался безопасно. Предпочтительнее использовать административный UI/API, поскольку он применяет проверку и шифрование. Сохраняйте файлы `panel.db`, `panel.db-wal` и `panel.db-shm` вместе при копировании активной базы данных.
