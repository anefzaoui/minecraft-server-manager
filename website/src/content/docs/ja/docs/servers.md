## サーバーの作成

ウィザードを開くには、**サーバーを作成**（上部バー）をクリックするか、**サーバーを作成**カードをクリックします。

![サーバーを作成](/docs/images/create-wizard.png)

ウィザードは、管理者がいつでも変更できる設定ページの**新規サーバーのデフォルト値**からJavaヒープとディスククォータを事前入力します。新規サーバーのCPU制限もそこから取得されます。

![新規サーバーのデフォルト値](/docs/images/settings-defaults.png)

以下の項目を選択します。

- **名前**（およびオプションの説明、アイコン、アクセントカラー）。フリートを整理するためのタグは、後でサーバーの設定ページに追加します。
- **サーバータイプ**：**バニラ**タブのVanilla、Paper、またはPurpur。Mod入りサーバーの場合、**Modから**タブでローダー（Fabric、Forge、NeoForge、またはQuilt）、Minecraftバージョン、ローダービルド（最新または特定のもの）を選択し、Modを検索できます。
- **Minecraftバージョン**：`LATEST`、スナップショット、または特定のバージョン（ベータ版とアルファ版を含む）。
- **ゲームポート**：空きポートが提案されます。リモートコンソール（RCON）は（デフォルトで）ポートが1000大きいポートを使用します。後で変更できます（[ゲームポートの変更](#changing-the-game-port)を参照）。
- **リソース**：Javaヒープ（コンテナメモリ制限はそれより50%高く設定されます）とディスククォータ。

**詳細オプション**をクリックすると、サーバーイメージがサポートする他のすべての設定、追加の環境変数、および（管理者向け）詳細なDocker設定が開きます。

Modpackをご希望ですか？ **Modpackから**タブは、代わりにCurseForge、Modrinth、またはGT New Horizonsパックをインストールします（[Modpack](/docs/modpacks/)を参照）。または、**アップロードしたカスタムzip**を使用します。Modrinthの`.mrpack`、CurseForgeのModpackエクスポート（`manifest.json`）、またはMod jarの任意のzipファイルです。マニフェスト（または特定されたjar全体での多数決）がローダーとMinecraftバージョンを埋め込み、すべてのModが1つのタスクでインストールされます。**ブループリントから**タブで保存済みの[ブループリント](/docs/blueprints/)から開始することもできます。

パネルは、選択したバージョンに適したJavaランタイムを自動的に選択し、イメージをプルし、コンテナを作成して起動します。これらすべてが1つのフォームから行われます。

## サーバーリスト

**サーバー**ページには、ステータスと簡単な統計情報とともに、フリート全体が表示されます。

![サーバーリスト](/docs/images/servers-list.png)

## 単一サーバー

![プレイヤー](/docs/images/players.png)

サーバーを開くと、タブ形式のワークスペースが表示されます。

- **概要**：プレイヤーと共有するアドレス、説明、ライブ使用状況、オンラインユーザー。
- **コンソール**：ライブログストリームとコマンド入力、ゲーム内チャット、および[チャットコマンド](/docs/console-and-chat/)。
- **プレイヤー**：プレイヤーリスト、インベントリ、統計情報。
- **Mod**：インストールされているModのリスト、[Modブラウザ](/docs/modpacks/)、およびコンテンツの更新。Mod入りサーバーでは、その**バージョン**サブタブで、どの将来のMinecraftバージョンにModのビルドがあるかを確認できます（[アップデート](/docs/updates/#minecraft-version-compatibility)）。
- **ワールド**：[ワールド、ライブマップ、ファイルマネージャー](/docs/worlds-and-files/)。
- **バックアップ**：このサーバーの[スナップショットと復元](/docs/backups/)。
- **監視**：サーバーごとの履歴とライブメトリクス、クラッシュレポートを含む（下記参照）。
- **設定**：**構成**（サーバーの実行方法に関するすべて）、および[統合](/docs/integrations/)（Discord、ステータスページ、招待、および管理者向けチャットボット）。

開始、停止、再起動のコントロールは、すべてのタブの上部ヘッダーにあります。各タブで実行できることは、そのサーバーでの[権限](/docs/users-and-roles/#per-server-permissions)によって異なります。たとえば、**ファイル**サブタブにはファイル権限が必要であり、コンソールコマンドの送信にはコンソール権限が必要です。

![サーバー概要](/docs/images/server-overview.png)

**ワールドコントロール**レールは、すべてのタブに表示されます。ゲーム内時計、天気、トグルチップとしての一般的なゲームルール、および残りのための「すべてのワールドルールを表示」です。

![ワールドコントロール](/docs/images/world-controls.png)

**監視 → ライブ**には、TPSとミリ秒/ティック、クラッシュ（過去24時間および7日間）、メモリ不足による終了、自動再起動を含むヘルスと安定性のカード、およびワールドごとのサイズが表示されます。

![ライブ監視](/docs/images/monitoring-live.png)

## サーバー設定

**設定 → 構成**は、完全な構成インターフェースです。名前、説明、MOTD、アイコン、色とタグ、リソース、ゲームポート、アップデートポリシー、パネル起動時の開始とクラッシュ時の自動再起動、サーバーイメージがサポートするすべての環境変数、詳細なDocker設定、およびブループリントのエクスポート、クローン、再構築、削除。サーバーを再構築した後にのみ有効になる変更はすぐに保存され、待機状態になります。サーバーのヘッダーに**変更を適用**ボタンが表示され、次回サーバーが起動したときにも適用されます。

**クラッシュ時の自動再起動**は、クラッシュしたサーバーを再度起動します。試行ごとに待機時間を長くし（5秒、10秒、その後20秒）、10分以内に3回の試行後に停止します。セットアップの問題（EULA、間違ったJava、新しいバージョンからのワールド、使用中のポート、メモリ不足、CurseForgeキーの欠落）としてパネルが認識したクラッシュはスキップします。これらは最初に修正が必要だからです。他のアクションがサーバーでビジー状態の場合（バックアップ、復元、ポート変更）、最大30分待機し、誰かが自分でサーバーを停止または開始するとすぐに中止します。

直接の設定変更は、常に再起動をまたいで保持されます。**ワールドコントロール**レールで行われたPvPまたは難易度の変更、**プレイヤー**タブでのホワイトリストの切り替え、または**ファイル**エディタでの`server.properties`の編集は、対応する環境変数を削除し（設定されていた場合）、サーバーを再構築するようにマークするため、コンテナイメージが次回の起動時に再アサートされるのではなく、ディスク上の値が優先されます。

![サーバー設定](/docs/images/server-settings.png)

**メモリメーターについて。**「RAM（Javaヒープ）」は、Javaに開始時および最大ヒープの両方として渡され、JavaはAikar / MeowIceフラグプリセットの有無にかかわらず、最初に与えられたヒープを1分以内に満たします。そのため、メモリメーターは約ヒープサイズで安定し、誰もプレイしていないときでもそこに留まります。メーターの目盛りは、ヒープがコンテナ制限の下でどこにあるかを示し、その下の注記がそれを伝えています。メモリが実際の使用量に追従するのを見たい場合は、**設定 → 構成**の**リソース**カード（またはウィザードの**詳細オプション**）で、サーバーに小さい開始ヒープ（例：512 MB）を与えてください。2 GBのヒープで、アイドル時の使用量が測定で2.6 GBから約1.3 GBに減少しました。Javaはヒープ外のメモリ（バニラで約0.5 GB、大規模なModpackで1.5〜2 GB）も必要とします。これはコンテナ制限のヘッドルームがそのためのものです。数値については、READMEの「2つのメモリ制限」を参照してください。

> **詳細Docker設定**（コンテナ名、Dockerネットワーク、追加のポートマッピング、追加のボリュームバインド）は、バインドマウントとパネルのDockerアクセスがホスト上のルートと同等であるため、**管理者のみ**です。 [ユーザーとロール](/docs/users-and-roles/)を参照してください。

### ゲームポートの変更

**設定 → 構成**の**ゲームポート**カードは、いつでもサーバーを別のポートに移動でき、独自の**ポートを保存**ボタンがあります。**次の空きポートを使用**は、最も低い空きポートを選択し、カードは入力したポートを保存前にチェックします。RCONは常にゲームポートより1000大きいポート（デフォルトオフセット）に従います。管理者は1024以上の任意のポートを選択できます。それ以外のユーザーは、最初のゲームポート（デフォルトでは25565）以上のポートを選択します。保存するとすぐに変更が適用されます。停止したサーバーは移動するだけで、実行中のサーバーは最初に確認を求め、その後新しいポートで再起動します（ワールドは最初に保存され、プレイヤーは新しいポートで再接続します）。新しいポートでサーバーが起動できない場合、古いポートに戻ります。他の変更が**変更を適用**を待っている間、ポートの変更は拒否されるため、まずそれらを適用してください。ポートの変更には、そのサーバーの**設定**権限が必要です。

![ゲームポートカード](/docs/images/server-port.png)

![実行中のサーバーが新しいポートで再起動する前のプロンプト](/docs/images/port-restart.png)

## クラッシュレポートとmclo.gs分析

クラッシュレポート（`crash-reports/*.txt`およびJVM `hs_err_pid*.log`ファイル）は自動的に収集され、例外と疑わしいModを含む1行の概要に解析され、**監視 → 履歴**の下にリストされます。

![クラッシュレポートカード](/docs/images/crash-mclogs-card.png)

各レポートカードには、組み込みビューア（折りたたみ可能なセクションとハイライトされた例外付き）、スタックトレースのコピー、ダウンロード、および2つの[mclo.gs](https://mclo.gs)アクションがあります。

- **mclo.gsに共有**は、レポートを公開ペーストとして公開し、リンクをコピーします。これは、Mod作成者やサポートDiscordが要求するものです。リンクはレポートに記憶されるため、何も二度とアップロードされません。
- **分析**は、mclo.gsの自動インサイトをペーストに対して実行します。既知の問題と提案された修正（依存関係の欠落、バージョンの不一致、一般的なModの競合）がパネル内に直接表示されます。

![mclo.gsインサイト](/docs/images/crash-insights.png)

両方のアクションは明示的な確認の後ろにあり、ペーストは公開されるためです。クラッシュレポートにはプレイヤー名と完全なModリストが含まれる場合があります。パネルは何も自分でアップロードしません。
