## ライブコンソール

**コンソール**タブは、サーバーログをリアルタイムでストリーミングし、コマンドを送信するためのコマンドボックスを提供します。`docker exec`やSSHは不要です。出力はインラインで、色付けされたまま返されます。コマンドの送信には、そのサーバーでのコンソール権限が必要です。それがない場合でも、ログを監視することはできます。

ログの上部では、テキスト（または`/正規表現/`）とレベル（INFO、WARN、ERROR）でログ行をフィルタリングできます。また、**ダウンロード**では、最近の出力、完全な`latest.log`、またはすべてのログファイルをzip形式で提供します。

![コンソール](/docs/images/server-console.png)

コンソールは、パネルがサーバーの状態を読み取る場所でもあります。ログを監視して起動フェーズ（「Loading mods」、「Generating world」、「Finishing startup」）を分類し、`list`を呼び出してオンラインプレイヤーを追跡するため、ダッシュボードとサーバーカードは常に実際の状態を反映します。

このポーリングは、サイクルごとに短命なRCON接続を開きます。これは、サーバーログでは約20秒ごとに`Thread RCON Client … started` / `shutting down`のペアとして記録され、（コアまたはプラグインがエコーするサーバーでは）読み取り専用のポーリング（プレイヤー数を数えるための`list`、ワールドコントロールが開いている間の`time query …`および`gamerule <name>`の読み取り）ごとに`Rcon issued server command: …`行として記録されます。ログの上部にある**コンソールノイズを非表示**トグルは、これらの行（RCONリスナーの起動行を含む）をフィルタリングします。これはデフォルトでオンになっており、ブラウザごとに記憶されます。生のストリームを表示するにはオフにしてください。

パネルから送信されたコマンドは、サーバーごとに設定されたラベル（**～としてアナウンス…**ボックス）の下でゲーム内にアナウンスできるため、プレイヤーはオペレーターが操作したことを、正体不明のコンソールではなく認識できます。

## チャット

**コンソール → チャット**は、サーバー実行中にゲームにメッセージを送信します。**スタイル付き**メッセージは色とフォーマットを取り、全員またはオンラインの1人のプレイヤーに送信できます。**プレーン**は、シンプルな`[Server]`ブロードキャストを全員に送信します。

![コンソール → チャット](/docs/screenshots/04-chat.png)

## チャットコマンド

チャットコマンド（**コンソール → コマンド**）を使用すると、プレイヤーはゲームチャットにプレフィックスコマンドを入力することで、パネルのアクションをトリガーできます。たとえば、ランダムテレポートのために`!spawn`を使用します。検出はログベースであり、実行はサーバーを経由するため、**MODは不要**です。

![チャットコマンド](/docs/images/chat-commands.png)

各コマンドには以下が含まれます：

- **トリガー**（例：`spawn`）：サーバーの**プレフィックス**（デフォルトは`!`、1〜2文字、`/`ではない）の後に入力します。
- **アクション**：ランダムテレポート、構造物へのテレポート、バイオームへのテレポート、または生のコンソールコマンドの実行。
- **権限レベル**：全員、ホワイトリスト登録されたプレイヤー、またはオペレーターのみ。
- プレイヤーごとの**クールダウン**（デフォルトは30秒）、およびプレースホルダー（例：`{distance}`）を含むカスタマイズ可能な保留中/成功/失敗メッセージ。

### 安全性に関する注意

サーバーを破壊する可能性のあるコマンド（`stop`、`op`、`ban`、`whitelist`など）は、**オペレーターのみ**のトリガーでのみ許可されます。パネルは、`execute … run …`チェーンにネストされている場合でもこれらのコマンドをチェックするため、低権限のトリガーが危険なコマンドを密かに実行することはできません。`say`メッセージのように、単にこれらの単語に言及する通常のチャットテキストはそのままにされます。
