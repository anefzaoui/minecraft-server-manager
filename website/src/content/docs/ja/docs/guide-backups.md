ほとんどのサーバーにはバックアップがあります。しかし、実際に機能するバックアップを持っているサーバーは少なく、その違いが明らかになるのは最悪の事態が発生した時だけです。それらを分ける3つの要素は、コピーが整合性を保っていること、別の場所に保管されていること、そして少なくとも一度は復元されたことがあることです。

## ワールドへの書き込みがない間にコピーする

稼働中のサーバーは、リージョンファイルを継続的に書き込みます。書き込み中にコピーすると、古い部分と新しい部分が混在したファイルになり、ロードに失敗するか、誰かの拠点があった場所に穴が開いた状態でロードされる可能性があります。コピーは成功したように見えても、警告は何もありません。

コピーを取得するための正しい方法は2つあります。

1.  **サーバーを停止し**、コピーしてから再起動します。シンプルで確実ですが、ダウンタイムがあるため不評です。
2.  **ゲームに書き込みを停止するように指示します。** `save-off` を実行し、次に `save-all flush` を実行して完了を待ち、コピーしてから `save-on` を実行します。コピー中はワールドが完成し、静止状態になります。

コピーをスキップしてはいけません。ファイルシステムやボリュームレベルのスナップショットは、それが真にアトミックである場合にのみ有効であり、プレイヤーがブロックを配置している最中の `cp -r` はそうではありません。

## ワールド以外もバックアップする

ワールドだけを復元しても、地形は手に入りますがサーバーは失われます。他に以下のものも必要です。

- `server.properties` およびルールを設定するその他のファイル。
- 実行されていた正確なバージョンのMODまたはプラグインJARファイル。ワールドは、そのブロックを作成したMODなしではロードされません。
- `whitelist.json`、`ops.json`、および統計情報と実績のフォルダを含むプレイヤーデータ。
- パックから導入した場合は、パックのバージョン。書き留めておくことが重要です。

バックアップの最も簡単な健全性チェック：アーカイブだけでこのサーバーを新規マシンに再構築できますか？答えが「そして、再インストールします」で始まる場合、それは完全なバックアップではありません。

## 同じディスク上の1つのコピーはバックアップではない

保護対象のマシンと同じ場所にあるバックアップは、削除されたものを復元するという1つの障害しかカバーしません。ディスクの故障、プロバイダーによるアカウントの一時停止、またはディレクトリ全体を削除するような間違いには対応できません。

完璧を目指すよりもシンプルに保ちましょう。

- 一般的なケース（誰かが荒らしたり、アップデートが失敗したりした場合）のためのローカルコピー1つ。
- 別の場所へのコピー1つ。別のマシン、オブジェクトストレージ、またはSSH経由で夜間にプルするホームNAS。
- すぐに気づかなかった問題から回復するのに十分な履歴。破損は数日後に発見されることが多く、3日分のバックアップを保持している場合、すでに良いものを上書きしています。

7日分のデイリーバックアップと4日分のウィークリーバックアップがあれば、ほぼすべての実際のインシデントに対応でき、スペースもほとんど消費しません。

## 復元を必要になる前にテストする

バックアップを選択し、スペアサーバーに復元して参加します。これがテストのすべてであり、15分で完了し、MODフォルダが欠けているアーカイブ、実行しなくなったバージョンが必要なワールド、ファイルを読み取れなくする権限、破損したアップロードなど、古典的なすべての障害を検出できます。

バックアップを設定したときに一度、サーバーに大きな変更を加えた後に再度実行してください。

## サイズと、それを健全に保つ方法

プレイヤーが探索することでワールドは成長します。誰かが直線で1万ブロック飛行したワールドは、その線上のすべてのチャンクを永遠に保持し、そのほとんどのチャンクは二度と訪問されることはありません。

3つのレバーがあり、効果の大きい順に並べられています。

1.  **未訪問チャンクのトリミング。** 最終アクセス時間でプルーニングするツールは、通常、よく移動されたワールドの大部分を、プレイ中に目に見える影響なしに削除します。
2.  **適切に圧縮する。** リージョンファイルはよく圧縮されます。それらのアーカイブには、特殊な圧縮はあまり効果がありません。
3.  **1年分のすべての時間ごとのコピーを保持しない。** 保留期間は圧縮よりも重要です。

## Minecraft Server Manager におけるバックアップ

バックアップは `save-off`、flush、コピー、`save-on` のパスを使用し、バックアップ中に要求された停止または再起動は、コピーが完了するまで拒否され、競合しません。アーカイブはサーバーディレクトリ全体をカバーするため、MOD、設定、プレイヤーデータはワールドと一緒に移動します。

バックアップは、再起動やコマンドと並行してスケジュールで実行でき、すべての新規サーバーはデイリーバックアップスケジュールで開始されます。保持期間は各種類を個別にカウントするため、自分で手動で取得したバックアップを、リスクの高い変更の前に削除してしまうことなく、自動的に蓄積された10個のスケジュールされたコピーが押し出すことはありません。また、年齢とサイズの制限も適用されます。管理者は、設定ページまたは各サーバーのバックアップタブでこれらすべてを変更できます。復元はまず新しいバックアップから行われるため、間違った時点への復元自体は元に戻すことができます。ワールドは単独で、またはバックアップの一部として縮小でき、これはサイズに関して最も重要なレバーです。

すべてのバックアップを含むパネル全体は、1つのディレクトリの下にあります。そのディレクトリを別の場所にコピーすることが、オフマシンでのバックアップの半分であり、コピーする必要がある唯一のものです。
