このパネルは、管理対象の各 Minecraft サーバー用に管理者が設定できるチャットボットを提供します。これは、サーバーの **設定 → チャットボット** タブでセットアップされます。これは、Ollama を別の LAN ホストで実行している場合を含め、OpenAI 互換のチャット補完エンドポイントに接続します。各サーバーには、独自のエンドポイント、モデル、呼び出し名、ペルソナ、トランスクリプトポリシー、アウトリーチメッセージ、およびパワーポリシーがあります。デフォルトの呼び出し名は `@wizard` で、デフォルトのペルソナは古代の遊び心のあるインワールドウィザードを模倣していますが、どちらも編集可能です。

![チャットボット設定](/docs/images/integrations-chatbot.png)

## プレイヤー体験

- どのプレイヤーでも `@wizard <メッセージ>`（または設定された呼び出し名）を使用して会話や、Minecraft のバージョンを認識した決定論的なバニラレシピのヘルプを利用できます。
- 参加時の挨拶と、設定可能な一度限りのプレイセッション確認により、プレイヤーはチャットボットが利用可能であることを思い出させます。`@wizard chat` は短いオプトイン会話ウィンドウを開き、`@wizard bye` はそれを閉じます。
- **一般ユーザー**は、有効化された自己/ワールドパワーを呼び出すことができます。**パワーコントローラー**は、オンラインの別のプレイヤーに影響を与える個別に検証されたアクションを呼び出すことができます。どちらのグループにも属さないプレイヤーは、会話のみに限定されます。
- 一般ユーザーによる自己ギフトは、アイテムの許可リストを使用します。コントローラーは、数量制限やその他のパワーセーフガードの対象となる、有効な名前空間付きのバニラまたは改造アイテムを別のプレイヤーに与えることができます。

![チャットボットトランスクリプト](/docs/images/chatbot-transcripts.png)

## 設計とセキュリティ

設定とトランスクリプトは管理者のみがアクセスできます。モデルは生の RCON や任意のコマンド実行を受け取ることはありません。メッセージは、その明示的な意図に一致する単一の固定ツールのみを公開します。サーバーコードは、既存のサービス操作を実行する前に、承認、引数、フラグ、数量、クールダウン、および正確なオンラインプレイヤー名を検証します。Minecraft セレクターは拒否され、クロスプレイヤーアクションは呼び出し元をターゲットにできず、パワーはドライランモードで開始され、試行されたすべてのパワーは監査されます。サポートされていないツール呼び出しモデルは、会話のみにフォールバックします。

Minecraft チャットの応答は制限されています。既知のバニラレシピは、バンドルされたバージョン管理されたレシピデータから取得され、安定した 2x2/3x3 のグリッドとしてレンダリングされます。LLM はレシピレイアウトを作成するようには信頼されていません。不明なレシピまたは改造されたレシピは、回答を捏造するのではなく、プレイヤーを JEI/REI に誘導します。

## 主要な実装ファイル

- `src/services/wizard.js`: サーバーごとの設定、OpenAI 互換リクエスト、チャット処理、アウトリーチ、トランスクリプト保持、および応答制限。
- `src/services/wizardPowers.js`: ロールチェック、意図固有のツールスキーマ、検証、実行、クールダウン、およびパワー監査。
- `src/services/wizardRecipes.js`: 決定論的なバージョン管理されたレシピルックアップとグリッドフォーマット。レシピとアイテムデータは、バンドルされた [`minecraft-data`](https://github.com/PrismarineJS/minecraft-data) パッケージから取得されます。（このドキュメントの以前のドラフトでは、コミットされなかった `src/data/recipes/` フォルダを指していましたが、そのようなフォルダはなく、データはパッケージ内にあります。「依存関係のフットプリント」を参照してください。）
- `src/analytics/ingest.js`: 解析された参加、離脱、およびプレイヤーチャットをチャットボットに転送します。
- `src/web/routes/wizard.js`、`public/js/pages/integrations.js`、および `views/partials/server/integrations.hbs` (`chatbot.hbs` 経由): 管理 API とサーバーごとの設定 → チャットボットタブ。
- `src/db/migrations/011_wizard_chat.js`、`013_wizard_invocation_name.js`、`015_wizard_powers.js`、`017_wizard_outreach.js`、および `019_wizard_power_controllers.js`: 永続スキーマ。
- `test/wizard.test.js`: 承認、ツール境界、保持、アウトリーチ、およびチャット動作テスト。

内部の `wizard` ルート/モジュール/テーブル名は、アップグレードおよび API 互換性のために保持されています。「chatbot」はユーザー向けの製品用語です。同様に、保存されている `power_testers_json` フィールドは、UI の **一般ユーザー** グループに対応します。

## 依存関係のフットプリント (`minecraft-data`)

レシピヘルプは `minecraft-data` パッケージを使用します。ディスク上で大きいです（インストール済みで約 429 MB）。これは実行時依存関係であり、開発依存関係ではないため、本番イメージに含まれています。ネットワーク呼び出しなしで、すべての Minecraft リリースでレシピヘルプがオフラインで機能するように、意図的に保持しています。

このサイズが驚きにならないように、次にこれを確認する人（人間または AI）向けの注意点：

- 現在使用されているのは Java (`pc`) データのみです。`wizardRecipes.js` は `minecraftData.versions.pc` と、バージョンごとの `recipes`、`items`、`blocks` テーブルを読み取ります。実際に触れるファイルは、すべての pc バージョンで合計約 15 MB です。
- パッケージの約 330 MB は `data/bedrock` であり、現時点では何も読み取っていません。意図的にそのまま残しています。将来的にパネルが Bedrock Minecraft のサポートを追加する場合、Bedrock のレシピとアイテムデータはすでに存在するため、新しい依存関係を追加せずにレシピ機能が Bedrock サーバーをカバーするように拡張できます。`minecraftData.versions.bedrock` から開始し、pc パスと同じ形状をたどってください。
- Bedrock サポートが利用可能になる前にサイズを削減する必要がある場合は、このリポジトリにすでにパターンがあります。`src/services/itemRegistry.js` は、必要なときに jsDelivr CDN から `minecraft-data` ファイルを取得し、`api_cache` にキャッシュします。このアプローチ、または少数の一般的なバージョンをカバーする小さな手動選択された `src/data/recipes/` サブセットのいずれかにより、イメージは大幅に縮小されます。

## ローカルストレージと手動検査

すべての設定と保持されたトランスクリプトは、パネルコンテナ内のパネル SQLite データベース `/data/panel.db` に保存されます。標準の Compose マウントを使用すると、ホストパスは `${DATA_DIR_HOST}/panel.db`（例：`/opt/msm/data/panel.db`）になります。関連するテーブルは `wizard_configs`、`wizard_transcripts`、および `wizard_outreach` です。パワー監査は、タイプ `wizard-power` を持つ `events` テーブルの行です。オプションの LLM API キーは、パネルの静止時キー（データフォルダ内の `.secret-key`、`SESSION_SECRET` とは別）で AES-256-GCM 暗号化されます。

直接 SQLite を編集する前にデータベースをバックアップし、パネルを停止して WAL が安全に処理されるようにしてください。管理 UI/API の使用が推奨されます。これは検証と暗号化を適用するためです。ライブデータベースをコピーする際は、`panel.db`、`panel.db-wal`、および `panel.db-shm` ファイルをまとめてください。
