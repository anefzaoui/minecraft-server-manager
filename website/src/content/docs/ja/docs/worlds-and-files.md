## ワールド

**ワールド**ページでは、サーバー間のワールドデータを管理します。アクティブなワールドの切り替え、ワールドのアップロード、またはダウンロードが可能です。

![Worlds](/docs/images/worlds.png)

## ファイルマネージャー

サーバーの**ワールド**セクションの下にある**ファイル**タブは、そのサーバーのデータディレクトリ用の完全なブラウザ内ファイルマネージャーです。ファイルのリスト表示、読み取り、編集、作成、名前変更、移動、コピー、削除、アップロードが可能です。SSH経由で通常行うすべての操作をブラウザから実行できます。

![File manager](/docs/images/server-files.png)

テキストファイルは2MBの制限付きでエディタで開かれます。それより大きいファイルはダウンロードできます。アップロードは一度に複数のファイルを受け付けます。

### サンドボックス内での操作

すべてのファイル操作は、サーバー固有のデータディレクトリ内に限定されます。パネルは各パスを解決し、ディレクトリ外へのアクセスを拒否します。`..`トラバーサル、絶対パス、さらにはディレクトリ外を指すシンボリックリンク（存在しないものも含む）も拒否されます。これにより、MODやプラグインがファイルマネージャーを欺いてホスト上の別の場所を読み書きすることを防ぎます。

## MOD

MOD導入サーバーの場合、**MOD**タブ（サーバーサイドバー内の独立したグループ）でMODセットを管理します。MODの参照と追加、およびインストール済みのMODの確認ができます。MODやパックのアップデートは、[アップデート](/docs/updates/)ページに表示されます。

### MODの追加

![Mods](/docs/images/mods.png)

MODの追加方法は4つあり、すべてMODタブのツールバーから実行できます。

- **MODを検索** - **ModrinthまたはCurseForge**を検索します（CurseForgeのチップは、設定 → APIキーにAPIキーが保存されると表示されます）。プラグインサーバーでは、**Hangar**（PaperMC独自のプラグインレジストリ）および**SpigotMC**（SpigetのCDNプロキシ経由）も検索できます。これらはキー不要です。すべてサーバーのローダーとMinecraftバージョンにフィルタリングされます。Quiltサーバーは、QuiltがFabric MODを実行するため、Fabricタグ付きビルドも自動的に表示します。すでにサーバーにある結果には**インストール済み**バッジが表示されます。CurseForgeの作者が自動ダウンロードを許可していない場合、またはSpigotMCのリソースが外部でホストされている場合は、パネルが事前に通知し、インストール中に失敗する代わりに**ページを開く** + **jarをアップロード**のパスを提供します。

  ![Hangar search](/docs/images/mods-search-hangar.png)

- **zipをインポート** - 1つのボタン、3つの形状、自動検出：
  - **Modrinth MODパック (`.mrpack`)**：ピン留めされたすべてのファイルは、ハッシュルックアップを通じてModrinthプロジェクトに正規化されます（これにより、インポートされたMODは実際の名前、アイコンを保持し、アップデートチェック可能になります。Modrinthが知らないファイルはパック自体のURLからインストールされます）。ダウンロード中にパックのsha512チェックサムに対して検証され、適合判定とともにプレビューされます。クライアント専用ファイルは目に見える形でスキップされ、オーバーライドツリー（`overrides/`、次に`server-overrides/` - サーバー固有のコピーが優先されます）が適用されます。

    ![mrpack import](/docs/images/mrpack-import.png)

  - **CurseForge MODパックのエクスポート**（CurseForgeアプリが生成するzip、`manifest.json`を含む）：ピン留めされたすべてのMODは一括で解決され、警告とともにプレビューされます（このサーバーに不適切なローダー/MC、CurseForgeに存在しなくなったファイル、手動ダウンロードが必要なMOD）。実際の進捗とともにインストールされます。パックの`overrides/`（設定、スクリプト）もオプションで適用できます。上書きされる可能性のあるファイルは、サーバーフォルダ内の`.import-backups/<タイムスタンプ>/`に最初にバックアップされます。
  - **自分で収集したjarのプレーンzip**：各jarは識別され（Modrinthハッシュ一致 → CurseForgeフィンガープリント → jar自体のメタデータ）、サーバーに対して評価されます - _適合 / 不適切なローダー / 不適切なMCバージョン / すでにインストール済み / 不明_ - そのため、インストール前に実際に必要なものを選択できます。
- **リンクから追加** - ほぼ何でも貼り付けられます：Modrinth、CurseForge、Hangar、またはSpigotMCのプロジェクトページ、GitHubリポジトリまたはリリースURL（単純な`owner/repo`でも可 - GitHubは最新の安定リリースを優先し、`-sources`/`-javadoc`サイドカーjarはスキップします）、Modrinthのスラッグ、または任意の直接的な`.jar` URL。パネルはサーバーのローダーとMCバージョンに合った正しいビルドを解決します。

  ![Add by link](/docs/images/mods-add-by-link.png)

- **jarをアップロード**（検索フォールバックまたは保留中のダウンロードリゾルバーから） - アップロードされたjarは同じ方法で識別されるため、実際の名前、バージョン、アイコンを保持し、アップデートチェック可能になります。

すべてのレジストリインストールは、**ダウンロード中にチェックサム検証されます**：ストリームは、レジストリが公開する最も強力なダイジェスト（sha512 → sha256 → sha1 → md5）に対してチェックされ、不一致が発生した場合はサーバーに何も着陸する前に中止されます。

zip全体（`.mrpack`を含む）で**サーバーを作成**することもできます：ウィザードの_MODパックから_タブで、それをアップロードすると、パックマニフェスト（または識別されたjar間の多数決）がローダー、Minecraftバージョン、およびローダービルドを埋め込みます。
