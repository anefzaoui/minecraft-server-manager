Minecraft Server Manager は、単一プロセスでサーバーレンダリングされる Node.js アプリケーションです。
[itzg/docker-minecraft-server](https://github.com/itzg/docker-minecraft-server) イメージを使用して Docker コンテナとして実行される Minecraft サーバーを管理します。
Docker デーモンとは、その API を介して通信します（`docker` CLI をシェルアウトすることはありません）。

## ランタイムの構成

- **Express + Handlebars**: ページをサーバーサイドでレンダリングします。SPA はありません。`public/js/` のブラウザ JS は、手書きのプログレッシブエンハンスメントです。esbuild ステップ (`pnpm run build:js`) がそれをバンドルおよびミニファイして `public/dist/js/` に出力します。アプリは、それが存在する場合にそのバンドルを、それ以外の場合は生のソースを提供するため、ビルドなしの開発実行でも機能します。
- **`node:sqlite`** (Node に組み込まれています。パネルは Node ≥ 24 を必要とします): データベースです。同期式で、ネイティブモジュールはゼロ、WAL モードです。小さなバージョン化されたマイグレーションランナーが、起動時に `src/db/migrations/*` を適用します。プリペアドステートメントは、SQL テキストをキーとして `src/db/index.js` にキャッシュされます。
- **`ws`**: ライブコンソールと統計ストリームを伝送します。どちらも**仲介**されます。サーバーごとに 1 つの上流 `docker logs --follow` (または `docker stats`) があり、一度デマルチプレクスされ、接続されているすべてのタブにファンアウトされます。ビューアごとに 1 つの上流ではありません。コンソールブローカーは、遅れて参加するタブのために小さなリプレイバッファを保持し、共有ストリームを遅延させるのではなく、ソケットが遅れすぎたサブスクライバーをドロップします。
- **`dockerode`**: アプリが Docker と通信する唯一の方法です。エンドポイントはプラットフォームごとに自動検出されます（Windows 名前付きパイプ対 Unix ソケット）。
- **すべての永続状態は 1 つのディレクトリの下にあります** (`$DATA_DIR`、デフォルトは `./data`)。そのディレクトリをコピーすると、パネル全体が移行されます。

## レイヤリング

依存関係は一方向に流れます。

```
                 ┌─────────────────────────────┐
   HTTP  ───────▶│  web/routes/*  (+ ミドルウェア)│   入力を解析・検証し、応答を整形します
                 └──────────────┬──────────────┘
                                │
                 ┌──────────────▼──────────────┐
                 │         services/*          │   ドメインロジック（実際の機能）
                 └───┬─────────┬─────────┬─────┘
                     │         │         │
        ┌────────────▼──┐ ┌────▼────┐ ┌──▼──────────┐
        │   docker/*    │ │  db/*   │ │  storage/*  │   インフラストラクチャ
        └───────────────┘ └─────────┘ └─────────────┘
```

- **`web/routes/`**: ドメインごとに 1 つのルーター（`servers`, `players`, `worlds`, `crashes`, `blueprints`, `files`, …）があり、`web/app.js` にマウントされます。ルーターは zod で検証し、サービスを呼び出し、JSON を返すかビューをレンダリングします。ビジネスロジックはここには属しません。2 つのルーターが**公開ゾーン**にマウントされます。`requireAuth` の前です。`routes/status.js` (サーバーごとの HTML ステータスページ、オプトイン) と `routes/apiV1.js` (`/api/v1`、管理者発行の Bearer トークンで認証された読み取り専用 JSON API、`services/apiTokens.js` から、設定で有効になっていない限りオフ。`docs/public-api.md` を参照)。
- **`services/`**: アプリケーションの心臓部です。各サービスは 1 つのドメインを所有し、インフラストラクチャや他のサービスに依存する場合があります。
- **`docker/`**: dockerode ラッパー: `connect` (エンドポイント検出 + デーモンの正常性)、`containers` (バインドマウント、メモリ/CPU 制限、ラベル付きでの作成/開始/停止/再作成)、`logs`、`stats`、`images`、および Docker イベントを履歴 + クラッシュ検出に変換する `watcher`。
- **`db/`**: SQLite ラッパーとマイグレーションランナー。
- **`storage/`**: `./data` のブートストラップ、**パスガード** (`safeJoin`、ファイルセキュリティのバックボーン)、およびバックグラウンドサイズインデクサー + クォータ強制。

横断的な処理:

- **`config/`**: 環境設定に加えて、**フィールドカタログ**: サーバー設定の単一の真実の情報源です。すべての itzg 環境変数がカタログ化されています（ラベル、ヘルプ、タイプ、単位、デフォルト、検証、セクション、危険フラグ）。ウィザード、設定フォーム、および zod 検証はすべてこれらから派生しているため、新しい設定を公開することは、新しい UI の配管ではなく、データ変更です。
- **`events/`**: `recordEvent()` は履歴ログへの唯一のエントリポイントです。ライフサイクルイベントは、コンテナログの抜粋も `data/logs/<id>/events/` にキャプチャします。
- **`ws/`**: 認証されたコンソール + 統計 WebSocket (アップグレード時にセッション Cookie を検証、`Origin` をチェックしてクロスサイトハイジャックをブロック)、サーバーごとに仲介されます（「ランタイムの構成」を参照）。
- **`logger.js` + `instrument.js`**: `require('./logger')(label)` は、モジュールごとの [Pino](https://getpino.io) ロガーを返します。レベルは `LOG_LEVEL` から取得されます。`makeFailureThrottle()` は、持続的に失敗するバックグラウンドループを 1 行のログと「回復済み」行に抑えます。`src/utils/logSanitize.js` は、構造化されたメタデータから資格情報形式のキーと Webhook トークンを赤化します。`src/config/logLevel.js` は共有レベルの許可リストです（`config` との循環参照を避けるために分離されています）。`src/instrument.js` は休眠中の Sentry シームであり、`src/server.js` で最初にロードされます。`src/web/middleware/requestLog.js` はリクエストごとに 1 行のアクセスログを書き込みます（`/healthz` と静的アセットはスキップ）。ESLint は `src/**` の下で `no-console` を強制しますが、`preflight.js`、`instrument.js`、および `config/index.js` は例外です（これらはロガーが存在する前に実行されます）。
- **レート制限**: `src/web/middleware/rateLimit.js` は、`express-rate-limit` を `/api` (`RATE_LIMIT_API_PER_MIN`、デフォルト 1200) およびログイン / 2FA / セットアップ POST (`RATE_LIMIT_AUTH_PER_15MIN`、デフォルト 100) の前に配置します。`0` はリミッターを無効にします。`req.ip` をキーとするため、プロキシの後ろでは `TRUST_PROXY` が重要です。`/api/v1` には、独自のトークンごとのリミッター (`RATE_LIMIT_PUBLIC_API_PER_MIN`、デフォルト 120) があり、Bearer トークンのハッシュをキーとし、IP フォールバックがあります。`src/web/middleware/auth.js` の別のトークンごとのソフトカウンターは、ログインロックアウト（IP ごとおよびアカウント全体、減衰あり）を処理します。

## 主要なドメインの動作

- **Modpack は常にピン留めされます。** イメージは、ピン留めされていないパックを再起動ごとに自動アップグレードするため、パネルはインストール時に「latest」を具体的なバージョン ID に解決し、ピン留めします。アップグレードは明示的なオーケストレーションフローです（`updates/`）：プレビュー → アップデート前バックアップ → グレースフル停止 → 再ピン留め → 再作成 → ヘルスモニター → ワンクリックロールバック。
- **カスタム Mod オーバーレイ**はパネル管理です。ユーザーが追加した Mod は、重複排除されたライブラリに着陸し、サーバーにハードリンクされるため、パックの更新後も存続します。無効化はクラスを認識します。
- **ポート**はベーススキームから割り当てられます（ゲームは `PORT_GAME_START` 以降、RCON = ゲーム + `PORT_RCON_OFFSET`、Bedrock は `PORT_BEDROCK_START` から）。利用可能性がプローブされ、DB で予約されます。
- **ディスククォータ**はパネルによって強制されます。Docker はバインドマウントの使用量を制限できないためです。インデクサーはディレクトリごとのサイズをキャッシュし、ディスク拡張操作はそれらにゲートされます。
- **シークレット**（RCON パスワード、API キー、TOTP シークレット、Discord Webhook URL）は、専用のランダムキー `$DATA_DIR/.secret-key`（モード `0600`、自動生成）を使用して AES-256-GCM で暗号化されて保存されます。これは `SESSION_SECRET` とは独立しています。`SESSION_SECRET` から派生したキーは、専用キーが存在する前に書き込まれた値の復号専用フォールバックとして保持され、`src/services/secretsMigration.js` は起動時にそれらを専用キーの下で 1 回再暗号化します。解析できない `.secret-key` が存在する場合、起動時に致命的なエラーとなります（上書きされてサイレントに再生成されることはありません）。ブループリントはエクスポート時にすべてのシークレットを削除します。

## データとワイヤフォーマット

- **`data/panel.db`**: SQLite データベース。毎日 `VACUUM INTO` を使用して `data/backups/_panel/` にスナップショットされます（最新の 14 件を保持）。`PRAGMA integrity_check` は起動時に実行されます。
- **`data/.session-secret`**: 自動生成された Cookie サインシークレット。初回実行時に `SESSION_SECRET` が設定されていない場合に作成されます。これを削除するとシークレットがローテーションされ（セッションが無効になります）。
- **`data/.secret-key`**: 専用の 32 バイト保存暗号化キー（モード `0600`）、初回実行時に自動作成されます。`SESSION_SECRET` とは独立しています。これを削除すると、保存されているすべての資格情報が復号できなくなります。したがって、バックアップと一緒に保管する必要があります。
- **ブループリント (`.mcserver.zip`)**: 設定、リソース、ピン留めされたパック参照、オーバーレイマニフェスト（ソース URL + sha256）、選択された設定ファイル、およびオプションでワールドを記述する `manifest.json` を含む zip ファイルです。インポートは、各 Mod を再ダウンロードしてハッシュ検証し、新しいポートを割り当てます。
- **パネルによって作成された Docker コンテナ**は、ウォッチャーが見つけられるように名前とラベルが付けられています。パネルはそれらの完全なライフサイクルを所有します。

## 起動シーケンス

1. 最初に `require('./instrument')`（Sentry シーム）、次に `require('./preflight')` を実行して、サポートされていない Node バージョンで明確に失敗させます。
2. 設定をロードします。`.session-secret` **および** `.secret-key` を確認/生成します。
3. `ensureDataRoot()` - `./data` レイアウトを作成し、`tmp/` をワイプします。
4. DB マイグレーションを実行し、次に `PRAGMA integrity_check` を実行します（大声でログを記録し、失敗した場合は `data/backups/_panel` を指します）。
5. レガシー `SESSION_SECRET` キーのシークレットを `.secret-key` の下に再暗号化します（`secretsMigration`）。
6. スターターブループリントをシードします（保護されています）。
7. HTTP + WS サーバーを起動します。公開されたバインドでは、初回実行時の `/setup` PIN を表示します。
8. 起動後のランタイムガードをインストールします（キャッチされない障害をキャッチします。`MSM_EXIT_ON_FATAL=1` は、監視対象のデプロイメントでハード終了させます）。
9. バックグラウンドサービスを起動します：WS ブローカー、ストレージインデクサー、クラッシュ + インベントリウォッチャー、スケジューラ、Discord イベントブリッジ、および**毎日のメンテナンスタイマー**（古い分析行を削除 + `panel.db` をスナップショット）。
10. Docker を**バックグラウンドで**初期化します。デーモンがダウンしていても UI は完全に利用可能です。Docker 機能は、それが到達可能になると有効になります。接続されると、`refreshStatuses({ boot })` はキャッシュされたステータスを再調整し、パネルが再起動される前に起動していて、再起動されないサーバーに対して 1 回限りの `offline-after-restart` イベントを発行し、起動ループは `auto_start` サーバーを起動し、障害中にクラッシュしたと検出された `auto_restart` サーバーを回復します（クラッシュループバックオフを尊重します）。

> Instrument-before-preflight の順序は意図的なトレードオフです。これにより、将来の Sentry 配線がランタイムを最初にパッチできるようになりますが、非常に古い Node ではわずかにフレンドリーでないメッセージが表示されるというコストがかかります。

## ビルドパイプライン

`pnpm run build` = `build:css` (Tailwind → `public/css/app.css`) + `build:js` (esbuild →
`public/dist/js/`、コード分割付き ESM)。`postinstall` は**CSS のみ**を実行します。`public/css/app.css`
と `public/dist/` は gitignore されたビルド成果物です。Dockerfile のビルドステージは完全な
`pnpm run build` を実行し、`public/` をランタイムイメージにコピーします。静的アセットは、
フィンガープリントされたファイルには `immutable`/long-cache、CSS/JS には short-cache、HTML と
`/api` には `no-cache` で提供されます。
