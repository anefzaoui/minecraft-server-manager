**Modpacks**ページ（および[作成ウィザード](/docs/servers/)の**From modpack**タブ）は、modpackをサーバーとしてインストールします。常に**正確なパックバージョンに固定**されるため、再起動によってパックがサイレントにアップグレードされることはありません。

![Modpacks](/docs/images/modpacks.png)

## サポートされているプラットフォーム

- **CurseForge** - パックを検索するか、URLを貼り付けます。検索およびプライベートパックにはCurseForge APIキーが必要です（設定 → APIキーで追加）。
- **Modrinth** - 名前で検索します。
- **FTB** - Feed The Beastパック。
- **GT New Horizons** - 1.7.10のエキスパートパック。GTNH独自のリリースインデックスからインストールされます。GTNHはパックバージョンごとにJavaランタイムを選択します（2.8.0以降はバンドルされたlwjgl3ifyパッチを介して**Java 25**で動作し、古いリリースはJava 21または17で動作します）。ウィザードはサーバーのRAMとディスクを適切な最小値に引き上げます。
- **Custom zip** - 公開されていないパックの場合：**CurseForge modpack export**（CurseForgeアプリが手動で選択したmodセット用に生成する`manifest.json`を含むzip）または**mod jarの任意のzip**をアップロードします。パネルはCurseForge APIを介してマニフェストを一括で解決し（またはハッシュ/フィンガープリント/メタデータで各jarを識別し）、適合するものをプレビューし、すべてを1つのタスクでインストールします。これには、オプトインした場合のパックの`overrides/`設定も含まれます。作者が自動ダウンロードを許可していないmodは、インストールの失敗ではなく、ブラウザリンクと手動アップロードスロットとともにリストされます。

## ピン留めの仕組み

パックを選択すると、パネルは正確なバージョンを解決し、それを記録してインストールします。**Updates**ページでは、新しいバージョンが利用可能になったときに通知されます。アップグレードは、事前バックアップとロールバックを伴う、意図的で保護されたアクションです。安定版を追跡するサーバーにはベータ版は提供されません。

非常に古いパネルバージョン（0.9.7より前）で作成されたサーバーは_ピン留めされていない_状態のままで、コンテナイメージが起動するたびに最新のパックバージョンをサイレントにインストールしていました。パネルは現在、起動時にこれらを修復します。各サーバーを実際にインストールされているバージョンにロックし（パネル自身の記録またはイメージのインストールマニフェストから読み取り、新しく解決された「最新」ではない）、イベントをログに記録します。何がインストールされているか不明な場合、サーバーの設定ページに警告が表示され、バージョンを手動で選択するように求められます。ピン留めされていないmodpack設定を保存しようとすると、完全に拒否されます。

## 更新ポリシー

各サーバーには**設定**に更新ポリシーがあり、3つのオプションはすべてその意味どおりです。

- **Manual only** - 何も自動的に変更されず、サーバーは更新バッジと更新ページから完全に除外されます。「放っておいて」モード：手動で調整された、またはインポートされたパックで、決して触られたくない場合に最適です。
- **Notify me** (デフォルト) - 毎日のチェックで利用可能な更新がバッジとして、また更新ページに表示されます。適用は常にあなたのクリックが必要です。
- **Auto-update** - スケジュールされた毎日のチェック後、保留中の**パック**更新は、手動アップグレードと同じ保護されたパスで適用されます。事前バックアップ、ヘルスモニタリング、および新しいバージョンが起動に失敗した場合の自動ロールバックが含まれます。サーバーを異なるMinecraftバージョンに移動させる更新は、常にイベントとともにスキップされます。ワールドを永続的に変換することは、パネルがあなたのために決定することを拒否する決定です。手動の「今すぐチェック」ボタンはチェックするだけで、自動更新をトリガーすることはありません。

## パックのアップグレード

ピン留めされたサーバーから、1つのアクションで新しいバージョンにアップグレードできます。パネルはまずバックアップを取り、ピン留めされたバージョンを交換し、コンテナを再作成し（新しいバージョンが異なるランタイムを必要とする場合はJavaを再解決し）、最初の起動を監視します。GTNHのような大規模なパック（数ギガバイトをダウンロードし、最初の起動時に数百のmodワールドを構築する）には十分な時間を与えます。
