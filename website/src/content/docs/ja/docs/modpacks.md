**Modpacks** ページ（および[作成ウィザード](/docs/servers/)の**Modpackから**タブ）は、modpackをサーバーとしてインストールします。常に**正確なパックバージョンに固定**されているため、再起動時にパックがサイレントにアップグレードされることはありません。

![Modpacks](/docs/images/modpacks.png)

## 対応プラットフォーム

- **CurseForge**: 名前で検索します。CurseForge APIキーが必要です（**設定 → APIキー**に追加してください）。
- **Modrinth**: 名前で検索します。
- **FTB**: Feed The Beastのパック。API経由のみ（数値のパックIDと明示的なバージョンIDが必要です）。パネルはまだFTBパックのアップデートをチェックしていません。
- **GT New Horizons**: 1.7.10のエキスパートパック。GTNH独自のリリースインデックスからインストールします。GTNHはパックバージョンごとにJavaランタイムを選択します（2.8.0+はバンドルされたlwjgl3ifyパッチ経由で**Java 25**で実行され、古いリリースはJava 21または17で実行されます）。ウィザードは、サーバーのRAMとディスクを適切な最小値に引き上げます。
- **カスタムzip**: 公開されているパックではありません。**CurseForge modpackエクスポート**（CurseForgeアプリが選択したmodセット用に生成する`manifest.json`を含むzip）、**Modrinth `.mrpack`**、または**mod jarの任意のzip**をアップロードします。パネルはマニフェストを一括で解決し（またはハッシュ/フィンガープリント/メタデータで各jarを識別し）、インストールタスクで全てをプレビューしてインストールします。これには、オプションでパックの`overrides/`設定も含まれます。自動ダウンロードが許可されていないmodは、ブラウザリンクと手動アップロードスロットと共にリストされ、インストールは失敗しません。

## ピン留めの仕組み

パックを選択すると、パネルは正確なバージョンを解決し、それを記録してインストールします。**アップデート**ページでは、新しいバージョンが利用可能になった場合に通知されます（サーバーの[アップデートポリシー](#update-policy)が**手動のみ**でない限り）。アップグレードは、アップグレード前のバックアップとロールバックを伴う、意図的で保護された操作です。安定版追跡サーバーにはベータ版は提供されません。サーバー自体の**バージョン**タブは、もう一方の質問に答えます。つまり、実際に存在するmodがどの将来のMinecraftバージョンに対応できるかということです（[アップデート](/docs/updates/#minecraft-version-compatibility)）。

modローダーバージョンもパックに含まれます。サーバーは、パックが宣言するForge、NeoForge、またはFabricのビルドをインストールします。ForgeまたはFabricのCurseForgeパックが、そのmod自体には古すぎるバージョンを宣言している場合、パックが修正されるまで**バージョン**タブでそれを上書きできます。パックのアップデートは、新しいバージョンが独自のバージョンを宣言するため、上書きを削除します（[modローダーバージョンの変更](/docs/updates/#changing-the-mod-loader-version)）。

非常に古いパネルバージョン（0.9.7より前）で作成されたサーバーは、_ピン留めされていない_状態になる可能性がありました。これは、コンテナイメージが起動するたびに最新のパックバージョンをサイレントにインストールすることを意味します。パネルは現在、起動時にこれらを修復します。各サーバーを、実際にインストールされているバージョンにロックします（パネル自身の記録またはイメージのインストールマニフェストから読み取られ、新たに解決された「最新」ではありません）。そしてイベントを記録します。インストールされているものを判断できない場合、サーバーの設定ページに警告と**バージョンを選択…**ボタン（CurseForge、Modrinth、GTNHパック用）が表示され、[バージョンピッカー](#changing-the-pack-version)が開きます。ピン留めされていないmodpack設定を保存しようとすると、完全に拒否されます。

## アップデートポリシー

各サーバーには、**設定 → 設定**タブに**アップデートポリシー**カードがあり、3つのオプションすべてがその意味どおりに機能します。

- **手動のみ**（デフォルト）：何も自動的に変更されず、サーバーはアップデートバッジとアップデートページから完全に除外されます。これは「放っておいてほしい」モードで、手動で調整またはインポートしたパックを絶対に触られたくない場合に最適です。バージョンはロックされません。[**バージョンを変更…**](#changing-the-pack-version)はすべてのポリシーで機能します。新しいバージョンについて通知を受け、ワンクリックで適用するには、**通知を受け取る**を選択してください。
- **通知を受け取る**：毎日のチェックで、利用可能なアップデートがバッジおよびアップデートページに表示されます。適用は常にユーザーのクリックで行われます。
- **自動アップデート**：毎日のスケジュールチェックの後、保留中の**パック**アップデートは、手動アップグレードと同じ保護されたパスを通じて適用されます。アップグレード前のバックアップ、正常性監視、および新しいバージョンが起動に失敗した場合の自動ロールバックが含まれます。サーバーを異なるMinecraftバージョンに移動するアップデートは、イベントとしてスキップされます。ワールドの永続的な変換は、パネルがあなたのために決定しないようにします。手動の**今すぐチェック**ボタンはチェックのみを行い、自動アップデートはトリガーしません。

## パックのアップグレード

ピン留めされたサーバーから、1つの操作で新しいバージョンにアップグレードできます。パネルは最初にバックアップを取り、ピン留めされたバージョンを切り替え、サーバーを再構築します（新しいバージョンが異なるランタイムを必要とする場合はJavaを再解決します）。そして最初の起動を監視します。GTNHのように数ギガバイトをダウンロードし、最初の起動時に数百のmodでワールドを構築するような大規模なパックのために、十分な時間が与えられます。

## パックバージョンの変更

特定のバージョン（新しいものまたは古いもの）を実行するには、サーバーの**概要**タブのパックカードにある**バージョンを変更…**を使用します。**Modpacks**ページで、インストールされているパックのカードを開くと、同じ選択肢が表示されます。ドロップダウンでバージョンを選択し、**このバージョンに切り替える**をクリックします。どちらもサーバーの**コンテンツ**権限を必要とし、CurseForge、Modrinth、GTNHパックで利用可能です（FTBパックにはまだバージョンリストがありません）。リストには、CurseForgeとModrinthの場合は最新の25バージョン、GTNHの場合はすべてのリリースが表示されます。

切り替えは、アップグレードと同じ保護されたパスを通過します。アップグレード前のバックアップ、新しいピン、再構築、および監視された最初の起動。サーバーが正常に起動しない場合は、ワンクリックでロールバックできます。カスタムmodは引き継がれ、無効にしたパックmodも引き継がれます。パックの他のインストール設定（強制されたmod、無視するファイル、追加プロジェクト）も同様です。異なるパックをインストールすると、それらの設定はリセットされます。それらは、作成されたパックにのみ意味があるためです。

各バージョンは、実行するMinecraftバージョンと共にリストされ、最後に保存されたワールドのバージョンと比較されます。

- **同じMinecraftバージョン**：通常の確認後に切り替えます。古いパックバージョンに戻すと、そのバージョンにないmodのブロックやアイテムが失われる可能性があるため、どちらの場合もバックアップはバックアップタブに残ります。
- **新しいMinecraftバージョン**：ワールドが永続的に変換されることを警告する確認後に許可されます。最初に取られたバックアップが、古いワールドに戻る唯一の方法です。
- **古いMinecraftバージョン**：利用不可。Minecraftは、最後に保存したバージョンよりも古いバージョンでワールドをロードできないため、パネルは起動時にクラッシュするサーバーを残すのではなく、拒否します。
