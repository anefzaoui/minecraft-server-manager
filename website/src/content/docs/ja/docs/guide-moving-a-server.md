ワールドの移行は簡単です。しかし、プレイヤーがインベントリ、ホーム、権限をそのままにログインできるサーバーの移行は、うまくいかないことが多い部分です。以下の手順に従うことで、ダウンタイムを数分に抑え、新しいマシンが期待外れだった場合のバックアップ手段も確保できます。

## まずは現状把握

作業を始める前に、以下の情報を書き留めてください。これらは、確認せずに「想定」したために移行が失敗した原因となることがよくあります。

- **Minecraft のバージョンとローダー**を正確に。1.20.1 NeoForge は 1.20.1 Forge とは異なります。
- **バージョンを含めたMODやプラグインのリスト。** それらなしではワールドは読み込めません。
- **Java のバージョン**。これは Minecraft のバージョンに依存します。
- `server.properties` からの **`level-name`**。ワールドフォルダの名前は `world` とは限りません。
- **オンラインモード。** 古いサーバーが `online-mode=false` で動作し、新しいサーバーが `true` で動作する場合、またはその逆の場合、すべてのプレイヤーは異なる UUID を持つことになり、結果として全く新しい空のインベントリになります。これは、このページで最も痛みを伴う間違いです。
- **サーバーフォルダの外にあるもの**、例えばプラグインの MySQL データベースなど。

## 稼働中にコピーし、停止してから再度コピーする

ダウンタイムを短くする秘訣は、時間のかかるコピーを最初に行うことです。

1. **サーバーを稼働させたまま**、サーバーディレクトリ全体を新しいマシンにコピーします。ワールドが大きい場合、これには1時間かかるかもしれませんが、誰も気にしません。なぜなら、何も停止していないからです。
2. **再起動を告知し、サーバーを正常に停止します。** 正常な停止により、ゲームはワールドをフラッシュしますが、プロセスを強制終了してもそうはなりません。
3. **再度コピーします。** 今回は変更されたファイルのみが移動するため、数秒から数分で完了します。
4. **新しいマシンで起動します。** 可能であれば非公開ポートで起動し、自分で接続して確認します。既知の拠点、自分のインベントリを確認し、プラグインやMODがエラーなくロードされたことを確認してください。
5. **その後**、プレイヤーにアナウンスします。

ステップ1と3では、通常 `rsync -a --delete` が使用されます。パーミッションとタイムスタンプを維持してください。間違ったユーザーとしてコピーされたワールドは、起動しないサーバーの原因となり、エラーメッセージも明確ではありません。

## 古いサーバーはまだ削除しない

古いマシンは、停止した状態でもそのまま数日間保持してください。それが唯一の真のロールバック手段です。誤って放棄されたコピーに接続して1週間も建築してしまう人がいないように、実行中の状態ではなく電源を切った状態で保管してください。

## アドレスを移行後も維持する

プレイヤーがIPアドレスに直接接続している場合、移行のたびにすべてのプレイヤーがサーバーリストを編集する必要があり、一部のプレイヤーは決してそれをしません。

自分で管理しているホスト名をサーバーに向けます。これにより、移行はDNSの変更となり、プレイヤーのクライアント上のアドレスはそのままになります。変更が迅速に伝播するように、移行の1日前にレコードのTTL（Time To Live）を短く設定します。

プレイヤーに、非標準ポートで実行されているサーバーに直接ドメイン名を入力させたい場合は、SRVレコードを使用します。これは、商用ホストが `play.something.net` のようなアドレスを提供するのと同じ仕組みです。

## 新しいマシンを信頼する前に確認する

ホスト間で異なり、移行後に問題を引き起こす可能性のある3つの点があります。

- **ファイアウォール。** ゲームポートが開いている必要があり、ゲームポートのみが開いている必要があります。ローカルホストで動作したからといって、管理パネルやマップをインターネットに公開しないでください。
- **シングルコア速度。** Minecraft はコアの数よりも1つのコアの速度をはるかに重視します。8つの遅いコアは、2つの速いコアよりもパフォーマンスが悪く感じられます。
- **ディスク。** 回転式ストレージや共有ボリューム上のワールドは、チャンクの読み込み中にカクつく可能性があります。

## マネージドパネルからの移行

コントロールパネルを提供しているホスティングサービスから移行する場合、ダウンロードまたはファイルマネージャー機能を使用して、ワールドだけでなくサーバーディレクトリ全体を取得してください。プラグインやMODのJARファイル自体を取得し、リストだけではありません。バージョンは重要であり、「最新」は来月には別のファイルになります。

バックアップが自分のものであることも確認してください。移行元のパネル内にしか存在しないバックアップは、あなたが所有するバックアップではありません。

## Minecraft Server Manager の場合

パネル全体が1つのディレクトリです。これを別のマシンにコピーしてパネルを起動すると、すべてのサーバー、ワールド、バックアップ、設定が一緒に移行されるため、パネル自体の移行はコピー作業となります。

すべてのサーバーではなく1つのサーバーを移行したい場合は、ブループリント機能を使用すると、その設定、MODセット、ピン留めされたパックバージョン（そして、チェックを入れるとアクティブなワールドも）を単一の `.mcserver.zip` ファイルとしてキャプチャできます。これを別のパネルにインポートすることで、同じサーバーを再構築できます。ワールドのみを移行したい場合は、ワールドを個別にダウンロードしてインストールすることも可能です。

サーバーが使用していたゲームポートが新しいマシンですでに使用されている場合、または最初に非公開ポートでテストしたい場合は、**設定 → 設定** で変更してください。**ゲームポート** カードには **次の空きポートを使用** があり、稼働中のサーバーは新しいポートで再起動する前に確認を求め、そこで起動できない場合は元のポートに戻ります。プレイヤーにアナウンスする際に、公開ポートに切り替えてください。
