このパネルはマルチユーザー対応です。アカウントは**設定 → ユーザー**で管理します。

![ユーザー](/docs/images/settings-users.png)

## 3つの役割

| 役割         | できること                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| **admin**    | すべて: ユーザー、APIキー、グローバルファイル、高度なDockerオーバーライド、およびすべてのサーバーアクションを管理できます。            |
| **operator** | サーバーの実行と設定（起動/停止、コンソール、バックアップ、ワールド、MOD、ほとんどの設定）はできますが、管理者専用の領域はできません。 |
| **viewer**   | 読み取り専用です。サーバーとそのステータスは表示できますが、変更はできません。                                                         |

ビューアーを含むすべてのユーザーは、自身の[二段階認証](/docs/two-factor-authentication/)を管理できます。これは、自身のログインを保護することがサーバー管理アクションではないためです。

## 管理者専用の機能とその理由

いくつかの機能は意図的に管理者に制限されています。

- **ユーザー管理、APIキー、グローバルファイル。**
- **[公開API](/docs/public-api/)** - `/api/v1`の有効化、およびその読み取り専用Bearerトークンの作成、スコープ設定、または取り消し。
- **高度なDockerオーバーライド** - カスタムコンテナ名、追加のポート公開、およびバインドマウント。バインドマウントは、任意のホストパスをコンテナにマッピングでき、パネルのDockerアクセスと組み合わせると、実質的にホスト上のroot権限となります。これらのフィールドは管理者のみに表示されます。

カスタムコンテナ名はパネル自身の `msm-` 名前空間に存在することもできません。これにより、手動で命名されたコンテナが他のサーバーをシャドウし、停止やコマンドを誤ったインスタンスに誤って送信することがなくなります。

## アカウントの管理

![プロフィール画像](/docs/images/profile-picture.png)

管理者は、ユーザーテーブルからユーザーの作成、役割の変更、パスワードのリセット、アカウントの削除を行うことができます。**2FA**列は、各ユーザーが二段階認証を有効にしているかどうかを示します。管理者は、他のユーザーの2FAを**リセット**できます（携帯電話の紛失やバックアップコードの場合など）が、自身のパスワードなしに無効にすることはできません。これはセルフサービスフローで処理されます。

ログイン失敗はアカウントごとにレート制限されます（IPごととアカウント全体のカウンターの両方）ブルートフォース攻撃を遅らせるためです。同じ制限が2FAコードのステップにも適用されるため、正しいパスワードがコード推測の前にカウンターをリセットすることはありません。その前には、ログイン/2FA/セットアップエンドポイントに対する、より粗いクライアントIPごとのリクエスト制限があり、`RATE_LIMIT_AUTH_PER_15MIN`（デフォルト100）で調整可能です（リバースプロキシの背後にある場合は、実際のクライアントIPでキーを設定するために`TRUST_PROXY`を設定してください）。
