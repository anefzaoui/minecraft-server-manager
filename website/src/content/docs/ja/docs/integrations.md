各サーバーは、**設定**グループの下に統合機能を持っています：**Discord**、公開**ステータスページ**、ワンクリック**招待**、そしてオプションの**チャットボット**タブ（管理者のみ）。このページではDiscordについて説明します。[招待とステータスページ](/docs/invites-and-status-page/)ではそれら2つについて、[チャットボット](/docs/chatbot/)については独自のページで説明しています。

## Discord通知

パネルは、Webhookを介してサーバーイベントをDiscordチャンネルに転送します。ボットやOAuthは不要です。

### 設定

1. Discordで：**サーバー設定 → 連携機能 → Webhook → 新しいWebhook**。チャンネルを選択し、Webhook URLをコピーします。
2. パネルで、サーバーの**設定 → Discord**タブを開き、Webhook URLを**Webhook URL**に貼り付け、カードを**オン**にして**保存**します。URLは暗号化されて保存されます（APIキーと同じ保管庫に）。
3. **テスト送信**を使用して、正しく機能するか確認します。

![Discord連携](/docs/images/integrations-discord.png)

保存されているURLを置き換えるには、新しいURLを貼り付けて保存します。現在のURLを維持するには、フィールドを空白のままにします。保存されているURLはマスク表示されます（トークンは非表示）。

### 送信される内容

通知は、切り替え可能なカテゴリにグループ化されています。すべてデフォルトでオンになっています。

| カテゴリ         | イベント                                                     |
| ---------------- | ------------------------------------------------------------ |
| **開始/停止**    | サーバー起動、サーバー停止                                   |
| **クラッシュ**   | クラッシュ、クラッシュループ検出、新しいクラッシュレポート   |
| **バックアップ** | バックアップ作成、バックアップ復元                           |
| **アップデート** | アップデート適用、アップデートロールバック、アップデート失敗 |
| **キック/BAN**   | プレイヤーキック、プレイヤーBAN                              |
| **アラート**     | サーバーを静かに壊れた状態にするもの（下記参照）             |

### アラートカテゴリ

`アラート`は、「人間による対応が必要なもの」チャンネルで、以前はパネルでしか見えなかった条件に対応します：

| イベント                | 意味                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `oom`                   | メモリ不足のためコンテナが停止しました。                                                                    |
| `unhealthy`             | プロセスは起動していますが、`mc-health`プローブが失敗しています：稼働しているが機能していないサーバーです。 |
| `startup-stalled`       | ログに「完了」が表示されずに約10分間起動し続けています（修正すべき問題の診断付き、可能な場合）。            |
| `stop-failed`           | 正常な停止が効果を発揮せず、コンテナがまだ実行中です。                                                      |
| `schedule-failed`       | スケジュールされた再起動/バックアップ/コマンドが失敗しました。                                              |
| `quota-exceeded`        | 厳格モードのディスククォータに違反したため、サーバーは停止しました。                                        |
| `offline-after-restart` | パネル再起動前は起動していましたが、現在は起動しておらず、自動起動しません。                                |
| `port-change-failed`    | ポート変更が失敗し、サーバーを古いポートに戻せなかったため、ダウンしています。                              |
| `auto-restart-gave-up`  | クラッシュしたサーバーは、他のアクションが長すぎたため再起動されませんでした。                              |

### 配信の仕組み

バックグラウンドブリッジが15秒ごとに[イベントログ](/docs/activity/)をポーリングし、マッピングされた行を転送します。Webhook POSTが一時的に失敗した場合、その行はドロップされるのではなく、後続のポーリングで再試行されます。数回の試行が失敗した後、その行はスキップされ、配信失敗はサーバーごとに1時間に1回まで記録されます。パネル再起動後、ブリッジはまだ配信されていないイベントを送信しますが、2時間以上前のイベントは送信しません。最初の実行時には、最新のイベントから開始します。
