各サーバーは、**設定**グループの下に統合機能を持っています：**Discord**、公開**ステータスページ**、ワンクリック**招待**、そしてオプションの**チャットボット**タブです。このページではDiscordについて説明します（他の機能はパネル内に独自のドキュメントとセットアップヘルパーがあります）。

## Discord通知

パネルは、Webhookを介してサーバーイベントをDiscordチャンネルに転送します。ボットやOAuthは不要です。

### セットアップ

1. Discordで：**サーバー設定 → 連携機能 → Webhook → 新しいWebhook**。チャンネルを選択し、Webhook URLをコピーします。
2. パネルで、サーバーの**設定 → Discord**タブを開き、URLを**Webhook URL**に貼り付け、カードを**オン**にして**保存**します。URLは暗号化されて保存されます（APIキーと同じ保存領域に）。
3. **テスト送信**を使用して、正常に機能することを確認します。

![Discord連携](/docs/images/integrations-discord.png)

保存されているURLを置き換えるには、新しいURLを貼り付けて保存します。フィールドを空白のままにすると、現在のURLが保持されます。保存されているURLはマスク表示されます（トークンは非表示）。

### 送信される内容

通知は、切り替え可能なカテゴリにグループ化されています。すべてデフォルトでオンになっています。

| カテゴリ          | イベント                                                     |
| ----------------- | ------------------------------------------------------------ |
| **起動 / 停止**   | サーバー起動、サーバー停止                                   |
| **クラッシュ**    | クラッシュ、クラッシュループ検出、新しいクラッシュレポート   |
| **バックアップ**  | バックアップ作成、バックアップ復元                           |
| **アップデート**  | アップデート適用、アップデートロールバック、アップデート失敗 |
| **キック / バン** | プレイヤーキック、プレイヤーバン                             |
| **アラート**      | サーバーを静かに壊れた状態にするもの（下記参照）             |

### アラートカテゴリ

`アラート`は「人間による対応が必要なもの」チャンネルで、以前はパネルでのみ表示されていた条件に対応します：

| イベント                | 意味                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `oom`                   | メモリ不足のためコンテナが停止しました。                                                                    |
| `unhealthy`             | プロセスは起動していますが、`mc-health`プローブが失敗しています：稼働しているが機能していないサーバーです。 |
| `startup-stalled`       | ログに「完了」が表示されずに約10分間起動し続けています（修正すべき問題の診断情報があれば表示されます）。    |
| `stop-failed`           | 正常な停止が効果を発揮せず、コンテナがまだ実行中です。                                                      |
| `schedule-failed`       | スケジュールされた再起動/バックアップ/コマンドが失敗しました。                                              |
| `quota-exceeded`        | 厳格モードのディスククォータがトリップし、サーバーは停止しました。                                          |
| `offline-after-restart` | パネルが再起動する前はサーバーは起動していましたが、現在は起動しておらず、自動起動されません。              |
| `crash-report`          | 新しいクラッシュレポートがキャプチャされ、解析されました。                                                  |
| `update-failed`         | 保護されたアップグレードが正常に起動しませんでした。                                                        |

### 配信の仕組み

バックグラウンドブリッジが15秒ごとに[イベントログ](/docs/activity/)をポーリングし、マッピングされた行を転送します。Webhook POSTが一時的に失敗した場合、その行はドロップされるのではなく、後続のポーリングで再試行されます。永続的に到達不可能なWebhookは、数回の試行後にミュートされます（1時間あたり1行のログ）。ブリッジは、パネル起動前のイベントを再生することはありません。
