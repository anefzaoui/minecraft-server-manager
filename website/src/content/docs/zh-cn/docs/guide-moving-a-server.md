迁移世界非常简单。但迁移一个玩家仍可登录、保留其物品栏、家园和权限的服务器，则容易出错。以下步骤可将停机时间缩短至几分钟，并在新机器不尽如人意时提供回退方案。

## 首先盘点

在进行任何操作之前，请记录下这些信息。如果想当然地认为自己知道这些信息而未进行检查，都曾导致迁移失败：

- **Minecraft 版本和加载器**，必须精确。1.20.1 NeoForge 不同于 1.20.1 Forge。
- **模组或插件列表及版本**。没有创建世界的模组，世界将无法加载。
- **Java 版本**，应与 Minecraft 版本匹配。
- `server.properties` 中的 **`level-name`**。世界文件夹通常不叫 `world`。
- **在线模式**。如果旧服务器运行在 `online-mode=false` 下，而新服务器运行在 `online-mode=true` 下（反之亦然），则每个玩家都会获得一个不同的 UUID，从而获得一个全新的、空的物品栏。这是本页面中最令人痛苦的错误。
- **服务器文件夹之外的任何内容**，例如插件的 MySQL 数据库。

## 运行时复制，然后停止时再复制一次

缩短停机时间的诀窍在于先进行耗时较长的复制操作。

1. **在服务器运行时**，将整个服务器目录复制到新机器。对于大型世界，这可能需要一个小时；但没有人会注意到，因为没有任何服务中断。
2. **宣布重启，然后正常停止服务器**。正常关闭会使游戏刷新世界；强制终止进程则不会。
3. **再次复制**。这次只移动已更改的文件，因此只需几秒到几分钟。
4. **在新机器上启动服务器**，如果可能，使用非公开端口，并亲自加入。检查一个你熟悉的地标、你自己的物品栏，以及模组或插件是否加载正常且没有错误。
5. **然后**再将玩家指向新服务器。

`rsync -a --delete` 是步骤 1 和 3 的常用工具。保留权限和时间戳：以错误用户身份复制的世界将导致服务器无法启动，且错误信息不会明确指出原因。

## 暂时不要删除旧服务器

保留旧机器，停止运行但保持完整，至少几天。这是唯一的真正回滚方式。将其断电而非运行，以免有人意外加入被废弃的副本并在此处花费一周时间进行建设。

## 让地址在迁移后保持不变

如果玩家连接的是裸 IP 地址，每次迁移都会迫使所有玩家编辑他们的服务器列表，而有些人永远不会这样做。

使用您控制的主机名指向服务器。这样迁移就变成了一个 DNS 更改，而每个人客户端中的地址保持不变。在迁移前一天降低记录的 TTL（生存时间），以便更改能够快速传播。

如果您希望玩家在服务器运行于非标准端口时输入裸域名，SRV 记录可以实现此目的。这与商业主机提供 `play.something.net` 的机制相同。

## 在信任新机器之前进行检查

以下三点是不同主机之间可能存在的差异，并且会在迁移后带来麻烦：

- **防火墙**。您的游戏端口必须开放，并且只开放您的游戏端口。不要仅仅因为在本地主机上可用就将管理面板或地图暴露给互联网。
- **单核性能**。Minecraft 比核心数量更关心单个核心的速度。八个慢速核心的体验会比两个快速核心差。
- **磁盘**。在机械硬盘或高度共享的卷上的世界会在加载区块时出现卡顿。

## 离开托管面板

如果您是从一个提供控制面板而不是机器的主机迁移，请找到下载或文件管理器，并获取整个服务器目录，而不仅仅是世界文件。获取模组和插件的 jar 文件本身，而不是列表：版本很重要，“最新”版本下个月就会变成另一个文件。

同时也要检查您的备份是否属于您。只存在于您即将离开的面板中的备份，并不是您拥有的备份。

## 在 Minecraft Server Manager 中

整个面板是一个目录。将其复制到另一台机器并在那里启动面板，会将其所有服务器、世界、备份和设置一并带走，这使得迁移面板本身成为一次复制而非迁移。

对于单个服务器而非全部服务器，蓝图会捕获其配置、模组集和固定的资源包版本（如果勾选，还会包含活动世界），并将其保存为单个 `.mcserver.zip` 文件，该文件可以在另一个面板中导入以重建相同的服务器。当只需要迁移世界时，世界也可以单独下载和安装。

如果新机器上已占用服务器使用的游戏端口，或者您想先在非公开端口上进行测试，请在 **设置 → 配置** 中更改它：**游戏端口**卡片中有**使用下一个可用端口**选项，正在运行的服务器会在新端口重启前询问，如果无法在新端口启动，则会回退到旧端口。当您将玩家指向新服务器时，将其切换回公开端口。
