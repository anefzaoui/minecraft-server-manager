每个服务器在其 **设置** 组下都包含集成：**Discord**、公开的 **状态页面**、一键 **邀请**，以及可选的 **聊天机器人** 标签页（仅限管理员）。本页介绍 Discord；[邀请与状态页面](/docs/invites-and-status-page/) 介绍了这两项，而[聊天机器人](/docs/chatbot/) 有其自己的页面。

## Discord 通知

面板通过 webhook 将服务器事件转发到 Discord 频道。无需机器人，无需 OAuth。

### 设置

1. 在 Discord 中：**服务器设置 → 集成 → Webhook → 新建 Webhook**。选择频道并复制 webhook URL。
2. 在面板中，打开服务器的 **设置 → Discord** 标签页，将 URL 粘贴到 **Webhook URL** 中，将卡片 **开启**，然后 **保存**。URL 会被加密存储（与 API 密钥在相同的静态存储中）。
3. 使用 **发送测试** 来确认设置是否生效。

![Discord 集成](/docs/images/integrations-discord.png)

要替换已存储的 URL，粘贴新 URL 并保存；留空字段则保留当前 URL。已存储的 URL 会被部分隐藏（令牌被隐藏）。

### 发送内容

通知被分组为可切换的类别。默认情况下全部开启。

| 类别          | 事件                                   |
| ------------- | -------------------------------------- |
| **启动/停止** | 服务器已启动，服务器已停止             |
| **崩溃**      | 发生崩溃，检测到崩溃循环，新的崩溃报告 |
| **备份**      | 已创建备份，已恢复备份                 |
| **更新**      | 已应用更新，已回滚更新，更新失败       |
| **踢出/封禁** | 玩家被踢出，玩家被封禁                 |
| **警报**      | 会悄悄导致服务器损坏的事件（见下文）   |

### 警报类别

`警报` 是“需要人工干预”的频道，用于处理以前只能在面板中看到的状况：

| 事件                    | 含义                                                                     |
| ----------------------- | ------------------------------------------------------------------------ |
| `oom`                   | 容器因内存不足而被停止。                                                 |
| `unhealthy`             | 进程正在运行，但 `mc-health` 探测失败：服务器处于活动状态但已损坏。      |
| `startup-stalled`       | 启动约 10 分钟后仍未在日志中显示“完成”（如果已知原因，会提供修复诊断）。 |
| `stop-failed`           | 正常停止未能生效，容器仍在运行。                                         |
| `schedule-failed`       | 计划的重启/备份/命令失败。                                               |
| `quota-exceeded`        | 严格模式磁盘配额被触发，服务器已停止。                                   |
| `offline-after-restart` | 在面板重启前服务器是运行的，重启后不再运行，并且不会自动启动。           |
| `port-change-failed`    | 端口更改失败，服务器未能恢复到旧端口，因此已停止运行。                   |
| `auto-restart-gave-up`  | 由于另一项操作占用时间过长，已放弃重启崩溃的服务器。                     |

### 发送机制

后台桥接器每 15 秒轮询一次[活动日志](/docs/activity/)，并转发匹配的行。如果 webhook POST 暂时失败，该行会在后续轮询中重试，而不是被丢弃；在几次尝试失败后，该行将被跳过，并且每个服务器每小时最多记录一次发送失败。面板重启后，桥接器会发送尚未发送的事件，但最多只回溯两个小时；在其首次运行时，它从最新的事件开始。
