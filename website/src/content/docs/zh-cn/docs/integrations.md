每个服务器在其**设置**组下都包含集成：**Discord**、公开的**状态页面**、一键**邀请**以及可选的**聊天机器人**选项卡。本页介绍 Discord（其他集成在面板中有自己的文档和设置助手）。

## Discord 通知

面板通过 webhook 将服务器事件转发到 Discord 频道。无需机器人，无需 OAuth。

### 设置

1. 在 Discord 中：**服务器设置 → 集成 → Webhook → 新建 Webhook**。选择频道并复制 webhook URL。
2. 在面板中，打开服务器的**设置 → Discord** 选项卡，将 URL 粘贴到**Webhook URL** 中，打开该卡片，然后**保存**。URL 会被加密存储（与 API 密钥存储在同一静态存储中）。
3. 使用**发送测试**确认其正常工作。

![Discord 集成](/docs/images/integrations-discord.png)

要替换已存储的 URL，请粘贴新 URL 并保存；将字段留空以保留当前 URL。已存储的 URL 会被掩码显示（令牌被隐藏）。

### 发送内容

通知被分组为可切换的类别。默认情况下全部开启。

| 类别          | 事件                                         |
| ------------- | -------------------------------------------- |
| **启动/停止** | 服务器已启动，服务器已停止                   |
| **崩溃**      | 检测到崩溃，崩溃循环，新的崩溃报告           |
| **备份**      | 已创建备份，已恢复备份                       |
| **更新**      | 已应用更新，已回滚更新，更新失败             |
| **踢出/封禁** | 玩家被踢出，玩家被封禁                       |
| **警报**      | 那些悄无声息地导致服务器损坏的状况（见下文） |

### 警报类别

`警报`是“需要人工干预”的频道，用于处理以前仅在面板中可见的状况：

| 事件                    | 含义                                                             |
| ----------------------- | ---------------------------------------------------------------- |
| `oom`                   | 容器因内存不足而停止。                                           |
| `unhealthy`             | 进程已启动但 `mc-health` 探测失败：服务器处于活动状态但已损坏。  |
| `startup-stalled`       | 启动约 10 分钟后仍未在日志中显示“完成”（并附带已知问题的诊断）。 |
| `stop-failed`           | 正常停止未生效，容器仍在运行。                                   |
| `schedule-failed`       | 计划的重启/备份/命令失败。                                       |
| `quota-exceeded`        | 严格模式磁盘配额被触发，服务器已停止。                           |
| `offline-after-restart` | 在面板重启之前服务器是运行的，但现在不是，并且不会自动启动。     |
| `crash-report`          | 已捕获并解析新的崩溃报告。                                       |
| `update-failed`         | 受保护的升级未能健康启动。                                       |

### 发送机制

后台桥接器每 15 秒轮询一次[活动日志](/docs/activity/)，并转发映射的行。如果 webhook POST 暂时失败，该行将在后续轮询中重试，而不是被丢弃；永久无法访问的 webhook 在几次尝试后会被静默（每小时一条日志）。桥接器绝不会重放面板启动之前的事件。
