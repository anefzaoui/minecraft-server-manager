**备份**页面显示您所有服务器的快照，包含大小、原因和创建时间。

![备份](/docs/images/backups.png)

## 创建备份

通过服务器的“**备份**”选项卡（或通过[计划任务](/docs/schedules/)），您可以一键快照整个服务器目录。面板会先使世界处于静默状态（`save-off` → `save-all`），然后压缩数据，再重新启用保存（`save-on`），因此即使在运行中的服务器上，备份也是一致的。压缩在后台工作线程中运行，不会阻塞面板。每个备份都可以附带一个备注。

每个存档在写入的瞬间都会进行**完整性检查**：面板会重新打开 zip 文件并读取其目录。损坏或无法打开的存档将被删除，备份操作会立即失败，而不是在数月后需要恢复时才发现问题。零条目存档（从未启动过的服务器）是允许的，但会在事件中标记出来。

勾选“**之后也收缩世界**”（在“备份”选项卡或备份计划任务中）可在存档安全写入后移除不常访问的区块（参见**[收缩世界](/docs/world-shrink/)**）。收缩仅在服务器停止时运行；在运行中的服务器上，备份仍会进行，但收缩会被跳过。

![服务器备份](/docs/images/server-backups.png)

## 备份原因

备份会根据创建原因进行标记：

- **手动** - 您点击了按钮。
- **计划任务** - 由[计划任务](/docs/schedules/)创建。每个新服务器还会自动生成一个每日计划备份（在凌晨 02:00 至 05:59 之间随机生成），因此服务器从第一天起就拥有自动保护，而不仅仅是在更新之前。
- **更新前** - 在包升级前自动创建，以便升级总是可逆的。
- **恢复前** - 在恢复或重置世界前自动创建，作为安全网，以防恢复结果不符合预期。

## 保留策略

保留策略是**按服务器、按原因**限制的：每个组中保留最新的，旧的在每次成功备份后自动删除：

| 原因     | 保留数量 |
| -------- | -------- |
| 计划任务 | 10       |
| 更新前   | 10       |
| 手动     | 20       |
| 恢复前   | 5        |

`恢复前`有自己的小存储空间，正是为了防止自动安全备份覆盖您特意保留的`手动`备份。

除了按原因计数外，还有两个可选的总体限制，两者默认关闭：**最大年龄**（删除超过 N 天的备份，无论其原因）和**每个服务器的最大总大小**（删除最旧的备份直到总大小符合要求，优先删除`恢复前`的备份）。服务器的最新备份永远不会被这两个限制删除。所有这些都可以在全局的“设置”页面上更改，并在其“备份”选项卡上为特定服务器覆盖。

备份可以从备份列表中**重命名**（每行的重命名按钮）。磁盘上的存档和面板的记录会一起移动，因此下载、恢复和保留策略会继续使用新名称。

![重命名备份](/docs/images/backup-rename.png)

> 保留策略会自动限制数量，但大型模组存档仍计入服务器的[磁盘配额](/docs/storage/)，因此请留意大型包的总大小。

## 恢复

恢复备份会停止服务器（在操作任何文件前验证容器确实已停止），创建一个`恢复前`的安全备份，用快照替换**整个服务器目录**，然后保持服务器停止状态供您重新启动。由于包升级总是先进行`更新前`备份，因此您总能回滚一次错误的升级。

## 面板自身的数据库

服务器备份仅涵盖每个服务器的世界目录。面板自身的数据库（`panel.db`，包含用户、角色、2FA 密钥、计划任务、包固定和历史记录）会在每日维护定时器中单独快照：

- `VACUUM INTO` 将一个一致的、碎片整理过的副本写入 `data/backups/_panel/`；保留最新的**14**个。
- 启动时，面板会运行 `PRAGMA integrity_check`，如果失败会发出响亮的日志，并指向 `data/backups/_panel` 以获取最新的良好副本。

备份整个 `data/` 目录树（它还包含 `.secret-key`，即静态加密密钥），您就备份了所有内容。
