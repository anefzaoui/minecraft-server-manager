**Modpacks** 页面（以及[创建向导](/docs/servers/)中的 **从 Modpack 安装** 选项卡）会将 Modpack 安装为服务器，并且**始终固定到确切的版本**，因此重启永远不会在您不知情的情况下升级 Modpack。

![Modpacks](/docs/images/modpacks.png)

## 支持的平台

- **CurseForge** - 搜索或粘贴 Modpack 的 URL。搜索和私有 Modpack 需要 CurseForge API 密钥（在“设置”→“API 密钥”下添加）。
- **Modrinth** - 按名称搜索。
- **FTB** - Feed The Beast Modpack。
- **GT New Horizons** - 1.7.10 专家级 Modpack，从 GTNH 自有的发布索引安装。GTNH 为每个 Modpack 版本选择其 Java 运行时（2.8.0+ 版本通过捆绑的 lwjgl3ify 补丁在 **Java 25** 上运行，旧版本在 Java 21 或 17 上运行），并且创建向导会将服务器的 RAM 和磁盘调整到合理的最小值。
- **自定义 zip** - 完全不是已发布的 Modpack：上传一个**CurseForge Modpack 导出文件**（包含 `manifest.json` 的 zip 文件，CurseForge 应用会为手动选择的 Mod 集合生成该文件）或**任何 Mod jar 包的 zip 文件**。面板通过 CurseForge API 批量解析 manifest（或通过哈希/指纹/元数据识别每个 jar），预览可安装的 Mod，并一次性安装所有内容——如果您选择加入，还包括 Modpack 的 `overrides/` 配置文件。作者禁止自动下载的 Mod 将会显示一个浏览器链接和一个手动上传的插槽，而不是导致安装失败。

## 固定版本的工作原理

当您选择一个 Modpack 时，面板会解析确切的版本，记录下来，然后安装该版本。在“**更新**”页面上，您会收到有关可用新版本的通知；升级是一个经过深思熟虑且有保护措施的操作，包含更新前的备份和回滚。稳定跟踪服务器永远不会提供 Beta 版本。

在非常旧的面板版本（0.9.7 之前）上创建的服务器可能会处于_未固定_状态，这意味着容器镜像在每次启动时都会悄悄地安装最新的 Modpack 版本。面板现在会在启动时修复这些服务器：它会将每个服务器固定到实际安装的版本（从面板自己的记录或镜像的安装 manifest 中读取，绝不会是新解析的“最新”版本），并记录一个事件。如果它无法确定当前安装的版本，服务器的“设置”页面会显示一个警告，要求您手动选择版本，并且任何尝试保存未固定的 Modpack 配置的操作都会被直接拒绝。

## 更新策略

每个服务器在“**设置**”中都有一个更新策略，所有三个选项都名副其实：

- **仅手动** - 没有任何东西会自行更改，服务器将完全不出现在更新徽章和“更新”页面上。“保持原样”模式：非常适合您不想被更改的手动调整或导入的 Modpack。
- **通知我**（默认） - 每日检查会将可用更新显示为徽章并在“更新”页面上列出；应用更新始终需要您点击。
- **自动更新** - 在计划的每日检查后，待处理的**Modpack** 更新将通过与手动升级相同的保护路径进行应用：更新前的备份、健康状况监控以及在新版本启动失败时的自动回滚。会将服务器更新到不同 Minecraft 版本的更新将始终被跳过并记录一个事件——面板拒绝为您做出永久转换世界的决定。手动“立即检查”按钮仅执行检查；它们从不触发自动更新。

## 升级 Modpack

从已固定的服务器，您可以一次性升级到新版本。面板会先进行备份，然后切换固定版本，重新创建容器（如果新版本需要不同的运行时，则重新解析 Java），并监控首次启动，为像 GTNH 这样下载几 GB 数据并在首次启动时构建包含数百个 Mod 的世界的庞大 Modpack 提供充足的窗口期。
