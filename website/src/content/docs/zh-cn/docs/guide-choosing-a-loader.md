根据玩家需要安装的内容来选择，而不是根据听起来最快的来选择。

| 你想要                                   | 运行这个           | 玩家安装   |
| ---------------------------------------- | ------------------ | ---------- |
| 和朋友一起玩生存模式，没有特别之处       | Vanilla            | 无         |
| 一个带有等级、领地和管理功能的公共服务器 | Paper              | 无         |
| 来自 CurseForge 或 Modrinth 的特定模组包 | 模组包说明的即可   | 模组包     |
| 你自己正在构建的现代模组包               | Fabric 或 NeoForge | 相同的模组 |
| 1.7 到 1.12 时代的老模组包               | Forge              | 相同的模组 |

这对大多数人来说就是全部的决定了。本页的其余部分解释了原因。

## 插件（Plugins）和模组（Mods）并非同一样东西

这是其他一切的基础区分。

**插件**只在服务器上运行。Paper、Spigot 和 Bukkit 加载它们。玩家使用普通的、未修改的客户端加入，并且永远不会知道。任何本质上与规则、权限、经济、领地、小游戏或管理相关的东西都是插件，这就是为什么几乎所有公共服务器都运行 Paper。

**模组**会改变游戏本身：新的方块、新的维度、新的机器。客户端必须加载与服务器相同的模组，否则它无法理解服务器在告诉它什么。加入模组服务器的任何人都会先安装模组包。

一个服务器不能有意义地同时是两者。存在混合项目，它们将插件 API 添加到模组加载器上，它们会起作用，直到它们不起作用，通常是在最糟糕的时候。如果你同时需要两者，请运行一个代理服务器，后面连接一个模组服务器和一个插件服务器，而不是一个混合服务器。

## 插件方面

**Paper** 是默认的选择。它是 Spigot 的一个分支，经过多年的性能优化，并提供了一个配置文件来处理几乎所有曾经让管理员烦恼的行为。来自 Bukkit 时代的 Vanilla 插件大多仍然可以运行。

**Purpur** 是 Paper 的一个分支，拥有更多的配置选项，包括游戏性方面的。如果你想要那些特定的开关，就选择它；否则选择 Paper。

**Vanilla** 在游戏本身就是重点时才值得运行。它在玩家很多时速度较慢，并且没有权限系统，因此管理是手动的。

Paper 默认会更改一些 Vanilla 的行为，以提高性能。如果视频中的红石装置在你的服务器上不起作用，通常就是这个原因，而且通常可以通过设置来解决。

## 模组方面

**Fabric** 体积小，能在几天内更新到新的 Minecraft 版本，并支持大多数现代性能模组。几乎所有的 Fabric 模组都需要 Fabric API，这是一个单独的下载。如果你的目标是运行一个带有少量生活质量模组的快速服务器，那么就是它了。

**NeoForge** 是当前版本中旧 Forge 生态系统的工作场所。它在 1.20.1 版本期间从 Forge 分离出来，大多数为 1.20.2 及更高版本构建的大型模组包都以它为目标。如果你今天开始构建一个重量级的新模组包，那么就是它了。

**Forge** 仍然主宰着过去。1.7.10、1.12.2 和 1.16.5 时代的一切，也就是很多备受喜爱的模组包，都是 Forge 的，而且将来也一直是。保留它来运行那些。

**Quilt** 是 Fabric 的一个分支，可以运行大多数 Fabric 模组。它的存在是有充分理由的，但如果你没有特别的理由选择它，就选择 Fabric。

一个加载器的模组不能在另一个加载器上运行。模组页面上写着 Fabric 就意味着是 Fabric。

## 如果你正在安装模组包，模组包说了算

不要自己选择。模组包会列出它的加载器和确切的 Minecraft 版本，两者都必须匹配。在这里，“差不多”是不存在的：1.20.1 的模组包不能在 1.20.4 上运行，而 1.20.1 的 NeoForge 模组包不能在 1.20.1 的 Forge 上运行。

通过模组包的 ID 或链接来安装，而不是手动挑选模组，并固定版本。模组包会更新，如果在赛季中途更新，就可能导致世界损坏。

## 使用哪个 Java 版本

Minecraft 的要求会随着游戏而变化，运行错误的版本会产生一个无用的 `UnsupportedClassVersionError` 而不是一个清晰的消息。

| Minecraft 版本    | Java |
| ----------------- | ---- |
| 1.16.5 及更早版本 | 8    |
| 1.17              | 16   |
| 1.18 和 1.19      | 17   |
| 1.20 至 1.20.4    | 17   |
| 1.20.5 至 1.21.x  | 21   |
| 26.1 及更高版本   | 25   |

旧模组包确实需要 Java 8；这是软件中少数几个最新版本反而错误的地方之一。

## 在 Minecraft Server Manager 中

创建向导会询问你想要运行什么，并从上面的表格中选择 Java 版本，这样就不会意外发生不匹配的情况。Vanilla、Paper 和 Purpur 在其 **Vanilla** 标签页下；**From Mods** 标签页接受 Fabric、Forge、NeoForge 或 Quilt，并指定 Minecraft 版本和加载器构建（最新版本，或你固定的版本）。从 CurseForge、Modrinth 或 GT New Horizons 安装模组包会将其固定到确切的版本。升级仅在你应用时发生（或者在每日检查后，如果服务器的更新策略是 **Auto-Update**），总是会先进行备份，并且可以回滚。

模组浏览器知道服务器运行哪个加载器，并相应地过滤它提供的模组，因此 Fabric jar 不会错误地放入 NeoForge 服务器。
