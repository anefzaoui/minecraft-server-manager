该面板支持多用户。在 **设置 → 用户** 下管理账户。

![用户](/docs/images/settings-users.png)

## 三种角色

| 角色                  | 每个服务器的默认权限                                                                            |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| **管理员 (admin)**    | 全部权限：管理用户、API 密钥、全局文件、高级 Docker 覆盖设置，以及所有服务器操作。              |
| **操作员 (operator)** | 运行和配置服务器（启动/停止、控制台、备份、世界、模组、大部分设置），但不能访问管理员专有区域。 |
| **查看者 (viewer)**   | 只读。查看服务器及其状态，但不能进行任何更改。                                                  |

每个用户，包括查看者，都可以管理自己的 [双因素认证](/docs/two-factor-authentication/)，因为保护自己的登录信息不属于服务器管理操作。

一个角色是所有服务器的 **默认** 权限。要为某个用户在特定服务器上授予不同的权限，请使用下方的服务器特定权限。

## 服务器特定权限

**权限** 页面（在侧边栏中，或在 **设置 → 用户** 下的 **服务器权限**）显示一个网格：左侧是所有操作员和查看者，顶部是所有服务器。点击一个单元格以决定该用户在该服务器上可以执行的操作。管理员不会列出，因为他们始终拥有所有权限。

![权限](/docs/images/settings-permissions.png)

每个单元格代表一组权限：

| 权限                 | 在该服务器上允许的操作                                         |
| -------------------- | -------------------------------------------------------------- |
| **查看 (View)**      | 查看服务器、其状态、控制台输出、玩家、历史记录和统计信息。     |
| **电源 (Power)**     | 启动、停止、重启、终止和重建服务器。                           |
| **控制台 (Console)** | 运行控制台命令和世界快速操作，发送聊天消息，以及管理聊天命令。 |
| **玩家 (Players)**   | 踢出、封禁、白名单、给予操作员权限、编辑玩家备注。             |
| **内容 (Content)**   | 安装和卸载模组、插件、模组包、世界、数据包，以及编辑物品栏。   |
| **备份 (Backups)**   | 创建、恢复、下载和删除备份。                                   |
| **文件 (Files)**     | 浏览、编辑、上传和下载服务器文件、存档日志和日志包；导出蓝图。 |
| **设置 (Settings)**  | 更改服务器设置、属性、集成、图标和升级版本。                   |
| **删除 (Delete)**    | 删除服务器。                                                   |

![权限编辑器](/docs/images/permissions-editor.png)

在网格下方，**每种权限的作用** 会详细说明每种权限允许的操作、不包含的内容以及它解锁的确切面板路由。最后一项列表会通过测试套件与运行中的代码进行比对。

![权限参考](/docs/images/permissions-reference.png)

各部分如何协同工作：

- **角色是默认设置。** 操作员在所有服务器上都拥有所有权限；查看者仅拥有查看权限。一个用浅色文本显示的单元格（其工具提示显示“角色默认”）表示从未被更改过。
- **一个单元格仅覆盖该服务器的角色权限。** 为查看者在某个服务器上授予电源和控制台权限，他们就可以运行它，而其他所有服务器对他们仍然是只读的。从操作员那里移除某个主服务器的删除权限，他们仍然拥有该服务器上的其他所有权限。
- **所有权限都包含查看权限。** 你无法操作你看不到的服务器。
- **关闭所有权限会隐藏服务器。** 该服务器将从该用户的侧边栏、仪表板、备份、计划任务、活动记录、更新、模组包、实时状态、运行任务和蓝图中消失，并且世界库将不再列出它。直接链接、API 调用或控制台套接字将返回“未找到”，就像服务器不存在一样。
- **面板范围内的操作仍遵循角色。** 创建服务器（包括克隆服务器）、存储、用户、API 密钥、全局设置和面板范围内的计划任务不是按服务器划分的，因此即使在某些服务器上拥有权限的查看者也无法执行这些操作。操作员保留服务器创建和面板范围内的计划任务权限；存储、用户、API 密钥和全局设置仅限管理员。
- **计划任务遵循服务器。** 服务器上的计划重启、备份或命令需要相应的服务器权限（电源、备份或控制台），无论其角色如何。
- **蓝图也遵循服务器。** 将服务器导出为蓝图需要相应的服务器文件权限，因为存档会携带其文件。从用户看不到的服务器导出的蓝图对该用户也是隐藏的。
- **管理员专有区域在所有服务器上保持管理员专有**：聊天机器人、备份保留策略和高级 Docker 覆盖设置。

所有更改都会写入活动日志，记录谁更改了什么；这些条目仅对管理员可见。删除用户会移除他们的行。移除服务器会保留这些行，因此对某人隐藏的服务器在其历史记录和保留的备份中仍然保持隐藏。

现有安装将保持不变：在管理员编辑单元格之前，每个用户都拥有其角色之前授予的权限。

## 管理员专有权限，以及原因

有些功能特意限制为管理员权限：

- **用户管理、存储、全局设置、API 密钥和全局文件。**
- **[公共 API](/docs/public-api/)**：启用 `/api/v1` 以及创建、范围限定或撤销其只读的 Bearer 令牌。
- **高级 Docker 覆盖设置**：自定义容器名称、额外的端口发布和绑定挂载。绑定挂载可以将任何主机路径映射到容器中，结合面板的 Docker 访问权限，这相当于在主机上拥有 root 权限。这些字段仅对管理员显示。

自定义容器名称也不能位于面板自己的 `msm-` 命名空间内，因此手动命名的容器永远不会覆盖另一个服务器的实例并错误地将停止或命令定向到错误的实例。

## 管理账户

![个人资料图片](/docs/images/profile-picture.png)

管理员可以从用户表中创建用户、更改角色、重置密码和删除账户。**2FA** 列显示每个用户是否启用了双因素认证；管理员可以通过用户操作菜单中的 **重置 2FA** 来重置另一个用户的 2FA（用于丢失手机和备用代码的情况），但永远无法在没有密码的情况下禁用自己的 2FA，这由自助服务流程处理。

登录失败会按账户进行速率限制（包括每个 IP 和全局账户计数器），以减缓暴力破解尝试，并且相同的限制也涵盖 2FA 验证码步骤，因此正确的密码无法在输入验证码之前重置计数器。在此之前，登录 / 2FA / 设置端点有一个更粗粒度的每个客户端 IP 请求限制器，可通过 `RATE_LIMIT_AUTH_PER_15MIN` 进行调整（默认值为 100；在反向代理后面，请设置 `TRUST_PROXY` 以便它基于真实的客户端 IP 进行键入）。
