该面板支持多用户。请在 **设置 → 用户** 下管理账户。

![用户](/docs/images/settings-users.png)

## 三种角色

| 角色                  | 可以做什么                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| **管理员 (admin)**    | 一切：管理用户、API 密钥、全局文件、高级 Docker 覆盖配置，以及所有服务器操作。                  |
| **操作员 (operator)** | 运行和配置服务器（启动/停止、控制台、备份、世界、模组、大多数设置），但不能访问管理员专有区域。 |
| **查看者 (viewer)**   | 只读。查看服务器及其状态，但不能进行任何更改。                                                  |

所有用户，包括查看者，都可以管理自己的 [双重身份验证](/docs/two-factor-authentication/)，因为保护自己的登录信息不属于服务器管理操作。

## 管理员专有功能，以及原因

一些功能被特意限制给管理员：

- **用户管理、API 密钥和全局文件。**
- **[公共 API](/docs/public-api/)** - 启用 `/api/v1` 以及创建、作用域限定或撤销其只读的 Bearer 令牌。
- **高级 Docker 覆盖配置** - 自定义容器名称、额外的端口发布和绑定挂载。绑定挂载可以将任何主机路径映射到容器中，并与面板的 Docker 访问结合，这相当于在主机上拥有 root 权限。这些字段仅对管理员显示。

自定义容器名称也不能放在面板自有的 `msm-` 命名空间中，因此手动命名的容器永远不会覆盖另一个服务器并错误地将停止或命令指向错误的实例。

## 管理账户

![个人资料图片](/docs/images/profile-picture.png)

管理员可以从用户表中创建用户、更改角色、重置密码和删除账户。**2FA** 列显示每个用户是否启用了双重身份验证；管理员可以为其他用户 **重置** 2FA（以防丢失手机和备用代码的情况），但不能在没有密码的情况下禁用自己的 2FA，这可以通过自助服务流程处理。

登录失败会针对每个账户进行速率限制（同时考虑 IP 和全局账户计数器），以减缓暴力破解尝试，并且相同的限制也涵盖 2FA 代码验证步骤，因此正确的密码无法在代码猜测之前重置计数器。在此之前，登录/2FA/设置端点有一个更粗粒度的每客户端 IP 请求限制器，可通过 `RATE_LIMIT_AUTH_PER_15MIN` 进行调整（默认为 100；在反向代理后面，请设置 `TRUST_PROXY` 以便它基于真实客户端 IP 进行键入）。
