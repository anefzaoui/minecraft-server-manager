简而言之，对于一个真正有人游玩的服务器：

| 你运行的是什么                     | Java 堆内存 | 分配给机器 |
| ---------------------------------- | ----------- | ---------- |
| 原版或 Paper，最多 10 名玩家       | 2 GB        | 4 GB       |
| 带插件的 Paper，10 到 30 名玩家    | 4 GB        | 6 GB       |
| 轻量级模组包，40 到 80 个模组      | 4 GB        | 6 GB       |
| 大型综合模组包，150 到 300 个模组  | 6 到 8 GB   | 10 GB      |
| GregTech New Horizons 及类似怪物包 | 8 到 12 GB  | 16 GB      |

两个数字，不是一个。这是大多数指南都忽略的部分，也是人们购买 4 GB 服务器，分配 4 GB 给 Java，然后看着它崩溃的原因。

## 堆内存和机器内存是不同的数字

Java 堆内存 (`-Xmx`) 是游戏本身可以用于世界、实体和模组数据的内存量。机器或容器必须容纳堆内存**加上** Java 所需的所有其他东西：类元数据、线程堆栈、垃圾回收器簿记、网络缓冲区以及 JVM 本身。对于带模组的服务器，这些开销大约为 0.5 到 1.5 GB。

如果堆内存等于机器内存，那么当 Java 尝试使用这些开销时，内核就会杀死服务器。在 Docker 中，这会显示为退出代码 137，而在日志中则什么也没有：进程只是在句子中间消失了。人们通常会责怪某个模组。

一个安全的规则是：**堆内存加上 25%，并且至少留出 1 GB 的空闲内存。** 8 GB 的堆内存需要 10 GB 的机器内存。

## 更多的 RAM 不等于更高的性能

Minecraft 在大多数操作中都是单线程瓶颈。给一个有 40 个模组的包分配 16 GB 内存并不会让区块生成得更快；它只会让每次垃圾回收的暂停时间更长，因为需要处理的内容更多了。一个每隔三十秒卡顿一次的服务器，通常是堆内存过大，而不是过小。

只有在看到以下情况时才增加堆内存，否则不要增加：

- 日志中出现 `java.lang.OutOfMemoryError: Java heap space`。
- 计分板中出现反复的“无法跟上！服务器过载了吗？”以及垃圾回收暂停。
- 内存使用量爬升到上限并长时间保持在那里。

## 为什么你的服务器在没有人在线时显示使用了 12 GB 内存

因为你让它这样做的。两个默认设置在起作用：

1. 常见的 Docker 镜像将初始堆内存设置为等于最大值，因此 `-Xms` 和 `-Xmx` 都是你的数字。Java 会预先占用这些内存，而不是逐渐增长。
2. 流行的 Aikar 标志集包含 `-XX:+AlwaysPreTouch`，它会在启动时遍历堆内存的每一页，以便这些页面真正被分配。这是故意的：它牺牲了更慢的启动速度和较高的空闲内存占用，以换取更少的后续暂停。

在 Paper 1.21.1 上，使用 2 GB 堆内存和 4 GB 容器内存进行测量，在世界加载完成后采样三分钟：

| 配置                                | 常驻内存 |
| ----------------------------------- | -------- |
| 无标志                              | 2.60 GiB |
| Aikar 标志                          | 2.59 GiB |
| Aikar 标志（不含 `AlwaysPreTouch`） | 1.95 GiB |
| Aikar 标志，初始堆内存 512 MB       | 1.38 GiB |
| 无标志，初始堆内存 512 MB           | 1.25 GiB |

因此，一个空闲时“使用”12 GB 的服务器通常是预先触碰过的 12 GB 堆内存，而不是内存泄漏。你的监控读数是正确的；只是这个数字的含义和你看到的有所不同。

如果你想要一个真实的空闲内存占用数字，请将初始堆内存设置得低于最大值。你将为此付出一些代价，即早期会有更多的垃圾回收。如果你更愿意获得平稳的帧时间，那就保持原样，不要去关注那个图表。

## 玩家数量的影响比你想象的要小

玩家数量从 10 增加到 20 所需的资源远少于添加 50 个模组。玩家主要增加实体和已加载的区块，这些资源的增长是平缓的。模组会增加类数据、注册表、世界生成特性以及它们自己的缓存，这些资源的增长则不是平缓的。首先考虑模组包的大小，然后为带模组的服务器上的每个普通玩家增加大约 100 到 200 MB。

视距是另一个重要的因素。将视距从 12 块降低到 8 块可以在繁忙的服务器上节省 1 GB 内存，并且在游戏中几乎察觉不到。

## 在 Minecraft Server Manager 中

每个服务器都有两个独立的字段：**Java 堆内存**和**容器内存限制**，这正是因为它们是不同的问题。创建向导会自动将容器限制设置为比堆内存高 50%，并且面板会拒绝保存容器限制低于其堆内存的服务器，因为这种组合会导致退出代码 137 而不是错误消息。

服务器上的内存计显示的是容器实际使用的内存量，并在堆内存被预先占用时进行提示，因此预先触碰过的堆内存不会被误读为失控。因内存不足而被内核终止的服务器会在历史记录中被准确记录，而不是被当作一个神秘的崩溃。
