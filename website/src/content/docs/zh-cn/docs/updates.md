**更新**页面在一个地方跟踪您的服务器群中所有过时的内容：

- **整合包**版本（[整合包](/docs/modpacks/)）与 Modrinth / CurseForge / GTNH 发布索引进行比对。
- 您自己添加的**自定义内容**（模组、数据包、资源包、插件），每个都与其来源进行比对：Modrinth、CurseForge、Hangar、SpigotMC (Spiget) 或 GitHub Releases。GitHub 查询使用 ETag 重新验证，因此每日检查几乎不会触及其速率限制。
- **Docker 镜像**过时情况：每个服务器容器的镜像 ID 与最新拉取的标签进行比对（在相同标签的服务器之间去重），作为仅重建升级提供。
- **独立版本锁定**：对于没有托管整合包的服务器，将显式 `mc_version` 锁定与 Mojang 的清单进行比对，并将显式加载器构建环境变量（`PAPER_BUILD`、`FORGE_VERSION` 等）与加载器的注册表进行比对。Paper 构建来自 PaperMC 当前的 **Fill v3 API**（旧版 v2 端点已停止接收新的 Minecraft 版本）。在有模组的服务器上，只有当[版本检查](#minecraft-version-compatibility)显示所有已安装的模组都有其构建版本时，才会提供更新的 Minecraft 版本。锁定的 Forge 服务器会提供 Forge 的推荐构建版本，绝不会提供比其锁定版本更旧的构建版本，并且锁定到发布版本的服务器绝不会提供预发布版本（已处于测试版状态的服务器可以提供更新的测试版或发布版）。应用加载器构建会首先进行预更新备份。将 Forge 或 NeoForge 服务器移动到新的 Minecraft 版本会清除其锁定的加载器构建号，因为构建是针对一个 Minecraft 版本制作的；像 `latest` 这样的关键字会保留，因为它会自行跟随版本。要自行选择特定构建版本，请参阅[更改模组加载器版本](#changing-the-mod-loader-version)。

## 工作原理

面板会检查每个服务器的锁定版本与上游来源，并列出任何有新发布版本的内容。匹配的数量也会显示在[仪表盘](/docs/dashboard/)的“可用更新”磁贴上。

检查默认情况下每天按[计划](/docs/schedules/)运行，也可以通过**立即检查所有**按需运行。行上的**忽略**会停止提供该特定版本；新的版本会再次提供。更新**策略**是按服务器进行的：面板将所有内容保留为手动（默认设置，这也会使服务器不在此页面上），仅通知您，或自行应用整合包更新（[更新策略](/docs/modpacks/#update-policy)）。

## Minecraft 版本兼容性

如果您的模组无法随之升级，那么更新的 Minecraft 版本就不是升级。每个服务器都有自己的**版本**选项卡（在模组下），可以回答这个问题：

- 服务器当前运行的版本，以及**每个已安装模组都有构建版本的最高版本**。
- 每个未来 Minecraft 版本一行可折叠，显示有多少模组已准备就绪，有多少尚未发布。打开一行可查看哪些模组会被留下，哪些模组没问题。

![版本兼容性](/docs/images/server-versions.png)

按**检查未来版本**即可运行。没有任何东西会自行扫描：检查会读取服务器模组文件夹中的每个 jar 文件，并向 Modrinth 和 CurseForge 查询每个文件，因此只有在您要求时才会发生。进度和部分结果会随之写入，因此关闭页面或刷新不会丢失任何内容，并且因面板重启而中断的检查会说明情况并提供再次运行。中断的检查已完成的所有工作都会保留，因此再次运行不会重复该工作。

报告仅描述为其制作的服务器。更改 Minecraft 版本、加载器或模组本身（添加、删除、更新）后，报告将被标记为过时并停止使用，直到您再次运行检查。

模组通过整合包自己的文件列表（如果有）进行识别，否则通过文件内容进行识别，就像启动器识别 jar 文件一样。有两种模组无法回答，也不会猜测：

- **无法识别**：注册表均不识别的手工构建 jar 文件或私人构建版本。
- **无法检查**：来自 GitHub Releases、Hangar 或 SpigotMC 的模组，或其项目已被下架的模组。这些模组不发布每个构建版本适用于哪个 Minecraft 版本的列表。

只要安装了其中任何一种，面板就根本不会提供一键式 Minecraft 版本更新，因为它无法诚实地说出什么会损坏。应用高于模组支持的版本会被拒绝，并会列出阻止它的模组名称。

您已**禁用**的模组不参与：服务器不会加载它们，因此关闭模组是绕过阻止程序的真正方法。打开或关闭模组会标记报告以重新检查。

这涵盖了运行模组的服务器：Fabric、Forge、NeoForge 和 Quilt。Paper 风格的插件服务器保留了普通的最新发布行为，并且没有版本选项卡，因为插件来自的两个注册表不发布任何可供检查读取的内容。

![打开一个版本，显示哪些模组会被留下](/docs/images/server-versions-expanded.png)

打开一个版本会首先列出没有构建版本的模组（决定答案的模组），并将已准备好的模组保留在点击之后。大型整合包一次加载一页模组，因此一个 300 个模组的服务器与一个 5 个模组的服务器一样快。

## 更改模组加载器版本

**版本**选项卡还有一个**加载器版本**卡片。它显示服务器已安装的 Forge、NeoForge、Fabric 或 Quilt 构建版本，以及在可以更改的情况下，一个选择器用于切换到另一个版本。

- **Forge、NeoForge、Fabric 或 Quilt 服务器**可以运行任何已发布的构建版本。选择器列出了服务器 Minecraft 版本的最新构建版本，并标记了 Forge 的推荐和最新构建版本。**其他构建…**通过其编号获取任何旧版本，而**默认**则恢复为让服务器选择。
- **Forge 或 Fabric CurseForge 整合包**安装其清单声明的加载器版本，因此更改它的常用方法是更新整合包。当整合包本身列出错误的版本时（其中一个模组要求比整合包安装的 Forge 版本更新），卡片可以覆盖它，而**整合包版本**会再次删除覆盖。更新整合包也会删除它，因为新版本声明了自己的加载器。如果新版本仍然列出错误的版本，请再次设置覆盖。
- **NeoForge CurseForge 整合包或 Modrinth 整合包**会显示其加载器，但无法覆盖：服务器镜像仅将覆盖应用于 Forge 和 Fabric 整合包。其加载器遵循整合包版本，因此请改为更新整合包。FTB 整合包的加载器也无法在此处更改。其卡片通常不会出现，因为 FTB 自己的安装程序保留了面板不读取的记录。

面板会在询问您任何问题之前检查构建版本是否存在。Forge 或 NeoForge 构建版本是针对一个 Minecraft 版本制作的，因此在遵循最新发布版本的服务器上，锁定一个版本也会使服务器保持在当前运行的 Minecraft 版本（确认信息会说明这一点）。之后选择**默认**会删除锁定，但会保留该 Minecraft 版本。遵循最新发布版本的服务器在重建时也可能会移动到不同的 Java 镜像，即该版本所需的镜像。从未启动过的此类服务器会被要求先启动一次，以便面板知道该版本。Forge 会跳过构建号（在 47.4.13 和 47.4.15 之间没有 47.4.14），因此“需要 47.4.14 或更高版本”的模组会通过下一个构建版本来满足，并且拒绝信息会命名它。更改会进行预更新备份，然后重建服务器。新构建版本会在服务器下次启动时安装，在此之前卡片会说明这一点。

## 撤销模组更新

模组更新的每个构建版本都保留在共享库中，因此损坏某些内容的更新是可逆的。模组选项卡上的模组行会有一个**恢复**按钮，可以将之前的构建版本放回去。没有下载，因此即使项目已从其注册表中删除，它也有效。您已恢复的构建版本将停止提供，直到出现更新的版本。

![将模组恢复到其更新前的构建版本](/docs/images/mods-revert.png)

## 应用更新

更新绝不会静默进行。当您选择升级整合包（或[将其切换到另一个版本](/docs/modpacks/#changing-the-pack-version)，包括旧版本）时，面板会：

1. 进行**预更新备份**（因此它是可逆的；默认情况下，每个服务器保留最后 10 个预更新备份，请参阅[保留](/docs/backups/#retention)）。
2. 重新锁定确切的新版本。
3. 重建服务器，如果需要，重新解析 Java 运行时。
4. 监控首次启动，并为每个平台设置时间预算。

如果它没有健康启动，您可以回滚到预更新备份。稳定跟踪服务器绝不会提供测试版，并且更新日志链接指向源提供时的真实版本差异。如果集成了 Discord，失败的更新还会触发 Discord [警报](/docs/integrations/)。
