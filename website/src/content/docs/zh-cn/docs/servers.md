## 创建服务器

点击**创建服务器**（顶部栏）或**创建服务器**卡片以打开向导。

![创建服务器](/docs/images/create-wizard.png)

向导会从设置页面的**新服务器默认值**预填充内存、CPU 和磁盘配额字段，管理员可以随时更改这些设置。

![新服务器默认值](/docs/images/settings-defaults.png)

您可以选择：

- **名称**（以及可选的图标、强调色和标签，用于组织您的服务器集群）。
- **服务器类型** - 原版、Paper、Fabric、Forge、NeoForge 等，每种类型在后台都映射到相应的 itzg 镜像。
- **Minecraft 版本** - `LATEST`、快照或特定版本。
- **资源** - RAM（堆内存）、容器内存限制、CPU 和磁盘配额。

需要模组包？**从模组包**选项卡会安装一个 CurseForge、Modrinth、FTB 或 GT New Horizons 包（请参阅 [模组包](/docs/modpacks/)），或者使用您上传的**自定义 zip 文件**：一个 CurseForge 模组包导出文件 (`manifest.json`) 或任何包含模组 jar 文件的 zip 文件。清单（或跨已识别 jar 文件的多数投票）会填充加载器和 Minecraft 版本，所有模组都将在一个任务中安装。您也可以从已保存的 [蓝图](/docs/blueprints/) 开始。

该面板会自动为您的版本选择一个合适的 Java 运行时，拉取镜像，创建容器，并（可选地）启动它，所有这些都通过一个表单完成。

## 服务器列表

**服务器**页面列出了您的所有服务器及其状态和快速统计信息。

![服务器列表](/docs/images/servers-list.png)

## 单个服务器

![玩家](/docs/images/players.png)

打开一个服务器会进入一个分栏工作区：

- **概览** - 状态、实时统计信息、运行时间以及主要的启动/停止/重启控件。
- **控制台** - 实时日志流和命令输入，以及游戏内聊天（[详情](/docs/console-and-chat/)）。
- **玩家** - 在线玩家，以及他们的物品栏、统计信息和[聊天命令](/docs/console-and-chat/)。
- **模组** - 已安装的模组列表、[模组浏览器](/docs/modpacks/) 和内容更新。
- **世界** - [世界、实时地图和文件管理器](/docs/worlds-and-files/)。
- **备份** - 此服务器的[快照和恢复](/docs/backups/)。
- **监控** - 每个服务器的历史和实时指标，包括崩溃报告（见下文）。
- **设置** - 服务器运行的所有配置，以及[集成](/docs/integrations/)（Discord、状态页面、邀请、聊天机器人）。

![服务器概览](/docs/images/server-overview.png)

**世界控件**栏会出现在每个选项卡上：游戏内时钟、天气、常见的游戏规则切换芯片，以及用于其他规则的“显示所有世界规则”。

![世界控件](/docs/images/world-controls.png)

**监控 → 实时**显示 TPS 和每刻毫秒数，一个健康和稳定性卡片显示过去 24 小时 / 7 天的崩溃和重启次数，以及每个世界的占用空间。

![实时监控](/docs/images/monitoring-live.png)

## 服务器设置

**设置**选项卡是完整的配置界面：重命名、资源、更新策略、自动启动/自动重启、环境变量和高级 Docker 覆盖设置。更改容器运行方式的字段会明确标记为需要重启。

![服务器设置](/docs/images/server-settings.png)

**关于内存计。**“RAM（Java 堆内存）”被用作 Java 的初始堆内存和最大堆内存，Java 会在第一分钟内填满其分配到的堆内存，无论是否使用 Aikar / MeowIce 标志预设。因此，内存计会稳定在堆内存大小左右，即使没有人在线也会保持不变；计上的刻度标记了堆内存相对于容器限制的位置，下方的注释会说明这一点。如果您希望内存使用量跟随实际使用情况变化，请设置一个较小的**初始堆内存**（高级设置）：在我们的测量中，一个 2 GB 的堆内存将空闲使用量从 2.6 GB 降低到约 1.3 GB。Java 在堆内存之外还需要内存（原版大约 0.5 GB，大型模组包需要 1.5 到 2 GB），这就是容器限制的预留空间。请参阅 README 中的“两个内存限制”以获取具体数字。

> 高级 Docker 覆盖字段（自定义容器名称、额外的端口和绑定挂载，以及原始覆盖设置）仅限**管理员**使用，因为绑定挂载加上面板的 Docker 访问权限相当于拥有主机上的 root 权限。请参阅 [用户和角色](/docs/users-and-roles/)。

## 崩溃报告和 mclo.gs 分析

崩溃报告（`crash-reports/*.txt` 和 JVM `hs_err_pid*.log` 文件）会被自动收集，解析成一行摘要，包含异常和疑似冲突的模组，并在**监控 → 历史**下列出：

![崩溃报告卡片](/docs/images/crash-mclogs-card.png)

每个报告卡片都提供内置查看器（带有可折叠部分和高亮异常）、复制堆栈跟踪和下载功能，以及两个 [mclo.gs](https://mclo.gs) 操作：

- **分享到 mclo.gs** 会将报告发布为公共粘贴文本并复制链接——这是模组作者和支持 Discord 要求的确切内容。链接会被保存在报告中，因此永远不会重复上传。
- **分析**会对粘贴文本运行 mclo.gs 的自动化分析：已知的带有建议修复方案的问题（缺失的依赖项、版本不匹配、常见的模组冲突），直接在面板中显示。

![mclo.gs 分析](/docs/images/crash-insights.png)

这两个操作都需要明确的确认，因为粘贴文本是公开的：崩溃报告可能包含玩家名称和您的完整模组列表。面板绝不会自行上传任何内容。
